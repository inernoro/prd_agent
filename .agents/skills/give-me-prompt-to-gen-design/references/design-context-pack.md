# 可分享的设计上下文包

当用户要求紧贴已有样式、统一组件行为或直接在现有骨架上设计时，交付一个包含最小可编辑工程的 ZIP。坚持用户已确认的限制，把其余选择留给设计者。自由探索可以只交付提示词。

## 内容与分享范围

- 必需入口用 `START-HERE.md` 标明实际技术栈、运行命令、从哪个容器或文件开始、哪些外壳属于系统、哪些代码可编辑或直接复用、哪些约束由原产品固定、哪些设计空间可自由探索，以及希望收回的文件和状态。
- 带上 `design-brief.md` 或同等内容的提示词。按设计者实际运行方式附最小入口、依赖清单和必要代码。优先选择已存在且被授权共享的组件、布局、样式变量和可运行样例。只有来源截图可用时写清素材范围与缺口。
- 颜色、字体、组件目录、现有页面截图、状态样例按需要挑选。每项标记为「要沿用」或「可以参考」。素材应能离线随包打开，或者明确记录其授权与依赖的公开入口。
- 用脱敏或合成数据。只复制用于这个容器的选中文件到独立目录。排除仓库历史、依赖缓存、环境文件、令牌、会话状态、内部地址与真实客户数据。发给用户与替用户向第三方发送是不同动作。

## 打包与自检

用工具现有的导出能力，或从已核过的 staging 目录压缩指定项。以下命令示例仅包含三个实际存在的条目，按需要列出当前实际文件：

```bash
cd "<仅含已筛选交付文件的目录>"
python3 -m zipfile -c "<产物目录>/design-context.zip" START-HERE.md design-brief.md starter
python3 -m zipfile -l "<产物目录>/design-context.zip"
python3 -m zipfile -t "<产物目录>/design-context.zip"
```

解压到新的目录，按说明启动或打开入口，点一遍关键状态。确认使用者能辨认编辑位置及可复用组件，确认最终清单只包含打算分享的文件。把 ZIP 的可访问链接和一段简短使用说明交给用户。
