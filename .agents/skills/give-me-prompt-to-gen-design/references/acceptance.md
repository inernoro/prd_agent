# 对照验收与拟真度口径

## 必交付表

| 标题 | 模块 | 验收报告 | 拟真度 |
|---|---|---|---|
| 具体页面 / 状态 / 视口 | 所属功能模块 | 实际执行结论、差异、证据入口 | 待评 / 等级与依据 / 有依据的分数 |

以上为字段示意，不是验收结果。每个真实条目应有稳定 ID、验收状态和对应版本。

验收状态使用“通过 / 需调整 / 阻塞 / 未执行”；用户判定另设“待审 / 通过 / 需调整”。不得预先替用户通过。

## 截图对齐

- 左侧必须来自固定版本的设计来源，右侧必须来自指定版本的真实系统。登记两侧来源，禁止同源自比冒充实现一致。
- 固定视口、设备像素比、浏览器、字体加载、页面缩放、数据、时间、筛选、展开状态、滚动位置和动画时刻。
- 先拍首屏，再按实际内容拍中段和底部。固定导航/工具区与滚动内容分别核对。
- 原始截图保持不变。裁剪、遮蔽或归一化仅用于辅助图，记录范围与理由。
- 真实时间或实时数据不同时，另列“数据差异”；能力缺失、文案换行和组件差异不能归入数据差异。
- 无法固定数据时记录限制，不宣称零像素差异。

## 拟真度

拟真度评价设计还原范围，不能替代功能是否真正可用的结论。

默认采用有说明的等级：

- **待评**：未检查，或证据不完整。
- **高**：本用例范围内布局、文字、组件、状态与适用交互一致，仅有已列明的轻微差异。
- **中**：主要结构可对应，存在可见的字号、留白、换行、组件或过渡差异。
- **低**：布局、主要组件、关键状态或交互存在明显偏离。

每次评价都写明检查范围、差异和证据。例如“中；已检查桌面首屏与详情静态态，详情换行及返回动画待修正”。只看静态截图时，不为动画评高。

用户明确需要数值时，先固定评分维度和权重，报告为“人工评分”，不能冒充像素相似度或自动测量。例如布局 30、字体与间距 20、颜色与材质 15、组件与状态 15、交互与动效 20，各项记录得分、依据和扣分。未检维度写待评，不擅自归一化成高分。

使用像素指标时报告图像尺寸、对齐方法、阈值、掩码、差异像素数及比例或实际算法。像素差异为零只说明该截图及环境下的结果，不代表所有业务与动效全通过。

## 交互与业务报告

每项记录前置条件 → 操作 → 预期 → 实际结果 → 证据。包含关键中间态及返回状态。

- 动效：入口、过渡、落点、返回、视角/滚动保持、减少动态效果。录屏应来自真实操作。
- 搜索筛选：结果正确、空结果、返回恢复及跨模块定位。
- 保存/接入：真实请求、成功与失败、刷新后保留、新对象初始状态。
- 通知/外部集成：按当前授权与环境验证。仅模拟时写明模拟，未发送不得报告发送成功。
- 加载：资源失败、控制台错误、损坏缓存等按项目需要检查，不用“本机能开”代替用户入口验收。
- 持久化/重启：需要时在隔离测试实例验证，避免影响用户正在使用的服务。

## 复核与版本

审核报告注明执行智能体、自审或实际独立审查者。实际允许时可独立复核；未发生的复核不写入报告。

报告与最终提交/构建 ID 绑定。修改后重跑受影响项。既有失败、跳过、未执行和阻塞保留，不用总通过数掩盖。

交付前验证表格行数、全部图片、原尺寸查看、录屏、报告、静态页面加载和结果导出。若用户要求公网验收且入口不可用，明确标为阻塞；本地通过独立保留。
