# 可复制的第三方设计委托

替换全部占位符；删除不适用项后再交给用户。不要将内部来源和执行凭据带入提示词。

```text
请为【公共产品/基础设施的通用描述】设计一套完整、可交互且可落地的高保真界面。

目标用户：【角色、使用场景】。
核心任务：【打开页面应知道什么、可以采取什么行动、成功结果】。

当前问题：
【列出具体问题，以及用户可观察的后果】。

必须遵守的视觉与产品约束：
- 品牌配色与状态语义：【来自现有系统的实际约束】。
- 导航、页面结构与内容：【必须保留的要素】。
- 页面利用方式与信息密度：【平铺/画布/列表等；首屏必须可见的信息】。
- 不采用：【明确被用户否决的布局或效果及原因】。

允许探索：
【可重新设计的构图、组件和交互范围】。

信息结构：
【全局、分类、对象等层级及各层内容】。
各操作的真实目的与数据语义：【状态、指标、更新时间、空档、错误】。

规模与分布：
最小：【】；典型：【】；最大：【】。
额外覆盖分类多、条目少、分类数量不均、长名称、异常集中等适用情况。
不得只针对一张截图或一种数据量优化。

交互与动态：
【进入、下钻、返回、搜索筛选、新增、更新、保存、重试】。
明确起始态、结束态、视觉锚点、运动方向、时长、缓动、中间帧和返回时保留的信息。
给出可操作原型；无法提供时交付完整运动说明。支持减少动态效果。

完整状态：
正常、异常、待确认、无数据、首次加载、空结果、请求失败、无权限、保存中、保存成功/失败。
【按实际业务补充接入、通知、鉴权等流程】。

响应式与长内容：
目标视口：【按项目填写】。
未指定时参考 1920×1080、1440×900、1280×800 和 390×844，并说明建议性质。
明确固定区、滚动区、伸缩规则、文本换行、溢出及窄屏导航。

交付：
1. 可编辑设计源文件和版本标识。
2. 全部页面、关键状态、不同数据规模和视口的画板清单及原尺寸截图。
3. 可操作交互原型或动画说明。
4. 组件、tokens、字体、图标和素材清单及可用来源。
5. 布局、响应式规则、组件状态和产品能力假设。
6. 缺少业务信息时列出假设，不把尚未实现的服务标为已经接通。

后续将按稿在现有系统实现，并逐页左右对照验收。
验收表至少包含：标题、模块、验收报告、拟真度。
请让设计中的状态和交互具备可复现的检查路径。
```
