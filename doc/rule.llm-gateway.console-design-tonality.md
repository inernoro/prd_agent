# LLM Gateway 控制台风格调性

| 项 | 值 |
|---|---|
| 类型 | rule（为什么不能那样做） |
| 状态 | active |
| 适用 | `llmgw/web/src/**` 全部页面 |
| 基准页 | 请求记录 `/logs` —— 一切对齐它，它变了其余页面跟着变 |
| 检测工具 | `llmgw/web/scripts/check-typography.mjs`、`e2e/llmgw-layout-drift.mjs` |

---

## 一句话调性

**数据是主角，界面是透明的。** 用户来控制台是为了读数据、找异常、改配置；
凡是不承载信息的东西（边框、标题、装饰、分隔盒子）都要让路。
好看不来自"加东西"，来自**同一层级的东西长得一模一样**。

---

## 五条原则

### 1. 一层卡片，不套盒子

一屏最多一层卡片。趋势图、指标、说明这类附属信息**不配拥有自己的卡片**：
- 趋势图 = 余光信息，无边框、无标题、无坐标轴，坐在表头正上方，可折叠，无数据时整块不渲染。
- 汇总指标 = 标题行下的一排小字（`请求 39 · 成功率 87.2% · Token 28k · 费用 $0.02`），不占卡片。
- 页面说明 = 标题下一句话；没有副标题层，没有 eyebrow 小标签。

判据：**主内容（表格/列表）在首屏占比 ≥ 60%**，非数据区不超过 ~250px。

### 2. 余量均匀，不许某一处独吞

眼睛对绝对空白不敏感，对**邻位之间的落差**极其敏感。一列宽松、邻列贴边 = 破洞；
所有列一起宽松 = 呼吸感。

- 列宽写成 `minmax(内容下限, 与下限等比的 fr)`，例如 `minmax(158px, 1.58fr)`。
  fr 权重与下限成正比 ⇒ 宽屏余量按比例摊给每一列 ⇒ 每列按同一百分比变宽。
- 判据：一屏内各列**占用率（内容宽 / 列宽）落在同一条窄带里**。
  参照 OpenRouter 的 48%~88%；出现某列显著低于邻列即为破洞。
- 表格最小宽度**必须由列自身下限推算**，禁止硬编码（历史事故：写死 1832px，
  怎么调列宽都强制横向滚动）。
- 数值列一律**左对齐**。右对齐 + 富余会在每列中间再撑出一条纵向空白山谷。

### 3. 字号只有七档，角色决定用哪档

档位定义在 `theme.css` 的 `:root`，角色映射定义在 `lib/typography.ts`。

| 档 | px | 角色 |
|---|---|---|
| `--fs-title` | 20 | 页面 h1 |
| `--fs-metric` | 17 | 指标数字、抽屉标题 |
| `--fs-heading` | 15 | 卡片 / 分区标题 |
| `--fs-body` | 14 | **正文、表格单元格与表头、表单输入、主要链接**（默认档） |
| `--fs-secondary` | 13 | 次要说明、字段名、工具条控件、mono 标识 |
| `--fs-caption` | 12 | 角标、tooltip |
| `--fs-micro` | 11 | 指标 caption —— 下限 |

口诀：**用户需要「读」的内容一律 14px；只有「扫一眼」的标记才允许更小。**
档位对了角色错照样翻车——历史事故：表格单元格用 12px、表头用 11px，
字号都在阶梯内，整页却比基准页糊一档。

### 4. icon 是扫描锚点，不是装饰

- 实体列（模型 / Provider / App）各带一枚 16px 圆角彩色标记，与文字间距 8px。
  作用是让"同一个 Provider 的行"在余光里自动成组。
- **没有品牌素材就用按名字哈希的确定性彩色首字母标记**（同名恒同色、异名异色），
  不要让所有陌生 Provider 退化成同一个灰云，也不要去抓别人的 logo。
- 表头 info icon 只给真正需要解释的列（全表 1 个为宜，4 个就是噪音）。
- **只有异常才配拥有视觉噪音**：成功行保持干净，失败/进行中的行用整行左侧色条；
  禁止给每一行都加状态圆点。
- 操作 icon 分级：无状态动作（刷新、更多）用无边框幽灵按钮；
  有状态控件（筛选、时间范围）带边框，因为它们会"亮起来"表示已生效。

### 5. 同一角色只允许有一种规格

这是最容易失守、也最影响"精致感"的一条。同一页/跨页出现多套规格，就会显得手工、拼凑。

| 角色 | 允许的规格数 |
|---|---|
| 卡片内边距 | 1 种 |
| 卡片圆角 | 1 种 |
| 主操作按钮（有无 icon、尺寸） | 1 种 |
| chip（高度 / 字号 / 圆角） | 1 种 |
| 指标展示 | 1 种（标题行小字） |
| 卡片底部操作行 | 1 种 |
| 容器间距 | 不超过基准页的种类数（新代码从 `surface.ts` 的四档里挑） |

### 附：数值格式服务于列宽

`$0.005097` 而不是 `USD 0.00509750`（14 字符白白撑宽费用列）。
符号前缀 + 有效位截断 + 去尾零。时间定长可读。

## 三层护栏（写歪了会被逐层拦住）

| 层 | 工具 | 管什么 | 何时跑 |
|---|---|---|---|
| 档位 | `pnpm check:typography` | 只能用七档字号 | CI |
| 角色 | 同上（第二条规则） | `th/td/labelStyle/inputStyle` 不许降到 caption/micro 档 | CI |
| 结构 | `node e2e/llmgw-layout-drift.mjs` | 页头是否裸露、内容是否撑满、表头与单元格字号、单行行盒、控件高度 | 改版后手动 |

## 历史背景

2026-07-28，用户拿 OpenRouter 的 Logs 页对比我们的控制台，连续三轮指出"不够精致"。
逐轮实测定位到的根因依次是：字号无 SSOT（9~24px 一次性字号满地）→
角色档位错配（表格正文塞进 12px）→ 结构差异（页头被关在卡片里、图表卡+指标卡两个盒子）→
列宽硬编码 1832px 导致强制横向滚动、51% 宽度空转 → 余量全灌进一列撑出空洞。

每一轮的教训都固化成上面某一条原则，并配了可测量的判据——
**"精致"不是感觉，是一组能被脚本量出来的数字。**
