## 明细

### D1 管道执行的供应链风险

- **是什么**：`curl ... | sh` 把远端内容直接交给 shell 执行。CDS 被攻破或 DNS 被劫持时，脚本内容即可被替换。
- **缓解**：UI 默认展示「先下载、可阅读、再执行」的两步版本，管道版折叠为快捷方式；脚本内不含任何密钥；脚本不改 shell profile、PATH 和用户主目录，破坏面限定在项目目录内。
- **什么条件下必须还**：对外正式推广之前，给脚本加校验和或签名，UI 同时展示期望的校验值。

### D2 无 Windows 原生脚本

- **是什么**：引导脚本是 POSIX sh，Windows 原生 PowerShell 环境跑不了。
- **为什么欠着**：目标用户（产品经理、老板）里 Windows 占比未知，先把一条路做穿比同时铺两套半成品有价值。
- **什么条件下必须还**：第一个 Windows 客户出现时。届时 CDS 按 User-Agent 或显式参数发 `.ps1` 版本，脚本契约不变。

### D3 预设不可自定义

- **是什么**：只能选预设，不能勾选技能自由组合。
- **为什么欠着**：先验证「预设」这个形态成立。过早给自由度会让「官方推荐组合」的价值被稀释——非技术用户面对二十个勾选框只会更迷茫。
- **什么条件下必须还**：出现多个用户反馈预设不合用时。MAP 侧已有依赖递归展开与打包逻辑，加一个接受技能列表的端点即可。

### D4 dev-project 预设缺套装

- **是什么**：`dev-project` 预设依赖的开发角色套装还没建。
- **关联**：`doc/debt.skill.role-bundle.md` D1。补一个套装是往 `scripts/skill-bundles.json` 加一个对象再重跑打包脚本。

### D5 代理缓存一致性窗口

- **是什么**：MAP 发布了新版技能后，CDS 缓存在过期前仍会发旧版。
- **缓解方向**：缓存带 TTL 且回源时比对 ETag；MAP 侧技能版本变更时可主动让 CDS 失效。
- **什么条件下必须还**：出现「客户装到的技能版本与预期不符」的实际反馈时；或缓存 TTL 需要拉长到小时级以上时。

### D6 phase0-guard 技能未编写

- **是什么**：设计里把 Phase 0 边界、六段式回复规范、术语翻译表、文档读者分层沉淀为一个技能，但技能本身还没写。
- **为什么重要**：这是把「四千字提示词」替换掉的关键载体。没有它，初始化出来的项目仍然缺少「AI 不许一上来就编业务实体」这条护栏。
- **什么条件下必须还**：实现阶段第一批就要写，它是 `pm-project` 预设的组成部分。

### D7 export-skill 依赖本地源码

- **是什么**：`GET /api/export-skill` 从 `config.repoRoot/.claude/skills` 现场打包，自托管 CDS 若不携带 prd_agent 源码，该端点会失败。
- **影响**：自托管客户能通过代理端点装到方法论套装，但装不上 CDS 自己的 5 个技能——而那 5 个才是操作 CDS 必需的。
- **可能的解法**：把 CDS 技能包也纳入代理路径（MAP 侧上架 CDS 技能），或 CDS 发布时把技能目录打进镜像。
- **什么条件下必须还**：第一个自托管客户要用项目初始化时。这条会直接决定该场景能不能走通，优先级高于 D2 至 D5。
