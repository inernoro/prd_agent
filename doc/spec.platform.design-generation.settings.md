# 网页生成设置与风格预设 · 规格

> **版本**：v1.0 | **日期**：2026-09-23 | **状态**：实施中

**一句话**：网页生成的默认执行器、风格预设和可编辑提示词都收进一份管理员可改的设置，每次运行把当时的设置冻结进任务书，出了问题能查到用的是哪一版。
**谁该读**：实现网页生成入口、设置页、OpenDesign 运行时的前后端研发；想调提示词或风格的管理员。
**读完能做什么**：知道设置有哪些字段、谁能改、一次运行怎样把风格与提示词带到 OpenDesign，以及界面上的入口在哪。

---

## 一、为什么要这份设置

此前三件事都写死在代码里：默认执行器是直连、OpenDesign 用什么风格没人指定（它自带的 151 套设计系统一套没用）、提示词散落在 CDS 源码里。结果是改一句提示词要发版，生成出来的页面千篇一律，出了问题也说不清这次用的是哪版提示词。

这份设置把它们变成数据：管理员在界面上改，改完下一次运行就生效；每次运行把当时的风格和提示词冻结进任务书，事后可追溯。

## 二、设置里有什么

| 字段 | 含义 | 默认值 |
|---|---|---|
| 默认执行器 | 生成与修改默认走哪条路 | OpenDesign（不可用时界面自动回落到直连并说明原因） |
| 自查强度 | OpenDesign 写完后的模型自查：关闭（不做模型自查，只剩发布闸门与修复回路）/ 轻量（一轮终审）/ 严格（终审后再加一轮只看视觉质量的复查） | 轻量 |
| 风格预设 | 用户在生成弹窗里能选的风格，每项对应 OpenDesign 的一套设计系统 | 内置 8 套通用风格，第一套为默认 |
| 创作提示词 | 新建页面时给 OpenDesign 的创作要求 | 内置默认稿，可整段替换 |
| 修改提示词 | 「帮我修改」时的要求 | 内置默认稿 |
| 自查提示词 | 写完后自查那一轮的要求 | 内置默认稿 |
| 平台契约 | 发布闸门必须满足的规矩（链接、按钮、占位、事实来源） | 只读展示，不可改 |

平台契约不开放编辑：它对应发布闸门的硬检查，改坏了页面会在最后一步被拒收，用户白等十分钟。可编辑的三段提示词拼在平台契约之后，只影响「怎么设计」，不影响「能不能发布」。

三段提示词只作用于精细设计（OpenDesign）。快速生成（直连）没有工作区与设计系统可读，只拿到所选风格的名称与说明作为视觉方向。发布闸门、修复回路与「修复次数上限」不受自查强度影响——关闭自查省的是模型终审那一轮，不是安全检查。

## 三、谁能改、在哪改

- 查看：有网页托管读权限的人都能看到当前设置（生成弹窗要用风格列表）。
- 修改：有网页托管写权限的管理员。每次保存记录修改人与时间。
- 入口：网页托管页面顶部「生成网页」按钮旁的设置按钮，直达「网页生成设置」；设置页里三段提示词各带「恢复默认」。

## 四、一次运行怎样带上风格与提示词

1. 用户在生成弹窗里选风格（不选则用默认风格），提交时带上风格编号。
2. MAP 创建运行时读取当前设置，把「风格编号、风格名、对应设计系统、三段提示词、自查强度」连同提示词指纹一起冻结进运行记录和任务书。之后管理员再改设置，不影响这次运行。
3. CDS 读取任务书：启动 OpenDesign 时指定设计系统，并把三段提示词接在平台契约之后。任务书里没有这些字段（旧运行）时，CDS 用内置默认，行为与改动前一致。

## 五、接口（前后端契约）

| 接口 | 用途 |
|---|---|
| `GET /api/design-artifacts/generation-settings` | 读取当前设置；风格列表、提示词（含是否为默认）、平台契约全文、修改人与时间 |
| `PUT /api/design-artifacts/generation-settings` | 保存设置；提示词传空字符串表示恢复默认 |
| `GET /api/design-artifacts/runtime-capabilities` | 其中的默认执行器改为读取设置 |
| `POST /api/design-artifacts/runs` | 新增可选字段 `styleId`、`attachmentIds`（直接上传的文件，最多 5 个；与知识库引用至少有一种） |
| `POST /api/web-pages/{siteId}/edits/runs` | 新增可选字段 `screenshotAttachmentIds`（截图，最多 3 张）、`attachmentIds`（补充资料） |

直接上传与截图都复用现有附件上传接口 `POST /api/v1/attachments`：文档类附件在上传时已提取正文，生成时与知识库条目一样作为事实来源放进任务书（只认本人上传的附件，正文合计不超过 6 万字）；图片附件原样放进工作区的参考目录，提示词里写明它只是视觉参考、不是事实来源。截图只对精细设计生效，快速修改收到截图会直接说明「需要换精细设计」，不会悄悄丢掉。直接上传的文件不写进网页的知识来源记录（那份记录只登记知识库条目，供之后「一键重生成」）。

「帮我修改」的单文件、无脚本限制只对快速修改保留：它把整页当一段文本改写，只能按声明式规则加固。精细设计拿到的是整站文件，产物按整包校验放行包内的脚本与资源，所以多文件、带脚本的网页可以用它修改。

运行记录新增 `styleId`、`styleName`、`designSystemId`、`promptFingerprint`，前端在运行详情里展示「本次用的风格与提示词版本」。

OpenDesign 运行期间，事件流新增 `preview` 事件：CDS 每隔约 8 秒查看一次工作区里的页面文件，变了就用本次运行的工作区传输凭证推给 MAP（与最终结果提交同一个受信地址），MAP 只写进事件流、不入库也不当产物；前端预览区随之刷新。预览推送失败不影响生成，但会在阶段事件里留一条记录。快速生成没有这一事件，前端用流式正文拼出预览。

## 六、验收标准

- 默认执行器为 OpenDesign：新开生成弹窗时执行器默认选中 OpenDesign。
- 选「编辑风格」生成的页面，与选「极简」生成的同稿页面在配色和字体上明显不同，且运行记录里写着各自的风格编号。
- 在设置页改创作提示词后，下一次运行的提示词指纹变化；恢复默认后指纹回到默认值。
- OpenDesign 运行中，预览区在首稿写出后一分钟内出现页面，而不是等到最后。
