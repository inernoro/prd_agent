## 四个概念的关系（结论）

| 概念 | 结论 | 依据 |
|---|---|---|
| 模型池 | **并进模型**，兜底降成行上一个「默认」标记 | 与逻辑模型逐字段对照，七项里六项一一对应（对外名、候选集、优先级权重、健康三件套、挑法、授权），唯一真差别是 `IsDefaultForType` |
| 模型（物理） | **收进上游详情**，不再是顶层入口 | `Model.PlatformId` 必填，脱离上游的模型不存在 |
| 上游 | **独立存在但降一级**，进「配置」区 | 密钥与地址是一对多：一把密钥挂一批模型，并进模型页就要重复配 N 次，轮换漏一遍即静默 401 |
| Exchange | **降成上游的一个属性**（协议要不要转换） | 它回答的是「这个上游协议标不标准」，不是另一类东西 |

## 为什么值得做

不是为了少几个页面。是**判据只剩一份**：池与逻辑模型两套熔断恢复实现各自漂移，2026-09-11 修的三个稳定性洞里有两个出在这儿——Offering 没有半开租约而池成员有，于是 Offering 熔断后永远不会自己回来。

## 明确不做

- 不改任何对外契约。调用方现在按什么名字请求，之后还是那个名字；池标识继续认，直到阶段 4。
- 不动 Mongo 集合名。旧集合原地保留，新表另写，回退就是把默认标记关掉。
- 不把四步合成一个 PR。阶段 4 不可回退，必须单独拿批准。
