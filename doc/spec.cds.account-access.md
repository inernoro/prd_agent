# CDS 账号与登录管理

对应设计需求 `cds/account-access` 和稿件 `DSN-AC303A86` V2。入口为「系统设置 › 账号与登录」，个人入口为「我的账号」。`/cds-settings#users`、`#auth` 和 `#activity` 仍可直接进入相应分区。

## 个人账号与登录

- 每个个人账号有稳定的 CDS ID。所有者可授予管理员角色，管理员管理普通成员，成员管理自己的登录。
- 首次激活链接有效七天，只在签发时回传一次。成员可自行设置口令，或使用此实例已开通的 GitHub 或 Google。激活保留原账号 ID、角色和项目授权。
- GitHub 依据数字 ID，Google 依据提供方主体标识。绑定使用当前浏览器的短时一次性流程和当前 CDS 个人会话。CDS 不按姓名、邮箱或账号标签关联身份。
- 解除绑定必须保留另一种可用登录方式。解除后旧会话失效，旧 GitHub 入口不会为这个身份自动另建账号。解除他人绑定需要逐次批准。
- GitHub 个人登录配置使用 `CDS_ACCOUNT_GITHUB_CLIENT_ID` 与 `CDS_ACCOUNT_GITHUB_CLIENT_SECRET`，回调为本实例 `/api/auth/external/github/callback`。
- Google 个人登录配置使用 `CDS_GOOGLE_CLIENT_ID` 与 `CDS_GOOGLE_CLIENT_SECRET`，回调为本实例 `/api/auth/external/google/callback`。
- 提供方状态以公开能力读取为准。两个应用各自独立于仓库 GitHub App 授权。仍在用的本地登录、GitHub 登录及 SSO 保留各自既有入口。

## 账号操作和恢复

| 动作 | 发起 | 批准、执行 | 记录 |
|---|---|---|---|
| 修改本人口令 | 有口令的本人 | 核验原口令 | 个人审计和会话退出原因 |
| 重置成员口令、停用账号、结束会话 | 所有者、管理员或获专门授权的设备 | 所有者确认目标、原因和影响 | 原申请和回执 |
| 授予管理员 | 所有者 | 授权即时生效 | 账号审计 |
| 撤销管理员 | 所有者 | 所有者逐次确认 | 原申请和回执 |
| 变更共用系统口令 | 所有者 | 核验当前口令、目标账号和通知确认 | 原回执、配置与会话代次 |
| 恢复个人登录 | 登录页提交 | 核实人与批准人分别确认 | 证据、审批回执及一次性恢复链接 |

逐次确认窗口为 30 分钟。会话或账号影响扩大后须根据最新状态再次登记。同一确认回执回读时不会重复修改。重置或恢复后的旧会话不能鉴权。共用口令和独立会话代次同时保存，口令改回原值不会恢复旧会话。升级前已经打开的共用浏览器在下次读取登录状态时登记到设备列表。实际使用者未知时按未知显示。

恢复核实记录引用实际证据，仅系统所有者签发和交付恢复链接。链接有效 24 小时，提交恢复申请的公开响应不透露账号存在情况。历史补录始终新增独立记录，并保存原始时间、证据和当时审批情况。

## Key 通知和 Agent

- 缺少签发账号字段的历史 Key 维持原受众。新 Key 的签发者、使用主体、审批者和通知接手人分别记录。经核实的移交只更新通知归属。
- 所有者能主动查看完整审批队列。个人收件箱和专用事件流按当前接收账号及项目范围返回。
- Agent 凭据须通过现有设备接入明确获提案权限，设备属于在用管理员，目标是同一授权项目内的普通成员。CLI 与 MCP 共用 `/api/auth/account-proposals`。回读限定原发起设备。受保护的确认、密码和账号审计仍按已登录人类的权限范围处理。
- CLI 使用 `cdscli account propose` 和 `cdscli account receipt`。MCP 使用 `--accounts` 服务的同名能力。各入口的可执行动作包括重置成员口令、停用及结束会话三种提案。
