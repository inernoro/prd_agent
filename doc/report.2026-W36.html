2. 多个分支同时开发，数据库不再互相踩

内部团队
以前
同一个项目的所有分支共用一个数据库。A 分支跑一次数据迁移，B 分支的预览立刻跟着变；想给某条分支单独一份数据，只能手工建库、手工改连接串，改漏一处就是「建了库但应用还连着老库」。
现在
项目设置里多了「数据库隔离」页签，每个服务可选共享库或分支独立库，保存前先写明这会影响哪些分支。选了独立库之后连接串里的库名自动跟着改，并明确标出「已跟随」还是「未跟随」；初始化可选「从共享库时间点克隆」，首次部署前自动拷一份，克隆完逐表数行数核对。所有派生出来的库进一本数据台账，按血缘成树，可备份、可演练验证（还原到临时库核对对象数）、可丢弃（门禁：必须有演练验证过的备份或手动复述库名）。分支数据要合回主库走派生库回写：先列冲突清单，回写前自动备份并演练验证（演练不过整个回写中止、目标库一个字节不动），回写后逐表校验，事后可一键回退。删分支时先展示会留下什么，派生库默认保留转台账孤儿条目，数据不丢。
意味着
多分支并行开发第一次有了「各自一份数据、要合的时候有门禁和后悔药」这条路；此前要么共用一份互相踩，要么手工建库然后忘记它的存在。

3. 钥匙丢了不再等于身份丢了；一个仓库能挂多个项目

内部团队运维
以前
部署平台的钥匙就是身份本身——钥匙文件丢了（换机器、重新拉代码、挪目录），就等于这个人不存在了，要走一次人工批准重新来过。而一个代码仓库只能绑一个项目，同仓放两个项目的话，推送只会触发第一个。
现在
身份拆成三张表（主体 / 用户级凭证 / 项目授权）。判据从「这个项目是不是我建的」改成「我在不在授权名单里」；钥匙丢了只要授权还在就当场自动补发，全程零人工；撤掉上级凭证，它签出去的全部下级钥匙同时失效。系统设置新增「权限总览」页，按人聚合、可撤销可停用，未认领的存量凭证明确标出。凭据自检把「未授权」拆成五类结论——有效 / 已吊销 / 从未签发 / 项目前缀不符 / 查不了。多项目那一侧：推送按仓库分发到该仓库名下的全部项目；每个服务可声明自己的构建输入范围，只改某个项目的代码不会把整仓重编；预览地址改由服务端派定，取不到时分三种情形说清楚，不再压成一句「取不到」。同批还修掉了兄弟分支共用同一数据库账号、互相覆盖口令的问题。
意味着
换机器不再是一次求人事件；一个仓库放多个项目从「只有第一个会动」变成「全部按各自范围分发」。

4. 打开分支总览，能看出它这半小时是什么状态

内部团队运维
以前
分支总览是八个等重方块（其中四个常年显示 0）加每服务一张大卡；抽屉一关指标历史就丢，窗口只有 5 分钟；而且它会说谎——部署正在进行时报「分支未运行」、就绪计数清零、当前值被抹掉。
现在
换成分段健康环、处理器堆叠面积图、内存横向构成条、吞吐双向图、部署耗时柱状图与入口卡组。指标历史下沉到服务端常驻采样（45 秒一轮），窗口拉到 30 分钟，抽屉关掉不再丢；没采到的时间桶留空、不画成 0；图的分辨率不细于采集节奏，避免整张图画的其实是采集节奏。出图前先给图形骨架 + 诚实进度（已有 N 帧 · 约还需 X 秒）。说谎那一类问题的根治是把总览的判断句、色调、入口卡副标题、骨架屏注解四处文案收敛到同一张有限状态表（九档全覆盖），替换掉五层嵌套的条件表达式，并配 25 条守卫钉住。

6. 授权失败第一次有一个地方能问「为什么」

内部团队运维
以前
用户会话、AI 访问钥匙、智能体钥匙、稳定冒烟签名、部署身份，五种授权各失败各的，都返回同一个「未授权」，看不出是哪一种、能不能恢复；更糟的是任何一次未授权都会触发前端刷新会话，于是一次智能体钥匙失效会把正在用的人踢下线。

意味着
「为什么突然没权限了」从一次排查变成一次查看——前提是它自己先验通。

7. 视觉创作：选了哪个模型就用哪个，等待时看得见进度

产品用户
以前
模型选择器里混着一堆写死的推荐型号，选了之后后端可能静默换成默认池里的另一个；换分辨率档会把 16:9 悄悄改成 1:1；生图等待时是一块纯平深色方块，进度条还会在放大或平移画布后跑出屏幕。
现在
选择器只展示业务模型（开放列表、默认项、排序和用途说明都在业务配置里显式管理），显式选择在授权范围内解析、禁用静默回退，结果里透传实际执行的模型；比例判定先认后端目录再退静态表，换档不再改比例。等待态改版：进度画在画框上，尺寸、阶段、剩余时间合并成底边一行，配色下沉到设计令牌、组件内零硬编码颜色；进度层跟着画布可见区域定位，缩放结束后补齐最后一次状态，选中时内缩到选择框里侧不再被盖住。
意味着
「我选的是这个、跑出来的是那个」这类困惑消失；等待期从一块静止的深色方块变成有产物形状的进度。

8. 管理员能看见每个人的导航长什么样，并一键清掉已下线的菜单

内部团队（管理员）
以前
导航顺序只能一个人一个人地看；菜单下线之后，已经排过序的人那里还留着一个点不开的入口，只能挨个重置——而重置会把人家自己排的顺序一起清掉。
现在
设置里新增「全部用户」视图：第一行是所有人的默认导航，其余每人一行，自定义的排前面、沿用默认的排后面，已下线菜单用虚线红框标出，可按人重置。新增「清理已下线菜单」：一键从默认导航和所有人的个人导航里拔掉目录中已不存在的菜单，不重置任何人的顺序；后端拒绝拔掉仍在目录里的菜单，防止权限不全的管理员误删别人的合法菜单。编辑器改用新的拖拽库，拖动时条目实时让位、支持键盘排序。同批下线了左侧的「模型」菜单——模型管理已经收口到模型网关，那个入口指向的是一个正在退场的页面。
意味着
菜单退场第一次有了干净的收尾动作，不再靠「让每个人自己发现点不开」。
