## 现状与目标

阶段 0 已提供后台启动总闸和有限请求窗口，但业务归属的用户 ID 不能证明人工触发，内部共享密钥也不能代表任意任务均获准。现有远程设计运行已使用有限次数短期授权，阶段 1 复用其服务端记录与原子核销原则，保持原来的限定能力。

新任务必须同时具备可信触发身份、明确操作与调用方范围、部署归属、有效期和正数次数预算。许可保存在网关治理库；后台服务获准启动只代表可以消费队列，不自动获得付费权限。

## 准入与来源

平台根据认证结果区分登录会话、Agent/API 凭据和自动调度；请求头、提示词、用户名字或业务中的用户 ID 均不能升级来源。会话表示一次已认证用户操作，不能证明操作鼠标的一定是人类；持有用户账号的自动化仍须受平台次数约束。

既有付费操作在集中登记表中申请许可。未登记的新操作可处理普通数据，但不得产生模型费用。任务许可随持久任务保存，恢复时核验其所有者、部署、过期与撤销状态；缺少许可的旧任务不能凭用户 ID 补发无限授权，需要重新明确提交。

一份许可下的队列范围和模型调用次数有限，共享父任务额度不能因生成新子任务而扩大。自动调度须提交具体有限任务，不能在后台服务启动时领取长期通票。

默认会话操作最多批准 128 次调用和 16 个执行对象；Agent 最多 16 次和 2 个对象；已登记调度最多 8 次和 1 个对象。已登记设计任务最多 256 次，运维自测只批准一次。许可最长 24 小时，恢复不延长有效期或补充次数。这是平台保守次数上限，尚不是金额预算或供应商账单。

执行来源与业务归属分别记录：管理员代办工作流保留原业务用户，操作者仍是当前管理员；自动调度记录调度服务，业务成员不会被误写成点击发起任务的人。匿名分享只能证明使用了已验证的分享凭据，不能据此确认访客真实身份。

## 统一出口

MAP 仅通过统一客户端访问 serving；模型选择仍由既有解析与发送合同决定。运输层自动附加经核验的任务事实，网关从服务端记录恢复来源和操作者，不信任请求自报字段。

Serving 新端点默认经过准入；只读查询、状态与健康路径采用精确白名单。新增业务忘记调用局部守卫不能绕过总闸。外部服务密钥与设计运行凭据保留各自既有范围，不能自报内部来源获取用户操作待遇。

运行时出口检查与构建守卫共同约束 MAP 的模型直连。是否达到网络层完全隔离必须以实际部署验证为准；不能把源码扫描当成已限制任意恶意程序的出网权限。

SDK 对话沿用用户已选模型和业务跟踪标识，运行器只取得父任务限定的短期密钥。CDS 托管运行的模型出口直接读取平台实际声明的网关入口；缺少声明时明确停止，不猜域名或回退厂商地址。网关进程内发送和实时语音首发、逐窗口也核验已批准事实。

构建守卫覆盖 MAP 和 serving 的新运输、供应商依赖与进程启动，已审计的附件、媒体和基础设施用途按具体调用保留。新增用途需要平台审计；不能靠把调用加进旧文件继承豁免。

## 验收设计

| 场景 | 必须看到的结果 | 主证据 |
|---|---|---|
| 正常登录后明确操作 | 产物正常返回，许可与请求能关联，来源来自认证 | 真实预览用户路径与网关日志 |
| 合法任务入队并恢复 | 同一许可保留来源与额度，不因重启重新发无限许可 | 持久化与后台回归，真实队列路径 |
| 漏登记操作、无许可后台调用 | 在网关/客户端前拒绝，上游执行次数为零 | 行为回归与预览负面请求 |
| 新增漏守卫网关端点 | 总闸拒绝，不执行端点的付费分支 | 真实测试宿主挂载未来端点 |
| 来源、租户、用户、调用方或部署伪造 | 不升级权限；许可范围不符则拒绝 | 入口合同回归 |
| 过期、撤销、非正额度及存储故障 | 不产生上游调用 | 故障回归 |
| 多实例并发核销 | 总成功数不超过许可预算 | 真实共享存储回归 |
| 只读和正常模型选择 | 查询可用，已选模型不被重算或覆盖 | 既有合同与代表性用户路径 |

验收先跑有限确定性回归，再用真实预览执行最小用户任务。高频拒绝用发送前失败或夹具证明，不产生大量供应商消费。测试必须分别记录通过、失败、未执行和存量跳过。
