# 网页托管与分享 · 设计

> **版本**：v1.0 | **日期**：2026-03-07 | **状态**：已落地

**一句话**：把一段网页内容变成可访问的站点：支持分享链接、密码保护与过期控制，其他功能直接调用建站能力。
**谁该读**：要把生成结果对外分享的工程师；关心分享安全边界的产品。
**读完能做什么**：说清托管流程与分享控制，并知道调用建站能力时必须填什么。

---

## 一、管理摘要

- **解决什么问题**：缺乏轻量级静态站点托管能力，工作流和视频 Agent 生成的 HTML 无法直接分享
- **方案概述**：用户上传 HTML/ZIP 文件，系统解压后托管到 COS 对象存储，支持分享链接、密码保护、过期控制；其他服务可通过 IHostedSiteService 直接创建托管页
- **业务价值**：为工作流、视频 Agent 等模块提供统一的网页输出和分享能力
- **影响范围**：prd-api WebPagesController + HostedSiteService、COS 对象存储
- **预计风险**：低 — 独立模块，不影响已有功能

## 概述

网页托管（Web Hosting）是一个轻量级静态站点托管平台，用户可上传 HTML/ZIP 文件，系统解压后托管到 COS 对象存储并生成可访问 URL。支持分享链接、密码保护、过期控制。

其他服务（工作流、视频 Agent 等）可通过 `IHostedSiteService` 领域服务直接创建托管网页，无需走 HTTP。

## 架构设计

### 分层结构

```
┌─────────────────────────────────────────────────────┐
│                   HTTP 层 (Controller)               │
│   WebPagesController — 路由: api/web-pages           │
│   职责: 参数校验、HTTP 状态码映射、Auth 上下文提取     │
└───────────────────────┬─────────────────────────────┘
                        │ 注入
┌───────────────────────▼─────────────────────────────┐
│               领域服务层 (IHostedSiteService)          │
│   HostedSiteService — 核心业务逻辑                    │
│   职责: ZIP 解压、HTML 改写、COS 上传编排、分享管理    │
│   可被 Controller / Worker / Agent 共同注入使用        │
└───────────┬───────────────────────┬─────────────────┘
            │                       │
┌───────────▼──────────┐  ┌────────▼──────────────────┐
│   MongoDbContext      │  │   IAssetStorage            │
│   hosted_sites        │  │   UploadToKeyAsync()       │
│   web_page_share_links│  │   BuildSiteKey()           │
└──────────────────────┘  │   BuildUrlForKey()          │
                          │   DeleteByKeyAsync()        │
                          └─────────────────────────────┘
```

### 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 存储方式 | COS 自定义 key（非 SHA256 去重） | 站点文件需保持相对路径结构 |
| HTML 路径改写 | 绝对路径 `/xxx` → 相对路径 `./xxx` | COS 子目录下加载资源需要相对路径 |
| 分享机制 | 12 字符 Base64 Token | URL 友好、碰撞率极低 |
| 服务层抽取 | IHostedSiteService 领域服务 | 其他模块可直接注入，无需走 HTTP |

## COS 存储结构

```
{prefix}/web-hosting/sites/{siteId}/
  ├── index.html
  ├── css/style.css
  ├── js/app.js
  └── images/logo.png
```

- **不使用 SHA256 去重**: 每个站点独立目录，保持原始文件路径结构
- **IAssetStorage 扩展方法**: `BuildSiteKey()`, `UploadToKeyAsync()`, `BuildUrlForKey()`, `DeleteByKeyAsync()`
- **域名路径**: `AppDomainPaths.DomainWebHosting = "web-hosting"`

## 上传处理流程

### 单 HTML 文件

```
用户上传 .html/.htm
  → RewriteAbsolutePathsInHtml（路径改写）
  → UploadToKeyAsync（上传到 COS）
  → 创建 HostedSite（1 个文件记录）
  → 返回站点信息
```

### ZIP 压缩包

```
用户上传 .zip
  → 内存解压（不落盘）
  → DetectRootPrefix（自动剥离根目录前缀）
  → 遍历文件：
     → 安全检查（路径遍历 / 禁止扩展名 / 大小限制）
     → 跳过隐藏文件和 __MACOSX 元数据
     → HTML 文件做路径改写
     → 逐个 UploadToKeyAsync
  → 自动检测入口文件：index.html > index.htm > 第一个 HTML > 第一个文件
  → 创建 HostedSite（完整文件清单）
  → 返回站点信息
```

### HTML 路径改写规则

将 HTML 中 `src="/xxx"` 和 `href="/xxx"` 的绝对路径改为相对路径 `src="./xxx"`，使站点在 COS 子目录下也能正确加载资源。

```
输入: <script src="/js/app.js"></script>
输出: <script src="./js/app.js"></script>

输入 (子目录): <link href="/css/style.css">  (entryFile = "sub/index.html")
输出: <link href="../css/style.css">
```

排除 `//` 开头的协议相对 URL（如 `//cdn.example.com`）。

## 安全措施

| 措施 | 说明 |
|------|------|
| 路径遍历防护 | 过滤 `..` 和绝对路径 |
| 文件类型限制 | 禁止 .exe/.dll/.sh/.bat/.py 等可执行文件 |
| 大小限制 | 单文件 500MB、解压总量 500MB、最多 20000 个文件；超过文件数上限时返回明确错误（「ZIP 包含的文件数超过上限，请删除无用文件后再上传」），不做静默截断 |
| macOS 元数据过滤 | 自动跳过 `__MACOSX/` 和隐藏文件 |
| 分享密码保护 | 可选密码验证 |
| 分享过期机制 | 可配置过期天数；过期判定统一走访问链接的豁免逻辑，历史分享链接不会出现「页面打得开、正文却报已过期」的不一致 |
| 分享撤销 | 支持主动撤销分享链接 |
| 匿名正文代理单请求上限 | 分享 token 域读取站点正文时对单次读取设字节上限与超时截止时间，防止单次请求拿分享 token 抓取超大或挂起的正文；不构成跨请求的频率限流 |

## 前端页面

### WebPagesPage (`/web-pages`)

管理后台站点管理页面，功能包括:
- 拖拽上传区（支持 HTML/ZIP）
- 站点卡片列表（iframe 实时预览缩略图）：缩略图渲染不受外部字体等外链资源加载慢拖累，超时不会永久卡在占位图标；大预览弹窗不会把「还在加载」误判成「加载失败」而盖住已渲染好的页面
- 筛选：关键词搜索、文件夹过滤、标签过滤、来源类型过滤
- 排序：最新/最早/标题/最多浏览/最大
- 站点操作：编辑元信息、重新上传、分享、删除、批量删除
- 一键分享弹窗（密码保护 + 过期天数）

### ShareViewPage (`/s/wp/:token`)

匿名分享查看页面:
- Token 验证 + 可选密码验证
- 单站点: 直接 iframe 展示
- 合集: 站点列表 + 选中后 iframe 展示
- 获取网页原文走服务端同源代理（而非客户端直接跨域抓取），避免降级方案因浏览器跨域限制而从未生效；打包型 SPA 入口直接走原始链接预览，不套同源代理的 `srcDoc` 包装，避免不透明来源下外链脚本被拦成白屏
- 原文加载遮罩限时让位给已渲染好的直链页面；让位后不会再用迟到的原文替换正在展示的页面，避免用户当面遭遇重载、丢失滚动位置与输入内容
- 页面自带的相对路径基准按站点真实地址重新解析，避免 `srcDoc` 预览下资源被解析到宿主应用自己身上

## 用户隔离设计

### 原则

网页托管数据严格按用户隔离，每个用户只能看到和操作自己的数据。

### 隔离范围

| 数据 | 隔离方式 | 说明 |
|------|----------|------|
| `hosted_sites` | `OwnerUserId` 过滤 | 所有查询/更新/删除都必须携带 userId 条件 |
| `web_page_share_links` | `CreatedBy` 过滤 | 分享链接只对创建者可见和可管理 |
| COS 文件 | `web-hosting/sites/{siteId}/` | 站点级隔离，siteId 全局唯一 |
| 文件夹 / 标签 | `OwnerUserId` 聚合 | 仅返回当前用户自己的文件夹和标签 |

### 实现要点

1. **Service 层强制 userId**：`IHostedSiteService` 所有方法都要求传入 `userId`，在 MongoDB 查询中作为必填过滤条件
2. **Controller 层提取身份**：从 JWT Claims 提取当前用户 ID，不接受前端传入的 userId
3. **匿名分享例外**：`ViewShareAsync` 不需要登录，通过 Token 查找分享链接后返回站点数据（只返回站点公开信息，不暴露 OwnerUserId）

### 不隔离的数据

- **匿名分享页面**：任何人持有 Token 即可访问（密码保护可选）
- **统一资产视图**：`WebPageAssetProvider` 也通过 userId 过滤，仅展示当前用户资产

## 向我提问（2026-08-11）

### 为什么只依据本页正文回答

分享页右下角的「向我提问」让访客针对当前托管站点直接提问，回答**只依据该站点的正文**，不接知识库、不接通用聊天上下文。这是刻意的边界：站点是创建者对外发布的确定内容，回答必须可被内容本身证伪——访客问到正文没提到的问题，系统应如实说「页面里没有提到」，而不是让模型自由发挥出一个查无实据的答案。

系统在提问前会对站点内容取一份「正文快照」：直读对象存储里的站点文件，覆盖单文件、多文件站点、PDF 包装站三种形状。正文体量超出预算时如实标记为「已截断」；如果站点的全部内容文件本身就超出单文件读取上限（比如唯一的一份大 PDF），快照会判定为不可用而不是硬凑一份空快照——两种情况都不会让提示词假装自己看到了完整内容。

### 默认开关与个人覆盖（2026-09-22）

「向我提问」此前系统级默认是开启的，访客一进分享页就能看到这个入口，即便创建者从未主动打开过它。修复后系统默认改为关闭——创建者需要显式开启，分享页才会展示这个入口，避免创建者在不知情的情况下就把模型额度暴露给匿名访客。创建者也可以在个人设置里配置自己的默认偏好，覆盖系统默认，新建站点时直接沿用这个个人默认，不必每次新建都重新勾选。

### 配额闸：保护创建者的模型额度

提问消耗谁的模型调用额度取决于访客身份：登录访客的提问记在访客自己账号下，只有**匿名**访客才回退到站点创建者账号——匿名提问本来就是在消费创建者对外开放的额度，这个归属才是对的。因此匿名访客的提问必须被限流，否则任何人都能通过反复提问烧光站点主人的额度。配额闸分两层，且各自的判定粒度不同：

- **访客维度**：登录访客按用户 ID 计数（每小时上限更宽松）；匿名访客按客户端 IP 的哈希值计数（每小时上限更紧，因为身份不可靠）。IP 哈希是粗粒度兜底——同一 NAT 出口的多个访客会共享同一个计数桶，且它不随浏览器会话刷新重置，这是已知的精度取舍，见 [debt.web-hosting.md](./debt.web-hosting.md) 条目 #34。
- **站点维度**：单个站点每天能被提问的总次数上限，防止某个爆款分享页被集中刷爆额度。

两层配额独立计数、独立拒绝。当前只在「配额已通过、但正文快照读取失败」这一种场景退回已扣的额度（避免用户为一次对象存储故障反复重试却烧光整窗配额）；访客维度或站点维度本身触发拒绝时，不存在跨层退回——即请求在站点日额度用尽后仍会被拒绝，但已经计入的访客侧计数不会因为这次被拒而回退。

### 开场问题：三态语义

创建者可以给分享链接配置「开场问题」（访客一进来就能点的引导性问题），这里存在三种状态而不是简单的「有/无」：

| 值 | 含义 |
|---|---|
| `null`（未设置） | 继承站点级题库——用这条分享链接的访客看到的是站点默认的一组开场问题 |
| 空数组 | 本条链接显式选择「不显示开场问题」，即便站点题库不为空 |
| 非空数组 | 本条链接使用自己单独挑选或新增的一组开场问题，覆盖站点默认题库 |

三态区分的意义在于：创建者需要能够精确表达「这条分享链接我不想放引导问题」，而不是被迫要么继承、要么留空但语义不明。

### 数据流

```
访客在分享页点击「向我提问」
  → 面板展示开场问题（若有）
  → 访客输入问题 → 先过配额闸（访客维度 + 站点维度）
  → 通过后取站点正文快照（缓存复用，读取失败不当作「无正文」处理）
  → 组装「仅依据本页正文回答」的提示词 → 走网关 SSE 流式生成
  → 逐字回传给访客，断线不影响服务端已生成内容的落库
```

回答失败时只向访客展示稳定的中文文案与错误码；网关或上游的原始错误会落进服务端日志与该站点的对话消息落库记录，但同样不会透传给匿名访客本人。这条消息记录目前只写不读——创建者尚无法通过界面查看，属于已知边界，见 [debt.web-hosting.md](./debt.web-hosting.md) 条目 #33。

「向我提问」其余的已知边界（IP 哈希粗粒度取舍 #34、正文快照文件数 off-by-one #26、追问历史失败后配对错位 #29、开场问题去重口径不一致 #27 等）见 [debt.web-hosting.md](./debt.web-hosting.md) 对应条目。

## 网页批注与讨论（2026-11-04）

网页评审的意见应留在所指内容旁边。站内预览与单站点分享页共用批注层：用户进入批注模式后点击元素或选择文字，页面保留编号与高亮；讨论侧栏展示原引用、回复及解决状态。整页评论沿用相同讨论模型，历史评论无需迁移即可阅读。

批注定位包含所属页面、内容版本、元素身份和文字上下文。滚动与窗口缩放后重新测量元素，优先恢复明确身份，其次接受唯一内容匹配；元素消失或匹配不唯一时保留讨论并显示原位置已变更，不猜测位置。批注模式拦截选择动作，退出后恢复网页原本交互。

凭据与保存请求由宿主处理，网页只交换定位事件。分享访问继续检查密码、有效期和可见性，写入仍需登录；回复只能归属同站点的根讨论，只有根讨论作者或站点所有者可以解决或重新打开。关闭评论同时关闭批注、回复及状态修改。

未登录访客可直接从批注入口登录，完成后返回原分享页、所选版本和讨论面板。禁用入口必须说明具体原因，区分站点关闭评论、登录状态失效、版本尚未加载和批注层未连接，避免只有禁用光标而没有下一步。

批注、显示切换与版本历史合在顶部的一体式工具条内，次要操作使用图标。讨论列表独立滚动，编辑器固定在面板底部。默认标准模式保留高亮、描边和编号；气泡模式在标注旁展开聊天式评论预览，一次只展开一条，支持关闭及进入对应讨论；隐藏模式收起页面标记。显示偏好不改变讨论数据或解决状态。批注入口采用柔和的周期提示，减少动态效果偏好下保持静止。

聊天气泡在宿主界面展示，评论正文和作者信息不传入托管网页。位置优先选择周围空白，不盖住所指目标，并保持在网页视口内；滚动时暂收起，停下后重新定位。手机切换到气泡模式时收起讨论面板，为正文和气泡留出空间。

进入全屏演示时收起讨论面板，让网页铺满视口；退出后可重新打开讨论，未发送的草稿保留。

桌面侧栏与页面并排，手机采用底部讨论面板，选取位置时收起面板。首版覆盖可运行批注脚本的普通 HTML 页面；严格声明式内容、原生 PDF 和内嵌第三方内容保留整页评论，具体边界见债务台账。


## 多版本评审与批注归属（2026-11-04）

版本列表只读取记录；尚未归档的当前发布仍作为当前版展示，旧版在覆盖前归档。读取分享不创建或改写历史资源引用，上传成功后直接返回已提交的站点，不追加可能导致误报失败的快照步骤。

顶部显示服务端记录的 V1、V2 等发布版本。作者或团队编辑者可上传 HTML、ZIP 新增并发布版本；上传前先保留当前网页及其全部资源，成功后直接展示新发布版，并在下一次覆盖前归档。选择历史版本只改变当前评审视图，不执行回滚，也不改变分享链接当前发布的内容。可推算地址上的历史资源在保留前复制到随机版本目录，引用切换后通过持久清理账本回收旧地址；复制失败不覆盖当前内容，旧地址未完成源站清理时不覆盖网页，也不创建或放宽对外分享。迁移会保留原内容与业务版本号，旧静态资源地址会失效，分享链接使用迁移后的地址。手动重传、AI 编辑、回退和整包发布共用替换层的核验；每次发布的入口及旁挂资源使用独立目录，当前版本地址不会暴露旧版归档目录。历史正文与资源字节不因地址迁移而改写。

每条根讨论绑定创建时所查看的内容版本，回复继承根讨论的归属。默认仅显示所选版本的批注及标记；“其他版本”列出其他历史讨论，点击版本入口后同时切换正文与批注。旧意见和解决状态不会自动复制到新版。发布记录不暴露草稿。分享链接只向外部访客开放当前发布版及对应讨论；即使已经登录，历史正文和历史讨论仍需独立的站点编辑权限，并继续校验原分享的密码、有效期与可见性。分享前已被删改的内容不会因新增版本入口而重新对外开放。站内团队只读成员同样只可访问当前版，版本与评论服务统一执行历史权限判定，不能通过站内路由绕过分享限制。

未记录版本的历史评论单独保留；找不到已保存快照的旧版讨论可读，但不猜测原网页，也不把其标记贴到新版。旧版未保留完整资源时禁用预览入口，避免把当前版内容冒充历史内容。历史阅读中的修改、提问及当前版下载入口会明确禁用或收起，防止动作落到错误版本。

为减少滑动滞后，已定位的标记随文档自身滚动；仅在正文结构变化时重新查找位置，滚动和缩放复用现有标记。运行时升级使用独立缓存标识，不新增用户内容版本，也不改变已有讨论的归属。

## 合集管理闭环设计草案（2026-11-10）

**状态：管理闭环已接入；以下说明现行规则与明确边界，验证结论以对应提交的测试和预览验收为准。** 遗留边界见[合集管理闭环审计](debt.web-hosting.md#合集管理闭环审计2026-11-10)。

### 先统一三个概念

- 合集负责长期组织内容：有名称、管理者、成员顺序和明确的主文档。
- 关联引用负责说明文档关系：区分作者手动组织与评论中产生的引用，引用保留来源，不自动变为合集成员。
- 分享负责授予本次入口的访问范围：密码、有效期和可见范围归分享入口管理，不能把同处一个合集视为已统一全部权限。

同一文档可以被多个合集引用，主文档和排序归属于各自合集。现有手动关联组仍限制一份文档只能归属一个组，两者独立保存。通过合集阅读时，导航使用该分享明确授权的成员快照；独立阅读仍使用原手动关联组。旧合集由作者在原分享页选择“管理合集”，确认名称与主文档后导入；原链接及成员范围保留，不自动建立、拆分或合并手动关联组。

### 创建与管理

| 场景 | 当前行为 |
|---|---|
| 创建 | 输入合集名称，确认成员与阅读顺序，明确选定主文档；历史未命名合集暂用现有数量标题，作者可补名 |
| 返回管理 | 作者在合集页和托管管理页都能找到同一个管理入口，修改名称、成员、主文档与分享设置，不另造重复管理清单 |
| 停止分享 | 撤销指定分享入口，说明其他仍有效入口；保留合集与原文档 |
| 移出成员 | 只移除本合集的归属；原文档及其独立分享继续按原规则存在，并清楚提示仍有效的对外入口 |
| 解散合集 | 展示本合集成员和需要失效的本合集分享入口，确认后解除内容组织并撤销这些入口；不删除原文档，不顺带撤销文档的其他独立分享 |
| 移出主文档 | 先明确选择替代主文档，再提交成员与主文档的整体变更；没有剩余成员时按解散处理 |

合集管理权只允许管理合集本身，不自动授予成员文档的编辑、再分享或权限修改权。删除原文档、管理合集和停止分享应使用不同文案，说明各自影响。

### 数量、顺序与阅读上下文

新合集支持 1–90 份文档。目录每页 12 份，可搜索标题和摘要，也可切换紧凑列表；成员在新标签页阅读，原目录的搜索、翻页和滚动状态保留。历史分享读取不按新建上限截断。候选文档和我的合集分别分页查询，避免把全部资料堆进创建弹窗。容量上限不是性能承诺，真实大批量数据的响应时间仍需独立验证。

合集主文档在导航中明确置顶，其余成员按作者保存的顺序展示；成员与评论引用可按来源筛选。自动引用按最近引用时间稳定排序，重复目标合并来源，不改变作者保存的成员顺序，也不自动选为主文档。主文档是合集的阅读入口，不能因为当前列表第一张卡片或当前访问者只能看见部分内容而静默更换。

### 权限与成员变更

默认保留文档原权限。管理者可查看差异，并在预览新增、收回的访问范围后主动执行一次性同步；主文档可作为明确选择的同步模板，但主文档身份本身不传播权限。同步仅限有权管理的文档和团队范围，无法处理的项目须明确列出，失败或中断后重新读取实际结果。

页面可见性、团队与受限分组、已有独立分享、合集分享入口分别核对。同步团队或页面权限，不代表其他公开分享已失效；密码和有效期不复制。评论引用不参与权限批量同步，访客看不到的来源标题、摘要与计数不展示。

合集内容组织与分享授权分开保存。修改名称、成员、顺序或主文档后，旧链接保留原成员快照；管理中标识早期快照，并引导先保存、重新核对访问范围、生成新链接，再按需停止旧分享。分享前展示所有目标成员、页面可见性与团队数量，校验内容版本及权限指纹；预检后发生变化时要求重新确认。新增成员不静默加入旧公开入口；移出成员不会撤回旧快照、其他独立入口、旧对象地址或已下载副本。停止全部分享先改变合集授权代次，阅读、正文、评论与保存共用服务端校验，阻止并发创建的旧代链接恢复访问。

权限差异与一次性同步复用已有规则；本轮仅在全部成员属于当前作者时开放同步。跨作者文档仍可按既有再分享权限加入合集，但不能通过合集管理替其他作者改权限。默认不修改原文档权限，也不把评论引用纳入同步。作者须明确选择对外访问范围；公开合集链接会授权其成员快照，不代表其他入口的权限已统一。

### 验收范围

验收优先覆盖真实创建、命名、重开管理、稳定排序、主文档更换、停止分享与解散的闭环。覆盖 12、30、90 份资料，以及长标题、无封面、主文档删除、跨作者、权限差异、旧链接仍有效、同步部分失败和历史合集重叠；模拟布局检查与真实业务验收分别记录，不能相互替代。
