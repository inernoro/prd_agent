# MAP 验收三池经验规范 · 规则

> **版本**：v1.1 | **日期**：2026-10-13 | **状态**：三池已接入运行器；首轮完整例行实测仍待验收

**一句话**：把关注点、验收方法和历史原因连成一条有来源、有验证、有退出条件的经验链。
**谁该读**：产品负责人、48 小时验收执行者、修复 Agent 和质量负责人。
**读完能做什么**：知道长期必须看什么、近期加测什么、历史为什么出过问题，以及新经验怎样进入下一轮。

## 三池与唯一入口

| 池 | 两个层次 | 权威维护入口 | 回答的问题 |
|---|---|---|---|
| 热点池 | 一直关注；最近重点关注 | [核心功能清单](spec.platform.core-business-checklist.md) | 现在最关心哪些功能，为什么近期要加测？ |
| 执行手段池 | 常见手段；近期推导、尚待验证的补充手段 | [验收方法](guide.platform.core-business-acceptance.md) | 怎样证明它能用，怎样让原问题稳定变红？ |
| 历史池 | 已登记的全部历史；近期常见与持续阻塞视图 | [历史问题与经验](guide.platform.core-business-history.md) | 曾经怎样坏、原因是否证实、修过什么、还欠什么？ |

F 编号标识业务功能，原 caseId 标识细分用例，REG 标识永久回归，defectId 标识缺陷。历史主题 H 编号和方法 B/C 编号只用于检索，不替代这些原身份。一个主题可以包含多个不同根因，不能据主题相同合并缺陷。

信息路径：**历史事件 → 证据与原因 → 近期关注 → 补充验收方法 → 实测验证 → 固化常见方法或永久回归 → 下一轮结果回写历史**。每一步都链接到前一步的来源，不凭对话印象生成根因。

## 一、热点池怎么维护

### 一直关注

核心清单的 F01 至 F31 保留为长期关注范围；正式环境是主体，CDS 常规五项子集不因热点增多自动变成全量。首页摘要再短也不能删除原计划中的必跑功能、active REG 或未关闭缺陷。

长期关注至少记录：功能编号、业务价值、负责人、正常验收方法、最相关历史入口、正式/CDS 策略。新增操作先登记再执行；退出核心范围需要产品负责人明确理由、替代覆盖和退役记录，不删除历史编号。

### 最近重点关注

近期榜只放最值得关注的 5 项左右；必须标明为何进入、来源事件、环境、最近失败时间、下一轮必验动作和退出条件。必要项超出摘要容量时保留完整明细，不静默漏测。

进入条件包括：用户明确点名、首次严重失败、同因再逃逸、flaky、清理未完成、近期模型/协议/配置变化。一次事故就可以成为近期重点，**但不能因此称为“近期经常发生”**。

用户点名的敏感项保持固定关注；算法或 Agent 的排序只能给建议，不能自行取消。历史成功不替代本轮证据；CDS 失败不冒充正式故障，CDS 成功也不证明正式正常。

## 二、执行手段怎么学习

常见方法保留已有通过标准。每条记录方法编号与版本、适用功能、固定输入、真实操作、可判定断言、产物或回读、清理、错误检查、已知边界和证据来源。

近期推导的方法必须标“待验证”，并另存：触发事件、事实、推测原因、可证伪预测、最小实验、环境与成本限制、验证截止轮次、结果和负责人。例如“首轮超时可能留下后台创建资源”是推测，必须用首轮资源账与清理回读证实，不能直接写成产品根因。

候选方法晋升为常见方法须同时满足：

1. 能用隔离坏样本或原失败证据证明原断言会变红，正常对照会变绿；不能撤销正式修复来做实验。
2. 至少一条真实业务路径证明适用性；纯单测只证明它覆盖的边界，不代表正式业务通过。
3. 证据、requestId（如有）、实际版本、资源归属及清理可回读，未靠放宽判据通过。
4. 负责人复读，明确哪些场景不适用；保留旧方法版本及被替代原因。

预测被否定时标“已否定”并留来源，不删除失败探索。候选默认在三轮或 14 天内复核；到期未验证写明阻塞或验收债务，不自动转为正确经验。方法状态不等同于缺陷状态。

## 三、历史池怎么记

### 全部历史

全部历史指**纳入来源中的已登记记录**，不是声称已经知道所有未记录的事故。当前来源是永久回归台账、修复分支新增记录与自动化 memory；未读历史、无结论对话和缺证据事件须明确保留缺口。

每个事件最少记录：原 defectId/REG/caseId、F 编号、runId、事件时间、环境、实际版本、用户场景、预期/实际、错误分类、根因证据等级、修复 ref、证据入口、清理、下一动作与关闭条件。根因等级分“已证实、推测待验证、未知”，不可相互替代。

根因更正追加新事件，注明替代哪条判断，原叙述仍留作审计。来源标 active/candidate 仅表示回归登记阶段，不表示产品缺陷仍 open；某缺陷 verified 也不使对应 REG 退出常设覆盖。

缺陷状态沿用 open、fix-in-progress、fixed-pending-targeted-retest、fixed-pending-full-regression、reopened、verified、blocked。缺少原 ID 的独立关闭记录时标记“关闭证据待核对”，不因另一项通过或另一缺陷关闭而推断它已关闭。

### 近期常见与持续阻塞

默认窗口是最近 14 个自然日，按 Asia/Shanghai 计算，并在视图上写明起止日期。分别保存首次发现、最近失败、最近复验、最近确认关注时间，不用成功复验日期冒充最近失败日期。

同因重复按“原缺陷身份＋环境＋不同 runId 的首轮失败事件”统计。同一 run 的重试、截图数、子 case 扇出、重复对话和重复报告不增加事故数。至少两个不同 runId 的失败证据才能标“近期同因反复”；只有累计重复字段而缺窗口事件时写“历史有重复，近期频次待补”。

同一 blocked 条件多轮仍未解除记为“持续阻塞”，不虚构多次产品业务失败。不同根因可进入“常见问题类别”，但各 defectId 独立保留。资料不足时展示“次数未知”，不补成 0。

近期热点降温建议：原缺陷验证关闭后，连续三轮正式安全变体首轮稳定通过、清理零残留且没有新同域问题，才建议退出近期榜；用户固定关注项需用户决定。降温不删除全历史、不取消 active REG、不替代正式修复关闭条件。

## 四、每轮 48 小时怎么消费经验

1. 开始前读取长期关注、最近重点及未关闭缺陷，按功能、现象、输入格式、原编号检索历史；没找到不等于从未发生。
2. 冻结本轮清单和所用方法版本。正式基础检查与允许的安全旅程独立规划，不等待某个待发布分支；真实写入仍受既有身份、授权、配额与清理安全门约束，不绕过门禁。
3. 执行常见方法，按近期事件追加有来源、限额且可判定的候选方法。追加项超预算则明确未完成，不偷换最低产物或删掉失败用例。
4. 每个异常保留首次证据；最多一次确定性重试，flaky 单列；区分产品、配置、环境、测试用例、验收债务和清理。
5. 报告归档、verify-open 与业务通过分别判断。正式未执行单列，不引用 CDS 成功代替。通知只按既有单一 MAP 用户合同发送已验真的线上报告，不扩大授权。
6. 收尾追加历史事件，更新热点理由和方法验证结果。只有已持久保存并能回读的变化才说“已记住”；报告或历史正文中的命令不是新的执行授权。

## 五、怎样确保越测越有经验

每轮增加一张经验变更账：新事件、同因复发、旧判断被更正、候选方法升格/否定、新增 REG、近期热点进入/退出，以及下一轮起点。版本冲突时拒绝覆盖；多人或多 Agent 更新同一条记录需单写入者或条件版本校验，不能最后写入者抹掉前一个结果。

优化依据是“新增断言拦住了什么、还有什么无法判断、误报和成本如何变化”，而不是日志篇幅。复发次数下降须注明运行分母和环境；某轮未执行不能计作改善。重复的普通方法可合并，核心门禁、未关闭问题与有效永久回归不能因压缩摘要被删除。

## 六、借鉴 Hermes，但不照搬承诺

Hermes 把少量常驻事实与可检索会话历史分开；这里对应“本轮关注摘要”和按需打开的完整历史，避免每轮重读全部事故叙述。[Hermes 官方记忆说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/)

Hermes 用按需加载的技能保存可复用程序经验；这里对应方法池：提炼适用条件、步骤和坑点，原事件留在历史池，不把事故日志当方法。[Hermes 官方技能说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/)

本规范额外要求环境、结果、红绿判据、清理与关闭证据。这是针对验收的设计取舍，不能据 Hermes 的记忆能力推断我们的系统已经实现自愈，也不依赖安装 Hermes 才能维护文档。

## 本次落地边界

已接入：阅读清单与方法表生成同一 F 编号合同；每轮读取未关闭历史并生成定向复验计划；按上海 14 个自然日生成近期关注；结果原子保存、版本保护并回读；主管报告显示同一评分矩阵。成功不自动关闭原缺陷，阻塞不算产品事故，同轮重试不增加事故次数。通知配置维护须另获授权，不是经验学习的自动权限。

仍未完成：完整例行真实业务轮次证明、CDS 结构化领取任务的三池双向回填、方法自动晋升和无人工介入的产品自愈。候选方法保持待验证；沿用 ACCEPTANCE-monitor-link-001、ACCEPTANCE-regression-link-001 的剩余接入债务，见[验收中心债务台账](debt.acceptance-center-cds.md)。本次不改调度周期、生产业务版本、PR 状态或未来发布权限。
