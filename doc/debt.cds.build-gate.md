# CDS 构建闸（build-gate） · 债务台账

> **版本**：v1.0 | **日期**：2026-07-16 | **状态**：开发中

**一句话**：记录构建排队机制那次大修里故意先不做的六件事，以及各自什么时候必须补。
**谁该读**：接手构建队列的工程师；构建又开始排长队时、想先确认「是不是已知问题」的排障值班。

### 发布前置与产品交接

本补丁改变常驻平台进程，没有验证过不重启的热加载或零中断切换路径。线上旧版的分支操作排空、部署及发布排空、状态落盘超时均可能继续重启。本次补丁对明确要求正数排空期限的原版本重启增加拒绝条件：任一排空失败、落盘失败或超时、最终复核发现未终态记录或新增分支操作，都返回失败，不安排重启或中断其他任务；成功历史在必要检查完成后才记录，拒绝只保留失败结果。陈旧心跳不作为执行已结束的证明；全局部署排空时间设为零也不能绕过该请求的安全检查。未选择该模式的历史默认策略保持兼容。

这一保护尚未在线生效，也不等于完整的无中断发布事务。旧进程首次加载补丁仍会走旧更新代码；原更新与强制同步先改工作目录及产物，再排空，拒绝重启不会自动恢复已换入的磁盘产物。本轮因此在这两个入口收到正数排空期限时，于任何 Git、产物或更新状态变更前返回明确拒绝；这表示受保护更新暂不可用，而非已经实现安全发布。未要求排空的历史更新路径不变。最终检查到延迟启动、进程退出之间也尚未建立覆盖全部内部派发的互斥屏障，因此禁止直接调用现有更新接口并宣称不会影响其他任务。

完整安全发布须独立补齐三个前置：在运行目录之外准备候选与可回退产物；在任何换盘前建立覆盖 HTTP、webhook、定时派发及内部重放的准入屏障；屏障持有到进程交接结束，超时、未知执行状态或落盘失败均取消换盘及信号发送。此结构变更跨越协调器、发布执行器及进程托管，不混入本次诊断补丁。维护者在这些条件未被实际验证前不能强行发布；本轮禁止共享重启的边界保持不变。

发布前需审查并集成本 PR 与所依赖的身份恢复来源分支，确认实际运行版本与预期起点一致，保存可回退版本；执行者须有有效的平台维护会话或主机运维会话。本轮只有项目范围的只读取证上下文，未验证线上维护权限或取得主机运维会话。预检通过也不等于补丁已经加载，发布后必须核对实际运行提交与进程启动时间。

平台维护者仍需在实际执行器上确认固定镜像内容、提交或组件等价性证明、平台与访问条件，并保留同一次阶段准入的资源与预约证据。平台放行后，由 APP-06 所属任务独占执行已批准的完整提交部署，核对全部 13 项服务状态和实际运行提交，再恢复产品验收；本 PR、本地测试或 CI 构建成功都不能代替这一步。若再次拒绝，应带回同一操作的产物核验或阶段超时事件，停止盲目重试，不通过修改 Profile 或业务四库绕过阻断。

### 只读容量证据与本轮复核

实际接口是 `GET /api/cds-system/perf-health`。补丁新增 `deploymentHostMemory`，报告门禁实际采用的内存采样来源、采样年龄和有效期、配置预算状态、daemon 用量样本及新鲜度、最终可用值；Linux 的 `MemAvailable` 与 `os.freemem` 回退明确区分。`deploymentPhases.start.queued[].memoryAdmission` 给出本请求需要量、其他预约、控制面余量、所需总量及缺口。读取不修改预算、预约或队列，不触发 Docker 盘点，也不返回环境变量原文或其他项目身份。

判定顺序：先排除无效预算和过期采样导致的保守零值，再比较有效余量与请求所需总量。预约异常必须结合不可变容器身份、真实运行状态及创建执行已结束的证据，不能因操作结束、缺少操作编号或当前看不到容器就清空预约。现有计算仍保守计入待确认的启动内存责任，本补丁不降低这项保护。

2026-10-15 20:58 PDT 的线上快照仍为 `500b08f55`：11 项其他分支启动请求报告内存余量不足，15 项预约共 7936 MiB，APP-06 排队和预约均为零；构建槽为空不代表启动容量充分。节点注册表的运行容器数为 21，而项目资源采样汇总为 89、66979 MiB；两者口径不同，均不能替代原始去重 Docker 盘点和宿主 `MemAvailable`。当前接口没有足够证据区分物理内存不足、预留重复计数、已结束执行遗留或启动成本估计偏差，仍未宣称根因已解决。

既有 `host.stats` 运维操作可只读获取主机信息，但执行须遵循平台系统所有者审批。本轮申请未取得可解析回执，受理状态未知，未重复提交；两次预留所属分支详情读取超时。项目范围凭据不替代维护身份。后续只读取证至少须包含同一时刻的可用内存、配置预算、daemon 采样年龄和预留容器身份，再决定是否需要容量算法修复。APP-06 的完整显式提交在部署输入中优先于旧 CI 缓存；认领预构建镜像仅更新元数据，不证明镜像校验或实际运行通过。

### 失败诊断的运行与日志证据边界

失败诊断现在先保留本轮产物或阶段准入失败，再核对已登记的完整容器身份、项目/分支/服务归属及容器启动时间。只采纳该部署时间范围内的日志；旧容器、身份缺失、归属不符、远端归属或日志读取失败均明确报告证据不足。正常退出码 0 不代表代码崩溃；容器不存在也不能单独证明应用有错。历史失败原文仍保留，不通过改写旧记录制造恢复结果。

共享数据库保护拒绝与普通进程退出区分，恢复应核对部署目标和保留的数据绑定，不能关闭保护或改绑定来放行旧版本。阶段队列已满和等待超时均不再保证旧服务可用；旧服务可用性需要独立的实际运行证据。

操作审计新增协调器收到的目标固定状态及版本引用。产物准入也会将缓存目标固定，因此固定状态不能单独证明原始请求显式指定了提交，仍须关联原始 HTTP 记录；默认的 user/manual 标签也不等于已识别具体人类。本轮旧目标事件已找到浏览器提交空请求体、随后内部重放固定旧目标的记录，但无法据此识别具体操作者。日志范围核验也不是退出原因证明：没有终态、退出码或业务错误证据时仍保留未知。此改动不改变镜像门禁、部署调度、资源上限、应用守卫或数据库。
