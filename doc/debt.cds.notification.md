# CDS 通知验收边界 · 债务台账

> **版本**：v1.0 | **日期**：2026-11-11 | **状态**：开发中

**一句话**：区分服务端可证明的投递与设备侧展示，并保留独立发送进程的升级要求。
**谁该读**：负责通知接入、发布与实机验收的人员。
**读完能做什么**：识别仍需设备或独立运行实例证据的检查项，不把受理回执当成已读。

| 边界 | 当前处理 | 关闭条件 |
|---|---|---|
| 手机与 Apple Watch 实际展示、字号与已读 | 服务端只记录发送与受理，不能证明设备实际显示或已读 | 用户实际设备核对同一演练消息，确认展示范围 |
| 独立手机发送进程 | 保留唯一发送所有权和持久化预算；CDS 项目脚本按固定提交切换程序和模板，失败回滚，私有配置及队列不迁移 | 运行实例提交与模板指纹一致，并取得真实发送回执；物理设备展示另验 |
| 独立进程服务器凭据的项目绑定 | 已关闭：既有主机已通过 CDS 系统配置预置到 MAP 项目，原项目 Key 读写发布目标通过；由服务器维持的私有部署连接已完成重连和权限限制验证 | 后续发布继续使用项目 Key、同提交 CI 和正常预检；独立进程实际版本验收仍按上一项核对 |
| 正式应用绕过 CDS 的变更 | CDS 内的发布、回滚与控制面启动有可关联记录。业务应用宿主机上的手动或自动重启、外部流水线发布、配置及数据库变更尚无统一事件来源 | 按已登记的生产目标接入运行时或 CI 审计事件，能在 CDS 失联期间独立记录并投递 |
| 紧急通知的备用出口 | CDS 失联由独立探针检测，状态页快照不可写时仍可提交告警。备用出口和真实值班确认、超时升级未接入 | 主推送出口不可用时，由不同通知服务报送同一事件并确认有人接手 |
| 存量报告未带交叉分类 | 保留原报告，显示未分类及环境待确认，可通过报告详情编辑分类 | 按真实证据逐份补录，禁止从标题猜成正式 |
| 监控检查次数与业务调用次数 | 明确分别统计，监控记录不推断用户失败任务数 | 上游或业务调用方提供结构化窗口和独立任务证据后按对应模板接入 |
| 通知生命周期改进的独立预览验收（2026-11-13） | 隔离样本验证持续、恢复、复发、知悉、免打扰及保存失败；正式实例只读取旧页面。本次不升级生产 CDS、不向真实用户外发演练通知 | 平台验收负责人以同提交的可运行 CDS 预览，从监控入口完成双主题、窄屏、动作与刷新闭环；设备外发仍按前述独立边界验收 |
