## 源码准备入口

在独立的本地平台工作区执行。命令只读取指定提交并写入该工作区已忽略的 `cds/.cds/platform-release-preparation/`，不调用 Docker、网络 API、线上更新接口或进程信号，不执行包内脚本。

```bash
# 在 inernoro/prd_agent 的本地独立工作区根目录；先完成本分支构建。
pnpm --dir cds build
# 两个变量都必须来自实际版本核对，使用完整的 40 位小写提交 SHA。
node cds/dist/cli/platform-release-preparation.js prepare "$PWD" "$candidate_sha" "$rollback_sha"
```

成功回执包含随机准备目录、清单 SHA-256、候选和回退源码包的提交及校验和。独立保存回执后再校验，不要从待校验清单重新生成“期望校验和”：

```bash
node cds/dist/cli/platform-release-preparation.js verify "$prepared_directory" "$manifest_sha256"
```

校验成功仍返回 `activationAllowed: false`。源码包只包含 Git 提交中的 `cds/`；未提交修改、其他应用目录、运行资料和依赖安装目录不复制。提交内若存在敏感资料路径、符号链接或 submodule，则拒绝准备。工具不自动 fetch、不 checkout、不 reset；回退提交不存在或候选未继承回退提交时直接失败。

源码包不是可直接换盘的运行产物，也不是签名证明。`origin` 检查用于防止选错工作区，不能代替可信提交审查；校验和用于核对回执后的内容完整性，不能代替 CI、供应链验证或发布授权。准备目录不是只读文件系统，不应由其他任务修改。

## 候选构建与校验

维护者须在准备目录下分别解包候选和回退源码，使用约定的 Node 与 pnpm 版本、冻结锁文件安装依赖，构建后端及 Dashboard，并保存最终产物逐文件校验和、依赖锁校验和、构建环境和精确提交。以下是候选的操作顺序；回退包同样需要生成经过验证的可运行产物。

```bash
mkdir "$prepared_directory/candidate"
tar -xf "$prepared_directory/candidate.tar" -C "$prepared_directory/candidate"
pnpm --dir "$prepared_directory/candidate/cds" install --frozen-lockfile
pnpm --dir "$prepared_directory/candidate/cds" build
pnpm --dir "$prepared_directory/candidate/cds/web" install --frozen-lockfile
pnpm --dir "$prepared_directory/candidate/cds/web" exec tsc --noEmit
pnpm --dir "$prepared_directory/candidate/cds/web" build
```

本轮没有将上述命令接到线上更新流程，也没有宣称源码回退包已完成运行产物构建。仓库完整测试依赖根目录设施，应在对应完整提交的独立工作区运行，不能以源码包中的局部测试替代仓库 CI。

## 首次换盘必须满足的条件

旧版 `500b08f55` 及本轮观察到的常驻进程不包含新补丁。向旧进程发送 `drain=true` 不能让尚未加载的保护生效。旧自更新先修改工作目录和产物，再等待排空；因此排空拒绝不代表磁盘未变化。禁止通过调用旧更新接口“试一下”来证明安全。

本轮后续补丁对解析为正数排空期限的自更新与强制同步返回 `safe_platform_release_unavailable`，发生在 Git 操作、构建、更新历史写入和重启安排之前，即使传入 `force` 也不能绕过。未选择该模式的历史更新行为保持兼容；原版本重启入口仍只有先前的局部排空保护，不是完整交接。不要改为无排空或原版本重启来绕过任务保护约束。

完整安全发布仍须由平台维护者实现、测试并单独授权以下步骤：

1. 准备并核验候选与回退运行产物；绑定当前完整 SHA、PID、进程启动时间、状态目录和宿主身份。任何漂移都重新预检。
2. 在换盘之前取得有明确所有者的独占维护租约，覆盖所有写入 HTTP、webhook、定时派发、内部重放及生产发布入口。已接受任务正常完成，新请求明确拒绝或可靠保留，不能中断任务或丢失待办。
3. 排空分支操作、部署和发布、准备读取与真实子进程，再完成状态落盘。未知状态、陈旧心跳、超时和落盘失败都拒绝换盘，不发送重启信号。
4. 持续持有屏障完成最终复核、产物事务和进程交接；不能在检查后至进程退出之间重新放行，也不能因租约到期而在换盘中途自动开闸。
5. 持久化事务日志。启动、健康检查或任一换盘阶段失败时按日志恢复旧产物与控制面；不得通过重建应用、修改 Profile 或业务库完成平台回退。
6. 核对新进程实际加载版本、PID 和启动时间，确认原应用容器身份及数据保持后才恢复准入。提前返回的 SSE、Git HEAD 或构建成功均不是发布成功证明。

首次安装还需要独立于旧进程的维护控制与进程托管路径；当前未验证该路径，也没有已验证的零中断热加载方案。必须先在隔离环境模拟旧基线、活动任务、晚到请求、落盘失败、换盘失败和控制器崩溃，证明拒绝时旧文件与进程不动、回退不操作应用。禁止把只有观察快照的检查当成互斥屏障。

当前保持共享平台运行，不进行换盘或重启。未来控制面交接可能短暂影响 API/SSE，持续时间未验收；若无法满足当时的任务保护要求，应记录具体维护窗口依赖并延期发布。HMR 性能目标保持暂停，其他项目与应用业务验收继续由所属任务负责。

## 交付验收边界

本工具的真实 Git 与文件系统测试覆盖：精确版本打包、候选继承关系、错仓库、敏感资料和链接拒绝、已忽略目录限制、并发准备互不覆盖、候选/回退/清单篡改检测，以及原工作区修改、应用文件、运行文件与分支身份保持。测试成功只证明准备工具的行为，不证明完整发布屏障或线上换盘成功。

局部屏障的回归覆盖真实分支协调器、生产发布服务及维护路由：取消资格后仍在执行的任务继续阻止维护；SSH 未返回时，发布账本终态不能解除阻塞；既有任务可完成派生工作，新的发布和回滚拒绝受理；落盘超时或取消不提前恢复准入。分支协调器目前只接受完全空闲时取得维护资格，准备请求、待重放和续接存在时直接拒绝，不取消或清空它们。没有模拟成功换盘，也没有共享平台发布验收。

完整屏障的完成条件见上节；优先级为平台发布前置，负责人为平台维护者。在完成之前，诊断修复可以审查、集成和构建，但不能宣称已经安全发布或阻挡应用日常验收。
