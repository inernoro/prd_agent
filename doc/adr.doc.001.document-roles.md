# ADR-DOC-001 文档原则与决策记录分层 · 架构决策

> **版本**：v1.0 | **日期**：2026-11-06 | **状态**：已接受

**一句话**：用原则文档解释各类文章的职责，用独立的架构与产品决策记录保存选择历史，让当前方案和历史依据各有位置。
**谁该读**：维护本项目文档分类、编写规格与设计、记录产品和技术决策的人员及 AI。
**读完能做什么**：选对文档前缀，理解原则、现行说明和决策历史的分工，并找到各类型的写作依据。

## 决策身份与依据

- 编号：ADR-DOC-001；领域：文档协作结构。
- 提出与接受日期：2026-11-06。
- 决策依据：本轮项目用户明确要求以 pri 缩写解释文档类型、建立 adr 与 pdr 文章类型；本文将该指令落实为分类约定，不代表用户批准了其他技术或产品提议。
- 维护责任：项目文档维护者；本文由 AI 整理，未代填个人姓名。
- 适用范围：本仓库根目录原则入口、长期文档及其校验和索引。
- 取代关系：无；此次为首次建立该分层记录。

## 背景与约束

原有长期文档按规格、设计、计划、规则、指南、报告和债务分类。设计文档要求持续反映现状，ADR 又要求保留已作选择的历史；将两者放在同一前缀会产生维护冲突。上一轮还把 Principles 的解释文字写入文件名，无法表达用户要求的类型体系。

## 候选方式与取舍

继续把决策放在设计文档中，入口少，但当前方案和冻结历史容易混淆；给所有文档加历史章节会让普通规格也负担决策流程；采用职责分层会多出少量原则入口和决策文件，但能保留不同内容各自的更新方式。

## 决策

采用职责分层。根目录 `pri.<类型>.md` 解释该类文章的作用、最少内容和维护方式；具体长期内容保留原七类，同时新增 `adr` 与 `pdr` 两类。

- ADR 保存重要架构、技术和工程流程选择；PDR 保存重要产品价值、业务语义与体验承诺选择。
- 规格、设计、规则与指南持续反映当前适用状态，通过链接引用决策依据。
- ADR/PDR 从提议进入审查，接受或拒绝后保留正文；重要变化使用新编号并维护取代关系。
- 根目录原则是写作方法入口，不是具体决策实例，不放入 `doc/` 的业务文档清单。

## 后果与落实

收益是未来读者能区分“当前怎样做”和“当时为何这样选”。代价是维护者要同时保持类型入口、当前说明和决策链接一致，因此不为普通小改动新增决策记录。

本次接入原则入口、类型规则、可读性校验、索引与初始决策记录。没有因此改变应用接口、存储结构或业务审批方式。初始记录各自标明状态，不能因本条已接受而把它们一并视为通过。

## 验证与重议条件

验证文档前缀、导读、链接、索引一致性与现有可读性守卫。出现读者持续分不清类型、内容重复维护或分类无法支撑真实任务时，由文档维护者重新评估并提出替代记录。
