# CDS 自动化任务健康与安全恢复 · 指南

**一句话**：负责人能分清任务为何没有完成，并通过核实已有产物恢复，避免重复调用和发布。
**谁该读**：任务负责人、报告生产流程维护者、CDS 运维与验收人员。
**读完能做什么**：配置报告验收、识别漏跑和失败、选择安全恢复路径，并理解通知与隔离演练的边界。

## 从哪里查看

进入 CDS 的「任务调度」，选择任务。地址保留所选任务，刷新后仍回到该任务；仅切换任务不重新加载整页。列表与详情展示服务器判定的健康状态；运行记录保留应执行时间、失败类别、逐步结果及已验证报告入口。最近成功率只统计定时运行。手动执行的成功不会消除定时漏跑或定时失败。

| 状态 | 含义与负责人动作 |
|---|---|
| 已暂停 | 不参与自动调度；恢复产物验证不会启用任务 |
| 未到执行时间 | 当前计划尚未到期，保留上次定时运行证据 |
| 已到执行时间 | 在调度宽限范围内等待认领 |
| 漏跑 | 应执行时间已过宽限，或已启用任务没有有效排期；核实调度与依赖 |
| 执行失败 | 命令退出异常、HTTP 非成功或动作异常，查看运行证据 |
| 执行超时 | 外部结果可能未知，先查询已有结果，禁止盲目重放 |
| 产物验证失败 | 执行返回成功，但报告数量、正文、归档或验收结论不符合要求 |
| 进程中断 | 持久化运行尚未结束，进程已经更换；只核实已有产物 |

默认调度宽限为两分钟，可按任务调整。漏跑留下失败批次并推进后续排期，不自动补跑过时批次。暂停、仅手动与事件驱动任务不因时间流逝判为漏跑。

同刻到期的不同任务先分别认领，不因等待其他长任务而错过宽限；同一任务仍遵守并发跳过和批次幂等。push 规则依据最近一次 push 的结果判断健康，发布失败会走原告警链路；手动成功和历史裁剪不会清除该故障，新的 push 成功后才恢复等待事件。

同一任务的并发跳过也会终结该批次并推进排期，不在前次结束后补跑，且不覆盖前次执行的失败。重启时先阻断所有结果未知的任务，再等待任务状态落盘；核实完成前，人工和自动入口都不能重放这些任务。

## 报告生产与定期验收

任务编辑的高级设置提供「报告验收」。可以要求报告数量、对象存储归档，以及仅接受验收通过的报告。未声明报告契约的已有 HTTP、命令任务沿用其执行结果；系统不会凭任务名称猜测业务产物。

启用前，报告生产流程必须支持将本次任务的运行标识带入归档。HTTP 生产者从请求中的 X-CDS-Job-Run-Id 取得标识；命令生产者从 CDS_JOB_RUN_ID 环境变量取得。归档时通过同名 HTTP 请求头，或 JSON 的 scheduledJobRunId 字段传回。归档只接受真实且同项目的运行。

任务在执行成功后继续等待报告，仍受原总期限约束。必须能读取实际正文，正文非空且字节数吻合，并满足归档和结论要求，才记为完成；同时保留报告 ID、正文哈希和字节数。别的项目、旧运行和只有元数据的报告不能充当本次产物。原报告中心继续承载展示和归档，不增加新的产物库。

## 恢复与重复触发

任务在调用外部服务前先确认批次与游标已持久化。同一应执行批次不再次执行；重复 webhook 的同一分支版本不再次发布。人工请求可携带带时间戳的幂等标识，最近请求复用结果，更旧的请求拒绝重放；无幂等标识的人工操作仍是一次新的明确执行。

发生进程中断、超时、产物验证失败，或有副作用的写请求与命令失败时，任务进入待核实状态，后续自动执行被阻断。点击「核实已有产物」，只验证该运行的报告或查询已经关联的发布终态。它不重新调用生成器、不再次发布、不启用暂停任务。验证通过后解除该运行的恢复阻断，并保留原失败种类、原因和时间，以及此次核实时间；验证不通过时保留原状态。漏跑批次没有执行，不能凭人工补报告标为定时成功。

自动重试只适用于 GET。发布、写请求与命令不自动重试。对于没有报告契约、没有可确认发布关联的未知副作用，系统拒绝自动宣布恢复成功；负责人必须先在原服务核实，再决定是否配置新的执行任务。幂等请求头不能替代外部服务自身的幂等支持。

## 通知与运行边界

故障事件进入既有事件总线、站内信账本及其已配置渠道，按任务合并并提供任务深链。不新增收件人、Webhook、电话号码、邮件或授权。

已有存活探测轮次只观测任务健康，所以任务调度循环停摆时也可发现逾期；它不会执行任务。如果整个 CDS 进程停止，仍依赖原有独立存活监控。如果原存活探测被关闭，本变更不会将其启用。通知账本的外发结果以原通道回执为准，代码演练通过不代表线上外发验收通过。

调度仍使用现有单进程、单写者状态架构。多个 CDS 主进程同时写同一任务状态不是分布式认领协议支持的运行方式。

## 回归与隔离演练

永久回归覆盖状态区分、手动成功不掩盖定时故障、幂等请求、持久化失败阻断、真实归档验证、项目隔离与原通知通道映射。隔离演练通过现有任务服务和真实回环 HTTP，强制终止子进程再重启，核实已有报告后恢复，并断言模拟付费与发布各发生一次。

页面诊断命令为 pnpm -C cds smoke:task-health-recovery，覆盖桌面与手机的明暗主题、恢复记录、任务选择与刷新连续性；CI 保留截图及带版本来源的报告。该诊断使用隔离数据，不能代替相同提交的公开预览与真实报告生产链路验收。

演练使用临时状态目录、无业务凭据的子进程与拒绝生产发布的服务端口。它不读取线上任务、不修改暂停状态、不连接付费服务。上线或更改任何存量生产任务仍须单独获得授权。
