# 通用对话智能体 · 设计

> **版本**：v1.0 | **日期**：2026-08-05 | **状态**：待决策

**一句话**：给全员一个能直接对聊的通用智能体入口，多轮不丢、对话里出图、说一句就存进知识库，执行体跑在主服务进程内不新增运行时。
**谁该读**：要拍板这次改动的决策者，以及接手实现的工程师。
**读完能做什么**：判断该不该做、边界卡在哪，并知道验收时该核哪十条。

配套的可交互方案预览（含操作页面演示、架构图、数据流转图、角色业务流）：[通用对话智能体方案预览](../assets/prototypes/chat-agent-preview.html)。

## 管理摘要

- **问题**：平台有十几个各司其职的智能体，唯独没有一个「打开就能聊」的通用入口。用户问「你们这么多智能体，我想随便聊聊、聊着聊着让它出张图、再把结论存下来，去哪儿？」，答案是没有。现有那个面向工程的对话入口定位不同、链路长、要二次认证、延迟高，普通用户用不了也不该用。
- **决策**：新增一个通用对话入口。不新建运行时、不新建鉴权、不改现有表结构；执行体跑在主服务进程里，工具用进程内直调，首版只开三把工具（出图、写知识库、查知识库）。
- **价值**：三个用户诉求一次答完——有地方对聊、对话里能生图、结果能沉进知识库。同时把「过度开发」的风险用范围契约和熔断线钉死。

## 为什么现在做

三个诉求来自真实提问，且都指向同一个缺口：

1. 「有没有类似聊天功能的智能体，我该在哪用」——缺的是**入口**，不是能力。
2. 「能不能对话里生图、能不能持久化到知识库」——出图和知识库都已经是成熟能力，缺的是**把它们接到对话里**。
3. 「不要过度开发，别又搞成一坨」——缺的是**明面上的边界与熔断机制**。

前两条说明这次改动的技术风险很低（复用远多于新增），第三条说明真正的风险在工程纪律，不在技术。

## 砖已经都有，缺的只是一条装配线

平台现成可用、本次直接复用的能力：

| 能力 | 现状 | 本次怎么用 |
|---|---|---|
| 任务队列与事件流 | 已有，服务端跑完、客户端断线可续订 | 对话的每一轮就是一个任务 |
| 工具注册与调用 | 已有，含审批机制 | 三把工具注册进去，进程内直调 |
| 出图流水线 | 已有，产物落素材库 | 出图工具转发给它，不重造 |
| 文档空间 | 已有，含权限与分享 | 写入与检索两把工具的落点 |
| 模型网关 | 已有独立部署，含模型池与调用日志 | 唯一的模型出口，天然可观测 |
| 消息渲染组件 | 已有 | 前端直接复用，不重写 |

因此新增部件只有两个：对话接口层与对话执行器。这是这份方案敢承诺「不会变成一坨」的物理基础——可写的代码本来就不多。

## 数据怎么流动

一轮对话的完整生命：用户在页面说一句话，主服务校验登录态后建一个任务并入队，入队时盖上部署作用域标记；对话执行器接单，把上下文交给模型网关；模型如果只出文字就直接收尾，如果要求用工具，执行器在同一个进程里直接调用对应工具，把结果回灌再问下一轮，轮数有硬上限；全过程的每个事件按序号落库并推回页面，页面刷新或换设备回来按序号续订，内容不丢。

三个鉴权点，没有一个是新发明的：

- **页面到主服务**：就是用户当前登录平台的那把凭据，不发第二把钥匙。
- **主服务到模型网关**：网关的内网服务密钥，用户既看不到也不需要知道。
- **工具读写数据**：沿用发起这次对话的人的身份，权限不放大。

失败一律显式：模型失败、工具失败、轮数超限，三种情况都在页面上转红并写清原因，会话不中断、可就地重试，且不留半截数据。用户中途离开不取消任务——这是平台既有的服务端权威原则，本次沿用。

## 关键取舍

**取舍一：为什么不复用现有那个面向工程的对话入口。**
它把执行体放在分支预览容器里，链路长、认证多、延迟高，而这三样正是用户抱怨的内容；它的定位是给工程做基础设施操作，人设与权限模型都不同。改造它比另起一条干净路径更贵，还会把两件事绑死。本次不删不改它，只是不用它，风险为零。

**取舍二：为什么执行体放在主服务进程内而不是独立服务。**
独立服务意味着新增对外容器、新增服务间认证、新增部署拓扑说明。首版的工具全是平台自身能力，进程内直调是最短路径。等真需要横向扩容或隔离时再拆，那时已有真实负载数据支撑，不必现在拍脑袋。

**取舍三：为什么首版只开三把工具。**
用户提的三个诉求，这三把正好一一对应。多开一把就多一层权限收敛和错误路径，而收益要等真实使用才知道。宁可先上线收反馈，再按真实呼声排序。

**取舍四：为什么另起一套会话记录而不复用现有的。**
现有会话结构绑着产品需求解读的角色概念。混进通用对话会互相污染，以后谁都不敢动。新开一套的成本远低于日后解耦的成本。

## 明确不做（本期承诺）

联网搜索与网页抓取、上传文件解析、自定义人设与角色市场、跨会话长期记忆、把工具箱内全部能力一次性接入、改动任何现有表结构或鉴权。

这六条不是做不了，是首版故意不做，全部进技术债务台账，等真实使用反馈到位后再排优先级。写在这里就是承诺不偷偷做，也不假装有。

## 熔断线

命中任意一条立即停止推进并升级给决策者：

- 连续八个提交没有新增可用功能，只在改文档、脚本或计划。
- 工具数量超过三把，或出现「顺手把某某也接上」的提议。
- 改动触碰到跨容器代理、既有那个面向工程的对话入口、或任何鉴权代码。
- 改动行数超过第一轮基线的两倍，或文件范围扩出第一轮清单。
- 同一份计划被重写五次以上而卡点未消失。

## 验收标准

十条判据，每条都由决策者本人或管理员亲自核，不接受作者自述：

1. 连问三轮，第三轮引用第一轮的内容，它接得住。
2. 干活途中刷新或关闭页面，回来内容齐全、任务照跑完。
3. 说「画一张横版海报」，等到底，**图真的显示在对话里**；停在进度条上不算。
4. 说「记进知识库」，点它给的链接能打开，内容就是刚才那段。
5. 新开会话问上一步存过的事，答得出来且标了可点开的出处。
6. 页面上指定的模型，与网关调用日志里实际跑的模型一致。
7. 改动文件清单里，跨容器代理、既有工程对话入口、鉴权三者一个字未碰。
8. 白天与黑夜两套皮肤各截一张图，均不破版。
9. 任一超过两秒的等待，屏幕上持续有内容变化，不是静止的转圈。
10. 故意触发一次失败，页面转红、写清原因、会话仍可继续。

**不算数的证据**：接口返回成功、测试全绿、通读自审、旧版本截图、以及截图里还在加载而文案写「已完成」。

## 分阶段与退出

三个阶段，每个阶段独立可验收、独立可停，在任一阶段结束时叫停都能拿到完整可用的东西：

- **阶段一 纯多轮对话，零工具**。页面、执行器、事件流、断线恢复。此时已回答「有没有能对聊的智能体、在哪用」，判据一、二、八、九、十可验。
- **阶段二 挂上出图**。第一把工具接入，同时把工具卡交互定型，后两把照抄。判据三可验。
- **阶段三 挂上知识库读写**。写入与检索配套上线，存得进去也查得出来。判据四、五可验。

退出方式：关掉入口权限，入口立刻消失且不影响他人；不改现有表结构，回滚无需数据迁移；不改现有鉴权，回滚不影响他人登录；新数据在独立集合里，彻底清理就是删一个集合。

## 位置与路径

- **位置**：左侧导航「对话」，同时在工具箱登记一条（先标未完成，通过验收后转正）。
- **路径**：登录后首页 → 点击左侧「对话」→ 新建会话 → 直接说话。
