# MAP 首页重构 · 设计思路与元素清单

> **版本**：v1.1 | **日期**：2026-08-25 | **状态**：第一批已落地（四幕真实面板场景）

**一句话**：现有对外首页是「视觉做完、说服未开工」的半成品——数字写死、产品图是手绘的、正中间挂着即将上线；本文给出重构的诊断、必备元素清单、叙事顺序与验收判据。
**谁该读**：接手首页重构的设计师（或设计智能体）、负责首页文案与素材的产品负责人、执行落地的前端工程师。
**读完能做什么**：知道这一页要说服谁、必须出现哪些元素、哪些视觉规格不许自造、交付后按什么标准判合格。

## 〇、这份文档怎么用

如果你是设计智能体，把下面这段当作任务陈述，其余章节当作约束与素材：

> 重构 MAP（米多智能体生态平台）的对外首页 `/home`。它现在是一个「我们有很多功能」的展示页，需要变成一个「你能拿这个平台干成什么、凭什么信我们、下一步点哪」的说服页。品牌视觉语言已经存在且有 CI 守卫（见第五章），不要重新定义品牌，要重新定义**信息结构、证据链与转化路径**。产出：桌面 + 移动的高保真设计稿，覆盖第四章的全部「必备」元素，按第三章的叙事顺序组织。

三条不许越过的线：不改品牌色系与字体系统；不新增未上线能力的宣传；页面上出现的每一个数字都要能说出来源。

## 一、现状诊断：半成品半在哪

现有首页共十一幕、约 3300 行组件代码，视觉执行是完成的——静态背景、进场动效、渐变体系、双语切换都已落地。问题不在「不好看」，在**它没有承担一个宣传页该承担的工作**。

| # | 症状 | 证据 | 为什么是硬伤 |
|---|---|---|---|
| 1 | 数字全是写死的字符串 | 「15+ 专业 Agent / 14 集成大模型 / 98 MongoDB 集合 / 99.9% 可用性」来自文案字典；「Live · Pulse」那一幕的 2,341 会话、4.2M tokens、Agent 使用排行全部硬编码在组件里 | 一个标着 Live 的区块显示的是永不变化的常量。访客一旦察觉，整页可信度归零。而且「98 个 MongoDB 集合」是内部工程指标，对访客零意义 |
| 2 | 最贵的一块地是空的 | 全站唯一的全宽电影位没有视频源，降级显示「Coming soon · 即将上线」 | 首页正中央挂着「未完成」四个字 |
| 3 | 没有一张真实产品图 | 首屏产品预览与六段能力深潜里的界面全部是 CSS 手绘示意图 | 访客无法确认这个产品真的存在、真的能跑 |
| 4 | 首屏说不清自己是什么 | 主标题「让创造，自由呼吸」，副标题是「碳硅共生 / 人机共治 / 价值共创 / 共同进化」 | 五秒测试必挂：读完答不出「这是什么、给谁、我能换来什么」 |
| 5 | 整条转化链路缺失 | 无价格或获取方式、无客户与案例、无安全合规与部署形态说明、无 FAQ、无法务页；唯一 CTA 是「进入 MAP」跳登录；联系方式挂在一个可能为空的环境变量上；「文档」直接指向 GitHub 仓库首页 | 陌生访客只有两个选择：注册，或者离开。没有中间地带 |
| 6 | 四次「我们有很多」，零次「所以呢」 | 三块基石 → 六段能力深潜 → 十五个 Agent 网格 → 十二家模型平台，四个区块都在做能力枚举 | 信息量很大，结论一句没有。读者要自己算「这对我意味着什么」 |
| 7 | 装饰权重高于内容 | 首屏含合成太阳、地平线光带、透视地板三层复古装饰，产品本体只占一张示意图 | 气氛做满了，论据没上桌 |

**一句话总结**：这一页目前在完成「品牌氛围」，没有完成「说服」。重构的重点是把每一幕从「展示」翻译成「主张 + 证据」。

## 二、设计前必须先理解的产品

设计师不理解产品就只能做版式。以下是从代码可核实的产品事实，请据此判断哪些卖点值得放大。

**MAP 是什么**：一个企业级的 Agent 工作台。不是聊天框，也不是单点工具集合。

**它真实具备的能力**（均已上线，可截图）：

| 能力簇 | 具体内容 | 对访客的意义 |
|---|---|---|
| 多 Agent 协同 | 15+ 专业 Agent：视觉创作、文学创作、PRD 解读、视频分镜、缺陷管理、周报、转录、代码审查、竞技场等，共享同一套上下文，可互相调用 | 不是十五个独立小工具，是一支能互相接活的团队 |
| 统一模型网关 | 十余家大模型平台接入同一套配置，按任务类型路由，带模型池策略、健康度监控、配额与失败回退 | 换模型不换流程；模型出事有兜底。这是企业决策者最关心的一条 |
| 工作流编排 | 可视化节点图把多个 Agent 串成定时流水线，带条件分支与错误回退 | 重复流程一次配置长期复用 |
| 产物沉淀 | 知识库（双链、反向引用、关系图谱）、作品广场、技能市场、更新中心周报 | 用完不是聊天记录，是可复用的资产 |
| 全平台 | Web + 桌面客户端（托盘常驻、快捷键唤醒、离线缓存、自动更新），同一套账号 | 不只是个网页 |
| 开放与自托管 | 开放平台 API Key、技能市场开放接口、分支预览部署 | 开发者与集成方有入口 |

**差异化的真正落点**（首页必须把这句话说清楚）：市面上大多数产品是「一个模型 + 一个聊天框」；MAP 是「一群专业 Agent + 一层模型治理 + 一套产物沉淀」。设计上要让这三层结构被看见，而不是被列举。

## 三、受众、目标与叙事结构

### 3.1 三类访客，三条动线

| 优先级 | 访客 | 他到这页要回答的问题 | 他需要的下一步 |
|---|---|---|---|
| 主 | 技术/产品负责人（选型决策者） | 能不能在我们这儿落地？数据在哪？能私有化吗？模型出问题怎么办？多少钱？ | 预约演示 / 读部署与安全说明 / 联系我们 |
| 次 | 一线使用者（设计、写作、PM、QA） | 我手上那件具体的活，它能干吗？干得怎么样？ | 看真实产物 / 直接试用 |
| 三 | 开发者与潜在贡献者 | 接口怎么用？能自己接 Agent 吗？开源到什么程度？ | 文档 / 开放平台 / GitHub |

**转化设计原则**：主 CTA 全页唯一且一致（「进入 MAP」或「免费开始」），次 CTA 是低承诺路径（「看 90 秒演示」「预约演示」），第三条永远存在的暗路是「读文档 / 看真实产物」。现在只有一个「跳登录」，等于把没准备好的访客全部劝退。

### 3.2 建议的叙事顺序（九幕，替代现在的十一幕）

每一幕都要能用一句话回答「读者读完这一幕获得了什么」。如果一幕说不出这句话，它就该被删或被合并。

| 幕 | 名称 | 读者获得的那句话 | 与现状的关系 |
|---|---|---|---|
| 1 | 首屏 | 「这是给团队用的 Agent 工作台，我三秒就懂了，而且我看见了真界面」 | 重写文案，示意图换真实产品图/录屏 |
| 2 | 信任带 | 「用的是我认识的模型，有人在真的用它」 | 扩展现有 POWERED BY 条，补客户或案例 |
| 3 | 场景价值（3-4 个） | 「我这个岗位的活它能干，而且省下的东西是可量化的」 | **新增**，取代六段能力平铺 |
| 4 | 真实产品证据 | 「我看见它真的在跑，不是概念稿」 | 现有电影位填上真录屏，或改为可交互微演示 |
| 5 | 差异化机制 | 「我明白为什么这是一个平台而不是一堆工具」 | 合并现有「三块基石 + 工作流」为一张机制图 |
| 6 | Agent 阵容 | 「覆盖面够广，且每个都能点进去看细节」 | 保留网格，但从十五个平铺改为按职能分组 + 可展开 |
| 7 | 模型与数据治理 | 「模型怎么路由、数据存哪、能不能私有化，我有答案了」 | **新增**，决策者的必答题 |
| 8 | 获取方式与 FAQ | 「我知道怎么开始、多少钱、常见顾虑已被回答」 | **新增** |
| 9 | 收尾 CTA + 完整页脚 | 「我知道下一步点哪，也找得到文档、条款和人」 | 现有页脚过薄，需重建信息架构 |

现有的「社区脉搏」一幕建议**降级或删除**：它的全部数据都是假的，若无法接真实数据源，删掉比留着更有利（理由见第六章）。桌面端下载可并入第 8 幕或保留独立小节，但必须给真实下载入口与版本号。

## 四、必备元素清单

这是本文档的核心交付。三档：**必备**缺一即不成立；**应有**决定专业度；**加分**决定记忆点。

### 4.1 必备（十一项）

| # | 元素 | 设计要求 | 判据 |
|---|---|---|---|
| 1 | 可复述的价值主张 | 一句主标题说清「是什么 + 给谁 + 换来什么」，一句支撑句给出机制。抽象愿景词（碳硅共生、共同进化等）移到「关于我们」，不占首屏 | 五秒测试：陌生人看完能用自己的话复述 |
| 2 | 对称双 CTA | 主实次虚、同高同圆角同字号；主 CTA 全页文案统一；次 CTA 是低承诺动作 | 全页 CTA 文案不超过两种 |
| 3 | 首屏真实产品视觉 | 真实截图或自动播放的短循环录屏，不是手绘示意图。允许做去敏与美化裁切，不允许虚构界面 | 图上元素能在产品里找到 |
| 4 | 信任带 | 模型平台标识 + 客户/团队/用例 + 一个可核实的公开指标（如开源仓库数据） | 至少一类是第三方可验证的 |
| 5 | 场景化价值区（3-4 个） | 每个场景写成「角色 → 原来怎么干 → 用 MAP 怎么干 → 省下什么」。配真实产物图 | 每个场景有一个可量化或可感知的结果 |
| 6 | 真实产品证据区 | 60-90 秒录屏或可交互微演示，覆盖一条完整链路（提出需求 → Agent 选型 → 流式产出 → 产物落地） | 录屏里必须出现最终产物，不能停在加载中 |
| 7 | 差异化机制图 | 一张图讲清三层结构：多 Agent 协同 / 统一模型网关 / 产物沉淀。用信息图，不用装饰插画 | 不看文字只看图能讲出结构 |
| 8 | 模型与数据治理区 | 回答四问：接了哪些模型、按什么路由、失败怎么兜底、数据存在哪能否私有化 | 决策者读完不需要再发邮件问 |
| 9 | 获取方式 | 价格表，或明确的「如何获取」（申请试用 / 联系销售 / 自部署），必须有确定答案 | 页面上不出现「敬请期待」类占位 |
| 10 | FAQ（6-10 条） | 把售前最常被问的问题直接写在页面上：数据安全、私有化、模型费用、迁移成本、支持范围 | 每条答案给结论，不给套话 |
| 11 | 完整页脚 | 产品 / 文档 / 开放平台 / 开源 / 法务（隐私政策、服务条款）/ 联系方式 / 备案信息 | 每个链接都能点开且不是 404 |

### 4.2 应有（六项）

| # | 元素 | 说明 |
|---|---|---|
| 12 | 可交互微演示 | 页面内嵌一个能点的迷你版本，比录屏说服力高一个量级 |
| 13 | 客户案例入口 | 至少一个可点进去的深度案例，哪怕是内部团队的真实使用记录 |
| 14 | 更新日志 / 路线图入口 | 项目已有更新中心与代码级周报，这是「持续在动」的真实证据，应当对外露出 |
| 15 | 开发者区 | 开放平台、技能市场、自托管三个入口独立成组 |
| 16 | SEO 与分享卡 | 页面标题描述、社交分享卡、结构化数据。现在这一页在搜索与转发场景等于裸奔 |
| 17 | 双语一致性 | 中英双语已具备，重构后需保证新增内容双语同步，不出现中文硬编码 |

### 4.3 加分（四项）

| # | 元素 | 说明 |
|---|---|---|
| 18 | 一镜到底片花 | 把现在那块「即将上线」的黑箱真正填上，这是全页唯一的电影时刻 |
| 19 | 效益测算 | 输入团队规模与内容产出量，估算节省。要标注估算口径 |
| 20 | 真实平台脉搏 | 若能提供匿名统计端点，这一幕可以复活并成为强证据；否则删除 |
| 21 | 浅色主题 | 现在只有暗色一套。可保持单主题，但需明确写进设计说明，而非默认 |

## 五、视觉语言：继承什么、可以改什么

品牌视觉已经成型且有 CI 守卫测试拦截，**不要重新发明**。SSOT 是 [首页与登录页视觉语言 · 规则](./rule.frontend.landing-visual-style.md)，以下是设计时必须遵守的硬约束摘要。

### 5.1 不可改（改了 CI 会红）

| 项 | 约束 |
|---|---|
| 品牌渐变 | 全站唯一一条陶土同族签名渐变（`#CE6B41` → `#D97757` → `#E0A06B`），主 CTA、Logo、标题渐变字共用。禁止自造第二条 |
| 禁用色相 | 紫、靛、品红全面禁用；旧青、旧玫红已作废。品类色走既定的八色墨带 |
| 渐变上的文字 | 渐变作底时必须用深墨字，不许用白字（对比度不达标，有守卫测试） |
| 字体 | 三套各司其职：展示字体（标题、导航、按钮，负字距）、正文字体、等宽字体（HUD 标签，全大写宽字距）。禁止引入第四套 |
| 背景 | 底层必须是六层 CSS 静态合成，且它单独存在时页面也成立。其上最多叠一层受控的 WebGL 墨场：拿不到就不画、减少动效只渲一帧、后台暂停、算力封顶、不吃点击、强度压在正文之下。粒子场、鼠标视差位移、mesh gradient 连续动画仍然禁止 |
| 进场动效 | 统一的 fade-up、一次性触发、同组阶梯延迟、尊重减少动效偏好。禁止滚回去重播 |
| 小标签规格 | 等宽 + 全大写 + 宽字距 + 强调色低透明底与发光边，是一套固定配方，不逐处调 |
| CTA 规格 | 主次对称双胞胎，同高同圆角同字号 |
| 文案 | 全部走双语字典，不硬编码 |

### 5.2 可以改（这次重构的空间就在这里）

- **信息层级与节奏**：现在十一幕权重接近平均，需要拉开——首屏、证据区、机制图应当是三个峰值，其余是过渡。
- **装饰与内容的配比**：首屏三层复古装饰可以收，把空间让给真实产品视觉。装饰是背景不是主角。
- **区块密度**：六段能力深潜是全页最长的一段，建议压缩为场景卡；十五个 Agent 平铺建议按职能分组。
- **移动端**：现有移动端基本是桌面的缩小版。重构需按移动优先密度设计——首屏内容占比、控制条合并、卡片单列节奏。
- **留白策略**：留白应当服务于呼吸，不是掩盖内容不足。内容密度不够时先补内容，再谈版式。

## 六、数据与素材：设计前必须备的料

设计做不下去，通常不是审美问题，是没料。这一节列清楚哪些料必须由产品侧提供，以及每个数字的真实来源。

### 6.1 页面上允许出现的数字，及其来源

**红线：页面上每一个数字都必须能说出来源；说不出来源的数字一律删除，不允许用「示意值」占位。**

| 数字 | 是否可获得真实值 | 来源 |
|---|---|---|
| Agent 数量 | 可 | 前端内置工具注册表，可自动统计 |
| 接入模型平台数 / 模型数 | 可 | 模型平台与模型配置表 |
| 桌面端版本、包大小、支持平台 | 可 | 构建产物与版本接口 |
| 开源仓库指标 | 可 | 代码托管平台公开接口 |
| 更新频率（如「本周合并 N 个变更」） | 可 | 已有的代码级周报数据 |
| 会话数 / token 处理量 / Agent 使用排行 | **当前不可** | 需要新增匿名聚合统计端点，否则删除该区块 |
| 服务可用性 99.9% | **当前不可** | 需要真实监控数据支撑，否则改为不承诺具体数值 |
| MongoDB 集合数 | 可但**不该用** | 内部工程指标，对访客无意义 |

### 6.2 需要产品侧交付给设计的素材清单

| 素材 | 说明 | 阻塞级别 |
|---|---|---|
| 真实产品截图（8-12 张） | 按场景拍，统一视口与主题，需去敏 | 高：无此项首屏无法定稿 |
| 产品录屏（60-90 秒） | 完整一条链路，必须拍到最终产物出现，不能停在加载态 | 高 |
| 三到四个场景故事 | 每个含角色、原流程、新流程、可量化结果 | 高 |
| 客户 / 团队 / 案例授权 | 哪怕是内部团队与开源用户 | 中：无此项信任带只能靠模型标识撑 |
| 价格或获取方式的结论 | 商业侧拍板 | 高：第 9 项必备元素依赖它 |
| 安全与部署形态说明 | 数据存储位置、是否支持私有化、权限模型 | 中 |
| 法务页（隐私政策、服务条款） | 页脚必需 | 中 |
| 有效联系方式 | 现在挂在可能为空的环境变量上 | 中 |

## 七、交付要求与验收判据

### 7.1 交付物

1. 桌面高保真稿（1440 宽为基准），覆盖第四章全部必备元素，按第三章九幕顺序。
2. 移动高保真稿（375 宽），不是桌面稿的等比缩小，需重新设计密度与节奏。
3. 组件与状态说明：CTA、卡片、标签、导航（含移动展开态）、空状态与加载态。
4. 动效说明：哪些元素进场、延迟阶梯、减少动效偏好下的降级形态。
5. 文案稿：中英双语，含首屏主标题的 2-3 个备选。
6. 素材需求清单：设计稿中每一处占位对应的真实素材要求（尺寸、内容、拍摄要点）。

### 7.2 验收判据（逐条可核对）

- [ ] 五秒测试：给三个不了解产品的人看首屏五秒，至少两人能复述「这是什么、给谁用」
- [ ] 页面上每一个数字都能指出来源，没有写死的示意值
- [ ] 页面上没有任何「即将上线 / 敬请期待 / Coming soon」占位
- [ ] 首屏及证据区使用真实产品视觉，不是手绘示意图
- [ ] 录屏或演示拍到了最终产物，没有停在加载中或进度条
- [ ] 主 CTA 全页文案一致，且存在至少一条低承诺次路径
- [ ] 决策者四问（模型、路由、兜底、数据与私有化）在页面上都有答案
- [ ] 获取方式有确定结论（价格 / 申请 / 自部署）
- [ ] 页脚含法务、联系方式、文档、开源入口，链接均可达
- [ ] 品牌渐变唯一、无禁用色相、字体三套、背景静态底可独立成立且动态层满足全部降级条件、进场统一——对照第五章逐条
- [ ] 移动端 375 宽下首屏核心内容占比达标，控制条不堆叠
- [ ] 中英双语内容完整对齐，无中文硬编码
- [ ] 深色背景下正文与次要文字对比度达标，渐变上的文字未使用浅色

### 7.3 明确不做

- 不重新定义品牌色系、字体系统与背景方案。
- 不设计登录之后的产品界面，本次范围仅限对外首页与其直接下级页面（如案例页、定价页）。
- 不为尚未上线的能力设计宣传区块。
- 不引入粒子场、三维场景、鼠标视差位移等重型装饰。唯一放开的是 5.1 那一层受控墨场背景，它必须满足那一栏列出的全部降级条件。

## 十、落地记录

### 10.1 第一批落了什么（2026-08-25）

把「四幕照真实产品面板复刻的场景」写进了首页，不再是通用示意图：

| 幕 | 位置 | 讲的是什么 | 可交互 |
|---|---|---|---|
| 视觉创作工作台 | 第一屏（取代原来的通用对话壳 mockup） | 画布铺满、左侧竖向浮动工具条、右侧 420px 浮动对话面板、顶部居中缩放胶囊 | 点画布上任意一张图，选中环与动作条跟着走 |
| 文学创作 | 统计条之后 | 左边文章逐段成稿（含内联配图与待生成槽位），右边 384px 竖向配图工作台，三态配图卡 | 切换四种风格，整列配图连同正文内联图换色，**正文一个字不动** |
| 知识库 | 文学创作之后 | 三栏阅读器（文件树 / 正文 / 本页章节）+ 划词浮层 + AI 改写 diff 预览 + 知识星系 | 无（静态展示，星系坐标手排、可复现） |
| 三层一体 | 取代原「三大支柱」 | MAP / LLMGW / CDS 各画一块那一层真实界面的切片 | 无 |

同时下线两块「通用线框 + 口号」的旧内容：三大支柱（三张单色线框图 + 三句放到任何 AI 产品都成立的话）、产品预览 mockup（手绘的对话壳）。第一章诊断里点名的「产品图是手绘的」由此消解。

### 10.2 落地时定下的三条约束

1. **结构必须照真实源码画**。前一版稿子在这里翻过车：只读了组件的 import 列表和命名就凭印象画布局，画出来「左右颠倒」。规矩改成：画哪一屏，先打开那个组件的 `return`，读完再画。
2. **场景配色收敛到一处**。`/home` 是固定暗色的宣传页，这些场景复刻的就是应用内暗色工作台的表面材质，翻成浅色反而失真——属于双皮肤规则里「暗色形态专用皮肤对象」的合法例外。例外不等于可以随手写：四幕共用一份表面/描边/文字阶梯，散着写必然各自漂移（签名渐变被手抄三份、三份各自漂色是前车之鉴）。
3. **色相只走墨系八色带**。视觉=陶土、文学=松绿、知识库=橄榄、三层=陶土/钢青/钢蓝，生成中=钢青、超预计=琥珀、完成=松绿。紫、靛、品红一律不在带内，由既有的配色守卫盯着。

### 10.4 第二批落了什么（2026-08-28，10.3 第四项「旧幕未动」在此批被处理）

- **四幕改节拍驱动**：开局是空的，滚到才演——视觉创作走打字→发送→思考→渲染→落回画布→选中→混合计算，文学创作走上传→打锚点→逐张落进正文→换风格；每幕加一行随节拍变化的旁白条。
- **尾部重绘**：原六段（Agent 深潜 + Agent 网格 + logo 墙 + 三步 + 桌面端 + 最终 CTA）合并为三幕——`RosterScene`（照百宝箱注册表画真实 Agent，演一次搜索筛选）、`ModelLayerScene`（照 LLMGW 模型池真实切片演成员半开与隔离兜底）、`StartScene`（三步 + 三端 + 收口通栏），整页高度显著下降。
- **新增独立幕**：`CdsScene`（拆出「分支即环境」的时间轴演示，日志逐字取自真实部署记录）、`WorkflowScene`（照 `/workflow-agent` 画舱库 + 真实模板执行日志）、`VocScene`（照 `/team-activity` 复刻热力图下钻）。
- **首页配图流水线**：新增槽位注册表 `landingPreviewSlots.ts`、匿名读接口 `GET /api/v1/landing/preview-assets`、系统设置「首页预览图」Tab 可逐幕生成，产物落 `HomepageAsset`（含生成用的 Prompt 字段）。
- **演示因果契约落地**：新增模拟鼠标指针（按节拍走位、先到位再按下、按下是一次完整手势）覆盖到视觉创作/文学创作/知识库/百宝箱/工作流/用户之声/CDS 各幕，配套衔接契约守卫（旁白写点击必须真有按下）与衔接体检脚本；沉淀为规则 [`demo-causality-contract.md`](../.claude/rules/demo-causality-contract.md)。
