## 一、为什么做（一句话背景）

三个议题——一个仓库当多个项目部署、请求指向要能可视化地改、预览地址要自动算出来——共用同一个问题：**这次改动波及了哪些项目、哪些服务、哪些入口**。这份判据只写一次，四处消费：决定要不要部署、生成指向候选、派发预览地址、划定接入作用域。

权限那条线是另一件事，但它止痛最快：今天四种凭据面加一层与凭据无关的审批记忆，任意一层失配都塌缩成同一句「未授权」，于是「动不动 401，CDS 很不好用」。

## 二、已定的十五条

### 多项目线

1. **不拆当前项目**。`cds-self` 已经是同仓库下的第二个 CDS 项目，拿它当第一个受益者，主项目结构一行不动。
2. **热替换 = 重启那一个容器**。不追求进程不重启，应用侧不改。
3. **依赖单开一区，声明住在 CDS 配置树，不进 compose**。仓库 compose 已被正式降级为纯结构种子、漂移巡检单向，而「谁连谁」是运行时拓扑、比代码变得快，放进要提交要人审的文件里必然跟不上。
4. **依赖默认作用在分支**，可一键让其它分支生效；后者等于改项目底座，走审批那道门并先提示影响面。
5. **数据类依赖 = 数据库与基建连接**。进依赖区，但单独颜色、单独确认、默认不参与「替换全部」。
6. **预览地址 `[项目 · 入口] URL`**，单入口收缩成 `[项目] URL`，全部列出、没有主从；客户端只送仓库与提交号，判定全在服务端。

### 权限线

7. **身份层三张表**：主体 / 凭证 / 项目授权。
8. **判据是「我在授权名单里」，不是「是不是我建的」**。建项目写「创建型」授权，页面批准写「批准型」授权，同表同权；默认只对自己创建的项目有权限，其余手动批一次。
9. **两级凭证**：用户级签发、项目级干活。用户级在用户目录按 CDS 主机索引，项目级维持仓库根。
10. **用户级只授权不操作，可跨项目换钥（按需换一个）**。能建项目、列项目、为已授权项目签钥；不能删分支、改配置、跑运维指令。
11. **第一把从已登录会话换**，纯终端退回「一辈子批一次」；不做无条件自签。
12. **自愈回落**：仓库级读不到 → 回落用户级 → 查授权表 → 当场补一张写回仓库根；没授权才走页面批准。
13. **用户级 90 天有效、用一次自动续 90 天**。必配三件套：签发留痕可见、级联撤销、权限总览页（看得到有哪些主体与凭证、可撤销、可管理用户）。
14. **吊销记录保留 90 天后归档**；主列表只给活的、按主体聚合；分不清的问题交给三态自检端点，不交给列表。存量凭据懒迁移认领主体。
15. **项目级凭证也改短命**（建议 30 天、用即续）。今天它永不过期是因为丢了很麻烦；有了自愈回落，丢了不麻烦，所以没理由再长生。

## 三、一条要摆正的事

「用户级只授权不操作」**不是拦截，是留痕**。拿到用户级凭证的人仍可以先签一张项目级、再用它去删东西，只是多走一步，最终能力并没有变小。它换来的是两样别的东西：每一次滥用都必然留下一条签发记录（直接操作不留痕，签发一定留痕），以及一处可一键切断的总闸。防不住，但一定查得到、能立刻止血。所以第 13 条的三件套不是「建议一起做」，是这套方案成立的前提。

## 四、P1 已落地：凭据三态自检

### 它解决什么

今天「未授权」是至少六种成因的公共出口，持有者只能猜：

| 成因 | 表现 |
|---|---|
| 运维审批记忆失配 | 按「凭据哈希 + 指令 + 参数哈希」记、七天有效；换凭据或改一个参数字就要重批，而凭据一直好好的 |
| 一次性建项目凭据被自动吊销 | 项目建成后系统立刻换发项目级凭据，没接住就全是 401 |
| 拿错凭据面 | 四种凭据长得都像密钥，能到达的路由完全不同 |
| 环境变量残留盖过凭据文件 | 接入命令开头显式清那三个变量，这行代码本身就是证据 |
| 凭据文件没跟着走 | 凭据存在仓库根，挪目录或在仓库外执行就读不到 |
| **项目改过 slug** | 鉴权先按 `cdsp_<slug 前 12 位>_` 定位项目再比哈希；slug 一改，存量凭据前缀对不上，鉴权直接跳过——凭据没被吊销、项目卡上看得见，就是进不来 |

最后一条是这次查证挖出来的，此前没人提过。

### 怎么做的

- 判据是一个纯函数：输入明文凭据加一份事实快照，输出 `active / revoked / never-issued / prefix-mismatch / not-checkable / malformed` 六态，每态带一句人话结论和一条具体的下一步。
- 与鉴权路径的关键差别：鉴权只关心「能不能进」所以跳过已吊销；自检要回答「发生了什么」，所以**必须看得见已吊销那条**——否则「被吊销」与「从未签发」永远分不开，正是要解决的问题。
- 端点是 `GET /api/credentials/self-check`，**免鉴权**：它的全部意义就是诊断一把过不了鉴权的凭据，挂在鉴权后面永远执行不到。

### 安全边界

出参不含明文、不含哈希，`never-issued` 不透露任何项目信息。凭据是 24 字节随机串，端点没让攻击面变大；拿一把真凭据换来的「已吊销」，发一次普通请求也能推出来。另加按来源的粗粒度节流，防的是拿它当免鉴权压测入口，不是防猜。

### 判据怎么证明自己有效

- 红绿闭环：把「找出同哈希的那条」改回鉴权那种「跳过已吊销」的行为，三条用例立刻变红；恢复后全绿。
- 漂移守卫：对同一把有效凭据，自检与真实的鉴权查找函数必须指向同一个项目与凭据 id。哪天签发路径换了哈希算法或前缀公式而只改一边，这条会红。
- 接线守卫：路由必须真的挂进服务入口，路径必须同时出现在两处免鉴权白名单里。少任何一处这条端点都会被鉴权挡住、只回「未授权」——正是它要治的病，而这种退化不报错、不变红、通读也挑不出来。

## 六、验收记录

### P1（2026-09-01，已验）

自托管项目上手动建分支 + 部署本分支（commit `21cd00f`），拿到预览入口后直接打端点：

- 不带任何凭据：线上旧构建 `401`，本构建 `200` 且给出 `malformed` 与「凭据该放哪个请求头」。**这条差异本身就是免鉴权接线生效的证据** —— 也很讽刺：一个专门诊断「未授权」的端点，在旧构建上正返回未授权。
- 随机项目级凭据：`200`，`never-issued`，且不带任何项目信息。

`active` / `revoked` / `prefix-mismatch` 三态**未在真实部署上验**：在预览实例上签发凭据需要它自己那套访问口令，按设计与父实例刻意不共享。这三态由判据回归覆盖，并有红绿闭环证明用例真的在测它们。

### P4（2026-09-01，代码就绪，等人工开关）

核对过线上事实：**自托管项目当前没有 `githubRepoFullName`**，即没有 link GitHub（与自托管设计里的取舍一致）。因此本次改动对本仓库是**零行为变化** —— fan-out 只是把「能分发给多个项目」这条路修通，真正打开开关的是 link 这个显式动作。

也正因如此，顺手补了服务级 `cds.build-scope` 声明能力：此前只有部署模式能声明构建输入范围，而自托管项目那个唯一的服务没有部署模式，于是作用域恒为空、恒等于全通配。真要 link 之后不至于每个 push 都把 CDS 重编一遍，这条声明是安全前提，不是可选项。

### P5（2026-09-01，代码就绪，回退路径已实测）

命令行不再在本地推断项目归属，改成把仓库、分支与可选的改动清单交给服务端；服务端与 push 分发**共用同一份作用域判据**，并按凭据过滤可见项目（项目级凭据只看得到自己那个项目）。取不到地址时分三种情形说清：本次与该项目无关 / 波及但还没有这条分支 / 分支在但还没有已发布入口。

生产 CDS 还没有这条端点，所以**新路径没有在真实环境跑过**；实测到的是回退路径：命令在生产上照常输出两条真实入口地址，说明回退没有把既有链路弄坏。新路径由 8 例判据回归 + 6 例路由回归覆盖（含可见性隔离、未波及仍出现在结果里、缺参 400）。

旧的本地推算路径与「自托管项目专用」特判**暂时保留**，因为生产 CDS 尚未更新；等它更新后删掉，那时客户端才真正零判据。

### P2 / P3（2026-09-01，本地端到端验过）

在沙箱里起了一个真 CDS 进程（隔离状态目录、basic 鉴权、静态管理员密钥），把四条链路各跑了一遍：

| 验的是什么 | 实测结果 |
|---|---|
| 自愈 | 无授权时被拒并给出「去批准一次，此后换机器不必再批」；管理员批一次后，同一主体自助补发成功，新凭据走既有鉴权路径 200，凭据自检认得出它属于哪个项目 |
| 权限边界 | 用户级凭证：列项目 / whoami 放行（200），读权限总览、停用主体、列分支一律 401；匿名 401 |
| 级联撤销 | 撤掉用户级凭证 → 它本身 401，**它签出的项目级凭据同时 401**，自检答得出「已在某时被吊销」 |
| 权限总览（**只验了接口，没验页面**） | 接口按主体聚合正确；撤销后两张凭证都进「已退役（折叠）」；用户级那张显示「已签出 N 张下游」。**页面当时是整页空白**——内容槽挂错了父节点，见下节 |

本地跑还撞出一个真 bug 并当场修掉：`auth=disabled` 模式下鉴权中间件整段被跳过，于是主体上下文永远不被 stamp，身份层路由一律 401 —— 路由在、鉴权分支也在，只有这一处没接上，页面照常渲染、测试照常绿。按既有 `cdsp_` / `cdsg_` 的同款兜底补齐。

未验：建项目自动写「创建型」授权那条链路。沙箱里没有 docker daemon，建项目在建网络那一步就失败，所以这条只有代码与阅读，没有实跑。**这一条已于同日在生产上补验，见下节。**

### 生产发布（2026-09-01，已发，两处缺口在发布中现形并当场修掉）

先把 main 并回本分支再发 —— 生产当时跑的版本已经并入 main，直接切过去会把 44 个提交的成果退回去。并完全量回归 6257 条全绿，才做切换（快进，7 秒，走 CI 预构建产物）。

上线后逐条打真接口，把本地补不上的那几块补齐：

| 验的是什么 | 实测结果 |
|---|---|
| 免鉴权自检 | 不带凭据 `200`，答「没收到凭据 + 该放哪个头」；静态密钥答 `static / active`；随机项目级凭据答 `never-issued` 且不泄露项目信息 |
| 存量凭据零回归 | 存量静态访问密钥照常鉴权 `200`；权限总览把 123 把存量凭据列为「未认领」、状态仍是有效，没有被新到期判定误伤 |
| 建项目写创建型授权 | **本地补不上的那条**：用用户级凭证建项目 `201`，`whoami` 当场出现 `origin: created` 的授权 |
| 自愈全程 | 未授权项目被拒 `403` 并给出「去批准一次」；自建项目自助补发 `201`，新签的短命项目级凭据立刻鉴权 `200` |
| 边界 | 用户级凭证列项目 `200`、whoami `200`、列分支 `401`；删项目它做不到（这正是「只授权不操作」） |
| 撤销与停用 | 吊销用户级凭证后 whoami `401`；停用主体成功 |

**发布中撞出的第一处缺口（已修）**：拿刚签出来的用户级凭证打自检端点，答的是「本实例从未签发过这把凭据」—— 而它三十秒前刚签出、whoami 正常。根因是判据面比凭据面窄：自检是 P1 写的，那时身份层还不存在，它只认四种面；P2/P3 加了第五种却没回头扩自检。两处各自成立、编译过、6000+ 用例全绿，只有拿真凭据打一次生产才现形。修法不止是补一种面：新增「到期」与「主体被停用」两种结论（身份层的凭据是短命的，到期与被吊销的下一步完全不同），判断直接借身份层那一份、不另写；再加一条接线守卫扫鉴权分支认得的每一种前缀，下一次扩凭据面漏掉就会红。

**发布中撞出的第二处缺口（已修）**：拆验证现场时删掉探针项目，指向它的授权还留在 `whoami` 里，而且项目没了连名字都显示不出来。删项目现在连带吊销它的授权 —— 吊销不是删除：总览里立刻消失，审计行按留存期保留。

|---|---|
| 界面：「停用后它名下所有凭证立刻不可用」 | 鉴权只看密钥自己的吊销标记，承诺最长落空 30 天 |
| 文档与界面：项目级凭据「用即续」 | 用一次只更新最近使用时间，到期日不动，一直在干活的 Agent 第 30 天照样被锁在门外 |
| 交付消息：「位置 = 系统设置 → 权限总览」 | 那一页是**整页空白** |
| 本文档：判不准就 fail-open | 推送清单被截断时（非空但不全）当权威用，可能把真被波及的项目静默跳过部署 |
| 提示语：「批一次，此后丢凭据不必再批」 | 批准只签一把无主钥匙，从不写授权行，走这条路自愈永远不成立 |
| 界面：为主体补签凭证 | 唯一路径永远新建主体，而新主体没有旧授权 |

**最该记住的一条**：权限总览整页空白，是因为内容被塞进了另一个页签的内容槽里。组件、路由、接口全都好好的，编译过、六千条测试全绿、页面照常渲染——而我在上一轮交付里写了「位置：系统设置 → 权限总览」，实际只验了接口返回 200，从没点进那一页。这正是本仓库真视觉验收规则要挡的那种事，我跳过了。补的守卫钉的是结构不变量（每个声明的页签都要有自己的内容槽），不是这一个页签。

### Codex 第二轮五条（2026-09-01，三条已修 / 两条记账）

已修：身份管理门卫只挡项目级凭证，全权机器钥匙可以给任意主体签凭证、停用主体、增删授权（安全，取更严的那种判据）；预览地址不看运行态，配了预览域名就无条件给一个可能打不开的地址，导致「分支在但没跑起来」这一档永远走不到；未认领存量凭证的说明写着「下次使用时认领」，而那件事没实现、也不可能按那种方式实现——光看一把凭证被使用，认不出背后是谁。

**记账不做的两条（本 PR 最大的一个洞，必须写明白）**：一个仓库现在**绑不了第二个项目**——建项目时命中已绑定就直接不写仓库名，link 接口对第二个项目返回 409。也就是说本 PR 的招牌能力「push 分发到仓库下全部项目」，通过受支持的流程根本达不到。与之捆绑的是：同一个 dispatcher 里还有 8 处仍在用单数查找，不变量一翻，预构建模式下多个分支会集体卡在等镜像、只有第一个被推进。

两条要么一起做要么一起不做，而它们动的是「一个仓库只能绑一个项目」这条产品不变量，不是补一个判据。按范围熔断规则记账、由人批准后再做。

**这一条同时订正了此前的一句错话**：先前写「本次对本仓库零行为变化，真正打开开关的是 link 这个显式动作」——那个动作不存在。

**没做的一件事**：修完之后要把这两处发上去，发现生产 CDS 已被另一条会话切走（它把本分支并进了自己那条分支再部署，所以身份层本身仍在线上跑，缺的只有这两个修复）。控制面切换闸门按设计拒绝了非快进覆盖 —— 抢回来会把对方正在跑的部署顶掉，那是要人来拍的板，不是我该自己决定的。这也顺带实测了隔离台账通道 5：生产 CDS 是单实例、所有 Agent 共用，谁 self-update 谁就替所有人换了版本。
