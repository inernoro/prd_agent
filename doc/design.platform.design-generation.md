# 知识驱动设计生成体系 · 设计

> **版本**：v2.0 | **日期**：2026-09-04 | **状态**：MVP 实施中

**一句话**：把知识、用户意图、设计执行器和可发布产物拆成稳定协议，使同一个生成任务可从不同业务入口发起并持续演进。
**谁该读**：维护知识库、网页托管、HTML PPT、LLM Gateway、CDS Agent 运行时的产品与研发人员。
**读完能做什么**：解释 OpenDesign 在系统中的准确角色、四个 MVP 如何共用内核，以及数据怎样从知识库流到 Agent 再成为可回退产物。

---

## 管理摘要

MAP 负责“为什么生成、用什么知识、谁有权限、任务进行到哪、产物如何保存和发布”；设计 Provider 只负责“根据规范化输入产出或修改设计产物”。OpenDesign、未来的 ClosedDesign、代码改造型 Agent 都是 Provider，不是 MAP 内核。

首版已经建立可注册的 Provider 目录：运行时名称、支持的产物和操作、执行归属、隔离方式、配置、健康与适配器状态均由目录给出，统一控制器不再逐个认识外部产品名称。普通网页由 MAP LLM Gateway 生成，HTML PPT 复用现有专用链路；OpenDesign、Codex、Claude 只有真实部署、健康和适配器同时成立时才能参与调度。

## OpenDesign 的角色

OpenDesign 在 MAP 中定位为“无头设计 Provider”。它不承担以下职责：

- 不直接读取 MAP 用户权限和知识库。
- 不成为任务、版本、发布和回退的事实源。
- 不决定用户从网页托管还是知识库发起任务。
- 不替代 LLM Gateway 的模型治理和调用审计。

MAP 向 CDS Remote Agent 提交已经整理好的设计任务包；CDS 为 OpenDesign 分配隔离运行时并把阶段事件、思考、HTML 增量和最终产物传回 MAP。OpenDesign 自身依赖可用的 Agent CLI，因此守护进程存在不等于设计能力可用，必须同时验证 Agent、工作区和隔离策略。

## 统一调用链

```text
网页托管 / 知识库 / HTML PPT / 帮我修改
                  |
                  v
        统一设计任务与知识快照
                  |
          权限校验、阶段与恢复
                  |
                  v
       MAP Design Provider 目录
          |              |
          v              v
   MAP LLM Gateway   CDS Remote Agent
                          |
                 会话容器 + OpenDesign
          |               |
          +-------|-------+
                 v
        HTML 增量、说明、完成事件
                 |
                 v
      隔离预览 -> 草稿/托管站点版本
                 |
                 v
           发布、历史、回退
```

HTML PPT 仍由自己的大纲和页面生成流程完成，但它接受同一知识快照并回写同一任务身份，因此用户从知识库进入、从 HTML PPT 发布、再到网页托管微调时，来源链不会断裂。

## 核心业务对象

| 对象 | 负责什么 | 不负责什么 |
|------|----------|------------|
| 设计任务 | 记录发起人、入口、目标、操作、阶段、进度、执行器和最终产物 | 不保存业务页面的全部交互状态 |
| 知识快照 | 保存所选知识的标识、标题、生成时正文和内容摘要 | 不替代知识库原文与权限系统 |
| 执行器能力 | 描述执行器是否部署、是否健康、支持哪些产物与操作 | 不把模型名伪装成产品能力 |
| 产物引用 | 把任务连接到托管站点、版本或 HTML PPT 运行记录 | 不复制托管系统的版本事实 |
| 阶段事件 | 支撑流式展示、断线续接、失败恢复和审计 | 不作为最终持久产物 |

## 插件式扩展合同

一个 Provider 要进入 MAP 调度，必须同时注册两部分：能力定义与执行适配器。能力定义回答“能不能做”，执行适配器回答“怎样执行”。二者缺一，界面必须显示不可用原因，不能把健康的远端进程误报成已接通能力。

| 合同维度 | 用途 | 扩展时的约束 |
|----------|------|--------------|
| Provider 身份 | 稳定标识与展示名称 | 标识不绑定公司名之外的业务逻辑 |
| 能力集合 | 产物类型、生成或修改、允许入口 | 调度按能力匹配，不按名称写分支 |
| 执行归属 | MAP 进程或 CDS Remote Agent | 外部 Agent 默认归 CDS，不进入 MAP 容器 |
| 隔离要求 | MAP 进程或会话级容器 | 要求未满足时拒绝启动，不降级冒充 |
| 运行事实 | 已配置、健康、适配器已安装 | 由运行时动态探测，不靠静态开关宣称 |
| 事件协议 | 阶段、思考、增量、工具、完成、失败 | 必须可续接、可取消、可审计 |
| 产物协议 | HTML、资源包、预览引用与来源摘要 | MAP 决定保存、版本、发布和回退 |

新增 ClosedDesign 时，产品入口、知识快照、任务、版本和发布流程不变；只新增能力定义、执行适配器和部署配置。如果它支持结构化局部修改，可在同一合同上追加“变更集”产物能力，而不是为它再造一套网页托管。

## 三个系统的职责边界

| 系统 | 应负责 | 不应负责 |
|------|--------|----------|
| MAP | 入口、权限、知识快照、任务、交互、版本、发布、回退、Provider 选择 | Docker 生命周期、外部 CLI 安装、运行时凭据下发 |
| CDS Remote Agent | Provider 目录、运行时容量、工作区、容器隔离、凭据注入、事件转译、停止与清理 | 业务知识权限、网页版本事实、产品入口 |
| OpenDesign 等 Provider | 设计循环、设计工具、HTML 或资源产出 | MAP 登录、知识库直连、托管站点发布 |

隔离容器可以且应该放在独立的 Remote Agent 基础设施项目。MAP 只持有远程会话标识和产物引用。目前 CDS 已有共享运行时容器与会话事件链，但会话级容器分配器尚未落地；接口会如实返回“每会话资源策略未强制执行”，并拒绝需要独立容器但尚未实现的 Provider。

## CDS Agent 从 OpenDesign 借鉴什么

借鉴的是运行时结构，不是设计产品界面：

- 以薄适配器描述 Agent，而不是为每个 Agent 复制一套调度器。
- 守护进程与 Web 控制面分离，长任务通过事件流观察和恢复。
- 工作区、Agent CLI、模型凭据和产物采用显式运行事实。
- 任务结果以产物交付，不把 Agent 内部对话当作业务事实源。

CDS 不照搬 OpenDesign 的本地单用户 MCP 登录方式。MAP/CDS 是多租户服务端，需要保留自己的授权、审批、审计、配额、容器和凭据隔离。

## 官方能力与自研边界

| 层 | 来源 | 当前结论 |
|----|------|----------|
| OpenDesign 设计循环 | OpenDesign 项目 | 尚未部署到 CDS，不宣称已接通 |
| Codex 或 Claude Agent 循环 | 对应 CLI 或 SDK | 仅部署并验证的运行时可用；名称不代表已集成 |
| Provider 目录与调度 | MAP 自研 | MVP 已落地，可追加 Provider |
| Remote Agent 会话与事件 | CDS 自研 | 共享运行时链路可用，Provider 事实接口已落地 |
| 会话级容器分配和资源强制 | CDS 自研 | 尚未落地，是启用 OpenDesign 的发布门 |
| 工具审批、知识权限、版本发布 | MAP 自研 | 继续由 MAP 持有，不委托给外部 Provider |

## 四个 MVP 的投射

| 入口 | 用户输入 | 共用内核动作 | 最终产物 |
|------|----------|--------------|----------|
| 网页托管知识生成 | 知识条目与两句话 | 建任务、快照知识、调度网页执行器、流式预览 | 新托管网页与首个版本 |
| 知识库智能生成 | 当前文档与目标类型 | 创建带来源的启动上下文并进入对应生成器 | 网页或 HTML PPT |
| HTML PPT | 知识、主题、页数与补充要求 | 复用大纲和生成链，统一记录来源与任务 | 可编辑幻灯片，可发布为网页 |
| 网页帮我修改 | 现有站点、知识与修改要求 | 建编辑任务、产出草稿、发布版本 | 新版本或回退后的版本 |

## 执行器策略

首版调度顺序由能力而非名称决定：

1. 网页生成与微调优先使用已纳入审计、配额和模型池的 MAP LLM Gateway。
2. HTML PPT 使用现有专用生成链，避免为统一而降低已成熟能力。
3. OpenDesign 只有在守护进程、工作区、允许的 Agent、会话级容器和健康探测全部可用时进入候选。
4. Codex 与 Claude 不作为默认依赖；只有显式部署、授权和启用后才展示。
5. 执行器失败不得丢失任务和知识快照；可重试或切换候选时保留同一业务任务链。

## 安全与合规

- 知识原文由 MAP 在用户权限范围内读取，执行器只得到本次所需快照。
- 生成 HTML 必须在与管理后台隔离的环境预览，脚本不能触达认证存储。
- 外部项目代码、模板和设计包分别核对许可证；保留必要声明，不复制外部智能体实现。
- 执行器凭据由 CDS 或服务端配置管理，不进入浏览器和生成产物。
- 任务记录保留来源摘要与产物引用，支持审计“哪份知识生成了哪个版本”。

## 取舍与风险

- 首版选择“明确选择知识”而非自动检索，牺牲一点智能程度，换取可解释、可验收和权限边界清晰。
- 不强行把 HTML PPT 重写进通用网页生成器，避免功能倒退；统一发生在任务和来源协议层。
- OpenDesign 先接 Provider 和 Remote Agent 合同、后接真实执行，可防止配置未完成时出现假能力；首版视觉效果仍主要由 MAP 提示词和模板质量决定。
- 当前 CDS 的资源策略还没有按会话强制到容器层，因此 OpenDesign 保持不可选。这是明确的发布门，不是静默降级。
- 快照会增加存储量；首版限制引用数量与正文长度，并保留摘要用于去重和审计。

## 验收标准

1. 任一入口创建的任务都能说明来源、目标、当前阶段、真实执行器和最终产物。
2. 网页或幻灯片生成过程中持续出现可见产物变化，刷新后可恢复。
3. 从知识库跳转后不要求用户重新选择同一文档。
4. HTML PPT 发布后可在网页托管继续微调，来源链和版本链均可追溯。
5. 未部署执行器不能被选中，界面给出可操作的缺失条件。
6. 网页新建、发布、回退和失败重试均有自动化或预览环境证据。
7. 新 Provider 可仅通过注册能力定义与适配器进入目录，统一控制器和四个入口无需新增名称分支。
8. CDS 能明确返回执行归属、所需隔离、当前隔离是否强制；未满足会话容器要求时 OpenDesign 不能启动。
