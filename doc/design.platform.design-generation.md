# 知识驱动设计生成体系 · 设计

> **版本**：v1.0 | **日期**：2026-09-04 | **状态**：建设中

**一句话**：把知识、用户意图、设计执行器和可发布产物拆成稳定协议，使同一个生成任务可从不同业务入口发起并持续演进。
**谁该读**：维护知识库、网页托管、HTML PPT、LLM Gateway、CDS Agent 运行时的产品与研发人员。
**读完能做什么**：解释 OpenDesign 在系统中的准确角色、四个 MVP 如何共用内核，以及数据怎样从知识库流到 Agent 再成为可回退产物。

---

## 管理摘要

MAP 负责“为什么生成、用什么知识、谁有权限、任务进行到哪、产物如何保存和发布”；设计执行器只负责“根据规范化输入产出或修改 HTML”。这样 OpenDesign 可以接入，也可以被替换，而知识引用、版本记录和用户入口不会跟着重做。

首版保留两条实际执行路径：普通网页由 MAP LLM Gateway 生成，HTML PPT 复用现有专用链路。OpenDesign、Codex、Claude 进入统一能力目录，但只有真实部署并通过探测时才能参与调度。

## OpenDesign 的角色

OpenDesign 在 MAP 中定位为“无头设计执行器适配器”。它不承担以下职责：

- 不直接读取 MAP 用户权限和知识库。
- 不成为任务、版本、发布和回退的事实源。
- 不决定用户从网页托管还是知识库发起任务。
- 不替代 LLM Gateway 的模型治理和调用审计。

MAP 向它提交已经整理好的设计任务包；它返回阶段事件、思考或说明、HTML 增量和最终产物。OpenDesign 自身依赖可用的代码 Agent，因此容器存在不等于设计能力可用，必须同时验证运行时和工作区。

## 统一调用链

```text
网页托管 / 知识库 / HTML PPT / 帮我修改
                  |
                  v
        统一设计任务与知识快照
                  |
          权限校验、阶段与恢复
                  |
                  v
       执行器能力目录与调度策略
          |              |
          v              v
   MAP LLM Gateway   OpenDesign 适配器
          |          （部署后可用）
          +------|-------+
                 v
        HTML 增量、说明、完成事件
                 |
                 v
      隔离预览 -> 草稿/托管站点版本
                 |
                 v
           发布、历史、回退
```

HTML PPT 仍由自己的大纲和页面生成流程完成，但它接受同一知识快照并回写同一任务身份，因此用户从知识库进入、从 HTML PPT 发布、再到网页托管微调时，来源链不会断裂。

## 核心业务对象

| 对象 | 负责什么 | 不负责什么 |
|------|----------|------------|
| 设计任务 | 记录发起人、入口、目标、操作、阶段、进度、执行器和最终产物 | 不保存业务页面的全部交互状态 |
| 知识快照 | 保存所选知识的标识、标题、生成时正文和内容摘要 | 不替代知识库原文与权限系统 |
| 执行器能力 | 描述执行器是否部署、是否健康、支持哪些产物与操作 | 不把模型名伪装成产品能力 |
| 产物引用 | 把任务连接到托管站点、版本或 HTML PPT 运行记录 | 不复制托管系统的版本事实 |
| 阶段事件 | 支撑流式展示、断线续接、失败恢复和审计 | 不作为最终持久产物 |

## 四个 MVP 的投射

| 入口 | 用户输入 | 共用内核动作 | 最终产物 |
|------|----------|--------------|----------|
| 网页托管知识生成 | 知识条目与两句话 | 建任务、快照知识、调度网页执行器、流式预览 | 新托管网页与首个版本 |
| 知识库智能生成 | 当前文档与目标类型 | 创建带来源的启动上下文并进入对应生成器 | 网页或 HTML PPT |
| HTML PPT | 知识、主题、页数与补充要求 | 复用大纲和生成链，统一记录来源与任务 | 可编辑幻灯片，可发布为网页 |
| 网页帮我修改 | 现有站点、知识与修改要求 | 建编辑任务、产出草稿、发布版本 | 新版本或回退后的版本 |

## 执行器策略

首版调度顺序由能力而非名称决定：

1. 网页生成与微调优先使用已纳入审计、配额和模型池的 MAP LLM Gateway。
2. HTML PPT 使用现有专用生成链，避免为统一而降低已成熟能力。
3. OpenDesign 只有在守护进程、工作区、允许的代码 Agent 和健康探测全部可用时进入候选。
4. Codex 与 Claude 不作为默认依赖；只有显式部署、授权和启用后才展示。
5. 执行器失败不得丢失任务和知识快照；可重试或切换候选时保留同一业务任务链。

## 安全与合规

- 知识原文由 MAP 在用户权限范围内读取，执行器只得到本次所需快照。
- 生成 HTML 必须在与管理后台隔离的环境预览，脚本不能触达认证存储。
- 外部项目代码、模板和设计包分别核对许可证；保留必要声明，不复制外部智能体实现。
- 执行器凭据由 CDS 或服务端配置管理，不进入浏览器和生成产物。
- 任务记录保留来源摘要与产物引用，支持审计“哪份知识生成了哪个版本”。

## 取舍与风险

- 首版选择“明确选择知识”而非自动检索，牺牲一点智能程度，换取可解释、可验收和权限边界清晰。
- 不强行把 HTML PPT 重写进通用网页生成器，避免功能倒退；统一发生在任务和来源协议层。
- OpenDesign 先接协议和探测、后接真实执行，可防止配置未完成时出现假能力，但首版视觉效果仍主要由 MAP 提示词和模板质量决定。
- 快照会增加存储量；首版限制引用数量与正文长度，并保留摘要用于去重和审计。

## 验收标准

1. 任一入口创建的任务都能说明来源、目标、当前阶段、真实执行器和最终产物。
2. 网页或幻灯片生成过程中持续出现可见产物变化，刷新后可恢复。
3. 从知识库跳转后不要求用户重新选择同一文档。
4. HTML PPT 发布后可在网页托管继续微调，来源链和版本链均可追溯。
5. 未部署执行器不能被选中，界面给出可操作的缺失条件。
6. 网页新建、发布、回退和失败重试均有自动化或预览环境证据。
