# 手机通知统一模板 · 设计

> **版本**：v1.0 | **日期**：2026-11-10 | **状态**：模板稿；尚未接入线上发送链路

**一句话**：所有手机通知文案集中在本文件，先说清哪个系统、哪个环境出了什么事，再用两句短话说明影响和下一步。
**谁该读**：审核手机通知文案的负责人，以及接入 MAP、CDS、LLMGW 通知的研发与验收人员。
**读完能做什么**：逐条查看模板和实际展示样例，核对环境、原因、操作和通知去向，明确运行接入前必须验证的边界。

## 交付状态

本次交付的是通知模板及其显示约定，供用户直接查看。文案以本文件为唯一维护来源，不再分别复制到各通道的说明文档中。

当前没有修改手机推送实现、通知通道、收件人、静音策略或线上配置，也没有向手机发送演练消息。因此，本文件的存在不代表线上环境混淆已经修复。后续运行接入应复用现有通知服务、队列和通道，不能另建一套通知系统。

## 手机统一格式

标题：`【{系统}·{环境}】{发生了什么}`

正文：第一句写当前影响；第二句写接下来怎么做。分支预览另加一行简短分支名称。

| 部位 | 显示内容 | 约束 |
|---|---|---|
| 标题 | 系统、环境、事件结果 | 尽量在 40 字内；系统和环境不可省略 |
| 正文 | 影响、下一步 | 尽量在 90 字内；最多三行；不要把长错误直接截断当摘要 |
| 分支提示 | `分支：{分支显示名}` | 分支预览必带；完整分支名留在详情中 |
| 点击通知 | 对应系统、对应环境的具体记录或产物 | 保留事件原有真实深链，不跳错环境、不猜域名 |
| 手机分组 | 系统、环境、实例或分支 | 正式与测试、不同系统、不同预览分支分别分组 |
| 详情页 | 时间、来源、诊断证据、完整日志、追踪号 | 技术信息在这里保留，不塞进锁屏正文 |

花括号表示需要由真实事件提供的业务信息。不能确认的内容要明确说“尚未确认”，不能由模板补出成功、欠费、已恢复或不会影响用户等结论。

## 系统与环境怎么区分

### 系统标识

标题中的系统是此次受影响或产生结果的系统，不是发送消息的程序。

| 事件 | 标题系统 | 检测或发送来源 |
|---|---|---|
| CDS 检测到 MAP 无法访问 | MAP | CDS 监控，放详情 |
| MAP 通过 LLMGW 调用视频，上游欠费导致生成失败 | MAP | LLMGW 与上游服务，原因放正文，线路放详情 |
| LLMGW 自身发现账号额度或计费配置问题 | LLMGW | 模型网关，放详情 |
| CDS 控制台或部署服务自身异常 | CDS | 对应检测来源，放详情 |
| CDS 将 MAP 新版本发布到正式环境 | MAP | CDS 发布，放详情 |
| CDS 读不到 MAP 的监控结果，未确认 MAP 是否异常 | CDS | 监控采集；不能改写为“MAP 不可用” |

没有确定系统标识时显示“系统待确认”。不能统一套用“MAP System”，也不能因为推送经 CDS 发送就都叫 CDS。

### 环境标识

| 真实环境 | 手机标签 | 必要补充 |
|---|---|---|
| 正式发布目标 | 正式 | 有多个实例时在详情与分组保留实例身份 |
| 明确登记的共享测试环境 | 测试 | 不能仅因为由 CDS 托管就认定为共享测试 |
| 明确登记的发布前验证目标 | 预发 | 与正式环境分别分组、分别统计 |
| CDS 分支预览 | 分支预览 | 正文加分支显示名，分组保留稳定分支身份 |
| 本地开发环境 | 本地 | 只有确知事件来自本地时使用 |
| 来源未提供，或来源互相矛盾 | 环境待确认 | 正文提示先核对环境；不可默认为正式 |

环境取自被通知事件的真实部署身份、发布目标或分支绑定，不能取手机推送服务自身的运行环境。生产构建模式也不等于业务正式环境。预览分支不能通过自报“正式”改变其环境身份。

不同系统、环境、实例或分支不能共用去重与合并范围。未知环境的消息也不能合并进正式环境摘要。以上是接入时的验收约束，本次不自动改变现有订阅范围或发送频率。

## 通知模板全表

下表的标题列省略统一前缀 `【{系统}·{环境}】`；实际手机标题必须加上。正文中的换行表示手机显示换行。

GW-01、GW-02、GW-03、GW-04、GW-05 必须按已确认的原因选择。不能把限流说成欠费，不能把资源授权说成余额不足，不能把“已选择备用线路”说成“本次请求已完成”。GW-03 不提示用户盲目充值，因为账号有余额仍可能触及密钥上限。

### 摘要与通知通道

| 编号 | 场景与使用条件 | 标题 | 手机正文 | 点击去向 |
|---|---|---|---|---|
| MSG-01 | 同一系统、环境、实例或分支内的既有聚合通知 | 有{消息数}项新消息 | {最重要的消息摘要}。<br>其余{剩余消息数}项可在通知中心查看。 | 已按相同系统与环境筛选的通知列表 |
| MSG-02 | 用户主动发起通道测试 | 这是一条通知测试 | 用于检查{系统}·{环境}的手机推送。<br>收到即可，无需处理业务问题。 | 通道测试记录 |
| MSG-03 | 已确认通知投递失败 | 有一条通知尚未送达 | {通知主题}未能通过{通道名称}送达。<br>请检查通道配置，原消息已保留。 | 投递记录与通道配置 |
| MSG-04 | 环境或系统身份缺失 | 通知来源需要核对 | 尚未确认这条消息来自哪个系统或环境。<br>请先核对来源，再处理问题。 | 原通知及其来源详情 |

MSG-01 的消息数必须来自同一范围；只有一项时展示原消息，不写“其余0项”。MSG-03 不能只发到刚失败的同一通道；至少在站内投递记录中可见，其他通道只有原本已授权时才能使用。通道收到请求不等于手机已送达或用户已读，状态必须据真实回执描述。

## 手机实际展示样例

以下仅为模板示例，不是已经发送到手机的通知。

### 示例 1：MAP 正式环境的视频账号欠费

> 【MAP·正式】上游账号欠费，视频生成受阻
>
> 新的视频暂时无法生成。<br>
> 请管理员处理对应视频服务的账单。

检测方可以是 CDS 或 LLMGW，标题仍是受影响的 MAP。具体上游、账号和错误回执放详情。

### 示例 2：测试环境的 OpenRouter 密钥用量上限

> 【LLMGW·测试】OpenRouter 调用额度已达上限
>
> 当前密钥已达到 $30 用量上限，付费调用受阻。<br>
> 请管理员检查这条线路的用量上限。

只有已登记为共享测试的环境才用“测试”；当前独立 CDS 分支应显示“分支预览”并补分支名。密钥上限不等于整个账户欠费。

### 示例 3：CDS 分支预览中的语音任务完成

> 【MAP·分支预览】语音已生成
>
> 分支：完整功能验收<br>
> 4秒音频已保存，可以播放或下载。<br>
> 点击打开结果。

分支显示名来自实际分支登记；详情保留完整分支身份。点击落到该分支的同一条音频任务，不跳正式环境。

### 示例 4：验收仍有阻塞，不说“全部通过”

> 【MAP·正式】本次验收有17项受阻
>
> 视频、图片等生成仍受额度或授权限制。<br>
> 需要恢复对应依赖后才能完成验证。

95项通过、17项阻塞的完整清单放报告，不在手机上列112个用例或技术编号。没有明确下一步责任时不承诺“已安排处理”。

### 示例 5：监控读不到，不等于 MAP 已经故障

> 【CDS·正式】暂时读不到监控结果
>
> MAP 的业务状态尚未确认。<br>
> 请先检查监控连接。

监控来源与实际故障主体需分别确认，不能拿采集失败代替业务不可用结论。

### 示例 6：来源缺失时如实显示

> 【系统待确认·环境待确认】通知来源需要核对
>
> 尚未确认这条消息来自哪个系统或环境。<br>
> 请先核对来源，再处理问题。

## 通知正文里不放什么

- 密钥、访问令牌、内部地址、请求正文、用户原文和未脱敏个人信息。
- 原始异常堆栈、HTTP回执、模型协议、运行号、用例号、提交哈希和完整追踪号。
- 让人自行换算的阈值长串、全量检查列表、长URL和重复的系统前缀。
- 未经证实的根因、“不会影响用户”“旧版本正常”“已经恢复”等保证。

技术信息继续保留在受权限控制的详情页。手机锁屏能看到的内容应比详情少，用户明确订阅的敏感协作事项也只显示脱敏摘要。

## 接入验收标准

| 必须证明 | 可观察结果 |
|---|---|
| 正式与测试分清 | 相同功能同时发生异常时，两条标题、手机分组和点击去向各自正确 |
| 系统分清 | CDS检测MAP异常时，手机标题写MAP；CDS自身异常才写CDS |
| 分支分清 | 两个预览分支不会互相去重或合并，正文能看出分支，点击回到各自原任务 |
| 来源不被猜成正式 | 缺失或冲突的环境显示环境待确认，不混入正式通知摘要 |
| 原因分清 | 欠费、密钥限额、限流、资源未授权各用对应模板，不互相替代 |
| 结果属实 | 只有真实产物可用才发任务完成；结果未知不会引导重复收费提交 |
| 正文可读 | 手机无需展开就能知道影响和下一步，长诊断只在详情可见 |
| 摘要不混环境 | 同一批正式和测试消息分别归组，统计数与各自通知列表一致 |
| 恢复不误报 | 原故障与恢复对应，且满足既有稳定恢复条件；状态未知不发已恢复 |
| 订阅不被扩大 | 未订阅的用户不会收到新增类型；演练消息只发送给明确指定接收者 |
| 脱敏与投递准确 | 锁屏不暴露凭据或内部诊断；未送达、已投递与已读不混为一谈 |

本轮仅校验模板完整性、措辞和文档链接。上表属于后续运行接入的验收门槛，尚未执行，不能据此声称真实手机链路已通过。
