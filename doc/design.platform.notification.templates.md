# 通知分类与短讯报告 · 设计

> **版本**：v1.1 | **日期**：2026-11-11 | **状态**：分类与模板报告；运行接入尚未实施

**一句话**：先按类别、系统、环境交叉查阅同一事件，手机与 Apple Watch 只显示一句事实，完整报告和实时监控统一归 CDS。
**谁该读**：需要快速判断告警的负责人，以及接入通知、报告中心与监控中心的产品、研发和验收人员。
**读完能做什么**：确定分类方式、查看完整短讯模板，理解 CDS 报告与监控如何关联，并核对环境、统计与事件对应是否正确。

## 本轮结论

查阅顺序：**类别 → 系统 → 环境**。三个维度允许交叉，不要求 MECE，也不要求一条事件只能放进一个目录。

短讯只回答：**什么环境、哪个系统、哪个功能、出了什么问题**。有统计时补时间窗口和次数，与判断有关时补上游或型号。

标准示例：**正式 MAP 生图 OpenAI 5分钟失败3次**。

本轮先交付并归档报告，替换上一版偏长的手机文案。分类规则、模板和报告约定只维护本文件，CDS 展示其发布副本。没有修改线上推送、收件人、分类筛选或去重实现，也没有发送手机演练消息。

## 一、分类：类别 → 系统 → 环境

### 1. 类别，可多选

| 类别 | 包含什么 | 常见交叉 |
|---|---|---|
| 服务可用性 | 无法访问、连接异常、监控读取失败、恢复 | 功能结果、上游依赖 |
| 功能结果 | 生图、视频、问答、识别等功能的成功或失败 | 上游依赖、任务协作 |
| 上游依赖 | OpenAI、OpenRouter、豆包、Azure OpenAI 等线路与授权问题 | 功能结果、额度账单 |
| 额度账单 | 账号欠费、余额不足、密钥限额 | 上游依赖、功能结果 |
| 价格用量 | 模型缺价、价格偏差、文本用量缺失 | 额度账单、上游依赖 |
| 发布回滚 | 发布结果、回滚结果 | 服务可用性、验收巡检 |
| 验收巡检 | 通过、未通过、未完成、外部依赖阻塞 | 被检查功能涉及的其他类别 |
| 任务协作 | 任务、缺陷、待审文档、用户反馈 | 功能结果、验收巡检 |
| 资源到期 | 服务器、域名、证书等资源到期 | 服务可用性 |
| 通知链路 | 通道测试、投递失败、来源不明、消息摘要 | 相关事件本身的其他类别 |

例如，生图因欠费失败可同时属于“功能结果、上游依赖、额度账单”。严重程度和处理状态单独显示，不拿“紧急”“已恢复”代替类别。

### 2. 系统，可交叉关联

| 系统 | 判定方式 |
|---|---|
| MAP | 受影响的用户功能或本次发布对象属于 MAP |
| LLMGW | 模型网关自身的线路、额度、价格、计量或调度问题 |
| CDS | 部署平台、报告中心、监控服务或通知投递本身的问题 |
| 其他系统 | 使用实际登记的系统名称 |
| 系统待确认 | 来源缺失或证据冲突时明确保留 |

具体事件保留一个用于短讯的主体系统，允许关联其他系统。MAP 生图经 LLMGW 调用 OpenAI 失败，主体是 MAP，关联 LLMGW，上游是 OpenAI；在 MAP 和 LLMGW 的相关报告中均可找到同一事件。

检测方不替代主体。CDS 检测到 MAP 异常，不能统一写“CDS异常”；实际坏的是 CDS 的监控读取时，才以 CDS 为主体，并明确“MAP状态未知”。

### 3. 环境，报告可覆盖多个环境

| 环境 | 使用边界 |
|---|---|
| 正式 | 被通知对象实际位于正式发布目标 |
| 测试 | 明确登记的共享测试环境 |
| 预发 | 明确登记的发布前验证目标 |
| 分支预览 | 实际绑定 CDS 预览分支，报告保留具体分支 |
| 本地 | 确认来自本地开发或运行 |
| 环境待确认 | 来源缺失或证据冲突，不默认为正式 |

单次调用或实例的环境按真实身份确定。跨环境报告可同时关联正式、测试和多个分支，但各环境结果与次数分别保留。不能因为推送由正式 CDS 发出，就将测试事件标成正式；生产构建模式也不是正式环境的依据。

### 4. 交叉分类示例

以下是说明样例，不是当前实时告警。

| 事件 | 类别 | 主体系统 | 关联系统 | 环境 |
|---|---|---|---|---|
| OpenAI 生图5分钟失败3次 | 功能结果、上游依赖 | MAP | LLMGW | 正式 |
| OpenRouter 密钥额度耗尽 | 额度账单、上游依赖 | LLMGW | MAP | 测试 |
| 生图因账号欠费失败 | 功能结果、额度账单、上游依赖 | MAP | LLMGW | 正式 |
| 双环境验收有阻塞 | 验收巡检、功能结果、上游依赖 | MAP | CDS、LLMGW | 正式、测试 |
| CDS 读不到 MAP 检查结果 | 服务可用性 | CDS | MAP | 正式 |

同一事件在多个分类中可见，事实与证据只保存一份。总数按事件去重，不能把三个标签命中算成三起故障。同维度多选默认匹配任一选中项，不同维度逐层收窄。

## 二、手机与 Apple Watch：一句话

顺序：**{环境} {系统} {功能} {上游或型号，可省} {时间窗口，可省}{结果}{次数，可省}**。

优先30字以内，最长以40个可见字符作为本版文案预算。这是内容预算，不承诺所有手表型号、字号与通知样式都免滚动；运行接入时需用用户实际手表核对。

没有窗口就不填“5分钟”，没有次数就不填“0次”，原因未确认就写“原因未明”。型号仅在区分线路或故障范围有帮助时出现。

| 情形 | 短讯示例 |
|---|---|
| 用户给出的标准 | 正式 MAP 生图 OpenAI 5分钟失败3次 |
| 已确认欠费 | 正式 MAP 视频 豆包账号欠费 |
| 密钥限额 | 测试 LLMGW OpenRouter额度已用完 |
| 资源授权 | 正式 MAP 转写 豆包未授权 |
| 上游限流 | 测试 MAP 问答 OpenAI 1分钟限流5次 |
| 模型缺价 | 正式 LLMGW 20个模型未配价格 |
| 文本用量异常 | 测试 LLMGW 文本11次用量为0 |
| 监控采集失败 | 正式 CDS 监控读取失败，MAP状态未知 |
| 真正恢复 | 正式 MAP 生图已恢复 |
| 分支任务 | 预览·分享修复 MAP 问答5分钟失败3次 |
| 来源不明 | 环境待确认 MAP 生图失败 |

不默认补“请管理员处理”“点击查看详情”等套话。处理建议、长日志、追踪号放报告。类别用于报告与订阅筛选，不强塞进短讯。

通道若要求标题和正文：标题写“正式 MAP 生图”，正文写“OpenAI 5分钟失败3次”，合起来仍是一句话，不重复。长对象使用已登记的短显示名，不截断型号、时间单位或次数；完整分支与实例身份保留在报告和分组中。

| MSG-02 | 通知链路 | {环境} {系统}手机通知测试 |
| MSG-03 | 通知链路 | {环境} {系统} {通道}通知投递失败 |
| MSG-04 | 通知链路 | {环境或环境待确认} {系统或系统待确认}来源需核对 |

不能仅凭上游失败次数宣布整个功能不可用；“已恢复”须满足稳定恢复条件，“备路完成”须有本次真实成功结果。欠费、余额不足、密钥限额、限流和未授权分别使用对应模板。文本零用量模板不用于图片。

上游重试失败三次，不等于三个用户任务失败。必须区分上游调用、独立请求与任务；备用线路最终完成任务时，不能同时写用户任务失败。

## 四、CDS 报告中心与监控中心

### 已有能力与本次归属

已核对现有入口：报告中心 `/reports`，监控中心 `/status`，项目检查总览 `/status/{项目}`。报告目前按项目和文件夹归档。交叉分类筛选是本报告规定的后续接入能力，尚未实现。

本报告归档在 CDS“通知系统 / 分类与短讯”。目录只是存放位置，不能通过复制多份正文来模拟交叉分类。

| 入口 | 回答什么 | 保留什么 |
|---|---|---|
| 监控中心 | 现在是否异常 | 当前状态、最近检查时间、影响对象与事件入口 |
| 报告中心 | 发生过什么、如何判断 | 时间范围、分类、证据、统计口径、原因与处理记录 |
| 手机与手表 | 此刻要知道什么 | 一句短讯，点击进入对应报告或事件 |

三处使用同一事件事实。报告能回到相关监控目标，监控能打开该事件报告；快照保留当时结论和时间，不能被后来恢复的状态抹掉。

### 报告首屏样例

以下数字仅用于说明版式，不代表当前环境状态。

| 项目 | 显示示例 |
|---|---|
| 标题 | 生图失败 · MAP · 正式 |
| 一句话 | OpenAI 5分钟失败3次 |
| 类别 | 功能结果、上游依赖 |
| 系统 | 主体 MAP；关联 LLMGW |
| 环境 | 正式；保留具体实例 |
| 功能与上游 | 生图；OpenAI；有必要时显示型号 |
| 发生时间 | 开始时间、最近发生、统计窗口边界 |
| 次数与口径 | 3个独立请求失败；已知总请求数时才显示比例 |
| 当前状态 | 异常、受阻、处理中、已恢复、完成或未知 |
| 已确认原因 | 已有明确回执；没有证据时写原因未明 |
| 建议操作 | 负责人需要采取的具体动作 |
| 证据与入口 | 同环境的任务、调用记录、监控目标与证据 |

首屏先给结果，技术信息放后面。没有总请求数就不编失败率，也不能把交叉标签命中次数相加。

### 筛选、去重与通知

1. 先类别、再系统、再环境；每个维度支持多选标签。
2. 一条事件可同时出现在功能结果和额度账单，总计只算一次。
3. 跨环境报告分别显示正式、测试明细；短讯不把它们合成一个环境的次数。
4. 恢复和处理与原事件关联，保留历史，不把每次状态变化都算新故障。
5. 不同实例、分支、上游或型号是否合并，必须有同一事件的证据；不能仅因短讯相同就合并。
6. 多个检测来源观察同一问题时，依据共同任务或调用身份核对，保留来源，避免重复。
7. 分类不自动扩大通知权限、接收人或频率，沿用原有授权与订阅。

## 五、后续接入验收

| 验收点 | 必须观察到 |
|---|---|
| 分类顺序 | 先类别、再系统、再环境，不用模板编号作为用户主导航 |
| 交叉分类 | 多个类别和关联系统共享同一事件，统计去重 |
| 环境准确 | 正式、测试、预发和分支独立；来源缺失不默认为正式 |
| 主体准确 | CDS检测MAP业务异常时显示MAP；采集失败不冒充业务中断 |
| 手表短讯 | 一句话优先30字以内；按实际设备字号核对可见范围 |
| 统计真实 | 窗口和次数来自记录，重试、调用、任务不混算 |
| 报告关联 | 短讯打开同一事件，报告与监控互查，不跳错环境 |
| 状态属实 | 成功有真实结果，恢复有稳定判据，未知不写成成功或失败 |
| 安全与投递 | 锁屏不暴露凭据或敏感原文；投递、手机送达、已读分别记录 |

本轮完成分类与短讯报告及 CDS 归档。运行时分类、合并、去重、手机发送链路和 Apple Watch 实机验收尚未实施；报告已交付不等于通知系统已修复。
