# 模型生命周期边界 · 债务台账

> **版本**：v1.1 | **日期**：2026-11-15 | **状态**：持续跟踪

**一句话**：记录自动模型升级尚未覆盖的供应商事实与并发边界。
**谁该读**：模型运营人员和网关维护者。
**读完能做什么**：判断哪些候选可以自动升级，哪些必须保留人工确认。

| 编号 | 边界 | 当前控制 | 后续条件 |
|---|---|---|---|
| 1 | 供应商模型目录通常不提供可靠的继任、退役和质量比较事实 | 新发现型号只列出待确认；必须登记官方继任关系和能力契约 | 接入可核实、可审计的供应商生命周期数据 |
| 2 | 图片供应商可能没有请求级美元硬上限，图片用量也可能缺少分类 | 使用显式独立预占上界，缺失可靠用量时保守保留额度；未知结果禁止自动重发 | 供应商提供可信分类用量和可证明成本上界 |
| 3 | 共享配置更新与请求进入之间存在跨集合并发窗口 | 已解析请求保留快照；切换前检查任务、版本和租约，仅支持单条启用线路，并保留补偿与历史 | 若要求严格停流切换，需要统一调度屏障或事务设计 |
| 4 | 网关持久请求记录没有完整逻辑模型路由快照 | 自动切换保守阻止组织内所有未过期的运行中或结果未知执行 | 持久化完整路由身份后缩小阻止范围 |
| 5 | 自动探测仅支持已登记且有授权、预算和协议约束的候选 | 未知协议、价格或规格保持阻止；固定版本不自动跨代 | 补齐真实供应商契约和回归证据后逐类开放 |
| 6 | 进入网关请求后，部分本地拒绝缺少可核实的上游发送事实 | 只对尚未进入付费调用的确定失败释放内部预占；其余保留额度且禁止按错误文案推断退款 | 网关提供与请求、租约、线路绑定的持久化发送证明后再缩小保守保留范围 |
| 7 | 指纹规则升级前建立的 MCP 任务记录包含当时的 SDK 传输上下文，无法无损重算原始业务指纹 | 保留旧记录的冲突保护，不自动改写许可或重发；已生成作品通过原任务 ID 使用查询工具取回。新规则只忽略已观测的有限传输字段 | 若需要迁移旧重放记录，先取得完整且可信的原始业务证据，并建立独立可审计迁移流程 |
| 8 | MAP 业务配置写入与 Gateway 删除检查分属两个服务，跨库检查不是跨服务事务 | 保存校验、退役引用检查、入队复核及发送前只读目录复核共同阻止失效执行；目录故障保留配置并标为状态未知 | 如需严格禁止并发保存与退役产生短暂悬空，需统一引用登记与调度屏障 |
| 9 | 已删除物理上游的活动业务配置缺少可信逻辑身份，无法从同名型号证明等价关系 | 从持久化的使用位置派生精确原身份，管理员明确选择替代后原位升级；未知结构或用途不符时阻止，不按相似名称替换 | 双环境验收完整升级与孤立引用修复；保留历史记录的真实模型身份 |
| 10 | 配置可在迁移结束后再次保存旧模型，跨服务写入尚未共享同一事务屏障 | 每次完成需反向扫描，完成计划定时复核并设证明有效期；发现残留、未知或过期时不能继续显示通过 | 若要求任意时刻绝无短暂悬空，需所有配置写入端统一引用登记与调度屏障；定时复核不是事务保证 |
| 11 / P1 / open | 旧型号仍经迁移后的知识库专用逻辑模型暴露给文学创作，并参与真实调用；平台退役意图未落实到活动线路和引用 | 已用 CDS main 真实目录、真实调用日志及退役预检确认，未以隐藏选项或绕过引用保护代替退役 | 明确替代方案，迁移调用方及竞技场引用，处理三条启用旧线路，完成真实调用和目录复验；详见下节 |

## 旧型号退役遗漏：知识库录音整理线路（2026-11-15）

**状态：open；优先级：P1；责任角色：模型运营与网关维护者。** 用户反馈 `gpt-4.1-mini` 等旧型号此前已取消，但文学创作仍可选择，实际请求也仍使用该型号。本条记录平台配置退役遗漏，不据型号名称推断供应商已停止服务。

### 已确认的业务影响与证据

文学创作写作模型目录将 `document-store-transcribe-summary`（名称“知识库录音整理池”，逻辑身份 `gw-logical-b35a98b43f5c4b3c8abfb8c428dd5735`）作为可选模型发布。该模型仍启用、未限制可用调用方，首选上游是 `gpt-4.1-mini`，另外两条启用备用是 `gpt-4o-mini`、`gpt-4.1`。健康状态只表示线路可调用，不能证明它符合平台退役决定。

PR #1989 的独立验收已证明旧型号确实被调用：日志 `0bfd9afb-2722-4cea-9ab2-2cc4b970ec83`，业务请求 `7fa9f6f85c2f42cd80dabfafb8b47538`，UTC 2026-11-15 09:18:20，发布提交 `5c41c8efce0d0d2b3cf7bf148732de3b662bdf94`。请求的逻辑标识为 `document-store-transcribe-summary`，网关解析与实际发送均为 `gpt-4.1-mini`，上游返回 HTTP 200。该次生成标记缺少约定的 `@AFTER` 前缀，最终界面为零标记；退役修复后仍须独立复测此结果解析缺陷，不能自动认定已解决。

完整截图及调用证据见 [PR #1989 CDS 验收报告](https://miduo.org/reports?project=prd-agent&folder=11313144468044c7bd014fb3cf52ad33&report=cdfc679876324e0f9246c88c68e7653d)。复现路径：登录 → 首页 → 百宝箱 → 文学创作 → 新建私有验收文章 → 写作模型 → 搜索 `gpt-4.1-mini`。不需修改已有文章即可确认目录残留。

### 本次修复受阻的实测结果

2026-11-15 通过仓库 cdscli 获取 CDS main 的真实 MAP 与 Gateway 地址，随后在该 Gateway 核对当前配置；没有假定正式环境与预览环境同步，也未向正式环境写配置。

- 尝试以现有 `gpt-6.1-sol` 逻辑模型为目标执行只读迁移覆盖检查，返回 HTTP 409、`REFERENCE_ROUTE_AMBIGUOUS`：原模型存在多条启用线路，当前迁移要求唯一且可核对的线路。此检查未建立迁移计划、未切换实际上游。
- 退役只读预检返回 `canDelete=false`：两处残留、两处阻断；知识库调用方仍指定该模型，另有一个模型竞技场槽位引用。原模型共有 39 条线路记录，其中三条启用；不能用删除历史记录来证明活动引用已迁移。
- 仓库记录了旧阵容迁往 `gpt-6.1-sol` 的方向，但当前受保护流程不能完成这条多线路专用模型的迁移。本次保留原配置及引用，没有直接改库、禁用引用保护或重写历史调用记录。

### 关闭条件

1. 模型运营明确这条专用模型及两条旧备用的替代关系、能力与预算；盘点其全部活动引用，保留历史作品和日志的真实模型身份。
2. 在受保护流程内迁移知识库调用方及竞技场槽位，明确多线路的处理方式；迁移需可恢复、可审计，不能通过临时取消备用绕过身份检查。
3. 退役检查确认活动引用及阻断为零，再停用原逻辑模型及不再需要的旧线路。核对文学创作目录、旧选择提示、刷新恢复及旧标识请求的明确反馈；不能静默把旧选择替换成另一型号。
4. 分别完成文学创作标记生成、知识库录音整理和竞技场的真实业务调用，对照界面、请求、解析及上游日志，确认新型号实际生效；零标记缺陷单独复验。按发布流程逐环境确认，不能用 CDS main 的结论替代正式环境验收。
