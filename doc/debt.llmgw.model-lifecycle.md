# 模型生命周期边界 · 债务台账

> **版本**：v1.0 | **日期**：2026-11-11 | **状态**：持续跟踪

**一句话**：记录自动模型升级尚未覆盖的供应商事实与并发边界。
**谁该读**：模型运营人员和网关维护者。
**读完能做什么**：判断哪些候选可以自动升级，哪些必须保留人工确认。

| 编号 | 边界 | 当前控制 | 后续条件 |
|---|---|---|---|
| 1 | 供应商模型目录通常不提供可靠的继任、退役和质量比较事实 | 新发现型号只列出待确认；必须登记官方继任关系和能力契约 | 接入可核实、可审计的供应商生命周期数据 |
| 2 | 图片供应商可能没有请求级美元硬上限，图片用量也可能缺少分类 | 使用显式独立预占上界，缺失可靠用量时保守保留额度；未知结果禁止自动重发 | 供应商提供可信分类用量和可证明成本上界 |
| 3 | 共享配置更新与请求进入之间存在跨集合并发窗口 | 已解析请求保留快照；切换前检查任务、版本和租约，仅支持单条启用线路，并保留补偿与历史 | 若要求严格停流切换，需要统一调度屏障或事务设计 |
| 4 | 网关持久请求记录没有完整逻辑模型路由快照 | 自动切换保守阻止组织内所有未过期的运行中或结果未知执行 | 持久化完整路由身份后缩小阻止范围 |
| 5 | 自动探测仅支持已登记且有授权、预算和协议约束的候选 | 未知协议、价格或规格保持阻止；固定版本不自动跨代 | 补齐真实供应商契约和回归证据后逐类开放 |
| 6 | 进入网关请求后，部分本地拒绝缺少可核实的上游发送事实 | 只对尚未进入付费调用的确定失败释放内部预占；其余保留额度且禁止按错误文案推断退款 | 网关提供与请求、租约、线路绑定的持久化发送证明后再缩小保守保留范围 |
| 7 | 指纹规则升级前建立的 MCP 任务记录包含当时的 SDK 传输上下文，无法无损重算原始业务指纹 | 保留旧记录的冲突保护，不自动改写许可或重发；已生成作品通过原任务 ID 使用查询工具取回。新规则只忽略已观测的有限传输字段 | 若需要迁移旧重放记录，先取得完整且可信的原始业务证据，并建立独立可审计迁移流程 |
| 8 | MAP 业务配置写入与 Gateway 删除检查分属两个服务，跨库检查不是跨服务事务 | 保存校验、退役引用检查、入队复核及发送前只读目录复核共同阻止失效执行；目录故障保留配置并标为状态未知 | 如需严格禁止并发保存与退役产生短暂悬空，需统一引用登记与调度屏障 |
| 9 | 已删除物理上游的历史业务配置缺少可信逻辑身份，无法从同名型号证明等价关系 | 保留旧配置与历史，明确标为待修复；管理员显式选择逻辑模型后原位修复，不自动改用默认或相似型号 | 有可审计的原始逻辑身份映射时才做自动迁移 |
