# 视觉创作 · AI 分层 · 验收债务台账

> **版本**：v1.0 | **日期**：2026-08-11 | **状态**：开发中

**一句话**：AI 分层这条链路上「我声称做了、但当前没有机械判据能证明」的每一条，连同它为什么证不了、要什么才证得了。
**谁该读**：接手 AI 分层的工程师；下一轮想问「这块到底验没验过」的人。
**读完能做什么**：一眼分清哪些是有冒烟守着的、哪些只是我推导的，并知道下一步该补哪条判据。

---

## 为什么要有这份台账

「已验证」和「我认为它是对的」之间隔着一条真实的判据。这两者混在交付消息里，
下一个人（包括我自己）就会把后者当成前者，在一个从没被证明过的结论上继续盖楼。

本台账只记**验收债务**：功能已交付，但缺少能变红的判据。工程实现层面的欠账
（想做没做的功能）不进这里。判据分档与坏形状的定义见文末「实现来源」列的判据纪律规则，
自测优先的要求见根目录的 Agent 约定第 8.1 条。

判据状态只有三档，不许有第四档：

| 档位 | 含义 |
|---|---|
| 已守 | 有能变红的自动判据（冒烟或单测），且做过红绿闭环 |
| 弱守 | 有判据但证明力不足（样本恒成立、只测了形状没测行为） |
| 未守 | 没有任何自动判据，当前只靠人工观察或逻辑推导 |

## 维护约定

1. 每次交付 AI 分层相关改动，**先更新本表**再报完成：新增的「说了但没判据」必须落一行。
2. 判据补上后把该行改成「已守」并写明判据名，**不要删行**——删了就看不出这条曾经欠过。
3. 「弱守」升「已守」必须做红绿闭环：把修复临时撤掉，确认判据变红。
4. 台账只增不隐：如果某条判据被发现是恒成立的假证据，降级回「弱守/未守」并写明为什么。

## 历史

**判据自己造假一次**：裁剪那条判据的第一版是恒成立的——挑了覆盖率 100% 的背景层去验裁剪，
它的最小矩形本来就等于整幅，裁没裁都会通过。发现后改成挑覆盖率最低那层并按面积比判。

**补判据时抓到真缺陷一次**：给「编组/解组持久化」补判据的过程中，冒烟报出「解组后刷新，
Frame 又有 2 组」。根因是读回时无条件拿产物血缘去补编组标识，于是「解组」在下一次刷新后
被静默撤销。修法是给新写出的记录盖一个迁移标记：有标记时缺失就是真的解过组，没标记才当旧数据补。
这条缺陷在补判据之前一直存在，没有任何人发现——**这就是为什么弱守要优先于未守**。

**判据太松放跑了两个现象一轮**：「部件裁成最小矩形」当时判的是「各部件尺寸不全相同」，
这条对「框比内容大一圈」完全不敏感。用户圈图指出文字层的框比字大一大圈、还有一层看不见的
空盒子占着位置，根因都是求包围盒用的 alpha 阈值太松（8，约 3% 不透明度），
模型返回的那层几乎看不见的雾就把框撑到了整幅。改成按「实墨」（alpha ≥ 64）求框 +
按实墨覆盖率判空层，两个现象一起消失。判据也补了：单测直接对比「松阈值撑到整幅 vs
实墨阈值贴着墨走」。
