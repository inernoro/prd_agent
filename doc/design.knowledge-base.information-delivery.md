# 知识库信息高效传递 · 设计

> **版本**：v0.1 | **日期**：2026-11-19 | **状态**：目标流程设计稿

**一句话**：让作者用同一份有据可查的资料交付易读、易听、易学的内容，让接收者更快理解并正确行动。
**谁该读**：模板维护者、产品设计者、实现者和验收者。
**读完能做什么**：按六步设计作者界面，明确生成与交付边界，并判断走通流程以后还需要证明什么。

## 要解决的问题

作者知道哪些内容最重要，却要把同一件事再讲给每位同事。接收者从长文里自行找重点、问作者，或者交给自己的 AI 再压缩，容易漏掉执行条件、例外和依据。MAP 让作者控制重点和业务判断，保留原文及来源，并用接收者愿意使用的形式传递。

成功分两层。**功能上**，接收者能查到原文、分清责任、按正确条件行动。**传递效果上**，比较初次接触资料时只看原文和使用交付物的表现。关键判断的准确性要保持，阅读、定位与回问的总成本要下降。把作者整理、生成、补答、校对、重做和交付的时间也算进去，团队总耗时仍应减少。两层各自取证。

## 作者的六步

| 步骤 | 作者怎么做 | 产品需要呈现什么 |
| --- | --- | --- |
| 1. 浏览模板 | 打开入口，只看平台团队创建的模板。打开任一模板，查看完整示例和可浏览骨架。 | 示例说明成品是什么样；骨架说明有哪些章节、各段要回答什么、可以交付哪些形式。示例资料标记为示例。 |
| 2. 准备资料 | 上传自己的文档，或从知识库选择已有资料。可以同时使用两类来源。 | 用户看得见资料名、来源和是否可用。知识库引用沿用原有访问权限。 |
| 3. 添加附件并开始 | 在像邮件附件一样的统一区域里查看、移除或补加资料。可以输入提示词，也可以直接开始。 | 区分上传与知识库引用。开始时记录模板版本、实际使用的资料版本或快照、提示词和本次要求的产物。模板示例提供结构，业务内容来自本次资料和作者补答。 |
| 4. 观看过程并纠正 | 在生成页看流式输出，发现偏差就发消息纠正。 | 用 SSE（服务器实时推送）显示实际任务进展、资料缺口、需要作者决定的问题和已生成的文件。作者看得见纠正已收到、何时会应用以及应用后改变了什么。 |
| 5. 查看正在生成的文件 | 生成期间打开已出现的文件，查看网页、分镜或其他实际产物。 | MAP 把任务交给 OpenDesign，由执行环境中的本地 Codex CLI 在同一工作区运行。文件随生成出现，预览标明草稿或已就绪。任务结束后，生成页显示结果入口，保留消息和文件记录。 |
| 6. 预览并归档 | 确认本次要求的产物全部就绪后，预览结果，选择归档到网页托管或知识库。 | 两个去向均可独立完成。交付前可查看目标访问范围。已交付的版本可再次打开，后续修改产生可区分的新版本。 |

## 同一份内容，按兴趣和任务交付

- **简化内容、保留原文。** 首屏先给关键结论、适用范围和接下来由谁做什么。读者可以展开条件和例外，从关键说法跳到对应的原文片段，并在有权限时打开全文。保留来源的版本和位置。作者后补的规则标明是作者补充，原资料按原版本保留。
- **同一判断支持多种形式。** 网页便于扫读、查条件和回到原文，音频便于连续收听，视频便于展示动作和前后变化。作者按本次场景选产物，接收者选择已交付的形式。音视频的关键判断有可查的字幕或讲稿，能从相应段落回到依据。不同形式可以改变顺序、节奏和举例，条件、例外、责任和关键数字应一致。
- **把教程文档变成可操作的教学。** 教师给资料，MAP 先组织出要理解的概念、动作顺序、每步完成标准和检验题。执行条件缺失或来源冲突时，MAP 找出具体段落，问教师一个可作答的问题。教师补的是业务判断，MAP 负责更新相关章节、讲稿或分镜，并重查跨形式一致性。

## 生成与交付的边界

**用真实反馈约束生成。** 模板给结构和质量要求，资料给事实，提示词表达本次重点。OpenDesign 和 Codex 逐步产出、检查内容并按反馈修订。若当前执行轮次只能在下一轮应用纠正，页面显示等待应用，继续在同一任务里处理。刷新或短时断线后回到原任务，能找回消息、已生成的文件和待处理的补答。模型或执行失败时保留已收到的输入、错误与可恢复进度。

**保住作者确认的内容。** 任务预览可以展示未决问题。会导致接收者执行错误的缺口应在正式交付前由作者裁定，原文冲突和出处保持可查。已经交付的内容按版本固定。资料更新后，作者可以看到哪些产物受影响，再决定是否更新并重新交付。

**按访问范围处理来源。** 预览与归档沿用资料的授权范围。公开托管不能通过附件、摘要或引用带出无权公开的内容。受限来源可以在有权限时追溯。若缺少可供目标读者核验的关键依据，交付前提示作者收窄受众或提供可公开的依据。

## 怎么算完成

1. **入口顺序正确。** 真实入口首屏只有平台模板，能先独立查看示例和骨架。同一次任务能添加上传文件和知识库引用，并在留空提示词时启动真实生成。
2. **过程可见、可纠正。** 同一任务显示实际 SSE 进展和可打开的中间文件，能从执行记录核对 OpenDesign 和 Codex。系统问到资料缺口时作者能补答，作者也能根据实时草稿主动纠正。刷新后消息可查，文件修订前后能看到实际变化。
3. **规则没有走样。** 用同一含缺口和冲突的资料，检查完整原文、网页重点和教程，并播放实际生成的音视频核对内容。点选视频章节时，选中状态、播放位置和内容一致。接收者答对关键边界，找得到正文和依据，说得清谁确认与怎么处理例外。越权用户无法借交付物取得受限来源。
4. **各个归档入口闭环。** 所选产物全部就绪后才交付。分别经网页托管和知识库打开实物，核对版本、访问范围和来源。刷新、失败重试或资料更新后，已交付版本仍可复查。
5. **证据跟得上操作。** 桌面和手机各按相同顺序完整取证，每条记录用同一设备和同一任务贯穿模板、附件、生成、补答、文件和归档。记录入口、版本和任务标识，并保留错误与恢复。传递效率按前述任务比较另行记录。
