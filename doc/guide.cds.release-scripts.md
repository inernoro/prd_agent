# CDS 项目发布脚本 · 指南

> **版本**：v1.0 | **日期**：2026-10-21 | **状态**：实施验收中

**一句话**：项目维护并测试发布规则，CDS 执行指定提交的脚本，不再替项目推断业务部署方式。
**谁该读**：项目维护者、CDS 管理员及客户交付负责人。
**读完能做什么**：选择正确的发布入口，理解 CI、脚本正文、运行版本和回滚证据之间的对应关系。

## 默认方式

项目根目录的标准发布文件名见文末事实入口。它随项目代码一起评审、提交和回滚，
支持只做校验的 check 和正式发布的 deploy。项目 CI 必须测试同一文件；发布规则变化
不是登录生产服务器修改另一份脚本，而是提交项目 PR 并通过 CI。

CDS 新目标默认引用该文件，也允许设置仓库内其他安全的脚本路径。平台不判断项目应当
使用容器、静态站或其他业务方案。缺少文件、语法错误、当前提交 CI 未成功或正文指纹
不匹配时停止发布，不自动切换另一种方式。

## 明确选择的备选

确需独立维护时，可选择“CDS 独立脚本”，由 CDS 保存正文。它不会自动覆盖项目脚本，
并且需要单独审查：项目 CI 成功不等于独立编辑的正文已通过项目 CI。密钥继续使用
受保护的运行配置，不写进脚本。历史部署方式继续兼容已有目标，不作为新目标默认。

## 什么才算成功

发布记录锚定完整提交与脚本正文哈希；远端建立隔离目录、核对正文、先校验再执行。
项目脚本负责真实数据库迁移、服务就绪和业务资源验证，CDS 负责执行、日志、配置的
最终入口探测与历史记录。不能拿另一版本的 CI 绿灯或单一容器 running 当成功证据。

回滚重新执行历史成功版本的脚本与配置，而不是今天服务器上恰好存在的脚本。
业务数据库降级、零停机切换和外部依赖兼容仍须项目明确设计，平台不能自动保证。

## 维护要求

改动代码或资源时同步检查发布合同。禁止为消除发布报错而删检查、借旧 CI、热改服务器
脚本或换旧模式绕过。操作入口是发布中心的环境配置向导；首次迁移前保留原配置及
生产数据备份，完成后核对真实公网页面、资源和服务版本。

## 事实入口

- 项目标准发布文件：`cds-release.sh`。
