# MAP 与 CDS 磁盘容量治理 · 指南

> **版本**：v1.2 | **日期**：2026-11-14 | **状态**：候选，未启用生产

**一句话**：把来源占用、增长速度、容量预警和引用感知回收分开核对，优先回收可重建且无人使用的产物。
**谁该读**：MAP/CDS 运维负责人、部署维护者和容量评审人。
**读完能做什么**：选择采集范围、解释增长与预警、复跑隔离演练，并识别仍须人工决策的数据与回滚保留边界。

## 为什么已有清理还会满盘

CDS 7 月事故的主要增长来自带 SHA 标签的历史镜像；普通悬空镜像清理无法覆盖它们。10 月的源码盘点又发现快照中混有数据库和对象数据，不能把所有未挂载快照都当缓存。MAP 11 月满盘导致 Redis 持久化失败和 MongoDB 退出，清理后的剩余容量仍不足以宣布风险解除。

这些历史证据分别见 [CDS 状态存储债务](./debt.cds.state-json.md)、[CDS 部署源码隔离边界](./debt.cds.md)和[正式机容量恢复边界](./debt.platform.production-release.md)。历史数值不是当前读数；没有新采集就不能外推今天的可用空间。

## 先确认来源，再决定能否回收

| 来源 | 解释增长的证据 | 控制与保护边界 |
|---|---|---|
| SHA 部署镜像 | Docker 镜像总量、台账、全部运行与停止容器引用、在途输入 | 沿用 CDS 最近代数策略及临删引用复核；不运行全局镜像清空 |
| 构建缓存 | Docker Build Cache 分类 | CDS 已有缓存保留预算；共享层的逻辑大小不等于实际可释放字节 |
| 部署源码、孤儿工作树 | 独立来源目录占用、回收摘要和保留原因 | 源码超过原两小时门槛且无引用、无未知内容才回收；注销 Git 注册；身份或挂载未知则保留 |
| 静态发布产物 | 版本目录、远端 current/previous、成功台账、在途发布 | 沿用当前发布回收器；保留窗口外的在用和回滚锚点也必须保留；有在途发布时跳过 |
| 固定发布 ZIP 与旧页面兼容资源 | 独立保留来源与消费者约定 | 不是普通缓存，禁止套用部署版本数量直接删除；旧页面支持时长仍待约定 |
| 日志、归档、备份 | 各自独立来源占用、实际轮转配置与校验记录 | 沿用所属组件策略；业务备份须先验恢复，不因空间不足直接删 |
| 数据库、对象数据、容器卷 | 来源占用、实际挂载与数据归属 | 只观测；禁止 volume prune、自动搬迁或按目录年龄删除 |

多实例共用同一镜像仓库、人工绕过受管创建入口、引用未知或长期不释放，都可能让保留量继续增长。保留策略约束可回收的历史产物，不是整台机器的硬字节限额。

## CDS 自动回收如何追上积压

原源码回收每轮最多尝试 20 份、默认每小时一轮；持续每小时产生 32 份可回收快照时，旧调度每小时会多积压 12 份，保留规则本身不能解决这类服务能力缺口。

候选调度在一轮确实删除了源码、且仍有待处理项时，一分钟后继续源码回收；每个常规周期最多追加五轮。默认每小时至多 120 次源码删除尝试，遇到保护或失败时实际回收数会更低。续扫复用原回收器，不更改两小时年龄线、单轮 20 次预算、引用保护、目录身份、挂载检查或 Git 注册清理。续扫不执行 Docker prune、镜像清理、孤儿普通工作树或业务分支到期回收。

没有删除进展就不安排下一次续扫，避免未知挂载、失败或保护项造成忙重试。停止服务会取消未派发的续扫，旧运行代际的完成回调也不能重新挂定时器；已经执行的受管动作按既有边界收尾。手工完整清理若碰上源码续扫，会等待它完成后执行完整请求。

磁盘读数未知、既有告警水位或保护档位、回收失败，以及未能继续处理的积压，进入现有通知账本并指向系统维护。相同风险状态变化时提醒，持续状态每小时最多重新提醒一次；已配置 MAP 外发时沿用原通知通道，未配置或投递失败会如实记录。源码续扫成功不能清除尚未复核的镜像失败；最近完整轮次的失败摘要单独保留，直到下一次完整检查。原生清理进程若无法确认终态，沿用既有的进程内占用保护，并持续报告未知；另一目录删除成功或仅重启定时器不能冒报恢复。来源产生速度超过调度能力、保护对象增加或单件变大时，仍须处理产生端与容量余量，不能无限追加删除轮次。

## 只读容量探针

运维入口是 [host-capacity.py](../scripts/host-capacity.py) 的 `--help`，面向具备 Python 3、GNU du 和 POSIX 文件锁的 Linux 宿主。它只读取显式选择的来源，写入独立的私有采样目录，不具备删除能力。每台主机各用一份状态；MAP 与 CDS 即使同机也不要重复配置相同来源。

首次接入先在隔离机选择几个互不嵌套的目录，以 `--source 名称=绝对路径` 分别标明镜像存储、部署源码、静态产物、日志和业务数据；`--state-dir` 指向这些目录以外、属于当前用户且权限为 0700 的独立位置。有 Docker 读取权限时再启用 `--docker`：只查询本机标准 Unix socket，忽略继承的远端上下文和 TLS 选择器，避免把另一主机的镜像与本机磁盘混算；不改用户的 Docker 配置。路径必须来自现场挂载和配置，不从本指南猜测。

输出为 JSON，包含各来源实际分配字节、净变化、日增长速度、所属文件系统、可用字节、inode 余量、预计写满与到达安全余量的时间。Docker 分类另外展示，不与目录大小相加；跨来源硬链接也可能重复计数。整盘容量读数才是容量风险判断依据，未选中的目录属于未解释空间，不假定为零。

默认每小时保留一点，最多 192 点、单个状态文件不超过 4MiB。提交暂存固定一份，正常历史与暂存合计最多 8MiB 内容；反复强杀也不会按次数累积暂存。频繁执行不会挤掉历史窗口。写入使用互斥与原子替换；文件损坏、主机/来源变更、并发执行、采集失败均返回未知，不覆盖损坏状态。已有正常文件在替换前失败时保留；断电后的磁盘持久性仍取决于宿主文件系统。

## 预警的判据与处置

| 判据 | 默认值与含义 | 处置 |
|---|---|---|
| 磁盘/inode 使用率 | 75% 警告、90% 严重 | 核对最大来源、失败回收与保护项；不要直接缩短业务保留期 |
| 绝对可用空间 | 不高于 6GiB 为严重 | 评估下一次构建峰值与数据库写入需求，按既有受管流程止增 |
| 预测安全余量耗尽 | 7 天内达到余量线则警告 | 查增长最大的来源；复核近期加速是否来自部署、日志或数据 |
| 采样未知 | 冷启动无基线、超过两小时断采、时钟倒退、来源采集失败 | 恢复采集，保留原状态，禁止把未知读数解释为健康 |

增长速度取八天窗口和最近可比点的较大净增长率，减少近期加速被长期均值稀释的情况；缩容释放显示负变化。预测依赖过去负载，不包含未发生的突发构建、保留项扩大或数据峰值。

退出码为 0 正常、1 警告、2 严重、3 未知。调度器应对非零结果和缺失运行分别报警，保留最近一份结果，并按状态变化去重。只跑探针不等于通知已送达；应先在隔离环境注入余量阈值和增长样本，确认外部告警接收方能看到，再安排正式接入。本批不安装定时任务、不改变生产阈值或回收策略。

## 将观测接入控制台

探针每次在私有 `--state-dir` 原子更新 `latest.json`。历史保留192点，历史、最新报告及固定暂存槽各最多4MiB，内容合计最多12MiB；采集失败会尽可能发布新的未知报告，原历史不被错误覆盖。文件系统分配块及目录元数据另计。

由部署配置显式指定 `CDS_HOST_CAPACITY_REPORT_PATH` 指向这份只读报告，并设置 `CDS_HOST_CAPACITY_EXPECTED_HOST` 为报告宿主身份。采样任务与只读挂载由运维选择和安排；本功能不安装生产定时任务、不扫描新目录、不执行清理。缺失配置、无新采样、超过两小时、格式非法、宿主不符或读取失败都显示未知，不能用旧绿色状态证明安全。

系统所有者正常登录后进入「CDS 系统设置 → 调度器」，查看来源实际分配量、净变化、日增长及预计触及安全余量的天数。项目凭据和普通成员不能查看整机来源。增长观测的风险及恢复进入既有事件总线和通知账本，动作链接定位到调度器；恢复仅表示新采样的增长与余量检查正常，不代表源码回收、其他清理阶段或原生任务已恢复。相同风险最多每小时提醒一次。

MAP 外发在每条新通知记入本地后读取当前配置，更新配置无需重启；读取失败记为外发失败，未配置记为未外发，同一合并窗口不重复外发。配置存在及 HTTP 成功仍不能替代接收账号的真实通知页面验收。

长期接入可复用「CDS 系统设置 → 通知通道」现有的 MAP 签名配置：MAP 只登记公钥、允许的部署域名及固定接收账号，CDS 保存私钥。签名账号可使用独立服务身份，接收账号必须与 MAP 的固定目标一致；请求不会用用户标识绕开该校验。每次投递使用新的时间戳和随机数，沿用 MAP 已有防重放协议，不依赖人类登录令牌续期。

新私钥写入必须先启用密封存储，保存结果等待持久写入完成；私钥不会通过读取接口回显，不进入项目环境。旧明文配置保持只读兼容，页面明确标记并要求重新保存；密钥无法解密时不会改用旧管理员凭据。显式配置的专用 Bearer 与关闭开关仍优先。应在隔离环境验证保存、重启、容器重建、撤销与重新配置后的真实送达，再接入主用实例；MAP 业务拒绝或无法确认的响应不得标记为送达。

## 隔离增长与恢复演练

可复跑入口是 [14 天增长测试](../cds/tests/services/capacity-growth-drill.test.ts)与[容量探针测试](../scripts/tests/test_host_capacity.py)。前者由 CDS 的 `pnpm test` 自动执行，后者由现有 CI Python 测试循环执行；只改探针时也会触发相应检查。

另有[行为区分验证](../scripts/capacity-behavior-proof.py)：显式选择包含旧百分比监控的本地基线提交，在私有目录给旧脚本和新探针同一容量场景，输出旧行为未预警、新行为提前预警的 JSON 证据。它还在临时副本中故意移除固定暂存槽和本机 Docker 选择约束，要求代表性断言失败，再验证候选通过。这两项是故障变体对照，不是假称历史版本存在对应缺陷；所有注入都在隔离目录，不访问生产。

源码演练逐日生成真实 Git 工作树，调用现有回收器和删除原语，检查目录与 Git 注册同时消失；另置运行、停止回滚、在途认领和业务数据四种长期保护。真实删除前注入一次 I/O 失败，并在独立删除进程完成第一项后发送 SIGTERM；重扫时只计算仍存在的产物，重试不重删已消失的对象。最后从旧回滚目录读取原字节，再释放引用验证可回收；对已删除缓存按其历史提交重新生成，并核验原始字节与提交身份。

静态产物演练执行真实隔离目录上的原生成命令，保留很旧的 current/previous，并模拟一天在途发布暂停；增长窗口结束后实际切换链接回滚并恢复，分别校验两版不同字节。镜像部分使用原生产规划器及模拟 Docker 清单验证代数上界，不代表真实 Docker 层或磁盘收益。探针另测低水位增长预警、inode、采集失败、原子写入中断和 14 天历史有界。

新执行的 generated-static 发布会在切换公开入口之前，保存一份私有、不可覆盖的内容证明，绑定发布目标、源提交、目录身份和文件哈希。证明与公开资源分开存放；旧版本没有证明时不会自动补签。回收仍遵循原保留窗口和单轮处理预算，保留 current/previous、最近可回滚版本、在途发布、运行或停止容器挂载及业务数据。内容变化、额外文件、硬链接、软链接、目录替换或查询失败都会保留对象并给出原因。

原生删除开始后保留私有执行记录；中断重试仅容许原证明中的文件已经消失，不接受新加入或修改的内容。执行终态不明时继续报告失败，直到确认目录消失；目录已消失但清理日志仍在时，后续只读盘点仍会发现该日志并完成终态清理，不因目录消失而遗漏。删除逐项核对目录身份，不对未知内容做递归强删。证明本身设置单份4MiB、2万项、单对象8GiB及20秒读取预算；私有证明与执行记录分别预留1024项/48MiB和1024项/16MiB预算，单条执行记录最多16KiB，总写入预算64MiB，达到限制会拒绝继续签发，必须检查原因。它们是安全处理预算，不是整盘硬字节上限。

正向14天演练逐日增加8份可证明静态成品，每轮最多处理20项；一天有在途发布时暂停回收，随后收敛到两份引用锚点与最近三份成品。它与无证明的历史负向演练分别报告内容字节、实际分配字节、对象数量、耗时和元数据量，不宣称源码工作树、镜像或生产数据同步获得相同收益。

判定必须同时满足：不少于七天的生成窗口；每日回收后历史数量有上界；保护字节不变；失败不冒报成功；中断后可重新扫描并重试；受保护业务数据与外部对象仍在。文件内容字节、实际分配字节和模拟镜像数量分别报告，不混成生产回收收益。

[自动调度回归](../cds/tests/services/janitor-continuation.test.ts)另按每小时 32 份、七天输入对比积压，并覆盖续扫上限、停止、并发手工请求及告警恢复。这是调度与数量模型，不冒充物理磁盘收益。CDS CI 同时执行每份 16MiB 的 14 天文件演练，以及[原生自动链路演练](../cds/scripts/capacity-reclaim-drill.ts)：后者使用真实启动延迟与续扫定时器，创建 25 份各 64MiB 的待回收源码和四类保护对象，注入一次删除失败，通过原生回收器重试，再检查通知落盘、重载和本机 HTTP 接收回执。接收端严格核对现有 MAP 通知请求格式，但不代表生产 MAP 已收到通知。机器回执按提交归档到 CI，保留七天；清理耗时包含实际执行开销，不作为跨主机磁盘吞吐基准。

## 上线前仍需完成

负责人应先获得当前主机的只读来源盘点，确认采样和告警接收链，再评估是否启用候选探针。业务数据迁移、旧页面资源生命周期、MAP 镜像回滚锚点与跨实例共享仓库仍需要独立方案及恢复验真。参见[正式机容量债务](./debt.platform.production-release.md)；隔离演练通过不能关闭这些线上风险。


源码删除失败的恢复判据：已有失败即使被年龄、有效引用、挂载或扫描游标暂时跳过，也不能凭另一批删除成功宣布恢复。已登记失败只有确认该目录消失或成功回收才能解除；追踪超过有界预算或原生进程终态不明时继续报告未确认。源码续扫仍不执行镜像、Docker或业务到期回收，次数、年龄与原保留窗口保持原值。

## 系统所有者启用真实只读采样

在 CDS 系统设置的调度与容量页，可显式启用、暂停或立即采样。默认关闭，配置持久确认后才开始；已接外部宿主报告的实例继续由外部采样方管理，不能同时打开内部生产者。

内部采样仅盘点实例已知的工作树、仓库副本、构建缓存和技能缓存目录，页面逐项列出实际覆盖路径。尚不存在的目录单独列出；权限、依赖、重叠或执行错误显示未知，不沿用旧的正常读数。业务数据库、Docker共享层和远端发布目录不因此获得逐项占用解释或清理授权。文件系统余量属于这些目录所在的真实文件系统，不是各目录占用的合计。

每小时最多一个受限采样进程，立即采样也不能并发；停止会终止自己的采集进程组，旧回调不能重新启动。探针只读目录，除自身有界历史与最新报告外不写被测内容。沿用192个小时点、单历史和最新报告各4MiB的上限。首次启动或少于有效增长窗口保持未知。已知缓存目录出现或消失时，在同一有界历史槽重新建立冷基线，不混合不同来源的增长；独立CLI默认拒绝宿主身份变化；内部受控采样在验证旧历史后，因容器主机名变化重新建立同一槽内的冷基线，不混用宿主增长；损坏历史继续报未知。暂停不宣布原容量风险已经恢复；进程重建后需要新采样证明当前状态。

远端静态产物与工作树共享原有删除预算时，交替分配候选，避免长期受保护的构建工作树耗尽全部派发名额。每项原生身份、内容与引用复核保持原值；未知内容仍保留，处理能力不足仍报告积压。

远端发布产物的每轮预算在工作树与静态成品之间交替分配，并为启用目标保留内存扫描位置，避免旧产物长期被保护时阻塞后面的可回收项。只读预览不推进位置；重启后从头扫描，不改变保留规则或提供磁盘硬字节上限。

## 独立CDS由另一个CDS托管时的API归属

独立实例需要自己的持久化密封存储时，可在启动配置中显式设置 `CDS_DASHBOARD_API_MODE=same-origin`。此时页面只调用当前实例的API，请求失败也不会转向父控制面。默认主控直通行为保留；该选项只决定请求去向，不改变登录权限、密封存储或预览实例的秘密清洗。
