# MAP 与 CDS 磁盘容量治理 · 指南

> **版本**：v1.1 | **日期**：2026-11-13 | **状态**：候选，未启用生产

**一句话**：把来源占用、增长速度、容量预警和引用感知回收分开核对，优先回收可重建且无人使用的产物。
**谁该读**：MAP/CDS 运维负责人、部署维护者和容量评审人。
**读完能做什么**：选择采集范围、解释增长与预警、复跑隔离演练，并识别仍须人工决策的数据与回滚保留边界。

## 为什么已有清理还会满盘

CDS 7 月事故的主要增长来自带 SHA 标签的历史镜像；普通悬空镜像清理无法覆盖它们。10 月的源码盘点又发现快照中混有数据库和对象数据，不能把所有未挂载快照都当缓存。MAP 11 月满盘导致 Redis 持久化失败和 MongoDB 退出，清理后的剩余容量仍不足以宣布风险解除。

这些历史证据分别见 [CDS 状态存储债务](./debt.cds.state-json.md)、[CDS 部署源码隔离边界](./debt.cds.md)和[正式机容量恢复边界](./debt.platform.production-release.md)。历史数值不是当前读数；没有新采集就不能外推今天的可用空间。

## 先确认来源，再决定能否回收

| 来源 | 解释增长的证据 | 控制与保护边界 |
|---|---|---|
| SHA 部署镜像 | Docker 镜像总量、台账、全部运行与停止容器引用、在途输入 | 沿用 CDS 最近代数策略及临删引用复核；不运行全局镜像清空 |
| 构建缓存 | Docker Build Cache 分类 | CDS 已有缓存保留预算；共享层的逻辑大小不等于实际可释放字节 |
| 部署源码、孤儿工作树 | 独立来源目录占用、回收摘要和保留原因 | 源码超过原两小时门槛且无引用、无未知内容才回收；注销 Git 注册；身份或挂载未知则保留 |
| 静态发布产物 | 版本目录、远端 current/previous、成功台账、在途发布 | 沿用当前发布回收器；保留窗口外的在用和回滚锚点也必须保留；有在途发布时跳过 |
| 固定发布 ZIP 与旧页面兼容资源 | 独立保留来源与消费者约定 | 不是普通缓存，禁止套用部署版本数量直接删除；旧页面支持时长仍待约定 |
| 日志、归档、备份 | 各自独立来源占用、实际轮转配置与校验记录 | 沿用所属组件策略；业务备份须先验恢复，不因空间不足直接删 |
| 数据库、对象数据、容器卷 | 来源占用、实际挂载与数据归属 | 只观测；禁止 volume prune、自动搬迁或按目录年龄删除 |

多实例共用同一镜像仓库、人工绕过受管创建入口、引用未知或长期不释放，都可能让保留量继续增长。保留策略约束可回收的历史产物，不是整台机器的硬字节限额。

## 只读容量探针

运维入口是 [host-capacity.py](../scripts/host-capacity.py) 的 `--help`，面向具备 Python 3、GNU du 和 POSIX 文件锁的 Linux 宿主。它只读取显式选择的来源，写入独立的私有采样目录，不具备删除能力。每台主机各用一份状态；MAP 与 CDS 即使同机也不要重复配置相同来源。

首次接入先在隔离机选择几个互不嵌套的目录，以 `--source 名称=绝对路径` 分别标明镜像存储、部署源码、静态产物、日志和业务数据；`--state-dir` 指向这些目录以外、属于当前用户且权限为 0700 的独立位置。有 Docker 读取权限时再启用 `--docker`：只查询本机标准 Unix socket，忽略继承的远端上下文和 TLS 选择器，避免把另一主机的镜像与本机磁盘混算；不改用户的 Docker 配置。路径必须来自现场挂载和配置，不从本指南猜测。

输出为 JSON，包含各来源实际分配字节、净变化、日增长速度、所属文件系统、可用字节、inode 余量、预计写满与到达安全余量的时间。Docker 分类另外展示，不与目录大小相加；跨来源硬链接也可能重复计数。整盘容量读数才是容量风险判断依据，未选中的目录属于未解释空间，不假定为零。

默认每小时保留一点，最多 192 点、单个状态文件不超过 4MiB。提交暂存固定一份，正常历史与暂存合计最多 8MiB 内容；反复强杀也不会按次数累积暂存。频繁执行不会挤掉历史窗口。写入使用互斥与原子替换；文件损坏、主机/来源变更、并发执行、采集失败均返回未知，不覆盖损坏状态。已有正常文件在替换前失败时保留；断电后的磁盘持久性仍取决于宿主文件系统。

## 预警的判据与处置

| 判据 | 默认值与含义 | 处置 |
|---|---|---|
| 磁盘/inode 使用率 | 75% 警告、90% 严重 | 核对最大来源、失败回收与保护项；不要直接缩短业务保留期 |
| 绝对可用空间 | 不高于 6GiB 为严重 | 评估下一次构建峰值与数据库写入需求，按既有受管流程止增 |
| 预测安全余量耗尽 | 7 天内达到余量线则警告 | 查增长最大的来源；复核近期加速是否来自部署、日志或数据 |
| 采样未知 | 冷启动无基线、超过两小时断采、时钟倒退、来源采集失败 | 恢复采集，保留原状态，禁止把未知读数解释为健康 |

增长速度取八天窗口和最近可比点的较大净增长率，减少近期加速被长期均值稀释的情况；缩容释放显示负变化。预测依赖过去负载，不包含未发生的突发构建、保留项扩大或数据峰值。

退出码为 0 正常、1 警告、2 严重、3 未知。调度器应对非零结果和缺失运行分别报警，保留最近一份结果，并按状态变化去重。只跑探针不等于通知已送达；应先在隔离环境注入余量阈值和增长样本，确认外部告警接收方能看到，再安排正式接入。本批不安装定时任务、不改变生产阈值或回收策略。

## 隔离增长与恢复演练

可复跑入口是 [14 天增长测试](../cds/tests/services/capacity-growth-drill.test.ts)与[容量探针测试](../scripts/tests/test_host_capacity.py)。前者由 CDS 的 `pnpm test` 自动执行，后者由现有 CI Python 测试循环执行；只改探针时也会触发相应检查。

另有[行为区分验证](../scripts/capacity-behavior-proof.py)：显式选择包含旧百分比监控的本地基线提交，在私有目录给旧脚本和新探针同一容量场景，输出旧行为未预警、新行为提前预警的 JSON 证据。它还在临时副本中故意移除固定暂存槽和本机 Docker 选择约束，要求代表性断言失败，再验证候选通过。这两项是故障变体对照，不是假称历史版本存在对应缺陷；所有注入都在隔离目录，不访问生产。

源码演练逐日生成真实 Git 工作树，调用现有回收器和删除原语，检查目录与 Git 注册同时消失；另置运行、停止回滚、在途认领和业务数据四种长期保护。真实删除前注入一次 I/O 失败，并在独立删除进程完成第一项后发送 SIGTERM；重扫时只计算仍存在的产物，重试不重删已消失的对象。最后从旧回滚目录读取原字节，再释放引用验证可回收；对已删除缓存按其历史提交重新生成，并核验原始字节与提交身份。

静态产物演练执行真实隔离目录上的原生成命令，保留很旧的 current/previous，并模拟一天在途发布暂停；增长窗口结束后实际切换链接回滚并恢复，分别校验两版不同字节。镜像部分使用原生产规划器及模拟 Docker 清单验证代数上界，不代表真实 Docker 层或磁盘收益。探针另测低水位增长预警、inode、采集失败、原子写入中断和 14 天历史有界。

判定必须同时满足：不少于七天的生成窗口；每日回收后历史数量有上界；保护字节不变；失败不冒报成功；中断后可重新扫描并重试；受保护业务数据与外部对象仍在。文件内容字节、实际分配字节和模拟镜像数量分别报告，不混成生产回收收益。

## 上线前仍需完成

负责人应先获得当前主机的只读来源盘点，确认采样和告警接收链，再评估是否启用候选探针。业务数据迁移、旧页面资源生命周期、MAP 镜像回滚锚点与跨实例共享仓库仍需要独立方案及恢复验真。参见[正式机容量债务](./debt.platform.production-release.md)；隔离演练通过不能关闭这些线上风险。
