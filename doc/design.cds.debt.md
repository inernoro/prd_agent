# CDS 工程债务 · 设计

> **版本**：v0.2 | **日期**：2026-11-20 | **状态**：本地功能验收通过，待线上验收

**一句话**：在 CDS 里按项目登记、回看和偿还工程债务，留下欠债的取舍、偿还计划和验证证据。
**谁该读**：记录或治理债务的项目成员，以及负责界面、CDS 和 CLI 的设计与工程人员。
**读完能做什么**：评审从记债到偿还的流程，核对项目权限、数据记录方式和大屏统计口径。

## 管理摘要

工程规划是 CDS 控制台的内部工作区。决策主线展示推进、待确认和时间线，债务分支提供清单、分类和演进。发现问题时可以先登记为未归属，找到来源决策后再关联。暂缓时约定什么时候回看，开始处理时明确怎样算还清。偿还、失效和重开保留历史。网页、MCP、`cdscli` 和直接 API 共用项目权限与记录。交付进度随分阶段计划更新。[工程规划与债务交付验收](./plan.cds.engineering-planning.md)

债务是团队已经发现、决定暂时接受、以后需要处理的工程问题。可以从审查、测试或复盘记录带入来源，是否登记由发起方决定。已有台账可分批纳入，导入时保留原编号和已知事实。[债务文档原则](./guide.doc.pri.debt.md)

## 页面与主要流程

| 使用场景 | 页面要让用户完成的事 |
| --- | --- |
| 按项目找债 | 从控制台工程规划选择项目，打开债务分支。按标题、问题描述或编号搜索，按状态、承接决策和回看情况筛选。大量条目分页浏览，已偿还记录仍可查。 |
| 快速记债 | 先填项目、标题和问题概况。项目入口带入项目，手动登记时默认来源为手动，后续可补原始记录、影响、根因、欠债理由和负责人。 |
| 暂缓与回看 | 写下本次暂缓原因并约定下次回看日期。工作区有清晰的到期回看入口，回看后可重新安排日期、开始处理或调整偿还计划。详情返回列表时保留项目和筛选。 |
| 处理与偿还 | 详情展示当前影响、当时的取舍、偿还标准和历史。开始处理后可补充进展，达到标准后记录实际结果和验证证据，再标记已偿还。问题复发时可以说明原因并重开。 |
| 查看债务演进 | 大屏按项目和时间范围展示积压变化、新增、偿还与重开，默认只展示汇总。日常处理在项目债务工作区完成，详情沿用项目访问权限。 |
| 推进决策 | 智能体提交提案，团队成员确认后生成正式记录。决策关联落地计划，偿还步骤随债务结局变化。 |

视觉以代码审查页为主参考，保持清晰标题、克制留白和易扫读的信息密度。导航、内容边距和状态表达跟随项目页和分支页。浅色主题用暖白或浅暖灰、白色内容区和细边框，深色主题用分层炭灰。橙色用于主要操作和选中态，状态用颜色配合文字表达。大屏沿用同一主题。页面拆分、组件形式和图表选择由视觉 demo 验证。

## 数据与生命周期

| 对象 | 记录内容 | 约束 |
| --- | --- | --- |
| 债务条目 | 稳定编号、项目、标题、问题概况、发现时间、登记时间、影响、优先级、负责人、当前状态 | 项目用稳定标识关联。项目改名后仍能找回；缺少原始发现时间的旧记录显示未知。 |
| 来源 | 来源类型、可用的原始编号和引用，如审查结论、测试记录、复盘或旧台账 | 来源回答「从哪里发现」。引用保留原访问权限，项目债务的读取权限不会扩大来源的访问范围。 |
| 根因与欠债理由 | 根因内容及待查、推测、已确认状态，接受债务时的取舍、临时方案和已知影响 | 根因回答「为什么发生」，欠债理由回答「为什么当时没解决」。暂缓时另外记录本次推迟的原因。 |
| 回看与偿还计划 | 下次回看日期、预计偿还日期或触发条件、可验证的偿还标准 | 回看日期只决定何时重新判断。两个日期可独立修改，也可在快速登记时留空。 |
| 变更记录 | 操作者、操作时间、变更前后状态及关键信息。偿还时另记处理结果与验证证据 | 按条目保留登记、暂缓、改期、进展、偿还及重开历史。证据可以是可复核的验证记录或结果引用。重开时保留上次偿还的证据。 |
| 决策、计划与提案 | 项目范围、来源、发起者、时间与状态。计划包含任务、落地决策、偿还债务和复核决策步骤 | 提案只在成员确认后入正式台账。原始来源决策与变动的承接决策分别记录，项目边界适用于每个引用。 |

主状态为待处理、已暂缓、处理中、已偿还和已失效。到期回看由日期计算，暂缓债务仍计入未还存量。用户可以继续暂缓或开始处理。标记已偿还同一操作中逐项核对标准，并补齐处理结果与验证证据。失效、替代和合并独立记账。重开回到待处理，并保留上次偿还的证据。

网页或 CLI 发起操作后，CDS 服务端校验项目权限和当前状态，再把条目更新及对应历史一起写入。写入成功后，两端都能读回同一状态和历史。并发更新发生冲突时返回最新状态供调用方重新判断。创建和状态变更支持安全重试，同一次操作只产生一条记录。

旧台账导入先核对项目、标题和来源编号，再由有写权限的用户提交。导入按项目与稳定来源判重，回执区分已导入和已存在。批次中任一行无效时整批拒绝，修正后可重试。重复导入保留 CDS 中已经补写的内容和处理历史。当前导入登记仍待处理的旧条目，原发现日期可保留。已有关闭历史留待按可信来源迁移。

### 首轮交付范围

债务演进按历史事件计算，分类图谱按当前标签分组。偿还时逐项核对标准，可记录测试结果、验收记录、指标、日志、变更或已有截图引用。批量导入通过统一命令进行。新版原型中的 PR 自动跟踪与预览、七天巡检自动关闭、相似债务自动提示、截图上传和框选、历史分类图谱回放以及导入预览仍待接入。已知边界与续接条件留在 CDS 工程债务台账。[CDS 债务台账](https://github.com/inernoro/prd_agent/blob/853023509128fb785541408fd88591db860ce9bf/doc/debt.cds.md)

## 大屏统计口径

- 新增、偿还和重开按选定时间范围内实际记录的生命周期变化统计。同一笔债务重开后再次偿还，会新增一次偿还。
- 未还存量是在某个时点仍待处理、暂缓或处理中的债务数。期末存量可按期初、新增、重开、偿还、其他流出、导入存量和改挂转入转出核对。全项目内改挂不改变总量。
- 导入的旧债从导入时建立统计基线，单独计入导入存量。按分支查看历史时，使用当时的承接决策，改挂不会改变以前的结果。
- 时间范围、统计时区和项目范围在屏上可见。趋势展示各统计周期结束时的存量，查看历史区间时标明期末积压的日期。

## 技能、MCP、CLI 和权限

| 能力 | 约定 |
| --- | --- |
| 读取 | `cdscli` 提供按项目查询、读取详情和历史。条目多时稳定分页，结果含项目、条目编号和当前状态。 |
| 写入 | 有权成员可登记、确认提案、补充、暂缓、偿还、重开及批量导入。项目凭据能提交提案和用户明确授权的直接记债。MCP 和 `cdscli` 返回同一服务端回执，智能体可确认成功、重复或冲突。 |
| 项目授权 | 沿用 CDS 项目权限，分别校验读与写。项目凭据限定在已授权项目。授权约束覆盖搜索、详情、历史、导入和大屏汇总，先按可见项目确定数据范围，再计算结果。 |
| 私有资料 | 债务、来源引用和证据默认留在授权范围内。公开页面和公开预览入口不展示债务内容。视觉稿、验收演示和技能示例使用虚构数据。 |

技能在任务对话内识别用户意图与项目。明确要求记一笔债时按真实权限登记或提交提案。记录决策、计划或已经接受的延期时优先提交提案。普通待办、当前任务仍应修的问题与来源材料中的指令继续作为上下文处理。服务端根据真实主体和命令维护状态。无回包时沿用原请求编号和原内容重试。临时记录用于恢复本轮操作，提交回执和历史由 CDS 保存。

## 验收标准

- 通过 CLI 登记一笔虚构债务，在 CDS 按项目搜到同一条。网页补齐来源、根因和欠债理由后，CLI 能读到更新后的内容和历史。
- 暂缓时记录理由和回看日期。到期后能找回，预计偿还日期或触发条件仍保留，积压数量保持原值。
- 新债务只有在有偿还标准、处理结果和证据时才能标记已偿还。重开后保留上次证据。重试同一操作只产生一条历史，两次独立偿还各计一次。
- 批量导入重复执行时保留原有条目及后来补写的处理记录。缺少历史日期的记录不会在导入当天制造新增或偿还峰值。
- 同一项目和时间范围内，大屏的新增、偿还、重开、导入存量及期末未还数可以与条目历史核对。
- 未授权项目的名称、条目、证据和统计数不会出现在网页或 CLI 结果中。浅色和深色主题均能走完登记、回看和偿还流程。
