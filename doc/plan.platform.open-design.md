## 二、目标与最终效果

MAP 提供统一入口、权限、模型选择、审计和版本管理；CDS 提供真实会话级隔离与工作区；OpenDesign 是可替换的无头设计编排器；Codex 是首个文件执行器；所有模型请求统一经过 LLMGW。

首批必须真实打通四个场景：

1. 网页托管引用知识库，用户补两句话即可生成完整网页并保存。
2. 在知识库选择智能体，直接生成可预览、可继续编辑的网页。
3. 网页托管在“向我提问”附近提供“帮我修改”，形成草稿、预览、发布新版本和回退历史版本的闭环。
4. 知识库生成 HTML PPT，并保留来源、资源和版本。

用户等待时必须持续看到阶段、文件或预览变化；静止等待超过两秒视为体验缺陷。

## 三、基座选择

| 问题 | 固定决定 | 最直白的通过方式 |
|---|---|---|
| OpenDesign 如何接入 | MAP 只认统一的设计执行器协议，OpenDesign 作为一个可替换适配器接入 | 不改业务入口即可把 OpenDesign 换成另一个设计器 |
| 是否写进 MAP Compose | 不把运行时编进 MAP；CDS Compose 只负责部署镜像、网络、健康检查和会话资源 | MAP 升级不要求重做 OpenDesign 镜像，OpenDesign 升级也不要求改 MAP 业务代码 |
| OpenDesign 如何控制 Codex | OpenDesign 负责拆任务和组织设计，Codex 负责在共享工作区读写文件 | 日志能看出谁下达任务、谁改了文件、何时结束，最终文件确实来自该会话工作区 |
| 模型由谁决定 | MAP 派发本次任务的 LLMGW Base URL、模型和短期凭据，OpenDesign 与 Codex 只被动使用 | MAP 选哪个模型，LLMGW 审计里就是哪个模型，运行时没有第二份永久配置 |
| 调用上限 | 应用侧不另设模型调用次数或输出额度，费用与额度由 Key 门禁控制；超时、并发、取消和隔离仍保留 | 长任务不会被应用自设额度截断，越权或失效 Key 仍会被拒绝 |
| 隔离放在哪里 | 真实会话容器、网络和卷隔离属于 CDS Remote Agent 底座，不塞进 MAP | 两个会话不能读取彼此文件、凭据、端口或日志 |

共同链路：

```text
四个应用入口
  -> MAP 统一任务与权限
  -> CDS 创建隔离会话和共享工作区
  -> OpenDesign 拆解设计任务
  -> Codex 在工作区执行文件修改
  -> LLMGW 统一调用模型并记录审计
  -> MAP 冻结产物、生成预览与版本
```

## 四、存储与通信

| 对象 | 存放方式 | 传递方式 | 最直白的通过方式 |
|---|---|---|---|
| 知识库源文件 | 原件继续保存在对象存储；任务开始时冻结文件版本、来源和摘要 | CDS 把本次快照装入只属于该会话的工作区 | 生成前后都能指出用了哪些原件，原件变化不会悄悄污染正在运行的任务 |
| 用户补充说明 | 进入任务快照，与知识来源和模型选择一同留痕 | MAP 写入任务说明，OpenDesign 和 Codex 从工作区读取 | 事后能还原用户当时说了什么，不靠聊天记录猜测 |
| 网页产物 | 工作区保存完整站点，候选版本冻结后进入对象存储 | 文件不在服务间来回上传，只传任务事件、清单和摘要 | 预览能打开 `index.html`，脚本、样式、图片和字体都能加载 |
| 局部修改 | 基于指定历史版本复制出新的候选工作区 | OpenDesign 指定修改范围，Codex 直接改工作副本，MAP 冻结新的完整版本 | 只改要求的部分，未要求内容不变，旧版本仍可预览和回退 |
| HTML PPT | 与网页相同，保存完整入口、页面资源、知识来源和版本 | 共享工作区完成生成，结束时只登记产物清单与摘要 | 每页能打开，引用可核对，刷新后仍存在 |
| 进度与日志 | 业务事件进入 MAP，执行日志留在 CDS，模型审计留在 LLMGW | 使用同一任务标识串联，敏感值不进入页面、地址和普通日志 | 用一个任务标识能找到入口、执行、模型和产物四段证据，且看不到密钥 |

接入层只接受受控任务、知识快照引用、工作区身份、模型派发和版本意图；只返回阶段事件、产物清单、摘要、预览状态和最终版本。实际文件通过同一会话工作区共享，避免自建上传、下载和双向同步系统。

## 八、独立验收方法

| 角色 | 能看到什么 | 只负责什么 | 失败时怎么处理 |
|---|---|---|---|
| 验收清单智能体 | 只看原始诉求和用户路径，不看实现 | 预先写“过或不过”的直白清单并密封 | 清单不随实现结果放宽 |
| 开发智能体 | 代码、日志和自测 | 开发、修复、自测和部署 | 不给自己的功能签最终通过 |
| 对抗审查智能体 | 候选、真实日志、故障注入结果 | 主动找串线、丢文件、泄密、假成功和不可恢复问题 | 阻断项全部修复后重新审查 |
| 视觉验收智能体 | 匿名产物和同类成熟 AI 产品 | 按内容、布局、可读性、交互和完整性严厉打分 | 低于 85 分必须返工 |
| 最终盲验智能体 | 密封清单、入口和最终结果，不看开发说明 | 对每项只判通过或不通过 | 任一核心项不过，阶段不得勾选 |

每份报告必须包含候选版本、环境、实际入口、输入、操作、预期、实际结果、截图或日志证据、通过或不通过、阻断问题和复验结论。报告没有可访问地址等同于没有验收。

## 九、优先风险

| 级别 | 风险 | 必须怎样证明已解除 |
|---|---|---|
| P0 | OpenDesign 镜像不是当前候选，或根本没有真实调用 Codex | 镜像版本固定，日志展示真实进程、真实文件变化和真实模型审计 |
| P0 | 知识原件、工作区或日志跨会话泄漏 | 两个并发用户互查失败，普通日志与地址不出现凭据和原文 |
| P0 | 预览或快速连续修改发生旧请求覆盖新请求 | 最后一次操作始终对应最后一次预览和发布，旧请求不能回写 |
| P0 | 只返回单文件或为了通过而删除脚本和资源 | 完整站点和资源均可加载，安全规则拒绝危险内容但不阉割正常作品 |
| P1 | MAP、OpenDesign 和 Codex 各自保存模型配置 | 只改 MAP 一处即可改变本次模型，其他运行时没有长期副本 |
| P1 | 作品能生成但视觉质量明显低于成熟 AI 产品 | 匿名严厉评分达到 85 分且阻断问题清零 |
| P1 | 升级后无法回退 | 人为发布坏版本后能恢复上一可用镜像与作品版本 |
