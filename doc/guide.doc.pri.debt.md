# 债务文档原则：让已知欠账有边界、有偿还条件 · 指南

> **版本**：v1.1 | **日期**：2026-11-09 | **状态**：已落地

**一句话**：把尚未解决的限制、影响、偿还触发条件与关闭证据留下来，避免交接后遗忘或反复讨论同一问题。
**谁该读**：交付时留下限制、接手维护、安排治理工作和判断风险的产品与工程人员。
**读完能做什么**：将真正的已知欠账登记到模块台账，并判断何时值得处理、怎样才算关闭。

## 作用与使用时机

`debt.*.md` 回答“还欠什么，何时值得还”。已知实现限制、兼容遗留和暂未落实的约束适用；普通功能愿望不自动构成债务。

## 最少写什么

稳定编号、发现日期、影响与触发条件、严重程度、当前状态、责任角色、偿还条件与关闭证据。原因为推测时明确标记，不凭猜测写成缺陷事实。

## 如何维护

默认一个模块一册，避免一债一文件。修复后保留关闭记录与证据；不能因补了文档或排进计划就标为已还。

## 与其他前缀的边界

已明确安排的工作进入[计划](./guide.doc.pri.plan.md)，重要选择去 [ADR](./guide.doc.pri.adr.md) 或 [PDR](./guide.doc.pri.pdr.md)，现行约束仍由[规则](./guide.doc.pri.rule.md)表达。债务台账引用这些内容，不复制另一套权威正文。

项目入口示例：[平台债务台账](./debt.platform.md)。检验标准是下一位维护者能否判断影响、处理时机以及关闭条件。
