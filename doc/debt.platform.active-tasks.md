# 活动任务清单 · 债务台账

**一句话**：这个功能交付时明确没做的部分，以及每一条该在什么条件下补。
**谁该读**：接手迭代的开发、要评估「能不能靠它管人」的负责人。
**读完能做什么**：判断当前版本适用到什么规模，以及下一期最该补哪一条。

版本：v10（2026-09-16）

| # | 债务 | 现状 | 补的条件 |
|---|---|---|---|
| 1 | 后端无单元测试 | 时长结算、粮草档位、结论生成都写成了纯函数便于单测，但本期没写。按「改动删掉后测试仍全绿就需要守卫」的判据，这几个函数全都欠一条 | 下一次改动这几个函数之前补上，尤其是「卡住期间不计入投入」这条跨状态结算 —— 它错了不会报错，只会让投入时长悄悄偏大 |
| 2 | 计时依赖人工切换 | 忘了点「完成」会一直计时，没有自动检测 | 出现真实误报之后再看；自动猜错比不猜更糟，不要为了「智能」加启发式 |
| 3 | 团队视图不分页 | 一次拉全部在途记录 + 近 7 天活跃用户（上限 200） | 团队规模超过 200 人，或团队视图首屏超过 1 秒 |

| 7 | 登录态三屏未做真视觉验收 | **匿名看板已验收**：真机双主题 + 桌面/手机取证，产物真实渲染、无横向溢出（过程中抓出并修掉了 390px 下 KPI 被切）。但「我的任务台 / 团队此刻 / 走过的路」三屏需要预览门禁口令才能进，Agent 按跨项目隔离规则不能自行轮换那对共享口令，所以**交互链路（完成切换、委派、标记卡住）至今没有被真人或脚本走通过** | 由人提供预览口令后补齐三屏截图与一条端到端交互录像，补完再把导航注册表里两条路由的 `wip` 摘掉。2026-09-15 这一版把交互整个换了（乐观完成 + 撤销、行内新增、桌面两栏、两端两种浮层），未验证的面积因此变大而不是变小。**同日拿到凭据后，AI 一键导入那条链路已真跑通并留证**（真实清单 → 9 条候选 → 全部落库，`/tmp` 证据 + 本轮 commit），并当场抓出三个缺陷（见第 14 条 + 候选行标题被日期挤截断）；手工链路与建议吸取仍未跑 |
| 16 | 45 份债务台账里只有 9 份接得进来 | 同步只收「主表」= 第一列是 `#` 且标题列叫 债务/项/事项/欠什么/缺口 的那张表，一份台账只取一张。实测 45 份里 9 份有主表（105 条），其余 36 份是纯叙述或标题列叫法没登记。**这不是解析器偷懒**：[debt.cds.md](./debt.cds.md) 一份里有十九张编号表，每张都从 1 开始编，全收会让 `cds#1` 被十几行争抢，同步时静默互相覆盖 | 想让某份台账接进来，就把它的债务整理成一张编号主表；或者把标题列的新叫法登记进解析器的表头映射表。守卫盯着标识唯一性，撞车会直接红 |
| 17 | 同步是人手动跑的，不是自动的 | 同步脚本要有人（或 Agent）在改完债务文档之后跑一次。没跑就是任务台看到的还是上一版正文；台账里删掉的那条也不会自动从任务台消失（只会停在原地不再更新 SyncedAt） | 接进 CI（改了债务文档就跑一次）或让 Agent 在收尾时顺手跑。在那之前，`syncedAt` 就是判断新鲜度的那个字段 |
| 18 | 开始计时之后的任务删不掉，只能「放下」 | 删除端点只受理「还在待做、且一秒都没投入过」的那一档；一旦点过开始，就只剩「放下」这条路，那条记录会永久留在「做完的」里。这是**有意**的留痕设计（历史的价值在于真实），但它的另一面是：误建、测试、演示造出来的任务清不掉。2026-09-16 验收结束清场时，109 条测试数据删干净了，剩下 11 条（8 条 V 开头的演示行 + 3 条随手敲的）因为在历史里，产品自己没有任何路径能动它们 | 出现「历史里的噪音多到影响判断」的真实反馈时，再考虑给历史一个「隐藏/归档」而不是删除 —— 直接开删除口子会把留痕这件事整个废掉 |
| 19 | WIP=1 是收敛的，不是原子的 | 同一个人两次切换若真的同时发生，各自读到的「当前在做」是同一条。现在靠两道兜底收敛：降级带 CAS 条件（重复降级不会把时长二次结算），切换末尾再扫一遍把除目标外的 active 全降级，所以末态恒为一条。但窗口内那几毫秒里确实可以有两条，且「后到者赢」意味着先点的那次会被无声顶掉 | 真原子要么上事务，要么给 `(UserId, State=active)` 建唯一部分索引——后者被 `no-auto-index` 规则挡着（索引归 DBA 手动建），且切换过程本身会短暂违反该约束。出现真实的「投入时长对不上」反馈时再谈，那时先把索引定义补进文末「实现来源」里的索引清单 |
| 20 | MCP 使用档能提建议，却查不到该提给谁 | `map_tasks_suggest` 是 `tasks:use` 档，但它的用法写着「userId 从 map_tasks_team 拿」，而那个工具是 `tasks:manage` 档。只拿使用档的 Agent 因此发现不了任何合法收件人，除非 userId 从别处带进来。2026-09-16 Codex 第三轮提的，属实 | 两条路：加一个使用档的人员查询端点（新增对外接口，且要想清楚使用档该看见多少人），或把提建议本身收进管理档。都是产品决策不是接线补漏，需要先定「使用档该不该看得见同事名单」 |
| 13 | 没注册进百宝箱（欠一对卡片插画） | 入口现状：Cmd+K 搜得到、「设置 → 导航顺序」的可添加池里有，但**默认不在侧栏**，要用户自己添加。规则 #9 要求新功能注册进 `BUILTIN_TOOLS`，试过了 —— 守卫要求每个条目配一对暗色/浅色卡片插画（其余 73 张都是 3D 渲染素材），糊一张风格割裂的图比不注册更糟 | 补到一对同风格的卡片插画之后再注册。守卫要的是 `--agent-card-artwork-{key}` 双主题两张 webp，没有豁免位，所以这条不是「忘了写一行」而是缺素材（2026-09-16 Codex review 又提了一次，结论不变）。**在那之前交付话术不许写「左侧导航任务台菜单」**，那是假的；正确说法是 Cmd+K 或导航设置里添加 |

| 8 | 后端无集成测试 | C# 编译与全量 `dotnet test` 已在 CI 绿灯（含跨实例同步覆盖守卫）；匿名端点在真实部署上返回过正确结论句与脱敏数据。但员工侧与管理侧的端点只有编译期保证，没有一条断言真实行为的测试 | 与第 1 条一起补：先给纯函数单测，再给一条走「建任务 → 开始 → 卡住 → 完成切下一件」的集成测试 |
| 9 | 建议吸取没有向量检索 | 引用知识库时取的是条目的标题 + 摘要 + 正文索引（前 2000 字那份）里最近更新的 40 条，总量封顶 12000 字。本仓库的 embedding 检索还没落地（`document_embeddings` 有表、检索服务没有），假装有就是无根之木 | embedding 供应商凭据到位、检索服务落地之后换成真检索 |
| 10 | 建议只有收件箱，没有发件箱 | 提出去的建议后来怎么了（被吸取成哪几条任务 / 被放下了），数据都记着（`AbsorbedTaskIds`、`State`），但没有任何界面读它 | 有人问起「我提的那条后来呢」的时候；这是形状 2（链路只建一半），别忘了 |
| 11 | AI 拆解与吸取都没有后端测试 | 两条 SSE 端点的 JSONL 逐行解析、跨行拼接、日期兜底（`NormalizeDue` 的 180 天窗口）全是纯函数级的判断，一条测试都没有。按「改动删掉后测试仍全绿就需要守卫」，`NormalizeDue` 尤其欠一条 | 与第 1 条一起补 |
| 12 | 撤销删除只还原标题、时间、位置 | 投入过时间的走软删（放下），reopen 原样回来；没投入过的是真删，撤销是按原标题、时间、位置**重建**一条。所以 id 变了，备注、来源指针（`sourceRefType` / `sourceRefId`）、委派人也一起丢了 —— 删一条从债务转过来的活再撤销，它与那条债务的链接就断了，债务那边的 `convertedTaskIds` 指向一个不存在的 id（读的时候会被摘掉，所以不会显示成假链接，但那条活的来源确实没了）。2026-09-16 Codex 第三轮提了这一点，属实 | 真正的修法是软删 + 服务端还原端点（保住整条快照），那是新语义不是改几行，所以不在建这个功能的 PR 里做。出现真实的「撤销之后来源没了」反馈时再排 |
| 15 | 债务台账接进任务台（已落地，留两条边界） | 已通：债务台账主表 → 同步脚本 → `map_debt_sync` → 任务台下半屏「欠着的」→ 「转成我的活」建任务并双向留链。SSOT 按原方向定死：正文归仓库（同步只覆盖标题/现状/补的条件），归属与状态归任务台（同步一律不碰），单向推送不做回写 | 剩两条边界见第 16、17 条。本条只在「同步方向被改成双向」或「正文变成可在界面上编辑」时重开 |

## 本期验收留下的两条经验

**一、部署报「成功」不等于跑的是你的代码。** 第一轮 CDS 部署返回 `status: running`，
但 `/api/version` 的 `commitMatch` 是 `mismatch` —— 容器还是旧镜像，因为镜像构建那步
在 CI 里失败了。判据应该是 `commitMatch == "match"` 且 `actualCommit` 等于你刚推的那个，
不是部署命令的退出码。

**二、验收判据自己也要有对照组。** 为了证明登录态端点已注册，试过用「未授权返回 401」
当判据；顺手拿一条**不存在的路由**做对照，也返回 401 —— 鉴权中间件在路由匹配前就拦了，
这个判据分辨不了存在与否。接着试 `/swagger/v1/swagger.json`，返回 200，但内容是前端
SPA 的兜底 index.html，同样不成立。两个判据都作废，于是这项如实记为「未验证」。
