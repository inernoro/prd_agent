# 网页生成统一走 OpenDesign · 设计

> **版本**：v1.0 | **日期**：2026-10-12 | **状态**：实施中

**一句话**：网页生成与修改不再让用户选择底层执行器，统一由 OpenDesign（无头设计编排器）驱动 Codex，经 LLMGW 调用模型；MAP 只补齐业务上下文、质量标准、过程呈现和发布能力。
**谁该读**：网页托管、OpenDesign、LLMGW 的产品和工程负责人，以及负责阶段验收的智能体。
**读完能做什么**：判断一项能力应该复用 OpenDesign、由 MAP 补齐，还是明确不做，并据此验收最终用户体验。

---

## 结论

用户只需要表达“生成网页”或“修改网页”，不应理解“直连”“打磨”“OpenDesign”“Codex”等执行细节。所有新的网页生成与修改任务统一进入 OpenDesign；OpenDesign 内部使用 Codex 执行文件级设计任务，并通过 LLMGW 获取模型能力。

“快速”不再代表一次性直出，而代表同一条高质量链路更早给出阶段反馈、页面骨架和可预览初稿。

## 用户问题

当前双模式造成了三类可重复的问题：

1. 被标为日常推荐的快速模式实际是一次性生成，结构、视觉与后续可编辑性都弱。
2. 用户无法根据技术名词判断该选哪条路径，生成与修改时还可能选择不同执行器。
3. OpenDesign 不可用时如果静默退回直连，用户以为正在打磨，实际拿到一次性产物。

这不是用户操作错误，而是产品把系统架构决策转嫁给了用户。

## 目标调用链

```text
用户需求、知识与品牌素材
        -> MAP 冻结设计简报、事实来源、品牌约束和质量合同
        -> design-opendesign
             -> OpenDesign 官方网页技能与设计系统
             -> Codex 文件工具循环
             -> 任务级受控模型出口
             -> LLMGW 原生 Responses
             -> 多轮检查、修复与阶段预览
        -> MAP 最终质量判定
        -> 网页版本、分享与发布
```

MAP 不代理模型请求正文；Codex 不作为用户可选模式出现；LLMGW 继续负责模型路由、授权、审计、成本和供应商隔离。

## 职责边界

| 层 | 负责 | 不负责 |
|---|---|---|
| MAP | 用户和权限、知识与素材、结构化设计简报、品牌包、任务状态、质量合同、网页版本、分享、发布、效果指标 | 不实现第二套网页生成器，不接管 Codex 工具循环，不代理模型正文 |
| OpenDesign | 隔离工作区、官方网页技能、设计系统、文件生成、多轮会话、终审、定向修复、阶段预览、结果打包 | 不管理 MAP 用户、站点发布和业务指标 |
| Codex | 作为 OpenDesign 内部执行智能体读写和检查页面文件 | 不直接暴露给普通用户选择 |
| LLMGW | 原生 Responses、任务授权、逻辑模型路由、调用审计、供应商隔离 | 不决定网页是否达到 MAP 的业务质量标准 |

## 直接复用的能力

以下能力沿用 OpenDesign，不在 MAP 重复建设：

- 官方网页原型技能、模板、布局参考和检查清单。
- 设计系统与设计 token 注入。
- Codex 文件工具循环和单任务内多轮会话。
- light 和 strict 终审、确定性质量检查与定向修复。
- 隔离工作区、结果包校验和运行中页面预览。
- 元素定位标识，为后续页面内评论和局部修改保留基础。

OpenDesign 当前的 Critique Theater 不能直接替换 Codex 结构化事件链上的 MAP 终审，因此现有终审和修复闭环继续保留。

## MAP 需要补齐的能力

### 单一路径权威

- 普通用户界面不再展示执行器选择。
- 新的网页生成和修改任务由服务端统一选择 OpenDesign。
- 旧客户端提交直连模式时，系统按兼容策略改写或拒绝，并留下弃用指标。
- OpenDesign 不可用或繁忙时明确排队或失败，不得静默降级到一次性生成。
- 历史任务保留原运行时，避免破坏恢复、审计和回滚。

### 可理解的制作过程

复用 OpenDesign 已有事件，经过白名单、脱敏和语义化后展示。用户看到的是“正在读取资料”“正在搭建结构”“首版可预览”“正在检查移动端”等成果语言，而不是内部命令、路径、工具参数或隐式推理。

页面文件或产物事件应触发即时预览检查，现有定时轮询保留为兜底。活动任务状态以服务端为准，浏览器本地缓存只作加速。

### 结构化设计简报与品牌包

MAP 在启动任务前冻结版本化设计简报，至少表达：页面目标、受众、核心信息、主行动按钮、内容顺序、必选章节、视觉意图、响应式要求、事实约束、品牌包版本和成功标准。

品牌包由 MAP 管理 Logo、色板、字体、固定声明、禁止样式、参考范例和版本指纹，再映射到 OpenDesign 的设计系统和 token，不复制设计系统本身。

### 真实视觉质量闭环

在隔离执行侧对桌面与真实移动视口进行浏览器渲染，先执行确定性检查，再对审美类问题做有限次数的视觉评审。硬问题回到同一 OpenDesign 任务做定向修复，修复前后证据与评分由 MAP 留档。

硬判据包括：无横向溢出和关键内容裁切、主操作可见、链接与锚点可用、移动端导航和表格可读、事实来源完整且没有无依据新增。

审美评分只作软判据，包括信息层级、版式节奏、风格一致性、卡片重复度、首屏吸引力和品牌符合度，避免为了评分把所有页面做成同一种模板。

## 失败与恢复原则

- OpenDesign 繁忙时进入可见队列或明确返回忙碌状态，不得回退直连。
- 浏览器关闭不取消服务端任务；重新进入后从服务端恢复同一任务。
- 服务重启导致任务无法继续时必须诚实显示中断，并允许使用冻结简报重新开始，不能伪装为续跑成功。
- 模型、供应商和协议错误只进入管理员诊断；普通用户看到结果、影响和恢复动作。

## 产品指标

北极星指标：首次生成后，无需重新生成即可发布或分享的比例。

配套指标：

- 首次可见反馈和首次真实预览耗时。
- 最长无有效进度间隔。
- 关闭后重新打开的恢复成功率。
- 生成后十分钟内重新生成率。
- 发布前平均修改次数。
- 二十四小时内发布或分享率。
- 品牌、事实与视觉质量首次通过率。
- 自动修复成功率和平均修复次数。

## 明确不做

- 不保留面向普通用户的快速和精细模式选择。
- 不把 OpenDesign Studio 整套嵌进 MAP。
- 不在 MAP 重建网页模板、布局体系、设计系统或 Codex 工具循环。
- 不原样展示模型隐式推理、命令、内部路径和工具输出。
- 不用一次性生成作为 OpenDesign 故障时的静默降级。
- 不立即删除历史运行时字段和直连执行器；它们只服务旧任务与内部诊断。

## 完成定义

本设计只有在以下条件全部满足后才算落地：

1. 所有新的网页生成和修改任务统一由 OpenDesign 执行。
2. 用户界面没有底层执行器选择，也不会因服务不可用而静默直连。
3. 生成过程中持续展示真实、脱敏、可理解的阶段与预览。
4. 设计简报、品牌包、事实来源与质量合同均可追溯到版本。
5. 桌面端与真实触控移动端的视觉质量闭环能够发现并修复硬问题。
6. 每个实施阶段均有 CDS 在线视觉验收报告，且打开验证通过。
