### 必须点名的三条

**1）09-17 到期线的默认期已经越过，而实际影响没人查过。**
不是「又拖了一周」，是**默认期自己到了**。到期日零点起，全仓每一条 PR 的部署平台构建检查一起变红——因为有一条测试用例断言「门禁上线前登记的存量库能启动」，而这件事只在豁免窗口内成立，那条用例走的是真实时钟。处置是让用例自己钉住豁免窗口（用生产同一个逃生阀，不是测试后门）。这个处置是对的，但它**只解决了 CI**。
**线上那一半是未知，不是已知的坏。** 门禁实际读的是运行时逃生阀 `CDS_INFRA_AUTH_GRACE_UNTIL`，代码里的默认值是 2026-09-17；运维显式设一个更晚的日期就仍然放行。那个值在部署平台自己的进程环境里，**没有接口能读到**，所以本报告只能确定「默认期已过」，不能断言「库已经起不来」——**把未知说成已坏，和把已坏说成没事，是同一种错。**
**下一步**：先查清后果——逃生阀现在是什么值、哪几台库受影响、有没有已经起不来的、要不要设、设到哪天。这件事从「给个决定」变成了「先把状态看清楚」。

**2）验收只覆盖了七天里的两天，而漏掉的恰好是改动最密的四天。**
09-16 落地 133 个提交、09-17 落地 63 个（两天占全周 57%），09-16 只有一份功能验收（任务台，有条件通过），09-17 起四天一份都没有。**模型网关概念收敛（144 文件）与部署平台指挥台改版这两件最大的事，在验收中心里没有任何一条记录。**
需要说清楚的是：这不等于没验过——模型网关那个 PR 自带 37 条部署实测冒烟与预览域名真人路径验收，任务台走了桌面 + 手机双主题取证。**但它们没有归档成独立的验收结论**，所以第三个人核不了，也进不了通过率。

**3）发布这一栏第一次有了正号，也第一次暴露了失败率。**
三周来第一次有正式发布成功（09-20，提交 `8788a4c`）。但同一天五次终态 run 里四次失败，涉及两个提交（`8788a4c` 三次：一成两败；`f445a13` 两次全败），**没有一句书面的失败原因**。「能发出去了」和「发得稳」是两件事，本周只做到了第一件。

## 二、本周做成了什么（业务价值看板）

> 每条先说**谁能多干什么**，再说证据强度。技术细节一律在附录。

### 能力 1：配一个模型，从在五个页面之间跳，变成填两个地方；上游出新模型不用再改代码发版

**谁受益**：平台运维与模型运营；以及未来任何要把模型网关单独接出去的外部团队。
**以前**：「模型池 / 逻辑模型 / 模型 / 上游 / 兑换所」五个入口，其中「模型池」和「白名单」说的本来就是同一件事——一个说「这几个模型可以互相顶替」，另一个说「这几个名字可以对外被点」。生图的尺寸契约和模型名录写死在代码里，上游出一个新模型就得改代码、编译、发版。
**现在**：收敛成「模型」与「上游」两个入口；模型名录与生图契约搬进数据库，在控制台就地补登，**同一次请求周期内重拉即生效，实测 737 毫秒，零重启零发版**。删掉了 11 个写入端点、一个 2225 行的管理页，主解析流程从 767 行缩到 88 行。
**证据**：作者侧在部署上跑了四组实测冒烟并全过（名录补登端到端 10/10、真人路径 17/17、主表精简复验 10/10、池退场 7/7），另逐个推演 24 个调用方的落点、无一走池，81 轮自动评审收敛到零新发现。**但验收中心无独立报告**——本条没有第三方结论。
**已知边界**：合并本身不改变任何线上行为（旗舰梯队、默认指向、名录补登都是数据面动作）；**合并后必须对网关库跑一次索引脚本**，否则五条库级唯一约束缺席；生图契约在网关那一侧因缺租户维度暂不生效；573 个上游模型里落进名录的只有 27 个，存量要人工逐批补。
**用量口径**：`none:平台能力`

### 能力 2：一屏看见每个人现在在做什么、团队欠着什么

**谁受益**：团队全员与管理者；外部 Agent（开放接口 + 七个 MCP 工具）。
**以前**：「谁在做什么」靠问，「我们欠着什么」躺在 45 份文档台账里没人读。
**现在**：任务台上半屏是每个人**此刻**在做的那一条（下面排队，做完补一句「做成了什么样」），下半屏是从文档台账同步进来的债务（**111 条已接进来**，可认领、可一键转成自己的活）。两者的差别是时态不是重要性，所以在同一屏。匿名对外看板**默认整个关闭**，要开得管理员显式打开并选可见档位。
**证据**：**有条件通过**（09-16 功能验收，L2 档，桌面 + 手机双主题取证）。
**已知边界**：**没进左侧导航**——守卫要求配一对卡片插画，素材暂缺，两条路由仍带在建标记，当前入口是快捷键与「设置 → 导航顺序」；45 份债务台账只有 9 份接得进来（其余是纯叙述）；同步要人手动跑脚本；「同时只做一件事」不是原子的，并发切换窗口内可能短暂出现两条。共 21 条边界已入账。
**用量口径**：`route:/active-tasks`

### 能力 3：连一次自己的 GitHub，文档目录就每天自动同步进知识库（含私有仓）

**谁受益**：任何登录用户。
**以前**：知识库要么手动上传，要么只能拉公开仓；私有仓会静默失败——因为解不出用户凭据时代码会悄悄退回匿名请求，而 GitHub 对无权访问的私有仓返回的是 404，和「目录根本不存在」分不开。
**现在**：连一次账号 → 系统扫出有权限的仓库目录 → **递归预勾全部 `doc`/`docs` 目录** → 一步开启每日同步。解不出凭据时**阻断并说清楚**，不再静默退回匿名。
**证据**：**通过**（09-14 缺陷复测，私有仓实拉 53 篇文档，P0/P1/P2/P3 全零）。这是本周唯一一条拿到「通过」的用户可见能力。
**用量口径**：`route:/document-store`
