## 保留与回收规则

| 对象 | 身份、引用与保留 | 执行链路及失败处理 |
|---|---|---|
| 镜像 | 复用现有 per-SHA 镜像、在途输入及原生运行/停止容器引用；常态5代、既有压力档3/2/1代不变 | Janitor 现有预览及受控逐项删除；查询失败保留；Docker 报告的 reclaimable 不是许可或实际收益 |
| 部署源码 | 项目桶、分支桶、UUID、Git实际根、目录身份、清洁状态、准备活动、服务引用及原生挂载共同判断；数据、未知与忽略文件保留 | 系统设置的调度器及 CLI 提供只读候选、保护原因与 partial 状态；原回收器每小时触发，至少保留2小时，扫描最多1024、每轮至多20次并续接游标，临删复核；不进行整目录应急删除 |
| 构建缓存 | 复用现有 builder keep-storage 10GB 及已登记缓存归属；持久化存储不按缓存处理 | 沿用既有串行清理；没有执行卷的全局 prune；未知缓存不能仅凭路径名回收 |
| 远端发布产物 | 复用目标锁、实际 current/previous、自动恢复、成功发布保留记录及漂移保护 | 原生执行在目标锁下复核目录设备与inode、Git共同仓库和台账提交，运行/停止容器、数据及未知文件保留；自动恢复派生目录仅在已有恢复开始记录、同目标上一版及实际提交一致时确认归属；仅使用支持的Git删除，不使用force或递归兜底；静态整版本缺少内容证明时保留。正式机仍为旧模式且台账漂移，历史兄弟worktree继续保护 |
| 静态兼容资源 | 默认保留全部；新增的有限窗口至少30天，以内容摘要和最后服务记录共同证明；当前/上一版原生资源及未知来源保留 | 新版本继承及逐文件退休均重新盘点；当前/上一版、最近20版、窗口内与运行/停止容器引用保留。每轮最多处理2份候选版本，未知文件及目录替换保留；只移除已验证生成文件和确认空目录，不递归删除。生产启用窗口须另行批准 |
| 日志 | 原生 Docker json-file 每容器50MiB×3；本次系统日志压缩保留全部字节 | Compose 配置已实现，存量容器仍未生效；发布前磁盘准入复用现有脚本；本批没有直接截断 Docker 日志 |
| 测试残留 | 仅清理本任务明确拥有、已确认无业务数据及有效引用的隔离对象；失败证据保留 | 精确容器ID、原生Git和受控夹具生命周期；不因停止、年代久或不在台账就删除历史环境 |

## 增长源与候选修复

现场完整盘点识别正式机126份发布 worktree，逐目录占用估计合计19724337152字节；该数未消除跨目录硬链接，不能当作可释放量。12个容器的日志均为未设上限的 json-file，原生日志分配约1051435008字节，其中gateway约1015951360字节；系统 messages、cron、secure 原先也没有纳入现有 logrotate。备份目录约9923702784字节、Docker目录约20965531648字节，不能把目录大小直接当作可释放收益。

新增的发布输入声明只用于项目脚本及受管脚本的新目录，缺省继续全仓。已有目录只验证同一仓库及同一提交，不执行 reset、sparse 转换、清理或数据迁移。声明与内容摘要进入执行日志，当前仓库的预构建发布输入为 scripts、deploy 及根文件；是否足够必须由同提交 check/deploy 与 CI 证明。旧 existing-script 目标须单独审查命令接线，当前没有在线改动。

固定1791c1acf同一实际仓库提交，三次整仓输入的文件系统净增中位数188489728字节，三次声明输入中位数10199040字节，减少约94.6%。中位准备耗时1419ms降至164ms；同目录同提交四次重试均净增0，最小目录中的真实发布帮助入口可用。此实验是原生Git输入准备，不能替代完整生产部署、数据库完整性或长期观察。

提前存储声明检查已接入部署、初始化及手动命令入口，避免非法旧宿主绑定在复制源码后才失败；创建分支的既有语义保持。业务数据仍须稳定存储绑定，混入历史目录的数据不能靠回收器自动迁走。

静态窗口的65次加速隔离部署以每轮模拟一天推进，实际调用切换后的逐文件回收链路。第36至65次当前资源集及版本数均稳定在31；旧版本也保留兼容资源，实际物理空间到第61轮才饱和，第61至65轮文件系统可用空间净变化0，第62轮起每轮回收274432字节，覆盖每轮262144字节的固定资源新增。空间试验使用私有tmpfs夹具，不能替代生产盘吞吐、长期观察或未知历史对象的收益判断。真实Nginx/浏览器覆盖缓存重载、旧标签页延迟加载JS/CSS及回滚。未知来源和实际容器引用继续保留；若容器挂载整个静态根，相关版本也保留，须明确服务引用后才能释放。

真实MySQL 8隔离演练使用64条合成InnoDB数据，执行一致性备份、压缩摘要、独立实例恢复、聚合校验、消费者切换和切回重启。原始数据库文件混入部署源码、改名为未知路径两种情况下，实际回收器均保留并保持内容摘要；未操作生产数据库，未据此批准生产迁移。
