# 指南文档原则：帮助读者完成一件具体的事 · 指南

> **版本**：v1.1 | **日期**：2026-11-09 | **状态**：已落地

**一句话**：面向明确角色写出可执行的操作路径、预期结果和失败恢复方法，让首次接手的人也能完成任务。
**谁该读**：编写操作说明、新人引导、运行手册和常见问题解答的产品与工程人员。
**读完能做什么**：组织可照做的指南，检验入口和步骤，并把解释原理与实际操作分清。

## 作用与使用时机

`guide.*.md` 回答“我现在该怎样做”。常见操作、接入、部署、排障和查找资料适用。

## 最少写什么

目标读者、前置条件、真实入口、按顺序执行的步骤、每步预期结果、常见失败及恢复方法。敏感凭据只说明安全获取渠道。

## 如何维护

随真实操作路径更新，失效步骤及时替换。示例与入口必须有来源；不能猜地址、虚构功能，或要求读者自行拼出关键操作。

## 与其他前缀的边界

结构和原理引用[设计](./guide.doc.pri.design.md)，约束引用[规则](./guide.doc.pri.rule.md)，重要取舍引用 [ADR](./guide.doc.pri.adr.md) 或 [PDR](./guide.doc.pri.pdr.md)。指南不承担审批，也不把“照做后应成功”写成已经验证成功。

项目入口示例：[决策治理指南](./guide.platform.decision-records.md)。检验标准是首次操作的人能否走到明确结果，并在失败时知道下一步。
