# 录音交付页设计稿还原工程

**一句话**：把录音全链路 40 块设计稿画板逐块还原，由审查智能体打分，每块 ≥99 分才算完成。
**谁该读**：接手这条链路的工程与设计双方，以及要判断「到底还差多少」的决策者。
**读完能做什么**：知道现在到哪一步、卡在哪、下一块做什么、凭什么说某一块过了。

版本：v1（2026-08-25 建立基线）

### 判分为什么会来回跳

同一块画板不同判官能差 4-6 分，所以单次分数不作数，一律取多判中位。
更要紧的是**判官之间实质分歧要自己去看基准图裁**，不能让两个判官互相打架：
P3 那轮 98 与 94 的差别在「章节标题该在卡内还是卡外」，翻开基准图是卡外，
给 98 那位漏了——照 98 走就会把一个真实缺陷判成通过。

还有一类分歧属于**判官对，但理由要按住**：连续三位判官报「稿面两枚黑底大词、
实现只有一枚」。按比例阈值算，稿面 29÷38=0.76 本就在黑档，我的样本第二名
5÷8=0.63 才掉到蓝档——是样本差异不是规则错。但稿面是 SSOT，与其每轮重新
辩解一遍，不如换成能稳定复现稿面形状的规则，并把这条写进给设计方的清单让
他们可以否决。

### 这一轮修掉的两个流水线缺陷

判分依赖取证，取证坏了分数就没有意义，所以单列：

1. **基准图曾是废图**。设计稿是可交互原型，画板内容由它自带的运行时渲染，
   而那个运行时开局就要远端 React——沙箱打不通。此前的绕法是剥掉脚本截静态副本，
   代价是凡由数据驱动的画板全切成了字面量模板（B1 整个播放区都是）。
   现在把本地 React 注入进去让它按自己的逻辑渲染，并加了一条硬判据：
   渲染后仍有未解析模板就直接失败，不许出图。
2. **画板判据曾整体失效**。判据读的是 `style` 属性字面量 `font-size:13px`，
   而运行时渲染出来是 `font-size: 13px`——冒号后多一个空格，40 块变 0 块。
   改读计算样式。

## 判分怎么来的

设计稿是一张画布，上面按编号排着一块块画板（`R1`/`P3`/`A4`/`B2`/`D1`/`S7`…）。
流水线做三件事：

1. **切图**：按设计稿自己的编号规则把每块画板单独截出来，形成基准图与索引。
   编号取设计稿给的代号而不是位置序号——序号会随抓取判据变化整体位移，
   我就因此把「失败卡」拿去和「自动重试」比了一轮，白跑两次评分。
2. **取实现图**：对照台上每块画板挂一个与设计稿相同的编号，深浅两档各截一版。
   没有编号的画板（本次新增、设计稿里没有的）不参与打分。
3. **判分**：审查智能体拿到「基准图 + 实现图 + 画板编号」，按六个维度打分并列出
   逐条缺失。它只审不改，也不给实现找借口。

六维度与权重：内容完整性 35 / 结构与层级 20 / 状态表达 15 / 交互可达 15 / 视觉样式 10 / 版式留白 5。
**判定原则是「设计稿里有的必须有，可以多不可以少」**——实现多出来的东西不扣分，
除非它遮挡或改变了设计稿定义的主路径。

流水线自身有一条已验证的可靠性：两轮配错图时，审查智能体**自己识破了**
「两张图讲的不是同一件事」并在报告里点名，而不是照着错图给一个像模像样的分数。

## 需要设计方补的（画板里没说清、无法据此实现）

这些是审查智能体在判分时标出来的 `design_gaps`，不是主观意见：

1. **三阶段画板的量化信息没有取数来源**：「24:18 · 19.1 MB · 耗时 1.2s」里的体积与
   单阶段耗时、「已生成 84 / 约 132 句」里的句子总数，都没说明从哪来。
   句子总数在转录完成前只能是估算，设计稿也没说允许多大漂移。
2. **原文逐句生成卡的溢出行为未定义**：骨架占位行画了两条，但没说正文超出卡高之后
   是内部滚动还是截断，也没说卡本身高度是否固定。
3. **命中面板只画了「已选中某词」这一态**：没画未选中时这块区域是空着、是折叠、
   还是显示别的内容。这决定了它是常驻区块还是按需展开。
4. **待办列表在画板底部被裁切**：没说总条数怎么展开、是否内部滚动。
5. **自动重试卡的倒计时「8s」**：没说是否实时递减、数值从哪来。
6. **离线卡的「3 处待同步」计数口径未标注**，且这张卡没画任何入口，
   无法判断它是纯告知还是可点。

## 需要决策方拍板的平台约束（不绕开就拿不到 99）

判分里视觉 10 分 + 版式 5 分共 15 分，其中大部分卡在下面三条。
**内容、结构、状态、交互这 85 分不受它们影响，可以先做。**

1. **字体**：设计稿指定 Noto Sans SC + JetBrains Mono；平台全站正文字体链是另一套，
   且是全局设置。要么这一条链路单独引设计稿字体，要么接受字体差异并把这一项从判分里
   显式豁免。
2. **强调色**：设计稿的强调色是蓝色并明令全稿无紫；平台主色是陶土橙，且有一条
   双皮肤守卫禁止在组件里裸写颜色。目前的做法是映射到平台已有的蓝色语义变量——
   语义对上了，色值对不上。要色值也对上，需要为这条链路开一组设计稿专用的主题变量。
3. **页面外壳**：设计稿画的是**全屏独立页**，自带顶部栏（返回 / 标题 / 更多）和
   底部主按钮；当前实现挂在知识库的文档阅读器里，外面套着平台的顶栏与底部导航。
   `B1`、`D1`、`A1` 这类「整屏」画板要还原到 99，必须给录音结果开一个独立全屏路由，
   而不是继续寄生在阅读器里。这是波次 3、4 无法开工的直接原因。
