| 项 | 值 |
|---|---|

## 一句话调性

**数据是主角，界面是透明的。** 用户来控制台是为了读数据、找异常、改配置；
凡是不承载信息的东西（边框、标题、装饰、分隔盒子）都要让路。
好看不来自"加东西"，来自**同一层级的东西长得一模一样**。

## 五条原则

### 1. 一层卡片，不套盒子

一屏最多一层卡片。趋势图、指标、说明这类附属信息**不配拥有自己的卡片**：
- 趋势图 = 余光信息，无边框、无标题、无坐标轴，坐在表头正上方，可折叠，无数据时整块不渲染。
- 汇总指标 = 标题行下的一排小字（`请求 39 · 成功率 87.2% · Token 28k · 费用 $0.02`），不占卡片。
- 页面说明 = 标题下一句话；没有副标题层，没有 eyebrow 小标签。

判据：**主内容（表格/列表）在首屏占比 ≥ 60%**，非数据区不超过 ~250px。

### 2. 余量均匀，不许某一处独吞

眼睛对绝对空白不敏感，对**邻位之间的落差**极其敏感。一列宽松、邻列贴边 = 破洞；
所有列一起宽松 = 呼吸感。

- 列宽写成 `minmax(内容下限, 与下限等比的 fr)`，例如 `minmax(158px, 1.58fr)`。
  fr 权重与下限成正比 ⇒ 宽屏余量按比例摊给每一列 ⇒ 每列按同一百分比变宽。
- 判据：一屏内各列**占用率（内容宽 / 列宽）落在同一条窄带里**。
  参照 OpenRouter 的 48%~88%；出现某列显著低于邻列即为破洞。
- 表格最小宽度**必须由列自身下限推算**，禁止硬编码（历史事故：写死 1832px，
  怎么调列宽都强制横向滚动）。
- 数值列一律**左对齐**。右对齐 + 富余会在每列中间再撑出一条纵向空白山谷。

### 3. 字号只有七档，角色决定用哪档

档位定义在 `theme.css` 的 `:root`，角色映射定义在 `lib/typography.ts`。

| 档 | px | 角色 |
|---|---|---|
| `--fs-title` | 20 | 页面 h1 |
| `--fs-metric` | 17 | 指标数字、抽屉标题 |
| `--fs-heading` | 15 | 卡片 / 分区标题 |
| `--fs-body` | 14 | **正文、表格单元格与表头、表单输入、主要链接**（默认档） |
| `--fs-secondary` | 13 | 次要说明、字段名、工具条控件、mono 标识 |
| `--fs-caption` | 12 | 角标、tooltip |
| `--fs-micro` | 11 | 指标 caption —— 下限 |

口诀：**用户需要「读」的内容一律 14px；只有「扫一眼」的标记才允许更小。**
档位对了角色错照样翻车——历史事故：表格单元格用 12px、表头用 11px，
字号都在阶梯内，整页却比基准页糊一档。

### 4. icon 是扫描锚点，不是装饰

- 实体列（模型 / Provider / App）各带一枚 16px 圆角彩色标记，与文字间距 8px。
  作用是让"同一个 Provider 的行"在余光里自动成组。
- **没有品牌素材就用按名字哈希的确定性彩色首字母标记**（同名恒同色、异名异色），
  不要让所有陌生 Provider 退化成同一个灰云，也不要去抓别人的 logo。
- 表头 info icon 只给真正需要解释的列（全表 1 个为宜，4 个就是噪音）。
- **只有异常才配拥有视觉噪音**：成功行保持干净，失败/进行中的行用整行左侧色条；
  禁止给每一行都加状态圆点。
- 操作 icon 分级：无状态动作（刷新、更多）用无边框幽灵按钮；
  有状态控件（筛选、时间范围）带边框，因为它们会"亮起来"表示已生效。

### 5. 同一角色只允许有一种规格

这是最容易失守、也最影响"精致感"的一条。同一页/跨页出现多套规格，就会显得手工、拼凑。

| 角色 | 允许的规格数 |
|---|---|
| 卡片内边距 | 1 种 |
| 卡片圆角 | 1 种 |
| 主操作按钮（有无 icon、尺寸） | 1 种 |
| chip（高度 / 字号 / 圆角） | 1 种 |
| 指标展示 | 1 种（标题行小字） |
| 卡片底部操作行 | 1 种 |
| 容器间距 | 不超过基准页的种类数（新代码从 `surface.ts` 的四档里挑） |

### 6. 容器贴边，可读宽度作用在内容上（v1.2 新增）

页面级 `max-width` + `margin: 0 auto` 一律废止。内容从侧边栏起一路铺到右边缘。

「贴边」不等于「什么都不设上限」——上限要落在**内容**上，而不是把整页居中：

| 对象 | 怎么限宽 |
|---|---|
| 成句正文 | `.lg-prose` → `max-width: var(--measure)`（42em ≈ 每行 40 个汉字） |
| 表单字段 | `.lg-form-grid` → `repeat(auto-fit, minmax(260px, 320px))` + 左对齐 |
| 长 JSON / 键值块 | 给该容器自己设上限，不要为它把整页居中 |
| 表格、列表、图表 | 不限宽，撑满 |

`--measure` 用 `em` 不用 `ch`：`ch` 是拉丁 `0` 的字宽，中文下不可预测，换个字体会悄悄跑偏。

反面：`repeat(auto-fit, minmax(N, 1fr))` 让输入框跟着屏幕一起变宽，2560px 下一个 10 字段的表单会被拉成横贯全屏的长条——这也是「页面看起来空、重心在中间」的真实成因之一，而不只是居中容器。

### 7. 文字预算与三轨接入（v1.2 新增）

**预算**：每页副标题 1 句；**常驻可见**正文段落 ≤2 段、汉字 ≤400（一段 = 连续 ≥24 个汉字）。
参照系：基准页 220 字 / 1 段。

**四个出口**——超出预算的解释往这里放，收进出口的文字不计入预算：

| 出口 | 组件 | 放什么 |
|---|---|---|
| 字段旁的 `?` | `<HelpPopover>` | 这个字段怎么填、这几个选项什么区别 |
| 空状态 | 页面自身 | 没数据时该做什么 |
| 默认收起的折叠块 | `<DetailsBlock>` | 工作原理、边界、为什么这样设计 |
| 深链教程 | `<TutorialLink chapter>` | 概念与背景，控制台不复述 |

**三轨接入**——治「教程很详细但普通人不会用，熟人又嫌啰嗦」：只有一条中间轨道时两头都不讨好。

- 老手轨：一行「Base URL + Key + 复制」，三秒拿走。
- 新人轨：**派生态清单**（有团队？有成员？有密钥？有过日志？），四项全绿**自动消失**——不是常驻教程。
- 深读轨：概念外链 33 章《模型网关权威教程》。

**注意**：`HelpPopover` 的浮层是 288px 绝对定位。触发点靠近容器右缘时必须传 `align="end"`，
否则会越过边界被祖先的 `overflow` 裁掉。另外 `overflow-x: auto` 会让**另一个轴也按 auto 计算**，
所以浮层不要放在横向滚动容器（如表格外壳）里——实测会把第 5 个角色切掉一半。

### 附：数值格式服务于列宽

`$0.005097` 而不是 `USD 0.00509750`（14 字符白白撑宽费用列）。
符号前缀 + 有效位截断 + 去尾零。时间定长可读。

## 三层护栏（写歪了会被逐层拦住）

| 层 | 工具 | 管什么 | 何时跑 |
|---|---|---|---|
| 档位 | `pnpm check:typography` | 只能用七档字号（数值 `fontSize: 18` 与字符串 `fontSize: '18px'` 都抓） | CI（已接进 `pnpm build`） |
| 角色 | 同上（第二条规则） | `th/td/labelStyle/inputStyle` 不许降到 caption/micro 档；按花括号配平取整个声明块比对，不是只看声明行 | CI（同上） |
| 结构 | `node e2e/llmgw-layout-drift.mjs` | 页头是否裸露、内容是否撑满、表头与单元格字号、单行行盒、控件高度、五类规格种类数 | 改版后手动（有漂移即非零退出，可直接接 CI） |
| 角色（小字号承载正文） | `pnpm check:typography` 规则三 | 同一声明块里 `--fs-caption/--fs-micro` 配了 ≥1.45 的正文行高即判错。**棘轮制**：`SMALL_PROSE_BASELINE` 记录每个文件当前处数，只许减不许增，未登记文件默认 0；降下来了还要求同步下调基线 | CI（已接进 `pnpm build`） |
| 文字量 | `pnpm check:prose` | 常驻正文段落数与汉字总量；页面级 `max-width + margin:0 auto` 直接判错。收进 `HelpPopover` / `DetailsBlock` 的文字不计入 | CI（已接进 `pnpm build`） |

### 关于漂移检测的两个前提（改之前必须知道）

1. **只测 9 条路由**（`llmgw-layout-drift.mjs` 的 `ROUTES`）：`/logs` `/platforms` `/models` `/service-keys` `/audits` `/app-callers` `/pools` `/logical-models` `/exchanges`。
   组织、用量、运维、Quickstart、概览**不在其中**。由此得出分工：**被测路由保持内联表单与扁平 DOM；未被测路由才允许抽屉 / 对话框。**
2. **基准是实时量出来的，不是存档值**（`SPEC_KEYS` 上限直接取 `baseline[k].length`）。
   所以动 `LogsView.tsx` 或任何 `.lg-log-*` 选择器 = 同时挪动其余 8 条路由的判定线。改版前先抓一份 `VERBOSE=1` 输出当参照。
3. **`headingBoxed` 是单点全失效**：它从 h1 向上走 4 层，命中任何边框或非透明底色即判「标题被卡片包住」。
   给 `.lg-page-shell` / `.lg-page-body` / `.lg-page-heading` 加一句 `background`（哪怕只是想做滚动阴影），8 条路由会同时开始漂移。

## 历史背景

2026-07-28，用户拿 OpenRouter 的 Logs 页对比我们的控制台，连续三轮指出"不够精致"。
逐轮实测定位到的根因依次是：字号无 SSOT（9~24px 一次性字号满地）→
角色档位错配（表格正文塞进 12px）→ 结构差异（页头被关在卡片里、图表卡+指标卡两个盒子）→
列宽硬编码 1832px 导致强制横向滚动、51% 宽度空转 → 余量全灌进一列撑出空洞。

每一轮的教训都固化成上面某一条原则，并配了可测量的判据——
**"精致"不是感觉，是一组能被脚本量出来的数字。**

2026-07-29（v1.2），用户对组织与自助接入等页面提出「设计得太小学生」「违反主流、页面居中、偏教程、啰嗦」
「教程很详细但普通人根本不会用，熟人又觉得太啰嗦」。实测确认与澄清：

- **面板不一致属实**：19 个页面 15 贴边、4 居中，四个居中值互不相同（1040 / 1060 / 1080 / 1180），没有一处是共享 token。
- **「预算与用量、系统运维居中」不成立**：这两页本来就是贴边全宽。它们的「居中感」来自
  ① 解释段落横跨整个内容宽度，② `auto-fit 1fr` 卡片网格在宽屏被拉成一排巨宽卡片。→ 原则 6。
- **「字号乱」是角色乱不是档位乱**：七档字阶与守卫早已存在，全站没有档外字号；乱的是
  组织页用 11px 排了 10 处整句话、Exchange 在 CSS 里把分区段落钉成 12px。→ 规则三守卫。
- **「全贴边」也不是主流的全部**：Stripe / Vercel / Cloudflare 是「容器贴边 + 正文按可读宽度截断 + 表单固定列宽」。
  纯贴边对表格对，对 10 字段表单是灾难。→ 原则 6 的三张限宽表。
- **两头不讨好的根因是只有一条中间轨道**：而 `llmgw/tutorial/` 已有 33 章权威教程，
  `ConsoleLayout` 也早就实现了 `?tutorialRoute=` 深链——控制台里那些段落是在复述已经存在的东西。→ 原则 7。
