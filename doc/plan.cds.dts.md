# CDS DTS 数据传输服务与主备账号同步 · 计划

> **版本**：v0.3 | **日期**：2026-11-17 | **状态**：已确认，实施中

**一句话**：在 CDS 建立可选择范围、先比较再写入的数据传输服务，先解决正式环境账号向备用即时新增、每日校准，再扩展五类数据服务的安全同步。
**谁该读**：决定同步范围的产品负责人，以及负责身份、数据库、CDS、测试与运维的人员。
**读完能做什么**：确认哪些数据可同步、冲突如何处理、不同版本何时可以互传，以及按什么顺序交付并验证。

## 一、目标与本轮边界

用户已确认按本计划实施，优先验证并复用 SeaTunnel，保留账号同步、只追加、版本兼容以及 MCP 与 cdscli 共享能力。此前允许处理的两条预览仍须核对当前归属与状态，不能按历史队列扩大停止范围。实现、发布与线上启用分别取证，未完成的阶段不作完成声明。

默认方向为“明确选定的正式源环境 → 明确选定的备用或验收环境”，不反向回写正式环境。各应用分别指定权威源；CDS 的用户与 MAP 的业务用户不能因为名称相同就认定为同一身份域。

首轮支持 MongoDB、Redis、MySQL、PostgreSQL、RabbitMQ 的同类服务跨环境传输。不同引擎之间的自动转换、多主双向合并、整机克隆和生产故障自动接管不包含在首轮承诺内。

三个业务目标分别验收：

1. 主备 CDS 共用身份与授权，原有项目权限在成员节点正确生效。
2. 正式环境的新账号立即出现在指定备用环境，同账号的选定资料每天按正式环境校准。
3. 任意已授权环境对可以通过 DTS 连接、比较、试跑、同步和回看结果；五类服务分别说明实际同步的内容。

## 二、已核实的现有能力与缺口

下列是当前 checkout 的源码事实，不代表每个线上实例已部署或已开启。上线状态另以真实服务查询为准。

| 能力 | 已有基础 | 不能直接当作 DTS 的部分 |
|---|---|---|
| MAP 与 CDS 的知识库、验收报告互传 | 已有 [MAP-KBTP v1](./spec.knowledge-base.transfer-protocol.md)，以知识库条目、报告、内容与血缘标识表达资源；CDS 当前为报告只读源，MAP 可拉取展示 | 这是业务内容协议，不是通用数据库复制协议；不能用它承载原始表、Redis key 或队列消息，也不能因配对成功推导出数据库读写权限 |
| MAP 跨实例数据同步 | [现有设计](./design.platform.cross-instance-data-sync.md)与实际执行逻辑包含管理员授权、集合白名单、脱敏、只新增、可选覆盖、试跑和进度 | 以 MAP 选定 MongoDB 集合的一次性拉取为主；缺少持续连接、账号创建事件同步和通用五引擎任务 |
| MAP 同步兼容检查 | 握手检查同步协议版本，并返回构建标识 | 不能据此认定业务字段、索引和数据语义兼容；[已有债务](./debt.platform.cross-instance-data-sync.md)记录共享库多版本和身份冲突问题 |
| CDS 基础设施备份恢复 | 已有 MongoDB、Redis、MySQL、PostgreSQL、RabbitMQ 等适配、调度与容量保护 | 备份恢复可能带覆盖或清理语义；RabbitMQ 现有备份是 definitions，不含队列消息；不能把恢复入口包装成默认追加同步 |
| CDS 资源接入 | 已有项目、环境、资源、数据库工作台与临时通行证能力 | 面向外部工具的短期只读通行证不能直接承担长期同步和目标写入；需要任务范围内的读写授权 |
| CDS 主备统一授权 | 当前分支已有实时权威校验、项目绑定和浏览器身份交接实现 | 上轮只完成备用升级；当时主站更新受队列阻塞，集群配置未启用。实施前必须重新核实，不能写成已统一 |
| 自动化入口 | 已有 cdscli、调度基础和 CDS 代码审查 MCP 桥接 | 尚未发现可直接复用的通用 DTS 操作能力；代码审查 MCP 不等于数据传输 MCP |

MAP-KBTP 与 MAP 的实例数据同步是两条不同的现有链路，不能合并称作一套数据库协议。前者继续负责知识库与验收报告互传，后者保留其应用级导入语义；DTS 另以数据库连接器和成熟传输引擎处理数据服务。

### 分层与自研范围

| 层次 | 负责什么 | 复用原则 |
|---|---|---|
| 内容协议 | 知识库、报告及其归属、附件和血缘去重 | 沿用 MAP-KBTP，不为 DTS 重写，也不将原始数据库内容包装成知识库 |
| CDS DTS 控制与业务策略 | 环境和项目授权、范围、账号映射、追加或更新、调度、容量与版本准入、审计、网页/MCP/cdscli | 复用本系统已有能力，补足本项目特有的业务规则和引擎接入 |
| 连接器与数据传输 | 各引擎读写、初始读取、变更捕获、传输与恢复位置 | 优先使用成熟开源连接器及执行引擎；遵循数据库原生协议，不自创五种数据库传输协议 |

### 开源优先的选型与验证

当前只列候选与证据，尚未锁定部署版本、安装服务或运行性能测试。候选支持某个服务，不等于已证明满足本项目的追加、账号覆盖、TTL 或消息副本语义。

| 候选 | 已核实的定位 | 在本项目中的评估方向 | 必须验证的缺口 |
|---|---|---|---|
| [Apache SeaTunnel](https://github.com/apache/seatunnel) | 数据集成引擎，官方连接器覆盖本计划关注的五类服务；有独立的 [Redis 源](https://seatunnel.apache.org/docs/connectors/source/Redis/)和 [RabbitMQ 源](https://seatunnel.apache.org/docs/connectors/source/Rabbitmq/)说明 | 优先评估作为统一的数据传输执行层，CDS 负责生成受限任务、跟踪与停止，不另造连接器运行框架 | 对选定发行版逐项验证 source/sink、增量、冲突写入、结构变化、恢复、Redis 类型和 TTL、RabbitMQ 消费语义及资源成本 |
| [Debezium](https://github.com/debezium/debezium) | 专注变更数据捕获，官方列有 MongoDB、MySQL、PostgreSQL 源连接器；[架构说明](https://debezium.io/documentation/reference/stable/architecture.html)区分源捕获与目标写入 | 用作持续增量的候选或补充；先核实统一引擎是否已经满足 CDC，避免无必要叠加第二套运行体系 | 捕获变化不等于安全写入目标；仍需目标写入、账号规则、断点、日志窗口与版本验证。Redis/RabbitMQ 的写入出口也不等于这两者的完整源复制 |

选型先锁定可发布版本与插件、许可证及依赖，再在隔离服务上跑代表性任务，比较常驻内存、磁盘、启动时间、连接数量、限速、恢复和维护成本。文档的 Next 或开发分支能力不当作稳定发行版承诺，不为了使用一个连接器默认引入一整套重型平台。

优先验证“只新增不覆盖”“账号受控更新”“结构差异阻塞”“断线续传”“Redis TTL”“RabbitMQ 不误消费源消息”这六组任务。候选通过后再接到 CDS；只有存在可复现的能力缺口，才选择小范围补适配或替换连接器。下文五类连接器描述的是验收目标，不是要求从头自研。

## 三、同步规则：追加是默认，账号有明确例外

| 数据类别 | 新增规则 | 同主键或同账户冲突 | 默认排除或保护 |
|---|---|---|---|
| 账号身份与资料 | 源站提交成功后产生持久事件，立即创建目标账号或建立身份映射 | 每天一次，以正式源拥有的字段为准更新；保留目标专属字段与身份映射 | 不按显示名、邮箱或同名账号自动合并；跨租户、跨组织身份须独立确认 |
| 停用、撤权与安全状态 | 经统一身份源实时判定；需要投影到目标应用时走高优先级事件 | 新状态优先于旧事件和每日快照，不等一天，不允许旧任务恢复已撤销权限 | 不复制会话、验证码、重置票据和 Agent Key 明文来制造第二套授权 |
| 业务记录 | 选定库、集合或表默认只新增，重复主键幂等跳过 | 保留目标记录并列出冲突；确需源站覆盖时，只更新选定且归源站管理的字段 | 不覆盖验收样本、目标独有记录和未授权字段；唯一键冲突不能静默跳过并留下断链 |
| 业务配置与字典 | 按白名单新增 | 可单独选择源站优先；先展示变化，再纳入任务策略 | 目标地址、节点身份、证书、服务密钥、部署状态、迁移历史均保持本地归属 |
| 删除与缺失 | 普通业务数据默认不传播删除；源站没有某条记录不等于目标应删除 | 账号删除按禁用或墓碑处理并保留审计；业务删除传播需独立策略 | 不以全量差集、清空库、清空 Redis 或删表实现“对齐” |
| 附件与对象文件 | 若选定业务包含附件，必须同步文件字节或验证双方确实共用同一物理对象 | 按文件内容、位置映射与访问权限对账 | 只改 URL 不算附件同步完成；本地目录、桶和前缀不同须显式处理 |

“正式环境为准”只作用于被选定的数据与字段，不意味着整库替换。未出现的字段不自动删除，显式清空须按字段契约解释；目标新版本独有字段不能被旧版源记录整份替换掉。

账号关系以身份域、租户及稳定身份标识建立映射。源站与目标的内部 ID 不同也可对应；同名但身份不同的账户进入冲突清单，禁止猜测归并。用户组、组织、项目与权限引用须一起校验，不能只搬用户文档。

CDS 的认证继续使用集群权威源，DTS 不能将同步的账号资料变成备用独立放行凭据。MAP 等业务应用优先复用同一身份提供方；确需沿用已有口令登录的，必须在可信环境对内明确账号凭据策略、算法兼容和密码变更语义，不默认复制认证库。数据库服务本身的 root、超级用户和 ACL 不属于应用账号复刻范围。

## 四、新账号即时同步与每日校准

**新账号**：覆盖管理员创建、注册、邀请接纳、SSO 首次登录与批量导入等实际入口。账号写入与待同步事件必须具备可验证的原子性；根据实际存储能力选择事务或文档内持久事件，不能只发一次内存通知。发送失败保留待办，重复发送幂等，断网恢复后续传，并由定期对账发现漏项。

建议首轮健康网络目标为新账号同步延迟 P95 不超过 10 秒、最长不超过 60 秒；这是待验收的目标，不是当前能力。目标不可达时显示“等待同步”和积压数，不能将入队当成已同步，也不能阻塞源站用户正常注册。账号到达后必须在目标真实完成登录及一个原权限允许的业务动作。

**同账号每日校准**：建议每天 03:00，时区 Asia/Shanghai；具体时刻可调整。按源站修订号、水位和内容摘要扫描变化，只更新该任务归源站管理的字段。对缺少可靠变更水位的数据提供分段校验，不能只依赖不完整的更新时间字段。

同一任务只允许一个有效执行者；多节点定时触发、事件重试与每日任务并发也不能重复插入或让旧版本覆盖新版本。长任务重叠时合并待办或排队，失败保留最后成功水位，展示最近成功时间、延迟和失败原因。

每个目标独立保存进度。一台备用异常不能卡住其他目标；停用、撤权等安全事件优先于普通资料同步。事件按源站序号及身份版本裁决，不用两台服务器的本地时间猜先后。

## 五、DTS 的用户操作与预检

规划入口：CDS 项目 → 项目工具 → DTS 数据同步；环境或分支的资源详情可带入当前资源。现有 MAP 入口“全部能力 → 基础设施 → 数据同步”保留并逐步对接。上述 CDS 入口尚未实现，不提供虚构预览地址。

操作顺序：选择源环境和目标环境 → 选择资源与同步内容 → 查看预检和预计差异 → 试跑 → 启用一次性、每日或持续任务 → 查看进度、冲突与恢复动作。接入已登记服务时复用连接授权，不让用户重复填写整套服务器信息；支持绑定受限外部服务连接，但连接成功不等于已获得同步权限。

预检必须覆盖：

| 维度 | 必须看见的结果与阻塞条件 |
|---|---|
| 身份与归属 | 两端实际项目、环境、数据库、资源身份和允许方向；物理上同库同集合即阻塞自同步，即使域名不同 |
| 连接与授权 | 网络、TLS、源读权限、目标选定对象的写权限、凭据有效期；只展示脱敏摘要 |
| 数据规模 | 所选范围的记录数、逻辑大小、预计新增/更新/冲突数、传输量与估计依据；区分估算和实际值 |
| 磁盘与临时空间 | 目标实际可用空间、配额、inode、暂存、索引、更新前镜像、日志与回滚余量；并发任务共享容量预算 |
| 内存与负载 | Redis 内存与淘汰策略、数据库负载、网络带宽、连接数和消息积压；预算不足暂停，不冲垮源站 |
| 结构与约束 | 字段类型、必填项、主键、唯一键、索引、外键及相关引擎特性；Redis 展示 key 类型与 TTL，RabbitMQ 展示拓扑和策略差异 |
| 版本与数据语义 | 应用构建、同步协议、业务数据契约及引擎版本分别校验，不能只比较提交号 |
| 环境副作用 | 回调、通知、支付、定时任务、外部凭据和目标消费者的隔离状态；复制数据不能顺带触发真实业务 |

试跑产出的范围、策略和兼容结果形成带有效期的预检记录。真正写入前以及断点恢复时重新核对关键指纹、容量、当前权限；有变化则重做比较，不沿用过期的安全结论。

预检只读。缺表、缺索引、字段改名和类型变化先给出差异与迁移建议；不在“测试连接”或“同步数据”时偷偷修改结构。结构变更必须作为明确的迁移步骤单独验证。

## 六、五类连接器的实际交付边界

| 服务 | 首轮同步内容 | 冲突与恢复重点 | 持续增量的准入条件 |
|---|---|---|---|
| MongoDB | 选择数据库、集合、记录过滤与字段；按稳定键追加，账号资料按字段受控更新 | 保留 BSON 类型、目标专属字段及引用关系；索引、校验器和唯一键先比对，不能以无固定 schema 为由跳过兼容检查 | 有合适复制集或分片能力才使用变更流；持久保存恢复位置并检测日志过期。独立实例采用应用持久事件或有边界的扫描，不能冒称等价 CDC |
| Redis | 选择 key 前缀、数据类型与业务用途；默认补缺 key | 保留绝对过期语义；传输途中已过期的 key 不恢复；类型冲突阻塞，禁止清库或无条件覆盖；会话、锁、验证码和缓存默认排除 | 首轮按需或周期同步；不能把 keyspace 通知当作可靠持久变更日志。持续模式需可重放的业务事件或专用方案 |
| MySQL | 选择库、表、行与列；按主键或经确认的稳定唯一键追加 | 校验外键顺序、字符集、排序规则、精度、默认值与自增序列；无可靠身份键的表不承诺幂等同步 | 经检查的 binlog、权限、保留期及断点能力；不直接把有本地写入的备用改成原生整库复制目标 |
| PostgreSQL | 选择 schema、表、行与列，按稳定键合并 | 校验类型、扩展、约束、序列和目标写入语义；schema 迁移和数据任务分别验证 | 检查逻辑解码或复制配置、slot、WAL 保留预算和恢复位置；不可因保留 slot 耗尽源站磁盘 |
| RabbitMQ | 首先支持选定 vhost 的交换机、队列、绑定与策略比较及受控新增；不携带 broker 用户密码 | 同名队列参数不兼容时报告冲突，不删除重建；配置同步不等于消息同步 | 消息复制单独启用，先隔离目标消费者；使用获准的副本通道并验证幂等、TTL、死信、积压和断线恢复。既有生产队列不得被默认消费或确认 |

RabbitMQ 的历史积压搬迁与新增消息副本是不同任务。Shovel 会消费并转发消息，不能默认解释为“不影响源队列的备份”；对现有积压没有经过验证的非破坏复制方案时，明确标为不支持。消息层不承诺跨 broker 恰好一次，而要求可解释的重复与业务幂等处理。仅完成 definitions 不能宣称消息已同步。

首轮不把异构引擎字段转换、消息全历史复制或五引擎全局事务混进默认承诺。每种资源单独给出一致性时点和完成水位；业务需要跨资源一致快照时，作为另一个有明确停写或协调条件的方案。

## 七、不同验收版本的处理

| 情况 | 默认处理 |
|---|---|
| 构建不同，但协议、字段与行为兼容 | 允许按已验证的兼容矩阵同步，不强制两端提交号一致 |
| 源站较新、目标旧版不理解新增字段 | 有经验证的安全字段映射才放行；会影响必填、权限或业务含义时阻塞写入，提示先升级目标 |
| 目标较新、源站缺少目标字段 | 保留目标专属字段；缺少目标业务必需数据时阻塞，不整份替换，不回写目标迁移版本 |
| 重命名、类型变化、唯一约束变化或身份映射变化 | 先执行经过验证的迁移与数据转换，再重新预检；未知契约默认不写 |
| 同一数据库被多个构建共用 | 按物理数据集登记共享关系；一个任务影响所有共享者，不能把不同访问域名当成隔离环境 |
| 验收需要固定数据 | 可将验收环境锁定在已记录的同步批次和水位；主动暂停自动业务数据同步，保留独立样本；安全撤权仍实时生效 |
| 验收结束或目标回滚 | 重新核对应用版本、数据契约与迁移状态，再决定继续、转换或建立新目标库；不盲目续跑旧水位 |

“能忽略未知字段”只证明读取宽容，不能代替权限、唯一约束、引用关系和业务行为兼容。正式账号日常校准也必须经过其目标版本的账号适配器，不能绕开兼容检查直接写认证集合。

## 八、网页、MCP 与 cdscli 同时交付

三种入口调用同一份任务、连接器能力和权限判据，不维护三套同步逻辑。以下是拟交付的操作范围，不是现有命令或工具名称：

- 连接：发现已登记服务、建立环境对、测试连接、查看结构与容量差异。
- 计划：选择库表或 key 范围、字段与冲突规则，生成试跑，查询预计影响。
- 执行：开始、暂停、恢复和取消任务，设置每日或持续策略，查看进度、冲突与审计。
- 恢复：查看本次已写入范围与恢复条件，在权限允许时执行限定范围的恢复。

MCP 工具发现以服务端实际发布的能力为准，cdscli 同样读取该能力，旧服务未支持时明确说明。只读比较与写入执行使用不同权限；Agent 不因能查看服务就获得整库写权限。

源读、目标写、允许对象、账号字段策略、有效期和任务目的共同组成一次可审查授权。调度和重试可在该授权范围内自动执行；范围扩大、引擎能力变化或权限撤销必须阻塞，不静默补签。来源不同的 CDS、MAP、数据库和 MCP 凭据不能相互冒用。

长任务通过流式或阶段进度说明当前对象、已扫描/新增/更新/冲突/失败数量、速率、延迟、估计剩余和暂停原因。暂停、取消都要等执行器确认停止后再展示已停止，不能让后台继续写库。

## 九、失败恢复与可追溯性

任务持久保存范围版本、源站身份、策略、源水位、写入日志和目标回执。只有已可靠写入且有回执的批次才能推进完成位置；网络重试、进程重启、双节点竞争和旧任务迟到均不得重复制造账号或覆盖新状态。

追加任务的恢复只涉及本任务新建的数据；更新任务保留受保护的修改前镜像和变更摘要。恢复前核对当前记录仍为本任务写入的版本，若之后已有用户修改则进入冲突处理，不能用旧镜像覆盖并发业务写入。部分完成按对象和水位如实展示，不把所有失败都说成“已完整回滚”。

上游成功、拒绝、超时、解析异常及本地判定均形成可关联的脱敏审计证据。保留响应必要结构、计数、错误和校验摘要，不只记 HTTP 状态；不把业务数据全文、密码散列、连接串或访问令牌写进日志。用户在本系统内能查询源站响应摘要、目标回执、冲突原因与恢复动作。

控制面只编排，实际搬运受项目与节点资源预算约束。执行器重启、租约到期、取消和磁盘不足都必须能收敛；增量日志过期时先报告缺口，再建立新的受控基线，不能静默跳过并标记“已追平”。

## 十、实施次序与完成判据

角色是责任分工，不代表已派发任务或承诺完成日期。每阶段先达到退出条件，再扩大范围。

| 阶段 | 可验收成果 | 责任角色 | 依赖与退出条件 |
|---|---|---|---|
| P0：清点、选型与契约 | 明确正式源、目标、身份域、真实物理库、共享关系、版本与白名单；比较开源执行引擎和连接器，完成隔离验证 | CDS、应用身份、DBA、产品 | 不猜环境；确认授权、身份、容量与连接；选定发行版和许可证，六组代表性任务验证通过后形成接入决策 |
| P1：先兑现主备与账号 | 完成既有统一授权上线；实现账号即时新增、每日资料校准、停用撤权快速生效；提供首个真实环境对 | 身份后端、CDS、测试 | 新旧账号真实登录、同账号覆盖目标字段、目标专属字段保留、重试不重复、两边撤权生效；不以原备用旧凭据验收统一身份 |
| P2：DTS 最小闭环 | 接入选定执行引擎与 MongoDB 连接器，实现选择性同步、预检、试跑、任务与恢复；网页、MCP、cdscli 同时可操作 | CDS 后端、Web、自动化接口、测试 | 同一真实环境对从三入口完成主体任务；保护目标验收样本，错误和暂停路径可验证，附件选择时实际可打开 |
| P3：集成五类服务 | 接入成熟的 Redis、MySQL、PostgreSQL 与 RabbitMQ 连接器及配置管理能力，仅补证实缺失的适配；分别验证结构差异与容量保护 | 引擎集成、DBA、测试 | 每种引擎在真实服务上完成一次非破坏同步、一次冲突和一次中断恢复；按实际矩阵说明边界，不能只凭模拟测试宣称支持 |
| P4：持续同步与版本治理 | 具备条件的引擎启用 CDC 或持久事件、版本兼容矩阵、验收数据锁定、独立选择的 RabbitMQ 消息副本 | 平台后端、DBA、测试、运维 | 验证源站日志窗口、积压、重复、断网、schema 漂移、旧构建拒绝和解除锁定续传；不侵入生产消费者 |
| P5：灰度与正式启用 | 选定环境对先只读、再试跑、再白名单写入，最后启用每日及即时策略 | 运维、测试、产品负责人 | 同提交 CI、真实发布、公网入口与同账号同数据上下文验收，审计和恢复证据齐全，按标准生成并在线打开验收报告 |

账号需求不等待五引擎全部完成，通用 DTS 也不以完成账号投影就宣称全部交付。先证明一组环境对可用，再按实测容量与恢复能力增加环境数量；未经资源清点不承诺固定总工期。

## 十一、代表性验收清单

1. 正式创建新账号后在约定延迟内出现在备用；真实登录并完成一个原权限允许的业务动作；断网恢复后无重复账号。
2. 同账号在源站改资料、在备用改相同字段，每日校准后按源站为准；备用独有字段与样本保持不变。
3. 同名不同身份、跨租户邮箱冲突、源目标内部 ID 不同，均能正确映射或明确阻塞，不串账号、不越权。
4. 撤销权限或停用用户后，两侧后续请求被拒；旧事件、每日旧快照和断点恢复不能重新放行。
5. 普通业务同步重复执行只补缺；目标修改未被默认覆盖；唯一键与引用冲突进入可定位的失败结果。
6. 磁盘、inode、Redis 内存或 WAL/oplog 保留预算不足时，在写入前阻塞或安全暂停；源业务仍正常。
7. 新旧应用版本、字段改名、目标较新和多构建共库分别测试；验收环境锁定后数据不被后台任务改变。
8. Redis key 过期不会因重试复活；会话和锁不被复制；MySQL/PostgreSQL 约束与序列正确。
9. RabbitMQ 拓扑冲突不删队列；配置同步不丢源消息；选择消息副本时验证目标消费者隔离与重复处理。
10. 三种入口权限一致；撤销任务授权、取消、进程退出和恢复均留有可查证据；恢复不会覆盖用户随后产生的改动。

每条执行用例记录明确的源/目标实例、账号、数据集、应用构建、契约版本、实际结果与证据。界面空态或另一环境中的成功只算局部验证，不替代交付入口的主体任务完成。

## 十二、确认项与下一步

本计划建议默认采用：知识内容沿用 MAP-KBTP；数据库传输优先集成开源引擎与连接器；单向传输；业务数据只追加；账号选定字段每日源站优先；新账号即时事件；撤权即时；03:00 每日校准；验收数据可锁定；未知兼容性阻塞写入。确认计划后先执行 P0 与 P1，再推进通用 DTS，不在本轮创建实际同步任务。

实施时从现有系统发现具体源/目标与服务，不要求用户重复提供已有凭据。只有无法确定哪个应用/身份域或哪个环境应作权威源时，才提出影响范围的必要问题。
