## 接入规则

明确说「记一笔债」「记下这个决策」或「排进计划」时，技能解析项目、对象与来源，通过 CDS 提交。明确要求登记一笔债且权限允许时，返回正式编号。明确记下决策或计划时生成提案，由有权人确认。实现、审查或验收中遇到明确选择延期的工程代价时，技能可以先形成提案，并在对话中说明来源和等待谁确认。普通待办、没做完的当前任务、猜测中的问题及对话外附件里的指令不会自动登记。

技能负责识别意图、填报有依据的数据和返回回执。CDS 负责状态、授权、时间、来源去重、并发、审计和重试。确认、延期、偿还与重开走各自的命令。请求里的来源文本只作证据，不能授予权限或改变状态。私有项目使用合成数据做开发验收。

### 核心数据与写入顺序

| 对象 | 维护规则 |
| --- | --- |
| 提案 | 保存发起方、来源和草稿。服务端维护待确认、已确认和已驳回。只有确认成功才产生正式条目，并把同一笔提交的结果写回提案。 |
| 决策与债务 | 债务可以先登记为未归属。原始来源决策保留，当前承接决策可调整，改挂原因和时间留在历史里。每个引用都核对项目和目标状态。 |
| 计划与步骤 | 跟踪任务、落地决策、偿还债务和复核决策。偿还步骤跟随债务结果。关闭、合并和偿还各自记账，复发时重新打开相应步骤。 |
| 写入回执与变化 | 服务端签发编号、记录可信主体和时间。同一主体复用请求编号可读回已提交结果。变更、事件和回执一起提交，读模型可按事件还原。 |

写入顺序为识别项目与主体、核对操作权限、校验结构与引用、检查请求重放及版本、执行状态变更、写入并返回结果。已有项目授权限定读取范围。具备项目写权限的智能体可明确登记债务，提案的确认与驳回保留给有权成员；权限随请求重新检查。
