# OpenDesign 接入 · 债务台账

> **版本**：v1.0 | **日期**：2026-09-11 | **状态**：开发中

**一句话**：记录 OpenDesign（无头设计编排器，负责拆解设计任务并驱动工具改文件）接入过程中交付时已声明的已知边界——哪些断言还没被真实跑过、哪些环境结构上就验不了、以及哪几个坑下一个人容易原样再踩一次。
**谁该读**：接手把这套东西推到能发布的人；以及验收时想知道「这一条到底验没验过」的人。
**读完能做什么**：不重复已经排除的可能性，不把别人的锅算进自己的改动，并且知道每条欠账要怎样才算还清。

---

## 一、还没被真实跑过的断言

| 欠账 | 现状 | 怎样才算还清 |
|---|---|---|
| 「工作室真的开张」的后半句 | 运行时可用性已由产品自身代码判定为可用（换回旧销钉即判不可用并给出具体理由），但「选定模型 → 真的生成出文件 → 审计里记的是同一个模型 → 一个任务标识串起四段证据」这一整条从没跑过 | 在一个能起容器的共享环境里完整跑一次，并由独立方出具地址可打开的报告 |
| 其余五步 | 都只有候选实现与本地测试，没有任何一步取得过独立验收报告 | 各自按计划里的「最直白的通过方式」跑通并留证 |

## 二、环境结构上的缺口

**预览型实例验不了这个功能。** 用于验收平台自身界面与接口改动的那类预览实例，故意禁用了宿主的容器操作命令。而本功能全部依赖容器操作去准备镜像、执行能力探针、启动会话容器。所以把特性分支部署成一个这样的实例**不能**用来验收本功能——它能证明服务启得来、路由注册得上，仅此而已。

这不是配置错误，是那类实例的设计定位。要验本功能，需要一个具备容器能力的实例运行该分支代码；现实里只有生产那套具备，而让它切到未合并分支会影响所有在用的人。**这条目前没有干净的解法，属于平台能力缺口，不是本功能的缺陷。**

## 三、容易原样再踩的坑

| 坑 | 表现 | 下次怎么避开 |
|---|---|---|
| 判据只验形状不验来源 | 供应链守卫断言销钉「长得像一个摘要」即放行，于是销钉与构建描述漂移了整整一批提交都没人发现，全程绿灯 | 凡是「指向一个外部产物」的判据，必须真的去取那个产物验一次，不能只验标识符的格式 |
| 拿未授权响应推断路由是否存在 | 子实例对目标接口返回未授权，看似说明它认得这条路由；实测对一条瞎编的路径同样返回未授权——鉴权排在路由之前 | 任何「某响应说明某事」的推断，先用一个必然为假的输入做对照实验 |
| 给探针加「标准错误必须为空」 | 只读文件系统下工具会往标准错误打一行无法创建别名的告警，不影响退出码 | 判据只看退出码；要看输出就得先确认正常路径下输出是什么 |
| 守卫自己没接上线 | 流水线的路径过滤不含被守文件，「只改那个文件」的改动根本不触发守卫 | 加守卫时问一句：只改被守文件、不碰守卫本身的那个改动，这条守卫会跑吗 |
| 环境失败与目标失败同码 | 校验脚本第一版在容器守护进程不可用时也返回 1，读者无法判断是守卫发现了问题还是守卫没跑起来 | 环境类失败与判定类失败用不同退出码 |

## 四、不属于本功能但撞见的

**共享库字段漂移打挂了本分支的一个服务。** 本分支预览环境里网关服务崩在启动阶段，原因是共享数据库中存在别的部署写入的新字段，本分支的类反序列化不了。时间戳早于本轮全部改动，与本功能无关，本轮未处理。

这是共享基础设施的老问题在新场景的又一次显形，判据与台账见跨项目隔离规则里的共享数据库通道。

## OpenDesign 不可用的排查结论（2026-09-15）

**不是配置问题，也不是凭据问题。** 逐层验过：

| 层 | 结论 |
|---|---|
| MAP 的 CDS 连接 | `status: active`、`lastProbeOk: true`、scope 含 `instance:read` 与 `shared-service:deploy`，够用 |
| CDS 路由 | 拿 `AI_ACCESS_KEY` 直打，返回 `Unknown API endpoint: GET /api/projects/.../agent-runtime-providers` |
| 线上 CDS 构建 | 跑 `claude/basic-error-solution-btq0os` @ `6d981fb2e`，其 `remote-hosts.ts` blob = `624091482`，与 `origin/main` 完全一致，都没有这条路由 |
| 主干上的 CDS 物料 | `agent-runtime-provider-registry.ts`、`agent-workspace-session-runtime.ts`、`open-design-runtime/` 在 `origin/main` 上都是 **0 个文件** |
| 销钉镜像 | GHCR 上仍可拉（manifest HTTP 200），`prepareImage()` 会自动 pull，不是阻塞点 |

**顺带一个诊断性缺陷（尚未修）**：`DesignArtifactProviderCatalog` 的 catch-all 把真实异常（404）吞掉，统一报「暂时无法读取 CDS Remote Agent 运行事实，请检查系统连接」。而连接是好的——这句话把排查指向了完全错误的方向。建议把 404 / 超时 / 连接失败分开报。

## Codex 首轮 review 收口后剩下的边界（2026-09-15）

三条 P1 都已在 [PR #1533](https://github.com/inernoro/prd_agent/pull/1533) 上改掉并各有红绿证明，
这里只记它们没覆盖到的部分，免得下一位以为已经全境干净。

| 条目 | 现状 | 影响 | 下一步 |
|---|---|---|---|
| OpenDesign 的 `modelBaseUrl` 未钉来源 | 会话创建现在要求 workspaceTransfer 的两个地址等于已验证的 MAP 连接来源，`modelBaseUrl` 仍然只校验「是合法 http/https 地址」 | 它由会话容器去打、容器网络是 egress-only，不构成 CDS 代打内网；但「MAP 自有」这个说法目前没有判据兜着 | 想钉就和 transfer 用同一份来源判据，一行的事；本轮不做是为了不把 PR 再摊开 |
| 非流式原生响应有 32 MiB 可校验上界 | 超过就返回 `NATIVE_RESPONSES_BODY_TOO_LARGE`（502），提示改用流式 | 「先校验再交付」必须有界，否则它自己就是内存洞。正常 Responses JSON 远达不到；大体积场景（整段 base64 图像）会被拦 | 真撞上再谈分块校验；不要为了绕开它退回裸转发——那正是这次要修掉的静默降级 |
| 跨源部署的预览走 SameSite=None | 仅当浏览器明确给出 `Sec-Fetch-Site: cross-site` 时才降；拿不到这个头维持 Strict | 老浏览器在跨源部署下仍会白屏，但不会因此放宽同源部署的默认 | 仓库现有全部部署都是 `VITE_API_BASE_URL=""` 的同源形态，这条暂时没人撞得到 |

### 顺带发现、但不归本 PR 改的一处（2026-09-15）

prd-admin 的共享弹窗在 2026-09-01「控制台形态」那一版里，把标题块和右侧动作区都设成了不让步，
标题一长、窄屏一挤，整行溢出而容器裁切，关闭按钮就被切掉——标题本身也没有截断兜底。

本 PR 原先有一条断言钉住旧写法（`min-w-0 flex-1`），那属于「调用方用字面量锁死别人的实现」，
谁改谁的 CI 红，已删掉，改为只守本组件自己的标题长度。真要修得由弹窗形态那一侧决定让谁先缩，
不该由网页托管这个调用方顺手改掉一个全站共享组件的版式主张。
