## 二、本周做成了什么（业务价值看板）

### 1. 会议录音上传后能直接变成可读文字，转写服务挂了也不中断

**谁受益**：内部团队 + 使用知识库的外部客户。

以前录音传进知识库只是一个躺着的文件，要听完才知道内容；现在上传即开始实时转写，转写服务不可用时会自动逐级降级（实时转写→异步转译→仅存档），而不是整条链路卡死或报一个看不懂的错。录音传完到看见结果页是连贯的，中途不再需要用户自己刷新猜进度。

**关联 PR**：#1261 #1270 #1282 #1286 #1291 #1301 #1312（7 个）
**验收背书**：**本周未做独立功能验收**——这是本周第二大证据空白（最大的是安全边界，已连续两周），已列入下周 P1。

### 2. 部署平台的 7 月 27 日宕机欠账基本还清，并补上了「主干分支被误回收」这个 P0

**谁受益**：运维 + 所有把项目托管在部署平台上的团队。

宕机复盘留下的根因这周逐条偿还完毕：宿主磁盘有了治理机制、写放大问题收敛、存活监控上线。更要紧的是修掉一个 P0——主干分支在某些条件下会被产物回收机制误删。同时数据库高可用（复制集）模式跑出了第一个可用版本，并把「不同项目共用一个库」改成真正的隔离库；关系型数据库的隔离逻辑此前在真实 Java 项目上从未生效过，这周才第一次真正修好。

**关联 PR**：#1262 #1268 #1273 #1275 #1280（5 个）
**验收背书**：每日巡检覆盖，结论为有条件通过（07-30、08-01）。

### 3. 发布过程从「黑盒等待」变成「看得见、算得清」

**谁受益**：运维 + 需要看交付效率数字的管理者。

发布中心整体改版：环境成为组织骨架、服务器可以就地添加、失败判据直接摆在首屏而不是埋在日志里。发布过程本身也被拆成了可见的步骤模型，带预计耗时、生产存活探测、日志有界（不再无限刷屏）、产物自动回收、配置漂移检测，并开始记账产出 DORA 交付效率指标。

**关联 PR**：#1281 #1292（2 个）
**验收背书**：功能验收 · CDS 与正式环境首次稳定冒烟 = **未通过**；合成测试登录与稳定冒烟调度 = 有条件通过。**这条能力是本周红灯集中区，功能已就位但尚未取得放行证据。**

### 4. 一条命令 + 一句话，就能把这套研发方法论装进任何一个项目

**谁受益**：外部客户与新接入团队——这是本周最具备**可售卖属性**的一条。

以前把这套方法论（规则、文档骨架、验收流程）搬到一个新项目，要人工抄一堆文件；现在按角色打包成技能套装，配合部署平台的项目初始化，一条命令即可落地，并会自检「已装什么 / 还缺什么 / 下一步做什么」。同期上线了角色化的上手助手和角色决策卡，新人接入时不再面对空仓库发呆；第二批通用技能套件也已发布。

**关联 PR**：#1225 #1277 #1294 #1295 #1298 #1309（6 个）

### 5. 模型网关控制台完成 v1.2 全量迁移，教程从「静态文档」变成「可点可跳的关系网」

**验收背书**：本周未验收。

**谁受益**：产品演示场景 + 视频创作功能的使用者。
