# 同批运行容器恢复 · 指南

> **版本**：v1.1 | **日期**：2026-10-19 | **状态**：维护中

**一句话**：核对同一批当前容器的完整身份，修复分支网络并验证就绪后恢复入口，保留数据库和历史失败结果。
**谁该读**：部署失败后需要恢复已有容器的 CDS 维护人员。
**读完能做什么**：判断何时可用同批恢复，准备精确身份快照，识别恢复失败与业务验收的边界。

适用于部署曾失败、保留入口与当前候选不一致，但整批当前容器已经创建且需要重新核验的分支。恢复不会重建数据库、删除旧容器、执行初始化脚本或修改历史部署运行的结论。

`POST /api/branches/:id/recover-runtime` 接收 `expectedCommitSha`（40 位）和 `expectedContainers`（本分支全部服务 ID 到完整容器 ID 的映射）。客户端先读取分支快照，再提交同一快照；范围、提交或任意容器改变即拒绝。只允许调用者有权限的本地分支，远端执行器不能从控制面代为恢复。

恢复按分支写操作租约执行：核对全部当前容器的项目、分支、服务标签和完整 ID；将当前容器接到同一张新分支网络；只摘除这些容器自己的旧分支网，保留共享基础设施网络和历史容器；原地重启项目声明的应用以刷新连接，分支额外数据库、缓存和存储不重启；最后按每个服务的就绪或启动信号契约验证。全部通过并持久化成功后才切换入口。数据库内容与历史失败运行保持原状。

如有分支额外代理或调度应用缓存旧连接，维护人员可显式传入 `restartProfileIds`，列出确需刷新连接的服务；仅接受当前分支的不同服务 ID。省略时仍只重启项目声明的应用。清单不应包含数据库、缓存或对象存储。主动原地重启按完整容器身份关联停止事件；仅重启执行窗口内的事件归为计划操作，启动后再次退出仍按真实故障处理。

额外服务的数据库或存储目录不能依赖每次部署的源码检出目录。可在 `extra-services` 的服务配置中声明 `prebuiltImage: true` 和 `cacheMounts: [{"kind":"volume","hostPath":"scheduler-data","containerPath":"/var/lib/mysql"}]`。CDS 自动为卷名加项目与分支的稳定命名空间，同分支换代码仍使用同一卷，其他项目/分支不能引用此卷。该入口不接受宿主目录挂载；省略 `cacheMounts` 保留原配置。迁移已有数据须另行核对、备份和恢复，声明新卷本身不会迁移旧数据，也不证明数据库业务内容完整。

维护过程中需要传入 SQL 等敏感输入时，`container-exec` 支持 `stdin`（最多 1 MiB）与 `expectedContainerId`。输入经标准输入送入容器，不拼进宿主命令参数；完整容器 ID 在入队前及执行槽开始时核对。不要将凭据或敏感输入打印、保存到报告或放进命令参数。

SSE `progress` 给出当前阶段，`complete` 返回网络与服务清单，`error` 返回首个失败原因。传输中断不代表服务端未受理；先核对该分支操作与容器状态，禁止重复提交。恢复中的新操作会使旧租约失效，执行槽在命令启动前重新核验租约。

任何未就绪、身份不符或落盘失败都不能宣布恢复通过。网络接续或应用重启失败后，已发生的连接变更会保留以便诊断，入口指针不发布为成功；恢复不是跨整个环境的网络事务。复测须保留首试失败，并从同一身份快照的实际状态重新检查。

验收仍需访问最终公网 HTML、实际入口资源和业务页面，完成真实命令、结果回查、负向与恢复流程。容器就绪不能替代业务验收。
