# CDS 本地多用户认证解耦 · 计划

> **版本**：v1.0 | **日期**：2026-09-29 | **状态**：实施中

**一句话**：让本地账号密码成为独立的多用户认证能力，同时完整保留原始环境变量账号密码的登录兼容性，不再要求先启用 GitHub OAuth。
**谁该读**：负责 CDS 认证、部署和验收的研发与运维人员。
**读完能做什么**：判断本地多用户重构的边界、兼容承诺、实施阶段和完成证据是否齐全。

---

## 目标与完成定义

CDS 的账号密码能力目前包含两套含义：原始环境变量账号是一道单账号访问门禁，持久化本地账号则是一套完整的多用户体系。两者被同一个“账号密码”名称掩盖，后者又借用了 GitHub OAuth 模式的会话接线，导致管理员必须配置无关的 GitHub 凭据才能管理本地用户。

本次重构完成后：

- 原始账号密码继续从原入口登录，已有部署不改配置也不失效。
- 持久化本地账号可以在账号密码模式下创建、登录、禁用、重置密码并留下操作痕迹。
- GitHub OAuth 只负责 GitHub 身份登录，不再决定本地用户管理是否可用。
- 前端依据后端声明的能力展示用户管理，不再从认证模式名称推断。
- SSO 账号仍由上游身份源管理，不在 CDS 内复制一份密码体系。

## 兼容矩阵

| 场景 | 登录方式 | 用户管理 | 兼容承诺 |
| --- | --- | --- | --- |
| 原始账号密码部署 | 环境变量账号密码 | 原始账号作为系统所有者管理持久化本地账号 | 原登录地址、凭据和会话行为保持可用 |
| 本地多用户 | 用户名与独立密码 | 所有者创建、启停和重置账号 | 不依赖 GitHub 配置 |
| GitHub OAuth | GitHub 身份与本地账号可并存 | 所有者统一管理可管理对象 | 现有 OAuth 回调和组织白名单不变 |
| SSO | 上游票据身份 | 上游管理账号，CDS 不维护第二份密码 | 现有 SSO 登录和退出不变 |
| 未启用认证 | 匿名访问 | 不开放用户管理 | 不把匿名访问误报为多用户能力 |

## 实施阶段

| 阶段 | 产出 | 完成条件 |
| --- | --- | --- |
| 1. 能力解耦 | 会话、用户存储和本地账号不再从属于 GitHub 开关 | 账号密码模式可装载本地账号服务，GitHub 凭据为空也能启动 |
| 2. 兼容接线 | 原始账号与持久化本地账号通过同一访问门协同工作 | 原始账号可继续登录并拥有管理权，本地账号可独立登录 |
| 3. 前端收口 | 用户管理按服务端能力显示 | 账号密码模式不再出现“仅 GitHub 模式支持”的错误提示 |
| 4. 回归验收 | 自动化测试、构建和真人路径证据 | 原始登录、多用户创建与登录、越权拒绝三条路径全部通过 |

## 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 两套会话 cookie 并存时误判身份 | 登录成功后被再次拦截，或机器凭据被当成人类所有者 | 统一访问门的判定顺序，并分别保留人类会话与机器凭据标记 |
| 原始账号与持久化账号同名 | 用户难以理解实际使用了哪套密码 | 原始凭据优先校验，并禁止新建同名本地账号，会话身份明确标记来源 |
| 易失存储重启丢用户 | 用户误以为账号已永久保存 | 首启引导继续要求持久化存储，界面保留存储边界提示 |
| 前端继续按模式猜能力 | 后端已支持但页面仍隐藏入口 | 公共认证状态直接返回用户管理能力，前端只消费该字段 |

## 验收标准

1. 只配置原始账号密码时，原账号仍能从登录页进入 CDS。
2. 原始账号登录后能创建第二个本地账号，并能读取用户列表与操作痕迹。
3. 新建的本地账号可以独立登录，但不能执行仅所有者允许的用户管理动作。
4. 不配置 GitHub Client ID 与 Secret 时，上述三条仍成立。
5. GitHub OAuth、SSO、机器凭据和匿名公开路径的既有回归测试不退化。
6. 设置页在账号密码模式下直接展示用户管理，不再要求切换到 GitHub OAuth。

## 非目标

- 本次不移除原始环境变量账号，也不强制自动迁移成数据库用户。
- 本次不改变 SSO 的上游账号治理责任。
- 本次不重做角色权限模型；沿用系统所有者与普通成员边界。
- 本次不把易失存储包装成可用于生产的持久化账号库。
