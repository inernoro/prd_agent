# CDS 角色化 Agent 一键上手范型 · 设计

> **版本**：v1.0 | **日期**：2026-07-29 | **状态**：开发中

**一句话**：让不懂版本管理与部署的人只说一句需求，就得到可点击、可登录、可验收的在线地址。
**谁该读**：做上手体验的产品与工程师。
**读完能做什么**：说清上手助手怎么把角色、技能与提示词串成一条路。

---

## 一、管理摘要

这项能力解决的不是“怎么下载一个技能”，而是更上层的问题：一个不懂 Git、部署和预览的产品经理，能不能只说一句需求，就得到一个可以点击、可以登录、可以验收的在线地址。

CDS 新增“上手助手”后，用户先选择 AI 开发经验和角色，再按推荐清单增减技能，并决定是否接入 CDS。系统随后生成一段角色化启动提示词和一个无密钥安装脚本。提示词负责约束 Agent 的沟通与交付行为，技能负责具体方法，CDS 负责扫描、构建、部署和真实预览。

首个锚点是“小登 + 产品经理”。底层同时支持老登、业务专家/需求专家、领域专家、开发和测试角色，避免未来重复建设。

## 二、用户最终得到什么

用户只需要完成四个选择：选择小登或老登、选择角色、增减推荐技能、决定是否接入 CDS。系统提供可复制提示词、技能独立下载地址和无密钥一键安装脚本。

接入 CDS 后，最终体验是：用户说完需求，Agent 自动修改、验证、提交、推送、部署，并返回真实预览深链和登录方式。

## 三、为什么必须高于具体产品需求

客户项目可能是静态网页、成熟软件、开发半成品，也可能包含多服务、复制集和隔离数据库。上手范型不能预设 React、.NET、单容器或无登录页面。

提示词只规定稳定行为：先识别项目形态，复用已有结构；缺什么补什么；文件发生修改后自动建立安全分支、验证、提交和推送；部署问题交给 CDS 技能；只使用 `preview-url` 返回的真实地址；需要登录时交付可验证的验收账号。

## 四、体验锚点

| 显示名称 | 内部 ID | 定义 | 交互差异 |
|---|---|---|---|
| 小登 | `newcomer` | AI 开发经验 1 年以内 | 少术语、强引导、自动处理技术步骤 |
| 老登 | `experienced` | AI 开发经验 1 年以上 | 更简洁，优先给计划、风险和证据 |

锚点只改变解释方式，不改变权限和执行能力。

## 五、角色范型

| 角色 | 默认推荐技能 | 默认关注点 |
|---|---|---|
| 产品经理 | 按角色从动态目录匹配、最多 6 个 | 用户、问题、范围、优先级、验收 |
| 业务专家 / 需求专家 | 按角色从动态目录匹配、最多 6 个 | 业务目标、需求规则、例外情况、验收标准 |
| 领域专家 | 按角色从动态目录匹配、最多 6 个 | 业务规则、例外情况、专业准确性 |
| 开发 | 按角色从动态目录匹配、最多 6 个 | 架构、实现、验证、可维护性 |
| 测试与验收 | 按角色从动态目录匹配、最多 6 个 | 场景、断言、证据、回归 |

实际安装的是**单个技能的集合**，不是整套套装：`AgentStarterTab` 从动态目录（`GET /api/skills/bundles`）按角色标签匹配推荐技能、取前 6 个预勾选，用户可增减；`defaultBundleKey` 只在角色定义里声明，未被安装流程消费。

## 六、提示词组合顺序

提示词按模块组合，不维护另一份静态副本：经验锚点、角色规则、项目形态识别、技能清单、长期规则写入、自动交付契约、登录账号安全交付、凭据隔离和可选 CDS 操作提示词。

技能清单来自动态官方 catalog，前端不维护第二份技能事实源。

## 七、项目形态适配

| 项目形态 | Agent 默认策略 |
|---|---|
| 静态网页 | 识别静态入口和构建产物，使用最小部署结构 |
| 成熟软件 | 保留现有构建、登录、数据和服务关系，只补 CDS 契约 |
| 开发半成品 | 找到最小启动阻塞，先修到可预览，不冒充业务完成 |
| 多服务或复制集 | 保留拓扑，将扫描、隔离、部署和诊断交给 CDS 能力 |

上手助手不实现项目扫描器。它只告诉 Agent 必须先识别事实，具体执行由 CDS 技能负责。

## 八、预览账号交付

“地址能打开”不等于“用户能验收”。无需登录时明确标注；需要登录时不得读取生产密码，优先使用已有测试账号机制，能够安全创建时创建分支专用、最小权限、可过期的临时账号，并在交付前通过浏览器真实登录。

临时账号只在当前私密对话交付，不进入 Git、文档、PR、日志或截图。无法安全提供时明确阻塞，不得编造密码。

## 九、凭据分层

| 内容 | 保存位置 |
|---|---|
| CDS host、角色、锚点、技能选择 | `.cds/bootstrap.json` |
| 非敏感平台地址 | 可放 `.env`，并加入 `.gitignore` |
| CDS 项目凭据 | `.cds/credentials.json`，权限 `0600` |
| 海鲜市场 Key | 用户级 secrets 或 Keychain |
| 技能地址 | bootstrap manifest 或 CDS API |

CDS 管理凭据、海鲜市场 Key 和已有用户密码不得放进 `.env`。

## 十、前端交互

“接入 Agent”弹窗新增首选“上手助手”页签：经验锚点、角色卡片、可增减技能卡片、默认开启的 CDS 交付开关，以及提示词预览、复制和一键脚本下载。

原有快速初始化、自动接入、手动安装和海鲜市场页签继续保留。

## 十一、harness 安全边界

生成脚本只检查依赖、识别项目级技能目录、下载技能、写入不含密钥的 bootstrap 记录、创建非敏感 `.env` 并确保敏感文件被 Git 忽略。

脚本不申请 CDS 权限、不写长期凭据、不修改 shell profile、不修改用户主目录。授权和扫描仍由 CDS 技能接管。

## 十二、首版验收标准

1. 默认选择“小登 + 产品经理 + 接入 CDS”。
2. 动态读取角色技能并允许取消或增加。
3. 每个技能可独立下载。
4. 可以复制完整启动提示词。
5. 可以下载不含密钥的一键脚本。
6. 提示词覆盖四类项目形态。
7. 提示词强制真实预览地址和登录可用性。
8. 关闭 CDS 后不拼接预览地址。
9. 原有接入流程仍可使用。

## 十三、非目标

首版不重新实现 CDS 项目扫描，不在前端保存 CDS 凭据，不创建生产用户，不实现角色选择的服务端记忆，也不更新 CDS 生产环境。

## 十四、决策卡与角色持久化（2026-08 后续演进，突破首版第 4 条非目标）

首版验收后新增两项能力，第 4 条非目标（角色选择不做服务端记忆）已被取代：

- **决策卡按角色分化**：五个角色不再共用同一套段落文案，各自拥有卡头、前言、编号段落清单、禁止项四层分区；结构从文本契约抽成结构化模型，界面预览与写入 `AGENTS.md` 的文案同源，靠同源守卫防止两者漂移。
- **角色声明落到 CDS**：新增 `GET/PUT /api/projects/:id/agent-profile`，角色改为读写共享 SSOT（`agent-role-store`），上手助手与任务地图读同一个值；未声明角色时任务地图保持原顺序、不冒充「已按某某重排」；角色只在用户点生成时才写入项目，避免完成页切换目标项目时把上一个项目的角色覆盖掉。
- **任务地图按角色排序**：任务清单与分类条按角色排序并标注常用任务/分类，排序对整个地图生效，不只限于当前分类内部。

### 事实入口

- 角色 SSOT：`cds/web/src/lib/agent-role-store.ts`
- `agent-profile` 端点：`cds/src/routes/projects.ts`

## 十五、技能库出口与来源自述（2026-09-01）

上手助手第三步「技能库」原来会在特定条件下被整块条件渲染掉，用户找不到主按钮；返回按钮也压在「已选择 N 项」文案上。改为浮层承载，出口固定为「关闭 / 放弃 / 完成」三个按钮，不再随选择状态消失。

完成页新增「技能来源」就地展开面板，取代此前跳转到接口裸 JSON 的做法。面板由 `GET /api/skills/bundles` 补的来源自述驱动：技能类数、技能总数、本机自带数、需要回源下载数、上游是否已配置——只报告查得到的事实（呼应 `no-rootless-tree.md`：查不到就不编）；面板同时给出分类明细与「按角色筛出 N 个」的说明，解释技能库为何比总数少。缓存可用性判据统一走同一个 `readCache` 函数，避免空文件或错误页被误判成「断网也能装」。

技能库浮层遮住的下层内容置为 `inert`，键盘 Tab 不会落到被遮住的主按钮上；浮层本身补上对话框语义与打开时的焦点收拢。

预览实例的演示数据（分支、定时任务、验收报告）改为按 id 逐条补播，不再让老实例永远停在最初那份固定清单上；演示定时任务全部标记为停用状态，调度器不会真的执行它们、也不会覆盖示例状态本身的一致性。
