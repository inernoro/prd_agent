# 知识库信息高效传递 · 操作与验收指南

> **版本**：v0.1 | **日期**：2026-11-19 | **状态**：目标流程指南草案

**一句话**：用一组资料走完从浏览模板到交付教程的全过程，再核对读者能否独立执行并找到依据。
**谁该读**：第一次制作资料的作者、接收学习材料的同事和验收者。
**读完能做什么**：照六步操作，在生成中补一次关键规则，并逐项核对交付结果。

## 从模板做一次教程

1. **看模板。** 在模板页打开平时要用的类型，比如「团队操作教程」。先看一份完整示例，再看骨架里会安排哪些步骤、判断和练习。确认它适合这次要教的事情。
2. **选资料。** 上传你手里的操作文档，在知识库中再挑需要引用的规则或说明。用下面的演练资料时，上传资料 A，把资料 B 存为验收知识库文档后从中选取。
3. **检查附件并开始。** 在同一个附件区核对两条资料，再移除或补加。提示词可留空。想突出重点时，可写「做成一份新同事能照着操作的教程，讲清 200 条边界、谁逐包确认，以及例外怎么处理」。选择本次要交付的形式，比如网页教程、音频讲解和视频演示，然后开始。
4. **看进度并纠正。** 保持生成页打开，查看正在处理的材料和出现的待确认问题。收到关于 200 条边界和截止时限的提问时，在原任务里回复下面的作者裁定。看到第一版步骤草稿后，在任务仍在运行时主动补一句「请把 199 条和 200 条的对比例子放在操作步骤前」。查看何时应用，刷新后确认两条消息都能找到。
5. **打开中间文件。** 过程中点击已出现的文件，打开实际网页、讲稿或分镜，核对哪些还在生成。完成时从生成页进入结果，检查关键规则是否在已选形式里同步修正。
6. **预览并归档。** 所选产物都就绪后，预览给读者的版本，检查资料出处和访问范围。按用途选网页托管或知识库。用接收者的账号打开实际交付结果，再查一次规则和来源。

## 同一组演练资料

本节使用合成的演练数据。

| 资料 | 内容 |
| --- | --- |
| A · 归档操作说明，上传附件 | 少于 200 条可单包提交。超过 200 条需分包。归档任务必须在首次提交当天 16:00 前关闭。 |
| B · 审核说明，知识库引用 | 执行人准备并提交归档包，审核人确认。归档任务必须在首次提交后的第二个工作日关闭。 |

作者在生成中补充：

> 恰好 200 条也要分包，每包必须少于 200 条。执行人逐包提交，审核人必须逐包明确确认。关闭时限按首次提交当天 16:00 执行。超时须由审核人明确批准并记录原因。

作者回复前，教程应明确 200 条未定义，且两份资料的截止时间冲突。作者回复后，在教程里把这两处标记为作者裁定，链接对应补答，并保留 A、B 原句。手机和桌面都用相同资料，以独立任务复跑。

## 接收者怎么用

- **现在就要做**。打开网页，先读适用条件和下一步动作。遇到 200 条时，展开分包规则，从相同位置找到原始条款和作者裁定。
- **希望先听或看**。从交付件里选音频或视频。通过字幕、讲稿或章节定位到分包和超时两段，点到对应依据。
- **第一次学**。跟着章节操作，再完成检验题。用自己的话说出 199 条和 200 条的处理差异、哪个角色逐包确认、超时如何处理，并指出答案来自哪里。

## 按顺序验收

| 看到的证据 | 需要符合的判断 |
| --- | --- |
| 首屏、模板预览、附件和开始 | 尚无自有资料也能完整预览模板。附件区同时显示 A 与 B；另一次真实运行用空提示词也能启动。模板示例中的事实未混入产物。 |
| 连续生成画面、任务记录和中间预览 | 看得到从开始生成到进入结果的过渡。真实任务经过 OpenDesign 和 Codex。能看流式进展、打开中间文件、补答资料缺口、主动纠正草稿。用修订前后的两版文件核对例子的位置确实改变。 |
| 最终文件、实际播放与教程题 | 199 条可单包，200 条必须分包，每包少于 200 条，审核人逐包明确确认。首次提交当天 16:00 截止，超时取得审核人明确批准并记录原因。实际播放音视频核对这些说法，点击视频的 200 条章节验证选中状态和播放都落在该章，能从对应字幕或讲稿回到依据。 |
| 刷新、执行失败与权限 | 刷新后恢复同一任务和已确认补答。真实失败能看到原因并可安全重试。原无权限及被撤回权限的账号都无法从直接链接或交付件获取受限来源。 |
| 两种归档和版本 | 两个去向用各自入口实测，能打开对应实际产物。另作修订后，仍有权限的账号可以打开初次交付版本并核对原句和作者裁定。 |

桌面和手机各自保留一条从「只看模板」开始的连续证据，标明设备、任务与实际版本。检查每张图和对应动作相符，保留打开模板骨架、开始、流式输出、补答、打开文件及归档后的结果。功能通过之后，分别记录初次接触案例的读者只看原文和使用交付物时的正确率、定位与任务用时、回问次数。另记录作者为整理、生成、补答、校对、重做和交付投入的时间。

产品规则和成功标准见[设计稿](./design.knowledge-base.information-delivery.md)。每一步的当前状态和证据记录在[分阶段验收计划](./plan.knowledge-base.information-delivery.acceptance.md)。
