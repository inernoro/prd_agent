# 网页生成统一走 OpenDesign · 实施与验收看板

> **版本**：v1.0 | **日期**：2026-10-12 | **状态**：实施中

**一句话**：用一张可持续打勾的表推进“网页生成统一走 OpenDesign（无头设计编排器）”，代码完成只代表待验收，只有对应 CDS 视觉验收报告通过后阶段才完成。
**谁该读**：查看进度的产品负责人、负责开发的智能体、负责独立视觉验收的智能体和主智能体。
**读完能做什么**：随时看出当前阶段、已完成项、阻塞、下一步、验收证据和是否真的达到阶段完成标准。

---

## 看板规则

1. `[x]` 只表示该项已经有可复核证据；“代码写完”不能代替运行验收。
2. 每个大阶段分为开发、自测、视觉验收、在线报告四道门；四项全勾后才允许勾选阶段完成。
3. 视觉验收使用独立智能体，按 `acceptance-test-design -> acceptance-scenario-orchestrator -> create-visual-test-to-kb` 执行。
4. 用户可见路径必须从登录后首页点击导航进入，桌面、真实触控移动端和适用主题都要覆盖。
5. 截图与报告草稿只能进入临时目录；正式证据归 CDS 验收中心，并通过 `verify-open`。
6. 验收失败时阶段保持未完成，开发智能体根据报告修复后重新验收；旧报告保持不可变。
7. 主智能体只校准范围、判据和差异，不直接承担开发或视觉签字。

## 阶段 1：单一 OpenDesign 路径

目标：普通用户只表达生成或修改网页，系统统一进入 OpenDesign；服务不可用时不静默直连。

- [x] 生成网页界面移除底层执行器选择。
- [x] 修改网页界面和分享预览修改入口移除底层执行器选择。
- [x] 管理设置不再允许把普通网页任务默认切回直连。
- [x] 服务端成为运行时选择的唯一权威，所有新的网页生成与修改任务统一使用 OpenDesign。
- [x] 旧客户端提交直连模式时按兼容策略收口，不产生新的直连网页任务。
- [x] OpenDesign 不可用或繁忙时给出明确状态，不静默降级。
- [x] 历史任务仍可按原运行时查看、恢复或诊断。
- [x] 容量与排队行为有明确上限和用户反馈，不因单实例忙碌改变执行器。
- [x] 前端、后端和设计执行服务相关自动化测试通过。
- [x] CDS 预览环境部署目标提交且状态可测。
- [x] 桌面端从导航进入生成和修改页面，确认不存在模式选择。
- [x] 真实触控移动端完成入口与生成准备状态验收。
- [x] 负面路径证明 OpenDesign 不可用时没有直连回退。
- [x] CDS 视觉验收报告归档并通过打开验证。
- [x] 阶段 1 完成。

阶段 1 完成门槛：新网页任务的实际运行时全部为 OpenDesign；界面不存在运行时选择；故障时直连回退次数为零。

## 阶段 2：真实过程事件与恢复

目标：把 OpenDesign 已有的真实事件和预览能力接给用户，不编造进度，也不暴露内部敏感细节。

- [x] OpenDesign 真实事件经过白名单、脱敏和稳定阶段码输出。
- [x] 页面展示成果语言，不展示内部命令、路径、工具参数或隐式推理。
- [x] 文件或产物变化能够触发预览刷新，定时轮询只作兜底。
- [x] 首个可见反馈与首次真实预览分别计时。
- [x] 活动任务可以从服务端恢复，不只依赖浏览器本地缓存。
- [x] 慢路径持续有可理解的变化，失败路径保留已获得结果并给出重试动作。
- [x] 服务重启时诚实显示中断，并能用冻结输入重新开始。
- [x] 正常、慢速、失败、恢复四态自动化测试通过。
- [x] 桌面和真实触控移动端视觉验收通过。
- [x] CDS 视觉验收报告归档并通过打开验证。
- [x] 阶段 2 完成。

## 阶段 3：设计简报与品牌上下文

目标：不重造 OpenDesign，而是让它不再猜用户目标、内容结构和品牌规则。

- [x] 设计简报表达目标、受众、核心信息、主行动按钮、章节、视觉意图、响应式和事实要求。
- [x] 设计简报在任务开始时冻结并带版本指纹。
- [x] 品牌包表达 Logo、色板、字体、固定声明、禁止样式、参考范例和版本。
- [x] 品牌包映射到 OpenDesign 设计系统和 token，不复制设计系统。
- [x] 没有品牌包时使用现有个人风格能力作为回退。
- [x] 生成提示遵循先规划、再成型、再检查和修正，不再强化一次写成。
- [x] 固定知识样本的必需事实覆盖率达到 100%，无依据新增事实为零。
- [x] 固定品牌样本的 Logo、主色、字体和固定声明符合品牌包。
- [x] 桌面、移动端和适用主题视觉验收通过。
- [x] CDS 视觉验收报告归档并通过打开验证。
- [x] 阶段 3 完成。

阶段 3 完成门槛：每个结果能追溯到设计简报和品牌包版本；固定样本事实与品牌硬要求全部满足。

## 阶段 4：浏览器视觉质量闭环与指标

目标：在真实渲染结果上发现硬问题，并把问题返回同一 OpenDesign 任务做有限次数修复。

- [x] 隔离执行侧能渲染桌面和真实移动视口并产出质量证据。
- [x] 确定性检查覆盖溢出、裁切、主操作、链接、锚点、导航、表格和对比度。
- [x] 审美软评分与硬门禁分开，避免页面趋同。
- [x] 硬问题能够回到同一 OpenDesign 任务进行定向修复。
- [x] 修复次数有上限，失败时向用户说明结果和恢复动作。
- [x] 保存修复前后问题码、截图、评分和规则版本，不保存隐式推理。
- [x] 记录首次预览、最大静止间隔、恢复、重做、修改、发布或分享等效果指标。
- [ ] 固定样本盲评“无需修改或轻改可用”达到 80%。
- [ ] 生成后立即重做率较基线下降至少 30%。
- [ ] 桌面、真实触控移动端和适用主题视觉验收通过。
- [ ] CDS 视觉验收报告归档并通过打开验证。
- [ ] 阶段 4 完成。

阶段 4 完成门槛：390px 与 1440px 无横向溢出或关键内容裁切；硬问题修复闭环可追溯；效果指标可以判断用户是否愿意使用产物。

## 分工

| 角色 | 职责 | 可更新的内容 | 不可越界 |
|---|---|---|---|
| 开发智能体 | 实现当前阶段、补测试、自测、提交开发结果 | 当前阶段开发项、自测项、进度记录 | 不给视觉验收签通过，不勾阶段完成 |
| 视觉验收智能体 | 独立设计用例、部署预览、真人路径取证、读图、归档报告 | 当前阶段视觉验收项、在线报告项和报告链接 | 不为让验收通过而修改产品代码 |
| 主智能体 | 校准范围、比较开发结果与设计、处理差异、控制阶段切换 | 总览、阻塞、阶段完成项和最终结论 | 不替代开发和独立验收的执行工作 |

## 风险与控制

| 风险 | 控制 |
|---|---|
| OpenDesign 单实例并发有限 | 统一路径前明确排队或扩容；繁忙不能触发直连降级 |
| 多轮生成与视觉检查增加成本 | 先确定性检查，审美评审限次数，记录成本与修复收益 |
| 视觉评分导致模板趋同 | 硬门禁与软评分分离，保留设计系统多样性 |
| 旧客户端仍发送直连模式 | 服务端权威收口并记录弃用调用方 |
| 服务重启无法原会话续跑 | MAP 冻结输入并诚实中断，允许创建新 attempt |
| 上游版本变化破坏事件或技能 | 固定版本、快照测试、升级单独验收 |
