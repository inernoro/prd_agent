# 产品管理智能体版本流程收尾 · 计划

> **版本**：v2.1 | **日期**：2026-11-06 | **状态**：规划中

**一句话**：按当前正式申领与公告后补的规则完成运行验证、历史兼容和状态口径澄清，避免重新引入已经取消的旧门槛。
**谁该读**：负责产品版本流程、历史迁移、状态解释和真实验收的产品、工程与测试人员。
**读完能做什么**：按现行规则安排验证与治理，区分已核实事实、仍有疑点的实现和待决定的产品取舍。

## 目标与当前依据

完成“立项 T、正式 V、历史兼容与公告后补”业务闭环。当前结构见[产品设计](./design.product-agent.md)，行为与实例见[申领规格](./spec.product-agent.version-claims.md)，理由与代价见[变化补录](./pdr.product-agent.002.version-claim-boundary.md)。本计划不再用旧步骤充当现行规则。

2026-11-06 的核对已说明：原计划中“负责人未同意不能发 T”“功能清单与公告先齐全”“旧版本仅只读”的描述不能继续无条件作为当前验收判据。历史资料、当前源码与既有针对性测试分别提供了更新依据；源码存在仍不等于生产已经验证。

## 已核实的现行边界

| 主题 | 当前依据支持的行为 | 验证时不能混淆 |
| --- | --- | --- |
| 立项与发号 | T 保留评审通过门槛；2026-10 资料与当前自动发号实现已取消旧人工审批步骤 | 不依据旧计划自动恢复审批，也不把历史审批人等同业务负责人 |
| 常规正式申领 | 关联同产品有效 T，继承方案资料，保留基础字段、权限、历史对照和防重 | 不允许手填 T 绕过来源；不把 T 的原资料悄悄改成另一份 |
| 功能与公告 | 常规申领不再要求功能清单非空或预先有公告，公告可以后补 | 临时优化的条件不同；简化表单不代表放开所有校验 |
| T/V 关系与编号 | 所查常规路径保护一个来源不重复申领，并按应用维度的占用机制发号 | 不用全局显示排序猜编号归属，不把回退当作回收编号 |
| 版本状态 | 当前 V 创建即写入已上线，需求推进受流程边限制 | 登记状态、需求同步与部署可用不是同一证据 |
| 旧版本 | 新主界面使用 T/V，旧模型和部分关联写入仍保留 | 不能据此宣称旧版只读，也不能在文档任务中删除旧数据或入口 |

## 下一步执行次序

| 阶段与优先级 | 工作 | 责任角色 | 完成条件 |
| --- | --- | --- | --- |
| P1 当前语义 | 明确正式记录、需求状态、部署可用与公告完整度的含义 | 产品负责人及业务专家 | 对正常和公告缺失实例给出一致解释，现行规格与 PDR 同步，不把提议写成已批准 |
| P1 引用与权限 | 复现无效、跨产品、已删除版本引用，以及流转补字段后的实际请求 | 后端、前端与测试维护者 | 验证拒绝发生在服务端且存储无越界写入，已填写关联能真实到达服务端；对应债务有关闭证据 |
| P1 主链路验证 | 在授权隔离数据和登录态中执行申领规格 S01—S09 | 工程与测试维护者 | 核对页面、请求、返回、存储、重复申领和需求状态，不只看接口成功或静态源码 |
| P2 自动推进与恢复 | 覆盖不同流程、缺边、部分失败、重试和中断恢复 | 后端与测试维护者 | 明确哪些需求可跳过，结果与活动可解释，失败不重复发号 |
| P2 历史兼容 | 核对旧版关联、历史 T/V、存档与公告的解释方式 | 数据与业务维护者 | 不猜测历史归属，不因重导覆盖原记录，旧引用可解释且新旧入口兼容 |
| P2 用户任务观察 | 请未参与原讨论的人定位规则、解释实例并完成任务 | 产品负责人 | 记录查找时间、追问与错误的真实基线，决定是否推广，不预设收益 |

角色尚未任命具体个人；本计划表达职责与条件，不代替团队排期承诺。

## 运行与发布证据

正式运行验证必须固定候选版本，使用现有受管验证和发布路径；普通源码断言、页面渲染、服务端集成与真实业务验收分开记录。若后续修改运行逻辑，再按仓库规则完成相应编译、测试与预览，不以本次文档提交替代。

历史导入仍需覆盖预览、重复执行、原始行错误、T/V 关联和旧版引用。真实历史修改必须按具体已授权范围执行；不能为了验证决策方法而操作真实申领、编号或公告。

## 持续跟踪与不在本轮处理的事

已发现冲突、影响与关闭标准只维护在[模块治理清单](./debt.product-agent.md#产品结构与决策治理2026-11-06)。本次完成文档与决策回放，不宣称该清单的运行风险已经修复。

不在本轮建立新的通用审批引擎、万能规则平台或全量历史迁移。是否需要规则版本存储与承诺节点绑定，依[规则历史提议](./pdr.product-agent.001.rule-evolution.md)的真实追溯需求再决定。
