# LLM Gateway 故障隔离与恢复 · 计划

> **版本**：v1.0 | **日期**：2026-08-12 | **状态**：开发中

**一句话**：分五个阶段把“职责单一、故障不扩散、零合成探测恢复、可人工止血”从生产临时处置升级为稳定产品能力。
**谁该读**：安排 MAP 与 LLMGW 开发、测试和上线顺序的负责人。
**读完能做什么**：知道每个阶段由谁交付什么、先后依赖是什么，以及什么证据才能宣布完成。

---

## 一、目标与完成定义

最终状态必须同时满足：

- MAP 查询 AppCallerCode 获准的多个模型池，并把池作为用户可选模型；
- LLMGW 默认只在所选池内调度，跨池代选默认关闭；
- MAP 展示平均耗时、最近 10 次成功率、样本数和风险建议，用户仍可坚持选择；
- 单成员、单 Provider 或单池故障不会关闭 MAP 整体能力；
- Open 成员无需合成付费探测即可进入 HalfOpen 并自动恢复；
- 通知中心、人工止血、回滚和审计始终可用，但不成为数据面依赖；
- 故障矩阵和生产演练证明上述边界，而不是只靠单元测试推断。

任一条缺失时，整体目标不得标记完成。

## 二、阶段计划

| 阶段 | 优先级 | 责任域 | 主要产出 | 完成条件 |
|---|---|---|---|---|
| P0 原则与止血基线 | 已完成基线 | 共同 | 生产恢复模型目录、隔离失败池、被动站内通知、规则与设计基线 | 生产模型选择器恢复多个选项；失败池仍隔离；无付费探测；规则、设计、计划、指南和债务进入索引 |
| P1 AppCaller 多池与严格路由 | 最高 | LLMGW | 获准池集合、默认池、跨池代选开关与候选顺序；默认关闭；结构化路由错误 | 用户选池 A 时，池 A 耗尽也不会落到 B；显式开启后只落到获准候选；未知和越权池 fail-closed |
| P2 MAP 业务关系与指标 | 高 | MAP | AppCaller 池目录、模型卡平均耗时和最近 10 次成功率、风险建议、坚持选择 | 单池故障只改变提示；目录项和页面不消失；指标带样本数与更新时间；用户选择值稳定 |
| P3 池内自愈与人工恢复 | 最高 | LLMGW | Healthy、Degraded、Open、HalfOpen 状态机；真实流量半开；隔离、恢复、临时跨池授权和回滚 | 无合成付费请求；恢复成功自动回池；失败指数退避；所有池不可用时恢复入口仍可操作 |
| P4 通知、演练与发布门禁 | 高 | 共同 | 结构化事件、站内通知深链、故障矩阵、演练手册、生产门禁 | 通知失败不影响请求和恢复；四条链路独立故障演练通过；审计能还原每次切换与恢复 |

P1 与 P3 是阻止再次发生“自己锁死”的核心路径；P2 不得以等待 P3 为由关闭现有模型入口。P4 完成前不能宣称具备完整自动自愈能力。

## 三、阶段目标

### P0 原则与止血基线

已取得的生产事实：

- 生图模型目录已恢复为多个可选项；
- 故障的同名池继续隔离；
- 现有请求可以产生故障和恢复站内通知；
- 止血未创建上游生图请求。

P0 只是恢复可用性和建立方向，不代表多池契约、HalfOpen 和长期恢复入口已经实现。

### P1 AppCaller 多池与严格路由

交付目标：

1. AppCaller 从单一池绑定升级为“获准池集合 + 默认池”。
2. 新增“允许跨池代选”策略，未配置和旧数据迁移后均为关闭。
3. 请求显式池必须属于获准集合；LLMGW 不再从全局池、逻辑目录或 legacy 配置猜测替代模型。
4. 同池成员重试和跨池代选使用不同的日志与错误原因。
5. 临时跨池授权必须支持失效时间，到期自动关闭。

验收门：

- 严格模式、授权模式、未知池、越权池、空池、全池 Open、非幂等结果未知全部有合同测试；
- 旧 AppCaller 迁移后实际默认路由不变；
- 控制台保存前展示影响范围，保存后可一键回滚。

### P2 MAP 业务关系与指标

交付目标：

1. MAP 的模型目录只读取当前 AppCaller 获准池，不读取池成员拼模型列表。
2. LLMGW 返回池健康事实和基于真实请求的近期指标。
3. MAP 保存推荐、排序、业务文案和用户偏好，不回写 LLMGW 健康。
4. 模型卡显示平均耗时、最近 10 次成功率、样本数和更新时间。
5. 风险模型默认给出换池建议，但允许用户确认后坚持选择。

验收门：

- 指标不足、全失败、全成功、混合成功、旧数据和目录暂时不可用均有页面状态；
- 目录读取失败时保留上次成功目录并标记陈旧；
- 一个池失败不会让输入框、画布、历史结果或其他池失效。

### P3 池内自愈与人工恢复

交付目标：

1. 健康状态机区分 Degraded、Open 和 HalfOpen。
2. 冷却、半开放行数和指数退避按成员独立执行，多实例下不能重复放行。
3. 只用真实业务请求作为默认恢复证据；探测型请求必须由人工明确确认费用。
4. 控制台提供隔离、进入半开、切默认池、临时跨池授权、关闭授权和回滚。
5. 自动恢复与通知解耦，通知中心故障时状态机继续运行。

验收门：

- 多实例并发下每个 HalfOpen 窗口只放行规定数量；
- 成功与失败分别收敛到 Healthy 和 Open；
- 用户错误不会推动状态机；
- 全池 Open 时仍能进入恢复页面并执行受审计操作。

### P4 通知、演练与发布门禁

交付目标：

1. 故障事件带 AppCaller、请求池、实际成员、错误分类、首次时间、最近时间和恢复状态。
2. MAP 站内通知聚合同一事故，提供日志、池配置和恢复操作深链。
3. 通知去重不吞恢复消息，预览环境不污染生产通知。
4. 发布门禁执行目录、执行、通知、恢复四条链路的独立故障演练。

验收门：

- Provider 5xx、超时、429、目录服务失败、通知服务失败、MAP 业务配置错误和所有池 Open 均有演练证据；
- 每个故障都能说明影响范围、用户体验、自动动作、人工动作和回滚方式；
- 发布后真实页面与公网入口验证通过。

## 四、依赖与顺序

```text
P0 原则基线
  -> P1 严格路由
      -> P2 MAP 指标与建议
      -> P3 自愈与恢复
          -> P4 演练与发布门禁
```

P2 和 P3 可以并行开发，但都依赖 P1 的稳定池身份。P4 必须在 P2、P3 合并后执行，不能用通知页面已完成代替数据面自愈验收。

## 五、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 旧逻辑模型选择值与池标识不一致 | 用户偏好丢失或选错模型 | 建立显式迁移映射，无法映射时回到 AppCaller 默认池并提示一次 |
| 多池迁移改变现有默认路由 | 生产结果漂移 | 先只写获准集合和现有默认池，开启严格模式前做解析对比 |
| HalfOpen 重放非幂等请求 | 重复计费或重复生成 | 只放行结果可确认的新真实请求；未知结果不进入自动重试 |
| 最近 10 次样本过少 | 指标误导用户 | 同时展示样本数和更新时间，样本不足只给事实不下结论 |
| 通知风暴 | 管理员忽略真正故障 | 按事故聚合、状态变化通知、持续故障节流，恢复消息单独发送 |
| 紧急操作扩大范围 | 一个池故障变成全局变更 | 默认单对象操作，批量动作必须预览范围并要求原因和回滚点 |

## 六、交付与发布纪律

- 每阶段独立提交、独立回滚，不把 P1 到 P4 混成一次不可拆发布；
- 数据迁移先兼容写入，再切读取权威，最后清理旧路径；
- 生产验证优先使用只读解析、真实既有日志和无费用假上游；
- 需要产生供应商费用的测试必须单独列出预算、次数和确认人；
- 每阶段关闭时同步债务台账与本计划状态，不用口头“已完成”代替证据。

## 七、当前实施进度

| 阶段 | 已实现并通过本地验证 | 关闭阶段前仍需完成 |
|---|---|---|
| P1 | AppCaller 获准池集合、默认池、跨池开关；旧单池规范化；严格池授权；默认不跨池；未知选择 fail-closed | 临时跨池授权失效时间；生产迁移、审计取证与回滚演练 |
| P2 | MAP 每池一个业务模型身份；平均耗时、最近 10 次成功率与样本数；不健康池不消失；用户可坚持选择 | 最近成功目录快照、陈旧时间提示、指标更新时间和生产页面验收 |
| P3 | 冷却后真实流量原子领取半开租约；人工恢复只授予半开资格；成功或失败收口租约；默认无合成探测 | 指数退避、多实例并发演练、用户错误不污染健康的端到端证据 |
| P4 | 复用现有故障与恢复站内信聚合；桌面端和移动端均可深链 LLMGW 日志 | 池配置与恢复操作深链、通知故障演练、四链路发布门禁和生产取证 |

本轮本地证据包括：四个核心工程构建通过、严格路由与半开合同测试通过、MAP 池级身份测试通过、故障通知策略测试通过，以及依赖隔离 MongoDB 的全量非集成回归通过。上述证据证明代码可进入部署验证，不等于 P1 至 P4 已完成生产关闭。
