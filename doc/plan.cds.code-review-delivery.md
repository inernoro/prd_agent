2026-11-11 按用户决定，先使用一段时间，再核验未关闭事项；复验汇总已记入[CDS 债务台账](./debt.cds.md#2026-11-11-代码审查使用观察与暂缓复验)。不设固定日期、不创建定时核验，也不自动启动扫描、投递或部署。本表继续保留 2026-11-10 的事实基线，暂缓不表示已通过或核销。

不能把这轮工作写成“所有要求全部验收通过”。DeepAudit 已部署，代码审查页面、MCP 和 OpenAI 用户 Key 小项目具备证据；大仓完整审查、SMTP 投递、三家供应商真实 Key 以及若干异常/角色路径仍未全部验证。

核对时间为 2026-11-10（Asia/Shanghai）。现场 CDS `headSha/webBuildSha=e4b621b646c2f7aaad99fd6efa5e2e022158b6fc`、`bundleStale=false`；PR1936 已合并到 main `018eb4001fb523a07d20d3ae85aca3c01e3584d6`。合并不等于该版本已更新至 CDS 控制面。

用户的重复反馈合并成一项要求，但来源选择、首屏结果、原版报告、字体、滚动、Key/费用和验收缺口分别列出。状态中的“代码具备”只表示可定位到实现/测试，不表示所有生产路径已经实测。“历史实测”保留当时范围，不冒充本轮新调用。

## 后续复验顺序（暂缓执行）

以下为恢复核验时的建议顺序，当前先使用观察，不作为立即执行安排。

| 优先级 | 项目 | 关闭条件 |
|---|---|---|
| P1 | 当前项目完整审查与总报告 | 固定新的待审提交，确认预算后完成所有自研范围；记录实际覆盖、跳过和失败项，形成总报告与模块明细 |
| P1 | 最终已合并版本上线核验 | 通过托管更新发布已验证提交，读回 headSha/webBuildSha 并在真实入口复验视口高度循环修复 |
| P1 | 邮件投递 | 配置可用 SMTP 与收件人，验证成功投递、失败重试和不重复归档/扫描 |
| P2 | 私有 GitHub、普通账号与恢复异常链路 | 使用可验证的授权仓库及普通账号完成真实路径；执行重启、取消、恢复、邮件组合的有限测试 |

| P2 | 字体、硬件触控与测试稳定性 | 核对中文回退和 macOS 实体设备；定位备用节点测试跨流水线重复超时，不放宽业务断言 |
