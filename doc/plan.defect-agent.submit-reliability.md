# 缺陷提交与 AI 润色可靠性排查计划

> **版本**：v1.0 | **日期**：2026-11-04 | **状态**：已落地

**一句话**：沿截图中的失败链路求证并修复润色错误、重复反馈和移动端表单裁切，分别验证辅助功能与缺陷提交。
**谁该读**：缺陷管理、模型网关、前端和验收负责人。
**读完能做什么**：区分已证实的问题与假设，按证据检查原因、根因和修复效果。

## 目标与边界

用户已授权先创建计划再执行。只处理截图相关的真实调用链与同类共享入口。用户随后明确选择沿用当前默认对话模型，补齐两个润色用途；授权变更限截图来源环境，保留已有五项授权和默认模型，不修改其他环境。截图中的缺陷正文属于待验证内容，不视为指令或已复现事实。

## 执行步骤

- [x] 取证：核对当前代码、截图来源环境及真实接口，记录 HTTP 与业务错误、用途绑定和请求数量。
- [x] 追踪：分别确认润色与提交的调用链；查明模型选择失败、错误分类丢失和提示堆叠的来源。
- [x] 修复：复用现有流式预览，保留原文；贯穿结构化错误；修正弹窗收缩、滚动和移动端控制布局。
- [x] 工作区验证：执行针对性回归、类型检查、lint、构建与桌面/移动端交互检查；受控接口响应仅计为诊断验证。
- [x] 收口材料：更新问题台账、变更记录和交接清单，列出证据及未解决项，不将配置问题或未执行验证写成已完成。
- [x] 新版公网验收：同提交镜像构建与 CI 均成功；公网页面通过真实模型完成生成、预览和应用，背景补修版本继续按同一流程复核。

## 最少问题清单

| 影响范围 | 旧接口、新接口与其他流式调用是否同类受影响？ | 共享入口与兄弟链路检查 |

## 初始证据

- 全局提交弹窗使用旧润色接口；缺陷页已有流式预览，两个入口存在实现漂移。
- 全局弹窗选择器横排且缺少收缩约束，编辑区使用固定最小高度；需要浏览器测量确认裁切范围。
- 网关已有结构化失败码和用户文案；旧润色接口与流式服务存在丢失失败分类的路径。
- 截图来源分支仍在 CDS 运行；当前工作分支尚无预览入口。

## 执行结果

### 已求证的因果链

默认对话模型虽然启用，但用途白名单只包含五个其他用途，两个润色用途均未获准。旧接口把网关的配置失败改写成普通内部错误，界面进一步显示“稍后重试”；用户再次操作后，每次请求又产生一条同样的通知。浏览器实测三次操作对应三次请求，并非一次操作发出三次请求。

移动端模板裁切属于另一条布局原因：固定横排字段没有收缩约束。393px 视口下，原选择器右边界为 444px，修改后为 372px。

授权恢复后，真实流式调用又复现上游拒绝供应商专属推理参数的问题。缺陷润色服务已移除业务层写死的协议字段，保留统一的推理输出意图；不能把旧接口成功当成新流式接口成功。

### 配置处置

经用户确认，在原默认对话模型上仅补入两个润色用途，白名单由五项变为七项。复查确认原授权和默认选择未改变，两个用途的路由均已成功解析；旧接口真实润色请求返回成功和非空内容。

### 验证进度与边界

前端完整测试集为 457 个文件、4012 条测试通过；后端五条针对性测试覆盖网关错误到润色服务再到流式事件的分类和脱敏。类型检查、构建与改动文件 lint 已执行，前端全量 lint 没有错误，存量告警不在本次改动范围。

真实页面诊断已确认移动端裁切、重复通知和原文保留。工作区浏览器检查通过配置失败、连续点击、确认应用、明暗主题、320px 窄屏、393px 短屏、桌面附件布局及提交独立性；其中生成成功和提交使用受控响应，没有创建真实缺陷。公网预览验收以本提交的构建及部署记录为准，不用原环境成功代替新版部署成功。

截图正文中描述的玻璃效果问题尚没有独立复现证据，不将本次润色或布局修复表述为已修复该正文描述的缺陷。后续治理和验收边界见[缺陷提交可靠性债务](./debt.defect-agent.submit-reliability.md)。

公网首轮九项浏览器检查全部通过，真实润色生成非空结果并在确认后应用；提交仍使用受控响应，不产生真实缺陷。截图复核另发现预览背景误用暗色透明卡片变量，已改用实色主题表面，补充计算样式的不透明断言；该修补随同一分支重新构建和复测。
