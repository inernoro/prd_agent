# MAP 核心功能验收方法 · 指南

> **版本**：v1.0 | **日期**：2026-10-10 | **状态**：草案（长期执行方法，不含本轮验收结果）

**一句话**：按清单的同一编号，明确真实操作、通过条件、证据、清理和失败后的交接动作。
**谁该读**：领取验收任务的智能体、测试人员与修复负责人。
**读完能做什么**：从正式环境真实页面逐项验收，把结果填回清单，而不是另造一张无法对照的技术表。

先看[核心功能清单](spec.platform.core-business-checklist.md)，再进入下面对应的 F 编号。F 编号是业务评分行，原 caseId 是已有细分用例；二者的对应关系写在每节末尾，不替换原编号。

## 共同执行方法

### 0. 准备与新会话检查

- [ ] 先读本地自动化记忆中的所有未关闭缺陷，保留原 defectId、caseId、修复 ref 和最近证据。
- [ ] 正式目标固定为 `https://map.ebcone.net`；从首页正常导航进入业务。CDS 地址只从 `preview-url` 权威查询取得，缺少 CDS 入口不能取消正式环境独立巡检。
- [ ] 使用独立巡检身份，核对账号启用、租户、权限、已配置授权范围和用量上限。本文不新增目标环境写入、管理配置或发布授权；已有授权不重复索要。
- [ ] 从安全存储加载凭据，不输出密码、密钥、token 或单次票据。检查模型、对象存储、ASR、浏览器和域名；缺项写明阻塞及唯一恢复动作，不能标正常。
- [ ] 为本轮生成 runId，并取得本地互斥锁。所有新增测试资源使用 `stsmk-` 前缀且记录本轮归属；禁止读取或操作真实用户数据。
- [ ] “冷启动”指新浏览器会话、新测试资源和旧测试残留核对，不是重启正式服务、清数据库或关闭真实模型供应。
- [ ] 冻结本轮正式子项、轮换项、CDS 五项子集及按缺陷追加的回归项。任何未登记的新操作先补映射；先记录实际线上版本，不等待某个分支发布。

### 1. 核心执行与效果验证

每节按“进入页面 → 提交固定输入 → 观察过程 → 读取产物 → 刷新回读”执行。自动化可以操作浏览器并辅助读取接口状态，但只调接口、页面能打开、HTTP 200、目录非空、模型 Healthy 都不能替代业务通过。

长任务在两秒内须有可见变化，之后有持续阶段或进度，结束态明确；支持思考时显示思考。用户看到的错误应说明结果与恢复动作，不泄漏底层异常或认证秘密。

### 2. 取证与回填

每个实际执行的原 caseId 记录环境、时间、runId、requestId（如有）、实际部署版本、预期、实际、证据和清理结果；没有 requestId 或版本时说明缺项，不捏造。至少保留操作中与最终状态的证据，截图须说明能证明什么、不能证明什么。

输出按 F 编号填回清单。多个子项共用一个真实任务时可复用产物，但各断言分别留证；轮换项记录本轮所选及未选子项。未执行、阻塞和首次失败后重试成功都不算稳定通过。每个失败最多一次确定性重试，保留首轮失败证据与 `flaky`。

指定用例筛选使用原 caseId，不把 F 编号当作执行器已有用例。冻结计划后逐项回读实际命中的编号，漏选按测试缺陷处理。网页托管的 WEB-001 至 WEB-007 每轮全部覆盖，按 F24 至 F30 操作，清理放最后。

### 3. 历史回归

按[永久回归台账](../.claude/skills/stable-smoke/reference/regression-ledger.md)带入 active 项和本轮未关闭缺陷，不把本文件列出的典型问题当成全部历史。正式环境只跑对应安全变体，不注入供应商故障、限流耗尽或过期租约；危险时序用隔离夹具复现，不能据夹具通过填写正式通过。

出现新问题时分类为产品、配置、环境、测试缺陷或验收债务；根因未确认写“未知”。绑定原 F 编号和原 caseId，追加能稳定变红的 REG，不通过放宽断言消除问题。修复必须给可定位的分支与 commit/PR；定向通过只进入待全量回归，满足原失败、边界、相关回归、视觉证据、清理和无新增同域问题后才能验证关闭。

### 4. 撤销与清理

仅撤销本轮创建的资源和分享，删除后再查询列表、资源状态和本轮台账，确认无残留。清理失败单列 P1 并停止相关写入；不得顺手删除上一轮无法确认归属的资源或真实数据。本例行任务不演练正式发布或服务回滚。

以上共性步骤对应 CORE-004、CORE-005、CORE-006、COMMON-003、COMMON-004。COMMON-003 在例行巡检中用于记录和回读当前线上版本；发布与回滚演练属于另外的任务和授权范围。

## F01

**功能：巡检身份登录、权限隔离。** 负责人：平台身份。

- [ ] 从登录入口使用专用合成身份进入首页，刷新后仍能访问应有业务；一次性票据重复消费须失败，短会话不可擅自延长。
- [ ] 核对账号应有权限，使用另一专用隔离身份验证跨工作区访问被拒绝；不要枚举真实用户资源。

**通过、证据与清理**：首页、权限回读和隔离拒绝三者一致；保存不含票据的页面与状态证据，票据消费与短会话按策略结束。

**失败交接**：身份无法登录或缺租户权限时写“监控未执行”，交平台身份负责人恢复该专用账号，不换通用管理员。非会话鉴权失败不得把当前用户踢出。

**原用例**：CORE-002、CORE-003、CORE-007、CORE-009；重点回归 REG-auth-diagnosis-001、REG-auth-synthetic-001、REG-auth-identity-permissions-001。

## F02

**功能：从首页找到并进入业务。** 负责人：前端导航。

- [ ] 登录后逐个点击清单对应业务入口，记录真实面包屑；桌面与真实触控移动端各验证一次，不用地址栏直达代替导航。
- [ ] 检查入口权限、页面主操作、失败图片及遮挡。专用账号教程点击“我已学会”后刷新回读，不能只看弹窗关闭。

**通过、证据与清理**：正常导航能到达可操作页面，静态资源完整；真实触控入口与教程回读各留证，只有本轮专用账号教程状态被改变。

**失败交接**：缺入口交前端导航；页面资源失败交发布与静态资源负责人；教程刷新丢状态交教程负责人。入口通过不能替代该模块产物通过。

**原用例**：CORE-001、CORE-003、CORE-008；重点回归 REG-avatar-asset-001、REG-auth-health-entry-001、REG-tutorial-progress-001。

## F03

**功能：创建知识库与保存内容。** 负责人：知识库。

- [ ] 首页 → 知识库 → 我的空间，创建本轮 `stsmk-` 知识库，新增含唯一正文标记的条目并保存。
- [ ] 刷新后核对标题、正文、知识库归属和身份；第二个专用身份不能读取该私有内容。

**通过、证据与清理**：条目可持续回读且未错放到其他空间；保留创建和隔离状态，后续 F04 使用完后删除条目与库并回读。

**失败交接**：入口缺失和归属错误分开记录，交知识库负责人，附本轮库与条目的脱敏身份及原步骤。

**原用例**：COMMON-001、COMMON-002；重点回归 REG-document-store-action-001。

## F04

**功能：已保存内容刷新后仍可读。** 负责人：知识库。

- [ ] 对 F03 及本轮录音、文件、短视频所保存的条目，刷新、离开页面再进入，打开同一条目。
- [ ] 核对唯一正文标记、标题、内容及归属，不通过创建新的条目“找回”旧内容。

**通过、证据与清理**：重开前后身份与内容一致；保留前后回读证据，清理原库、关联条目与附件并确认无残留。

**失败交接**：明确是哪类内容丢失或错归属，交该业务与知识库负责人；不能把入口可见当作正文已保存。

**原用例**：COMMON-001、COMMON-002、COMMON-004。

## F05

**功能：实时录音转笔记。** 负责人：文档空间与语音转写。

- [ ] 首页 → 知识库 → 我的空间 → 新增 → 录音转笔记；允许专用麦克风，读固定短句“白桃验收，今天测试录音转笔记”，记录计时或波形。
- [ ] 本轮选测暂停后继续；结束录音，观察上传、转录、保存阶段，打开原文并刷新。

**通过、证据与清理**：原文非空且含固定短句的关键内容，暂停不丢前后内容，重复完成不生成重复条目；留录音、阶段和原文证据，删除录音、条目及临时分片并回读。

**失败交接**：设备不可用按环境阻塞；无法转写时交语音负责人并附实际调用与额度状态，原文为空不得因任务完成而通过。静音、断网夹具只用于授权隔离复验。

**原用例**：REC-001、REC-002、REC-003、REC-006、REC-009、REC-010、REC-012；重点回归 REG-asr-routing-001。

## F06

**功能：已有音频上传转笔记。** 负责人：文档空间与语音转写。

- [ ] 在录音入口选择上传已有音频，使用固定短音频，预先登记时长与预期关键句；不读取真实用户录音。
- [ ] 观察上传和转录，保存后重开条目，核对原文；选测主动整理时，原文不能被整理结果覆盖。

**通过、证据与清理**：文本对应音频而非固定占位内容，原文持久保存；留进度与原文证据，删除音频、条目和派生资源并回读。

**失败交接**：上传与 ASR 失败分开记录；不支持录音时应有上传兜底，交相应负责人恢复原路径。

**原用例**：REC-007、REC-008、REC-011、REC-012；重点回归 REG-asr-routing-001。

## F07

**功能：录音后台继续与中断恢复。** 负责人：文档空间。

- [ ] 使用本轮录音任务，转录期间关闭面板，重新打开并核对任务身份；再通过正常刷新或路由离开检查恢复入口。
- [ ] 若主任务已完成而无法取到执行中状态，单列缺失阶段；不能凭完成截图声称后台继续已验证。

**通过、证据与清理**：任务和原文属于同一记录，恢复不生成重复条目；留前后身份、状态证据，删除关联资源并回读。

**失败交接**：注明关闭、刷新还是路由离开导致丢失；交文档空间负责人，不用另一次录音成功代替恢复通过。

**原用例**：REC-004、REC-005、REC-010、REC-012、CORE-004。

## F08

**功能：上传文档并得到可读内容。** 负责人：文档解析。

- [ ] 首页 → 知识库 → 我的空间 → 新增 → 上传与导入 → 上传文件。每轮选择两种最小格式，轮换覆盖 PDF、DOCX、XLSX、PPTX、TXT；至少一个中文文件名。
- [ ] 样本预置唯一标题、正文标记或表格单元格；观察上传与解析，打开结果并刷新。轮换验证取消、重试和重复上传，不让状态或重复条目悬空。

**通过、证据与清理**：两种格式各有可读结果，基准内容一致、文件名正常；留每种格式的产物及回读，删除条目、原件和中间文件并回读。正式仅验证零字节上传前拦截，不主动上传损坏文件。

**失败交接**：注明格式、输入基准与缺失内容；交解析负责人。只有空条目或上传成功不算通过，损坏夹具只能在授权隔离范围验证。

**原用例**：FILE-001、FILE-002、FILE-003、FILE-004、FILE-005、FILE-006、FILE-007、FILE-008、FILE-010；重点回归 REG-file-001。

## F09

**功能：下载原件。** 负责人：文档空间与对象存储。

- [ ] 在 F08 已生成条目中点击下载原件，实际读取下载字节，核对原文件名、类型、长度和内容哈希。

**通过、证据与清理**：下载的是同一原件而非错误页；保存下载断言与条目入口证据，完成后按 F08 清理并回读。

**失败交接**：注明按钮是否无响应、地址是否失效或字节是否错误；交下载或对象存储负责人，不把链接出现当作下载成功。

**原用例**：FILE-009、FILE-010。

## F10

**功能：上传短视频并转写。** 负责人：视频解析与语音转写。

- [ ] 知识库 → 我的空间 → 新增 → 上传与导入 → 解析短视频，上传固定最短视频，预先记录时长、对白和是否有字幕。
- [ ] 观察上传、音轨抽取、转写和时间轴，打开字幕或原文；刷新回读，本轮选测取消时状态必须收敛。

**通过、证据与清理**：转写对应视频、时间轴未超出媒体时长；留阶段与时间轴证据，删除视频、派生音轨和条目并回读。

**失败交接**：区分上传、抽音轨和 ASR 哪段停住；交对应负责人，无字幕样本必须进入真实转写而非返回空成功。

**原用例**：PARSE-001、PARSE-005、PARSE-006、PARSE-007、PARSE-008。

## F11

**功能：通过公开视频链接解析。** 负责人：视频链接解析。

- [ ] 同一解析入口粘贴固定、合法且可公开访问的链接，核对来源标题、媒体和字幕或真实转写。
- [ ] 输入“这不是链接”，应在创建任务前说明支持范围与重新输入动作；自然遇到私有或失效链接时，应区分不可访问与解析失败。

**通过、证据与清理**：合法链接产生匹配结果，非法文字无任务残留；留成功产物和前置拒绝证据，清理视频、音轨和条目并回读。

**失败交接**：保留链接来源类型和用户提示，交解析负责人；外部站点不可用写依赖阻塞，不自行猜测产品根因。

**原用例**：PARSE-002、PARSE-003、PARSE-004、PARSE-007、PARSE-008；重点回归 REG-short-video-input-001。

## F12

**功能：从文字生成成片。** 负责人：视频创作。

- [ ] 首页 → 视频创作，新建本轮项目，输入固定两镜头短脚本；从脚本进入分镜、关键帧和最短时长成片，使用已配置最低成本且业务支持的档位。
- [ ] 观察各阶段，核对镜头顺序、时长、提示词和关键帧；实际播放或解码成片，检查时长和音视频轨是否符合所选配置。

**通过、证据与清理**：不是空项目或只有脚本，必须得到可播放、时长大于零的成片；留阶段与播放证据，删除项目、关键帧、成片及任务并回读。

**失败交接**：精确指出失败镜头或阶段；交视频负责人。正式不主动取消计费任务或注入部分失败，额度不足写监控未完成。

**原用例**：VIDEO-001、VIDEO-002、VIDEO-003、VIDEO-004、VIDEO-005、VIDEO-006、VIDEO-007、VIDEO-010。

## F13

**功能：视频刷新恢复与下载成片。** 负责人：视频创作与下载链路。

- [ ] 在 F12 长任务执行中刷新，重开同一项目确认仍是原任务；完成后从页面下载成片，读取字节并解码播放。

**通过、证据与清理**：刷新不丢任务，下载不是需要上游鉴权的错误页；留前后任务与下载播放证据，按 F12 清理并回读。

**失败交接**：只有完成态而无执行中恢复证据时单列未测；下载鉴权失败按原缺陷复现，交视频下载负责人。

**原用例**：VIDEO-004、VIDEO-007、VIDEO-008、VIDEO-009、VIDEO-010；重点回归 REG-video-001。

## F14

**功能：文学创作、保存与刷新回读。** 负责人：文学创作。

- [ ] 首页 → 文学创作 → 新建作品，输入固定短主题，使用页面配置的默认模型生成内容；观察流式增长并保存。
- [ ] 刷新、重开，核对正文全文、开头、结尾和版本。正式长文边界使用 4,096 字固定小样本；64,000 字专项只在隔离复验中运行。

**通过、证据与清理**：生成过程可见，保存后全文完全一致，无静默截断；在真实触控移动端检查输入、键盘和保存无遮挡。留生成与回读证据，删除作品和配图并回读。

**失败交接**：区分流式生成、保存或回读失败；交文学负责人，不能用短文成功关闭长文截断问题。

**原用例**：LIT-001、LIT-002、LIT-005、LIT-007、LIT-008、LIT-009、LIT-010。

## F15

**功能：停止续写、改写与扩写。** 负责人：文学创作。

- [ ] 轮次开始时从停止续写、改写、扩写中确定本轮子项，在 F14 本轮作品上操作；记录选区前后正文。
- [ ] 停止后内容不再增长，续写接在正确位置；改写或扩写只影响选区，未选正文逐字不变。

**通过、证据与清理**：所选子项符合各自断言，未选项明确列为未测；留操作前后与选区证据，按 F14 清理并回读。

**失败交接**：附原选区、预期边界和实际被覆盖范围，交文学编辑负责人；不能把重新生成全文当作改写恢复。

**原用例**：LIT-003、LIT-004、LIT-010。

## F16

**功能：为文章生成并插入配图。** 负责人：文学创作与图片生成。

- [ ] 在本轮作品中选择文章配图，以最低受支持档生成一张图片，插入约定段落后保存并刷新。
