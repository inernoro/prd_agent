# CBD 平台发布屏障与回滚准备 · 指南

> **版本**：v1.0 | **日期**：2026-10-16 | **状态**：事务内核及隔离验证，尚不可用于共享平台激活

**一句话**：平台发布先封闭准入、等待真实执行结束，再切换独立运行包；失败恢复旧包，无法确认时保持维护状态。
**谁该读**：共享 CBD 平台的系统所有者、发布维护者和 PR 审查者。
**读完能做什么**：区分已实现的保护与真实宿主适配缺口，提供最小只读信息，安排后续首次安装验证。

## 当前能用什么

实际平台源码为 `inernoro/prd_agent`。PR #1717 集成生命周期、产物和阶段诊断、依赖失败阻断，以及失败日志的运行身份核验。本轮继续增加平台发布屏障和持久化事务内核。

屏障有唯一持有者，拒绝迟到的新任务，不因时间流逝自动开放。真实分支协调器与生产发布服务已提供参与者：被取消资格但尚未退出的执行、准备读取、待重放和续接均不能被当作空闲；发布服务等待真实 Promise 和 SSH 返回。分支协调器目前只允许完全空闲时取得维护资格，忙时拒绝维护，不强行清空待办。

事务在独立维护进程中运行，要求预先准备完整候选与当前运行包的可信校验回执。校验包括文件路径、内容和权限，拒绝缺入口、符号链接、硬链接和非普通文件；只允许编译产物和运行依赖，状态、凭据与业务目录即使校验和正确也拒绝进入运行包。换盘前再次核对原进程身份及两份运行包，持久化阶段后才停止本事务拥有的控制面进程；原包不会在启动候选前删除。

候选只有在实际进程代际、加载版本、运行包、页面及入口资源、应用保持指纹全部通过后才完成并解除屏障。启动或验真失败会恢复旧包并重新验真。回滚成功仍保留原发布失败；回滚失败、落盘未结束或监督器回执不明时保留维护锁。另一控制器只能取得监督器的独占恢复资格后接续，不能靠锁龄或旧 PID 不存在自动抢占。

这些能力目前通过隔离测试调用，**没有新增线上激活 API、自动发布、SSH 命令或默认监督器适配器**。现有受保护自更新与强制同步仍在任何换盘前明确拒绝。原版本重启的局部排空也不能替代完整发布事务。不得为了发布本补丁而省略排空参数。

## 为什么还不能线上激活

七类入口必须全部受控：HTTP 与 webhook、分支操作、部署执行器、生产发布、定时任务与内部重放、状态写入、Forwarder 交接。事务要求适配器提供全部覆盖并持续持闸，但声明了名称不等于实际接线完成。当前只有分支协调器和发布服务具有具体参与者；其余入口、远端执行状态及首次安装的外部监督器仍需实现和宿主验证。

线上旧进程不会因为磁盘上出现新代码而具有新屏障；旧更新接口也不能作为首次安装入口。事务使用专用运行包目录，不直接修改现有 checkout。当前编译包不是已验证的线上回退包：从旧提交重新编译不能证明与实际加载的后端、前端、Node 和依赖一致。

APP-06 验收期间不激活、不重启、不代部署。平台修复不修改接入项目代码、Profile 或四库，也不恢复暂停的 HMR 目标。这些约束不因 CI 通过或隔离回滚通过而解除。

## 系统所有者最少提供什么

可以提供一份只读导出，不必开放新登录；若已有授权维护通道，提供 SSH 别名及身份选择方式即可，不在聊天或 PR 中发送密码、私钥和环境变量全文。

| 信息组 | 最小内容 | 用途 |
|---|---|---|
| 控制面托管 | master、Forwarder 的托管方式与服务名，MainPID、启动时间、启动命令、工作目录；停止信号、停止超时、KillMode 或等价子进程范围 | 实现只操作控制面的适配器，避免连带终止应用或其他任务 |
| 真实运行与回退 | 实际加载的完整提交、后端与前端路径及校验值，Node/依赖版本，状态目录；当前运行包的只读备份位置和校验值 | 校验原身份，划分只读业务状态与可切换代码，准备可运行回退包 |
| 维护通道 | 已授权的只读通道或上述导出文件位置 | 获取前两组事实；不是发布授权，也不要求重复提供凭据 |

全入口接线、隔离测试、事务恢复和探针适配是平台维护者的工程工作，不要求系统所有者编写补丁。APP-06 所属任务确认验收结束，以及后续明确的维护窗口授权，是未来激活条件，不是当前只读取证的前提。

若继续追溯历史阶段超时，另需同一采样时刻的宿主 `MemAvailable`、数值化资源预算、daemon 采样新鲜度、对应预约与不可变容器身份。它们用于容量归因，不可用当前空闲快照替代历史证据，也不需要读取四库数据。

## 验证范围与交接

常态回归覆盖：完整性拒绝、未知与迟到任务、排空及落盘失败、进程身份漂移、停止/换盘/启动/页面验真失败、旧包篡改、回滚失败保持封闭、终态开闸失败和重复恢复。控制器在关键阶段直接退出后，由另一个控制器根据实际文件和日志恢复，避免只测试正常 catch 路径。

独立 Node 进程监听随机 loopback 端口，验证实际 API、HTML 与入口资源；注入候选入口资源混版后，恢复旧页面并核对恢复进程代际。此验证不访问共享平台、Docker 或应用数据，不能称为线上页面验收或宿主首次安装演练。

现有远端发布路径保持默认开放，新的维护参与者只有取得明确发布资格时才关闭；正常发布、回滚、预检与 SSH 生命周期仍须通过既有回归。共享平台的实际托管、完整入口接线与可用性不能由这些测试替代。

后续顺序：取得上述只读事实，完成具体宿主适配与剩余入口接线，在独立同构环境证明首次安装、进程中断恢复和应用保持，等待验收冻结解除及明确授权，最后才考虑共享平台激活。各阶段不能跳过。
