# 平台业务幂等、执行租约与取消撤销 · 阶段 2 计划

> **日期**：2026-10-15 | **状态**：按用户授权实施中 | **基础**：阶段 1 任务许可、来源与统一模型出口。

**一句话**：同一业务意图只能有一个有效执行者，失联、失效或被取消的执行者不能继续获得发送和任务提交权。
**谁该读**：平台架构、任务业务、网关、身份、质量与运维负责人。
**读完能做什么**：掌握阶段 2 的统一边界、恢复取舍和验收标准，按证据完成预览交付与后续推广。

## 目标与不变量

阶段 1 能限制一个许可的总调用次数，但两个合法请求仍可能各拿一份许可处理同一业务；取消业务任务也不一定撤销网关授权。本阶段把业务意图、执行领取、续期、失效代次和取消事实统一保存在平台执行账本。

同一租户、业务操作、业务对象或周期、明确提交意图使用稳定身份。重复投递复用已有结果或明确提示已有任务，不启动第二次付费执行；同一幂等身份不能用于不同参数。身份不包含机器、实例或提交版本。调度以既有具体任务和周期识别，用户的新一次明确操作保持独立，不能仅凭提示词相同就永久合并。

平台默认要求每个付费执行有有效租约；新业务漏写领取、来源或租约保护时由统一出口拒绝。业务队列和本地运行状态继续服务用户观察，不能单独授予发送权。

## 执行与恢复原则

每次领取都获得递增的执行代次。续期必须仍持有当前代次且原租约未过期，过期执行者不能通过迟到心跳恢复身份。所有实例依照同一存储判据竞争，网关在实际发送前重新核对，不能只在 HTTP 入口检查一次。

未产生外部调用的失联任务可以安全竞争接管；已有外部调用而业务完成状态无法确认时停止自动重跑，明确要求核对已有结果后重新提交。这样避免用一次貌似成功的重试产生第二份费用。正常长任务持续续期，刷新页面或客户端被动断开不撤销后台任务。

任务终态与执行者代次关联，旧执行者不能把平台账本从已取消或新代次覆盖回成功。既有业务产物仍遵循各自的权限、版本与发布合同，不声称仅靠一条租约能回滚已经发生的外部副作用。

## 取消与授权

取消沿原有访问权限核验，由平台先登记不可逆的本次执行撤销，再同步业务取消状态；返回取消成功后不再批准该范围的新发送。取消范围使用已登记的任务关系，不把业务用户 ID 当作取消凭据，也不能随意扩大到其它独立操作。

SDK 短期凭据绑定原父任务及当前租约代次；原凭据即使还有次数，也不能在取消、租约过期或执行者换代后继续使用。账号禁用和触发凭据撤销同样纳入当前授权有效性核验。已经发到供应商的调用不能承诺撤回，其结果和未知费用保留给后续结算。

## 验收标准

| 场景 | 通过标准 |
|---|---|
| 正常用户新操作 | 产生预期结果；两次明确新意图互不误合并，模型选择保留 |
| 重复提交与多实例 | 同一意图和参数不启动第二次执行；换实例或部署提交不获得新业务身份 |
| 幂等身份冲突 | 相同身份、不同参数拒绝，不误返回其它任务或用户结果 |
| 续期与失联 | 正常续期有效；迟到心跳不能复活；未知外部结果停止自动重跑 |
| 旧执行者 | 新代次建立或取消后，旧发送及平台终态提交均被拒绝 |
| 取消与短期凭据 | 原有 ACL 保留；取消确认后旧许可、租约和 SDK 短凭据不再获准新发送 |
| 新业务遗漏 | 未登记身份、没有有效租约或新增漏守卫付费端点，上游发送数为零 |
| 故障与普通操作 | 治理不可用时付费停止，普通创建、上传、只读和缓存不被扩大阻断 |

并发、过期和故障先以真实隔离存储及受控发送器证明，不在预览制造高频供应商消费。最终必须从真实预览正常入口取得产物，再以公开 API 与持久证据核对重复和撤销；容器健康不能代替业务通过。

本轮覆盖 MAP 任务准入、持久执行、原有取消入口、网关与 SDK 授权。不新增业务页面或导航，不发布生产；CDS 临时预览按用户授权自行处理，重要全局配置另行说明。

金额预占、供应商账单、未知费用对账与动态告警仍按后续阶段推进。网络隔离和工作负载签名、旧实例推广、既存对话页面与流式审计缺口继续由平台债务台账追踪；不能以放松租约、自动补授权或厂商长期密钥回退消除验收错误。
