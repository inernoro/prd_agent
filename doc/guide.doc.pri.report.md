# 报告文档原则：说明某一时间范围实际发生了什么 · 指南

> **版本**：v1.1 | **日期**：2026-11-09 | **状态**：已落地

**一句话**：将特定时间与范围内的结果、证据和未确定事项分开呈现，让读者能判断真实进展及下一步行动。
**谁该读**：编写周报、汇报交付结果、查看验收与运行事实的产品、工程和管理人员。
**读完能做什么**：选择报告的正确存放位置，区分事实与建议，并避免把历史快照当成当前承诺。

## 作用与使用时机

`report.*.md` 回答“在什么时间范围发生了什么”。报告是有时间边界的事实快照，不是持续有效的产品规格。

## 最少写什么

时间与范围、业务结果、证据来源、验证边界、问题和建议行动。未测试写未测试，未上线写未上线；不能用流程执行完毕代替用户任务完成。

## 如何维护与存放

本项目 `doc/` 中新增报告仅使用周报 `report.YYYY-WNN.md`。验收、审计、运行和评测报告按[命名规则](./rule.doc.naming.md)进入既有知识库；被引用的存量报告按原契约保留。

历史事实若需纠正，标明更正依据和日期，不能悄悄改成后来希望发生的事实。长期结论回写对应规格、设计、规则或债务。

## 与其他前缀的边界

报告提供决策输入，不自动形成 [ADR](./guide.doc.pri.adr.md) 或 [PDR](./guide.doc.pri.pdr.md)。报告里的建议也不等于已批准的[计划](./guide.doc.pri.plan.md)。
