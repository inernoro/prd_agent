# 周报管理 Agent · 月报 · 设计

> **版本**：v1.0 | **日期**：2026-10-15 | **状态**：已落地

> **appKey**：`report-agent`

**一句话**：在周报基础上加一份固定四章、全部手写的月报，第一章可以直接勾选本月周报，互动与周报完全一致。
**谁该读**：周报智能体的产品与工程师，以及要配置团队可见性的团队管理员。
**读完能做什么**：说清月报的四章结构、可见性规则、与周报共用的部分，以及验收方式。

## 一、管理摘要

周报回答「这周做了什么」，管理者还需要一份按月回看的材料：本月成果、遇到的问题、对同事的认可、对组织的建议。月报给每个团队成员按月写一份，负责人按月看。

本期**不接入 AI**。月报的价值在于作者本人的判断与表态（尤其是第三、四章），由模型代写既不可信也没有意义；第一章通过「勾选本月周报」复用已有内容，已经足够减负。

## 二、四章结构

| 章 | 标题 | 必填 | 内容 |
|---|---|---|---|
| 1 | 本月工作成果 | 关联周报与手写文字至少一项 | 手动勾选要关联的周报（存快照，周报被删后显示「已删除」）+ 手写补充 |
| 2 | 问题与对策 | 选填 | 手写 |
| 3 | 本月印象最深刻的三个伙伴 | 选填，最多 3 位 | 手写名字（不要求是系统用户）+ 多行理由；写了理由就要写名字。早期按用户选人存下的数据回退显示原来的姓名，不需要迁移 |
| 4 | 对上级/团队/公司的建议 | 选填 | 手写 |

章节标题与提交校验都由后端给出，前端只放引导文案；编辑页的「提交前还差」直接展示后端算出的未完成项。

**周归属规则**：一周归属它的周四所在的月份（ISO 惯例），每一周恰好属于一个月。这条规则只决定「关联周报」选择框的默认分组，用户可以勾选自己在本团队的任何一份已提交周报。草稿周报不能被关联，避免负责人点开看到半成品。

## 三、数据怎么流动

- 新集合 `report_monthly_reports`，一人一团队一个月一份（唯一索引由 DBA 手动创建；创建接口先查后建，并发重复由唯一索引兜底返回已有那份）。
- 状态：草稿 → 已提交 → 已查看（负责人或副负责人首次打开时自动翻面）。不支持退回；提交后作者仍可修改，修改留下 `edited` 记录。
- **互动与周报共用**：评论、点赞、浏览记录直接写入 `report_comments` / `report_likes` / `report_view_events`，按 ReportId 关联（周报与月报的 Id 都是 Guid，不会冲突）。读写逻辑收在一个共享服务里，周报与月报两个入口都调用它。删除月报草稿时一并清理这三张表里它的数据。
- 评论的 `SectionIndex` 0–3 对应四章，支持段落评论、划词评论、回复、带图、修改删除。

## 四、可见性

团队设置里新增「月报可见性」，与周报独立（第三章是对同事的评价，团队可能希望周报公开、月报只给负责人）。老团队无此字段时视为「团队成员可互相查看」，不需要迁移。

| 访问者 | 草稿 | 已提交 · 全员可见 | 已提交 · 仅负责人 |
|---|---|---|---|
| 作者 | 可看 | 可看 | 可看 |
| 负责人 / 副负责人 | 不可看 | 可看 | 可看 |
| 普通组员 | 不可看 | 可看 | 不可看 |
| 「查看全部」权限 | 不可看 | 可看 | 可看 |
| 其他人 | 不可看 | 不可看 | 不可看 |

可见性只有一个判定源，查看、评论、点赞、浏览全部走它。同一处顺带修正了周报的一个缺口：周报详情遵守「仅负责人可查看」，但评论、点赞、浏览接口原先只判断「是否团队成员」，组员能读到别人周报下的评论与点赞名单；现在周报互动也走同一个判定源。

## 五、负责人视图与通知

- 「月报」标签页里，负责人和副负责人可以切到「团队月报」，版式与周报「团队」页一致：左侧月导航（年 / 月两级，展开某月列出已提交成员），右侧「团队月报列表」带「团队人数 / 已提交 / 待提交」，悬停「待提交」看名单（正在写 / 未开始）；点成员或列表行在右侧直接阅读。
- 负责人与请假成员免交，不计入待提交；他们交了照样计入已提交。草稿只有作者可见，团队视图里只显示「正在写」。
- 提交前的月报可以修改，也可以在「我的月报」卡片或编辑页删除；已提交的不能删除。
- 成员提交月报时通知团队负责人与副负责人；别人评论了月报时通知作者。通知归在「月报」来源下，点击直接打开那份月报（周报通知目前只能跳到周报首页）。通知发送失败只记日志，不影响提交和评论本身。

## 六、取舍与已知边界

- 不做 AI 生成、月末提醒、正文插图、导出 Markdown、对外分享链接（记在 [debt.report-agent.md](./debt.report-agent.md)）。
- 「设为默认登录页」的偏好暂不包含月报标签。
- 首页「继续上次」不记录月报的打开。

## 七、验收标准

1. 「周报智能体 → 月报」标签可以写本月月报：关联 2 份周报、补充文字、手写伙伴名字与多行理由（可不写）、提交；提交前可在卡片上删除草稿。
2. 详情页点击关联周报能打开对应周报；负责人打开后状态变为「负责人已查看」。
3. 组员可以点赞、段落评论、划词评论、回复、带图评论，作者能看到浏览记录。
4. 团队管理员把月报可见性改成「仅负责人可查看」后，组员打开月报被拒并看到原因。
5. 周报详情页的评论与点赞照常工作。
6. 负责人在「团队月报」里能看到本月提交情况，并收到「收到新月报」通知，点击直达那份月报。
