# prd-agent 稳定冒烟视觉覆盖 · 验收债务台账

> **版本**：v1.0 | **日期**：2026-10-08 | **状态**：开发中

**一句话**：把 148 个视觉验收位的代码接线、真实线上证据和最终报告门禁分开记账。
**谁该读**：维护稳定冒烟、视觉取证、CDS 预览和验收报告的人。
**读完能做什么**：知道哪些模块已有能变红的接线守卫，哪些仍缺固定版本的真人浏览器证据。

## 验收方式

范围说明：下述148槽位是显式full专项，不是每48小时routine的前置。routine以正式安全集合为主，CDS仅五个核心及有来源的复验，核心视觉14位；记录现有部署版本，不要求先发布巡检工具分支。

每个模块只有同时满足以下三层，才能从“代码已接线”升级为“线上验收通过”：

1. 每个计划槽位都有唯一的真实业务步骤，源码守卫在缺少任一槽位或关键顺序时变红。
2. 固定 commit 的 CDS 环境用真人浏览器完成输入、提交、进度、结果、失败恢复、移动端和清理，并生成不重复截图。
3. 148 张证据通过视觉门禁，报告归档到验收中心后通过在线打开、正文和内部链接验证。

## 当前结论

2026-10-15 通知聚合补充：REG-stsmk-notify-aggregate-001 以136条异常映射旧红新绿约束同轮只返回一个固定汇总身份，已接入每轮通知证据回归。原始逐项执行账本不删减；历史已投递136条定向通知保留事实，不使用全局处理清理。实际汇总事件和收件验真仍未完成，DEF-STSMK-NOTIFY-002保持未关闭。

2026-10-15 补充：基础登录不得混入头像与受限账号创建。REG-stsmk-account-scope-001 已通过旧红新绿守住双环境独立登录和写入前范围检查；临时用户名不得以 stsmk_ 替代本轮 stsmk- 授权前缀。原头像与跨用户隔离专项在取得预置独立身份前仍未完成，禁止以单测通过关闭业务缺口。

短视频解析、文学创作和视频创作的代码接线分别达到 12/12、14/14 与 16/16；图片模型路由和综合错误响应式也已完成 24/24 接线，因此整套视觉计划代码守卫达到 148/148。视频创作的真实链路覆盖文稿拆镜、关键帧模型、最短成片解码、刷新回读和清理；受控状态只验证失败、移动进度和部分失败 UI。线上结论仍未形成：代码接线完成不等于正式证据完成，必须在 CDS 部署固定版本后，用同一 runId 重新生成 148 个验收位的证据，不能继承旧运行截图。
