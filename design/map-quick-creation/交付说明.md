# 快速创作 · 交付说明（V9）

## 这一版交付了什么

V9 续 V8（DSN-1400E277），回应「成片太短、不知道多长」与「能不能用用户浏览器渲染」：时长和风格收在输入框同一个按钮上，默认自动并写出估算值，可选约 1 / 3 / 5 / 10 分钟；服务端按目标算幕数和每幕字数并校验脚本时长；脚本卡每幕写秒数，可「短一点 / 长一点」；3 分钟及以上默认先试看片头和第 1 幕，满意从断点做完，不满意回去换风格；成片交付成能播放的网页，导出在用户浏览器里（WebCodecs + Mediabunny），浏览器合成不了才请服务器导出；物理可行性、推荐框架与画面代码契约见 `设计文档/成片时长与浏览器渲染.md`。V8 续 V7，回应「塑料感、字太多」的反馈：手机按钮的点按区域仍是 44px，但只画中间 30–32px；描边盒子从一屏 14 个减到 4 个；不可用的主按钮改为实心中性底；手机输入框只留左下「+」（上传、知识库）与「视频 · 风格」、右下语音与一个动作（有字是发送，没字且稿件齐了是「生成」），输入框下不放字；语音输入复用正式实现的 useSpeechInput。V7 续 V6，回应「像伪智能体」的反馈：新增对话起稿——不知道选什么的人直接说想做什么，快速创作每轮问一个问题并给可点的回答；输入框上方的「创作简报」显示开工条件（必填：做成什么、讲什么、风格；建议：给谁看、时长）；按目的与感觉推荐 3 个风格并说明理由；必填齐了出现「准备好了」卡，说「可以开始了」效果一样，条件不够时说明还缺什么；开工前先看分镜脚本，可一键跳过；没有稿件也能只靠对话出片；放稿件、选风格、快捷生成的快捷路径保留。V6 续 V5，按 main 最新设计规范与第二轮反馈修订：模板改为 Lemo-Opuscar 风格库（15 类 99 种，可筛选、搜索、看样片说明）；「视频 / 网页」与风格按钮都在输入框里，风格按钮就地弹出选择面板；风格与产出相互独立；右栏改为「选择与资产」，新增「产物」页签回看我的与团队生成过的成品，可打开、带回风格、去网页托管；验收计划补齐八种手段与六个覆盖维度（见 `设计文档/验收计划.md`）；基线改到当前 main。V5 续 V4：按设计反馈打磨界面：版式改为复用网页生成工作台（左栏一个对话 + 一个输入框，右栏选模板、管理资料、看过程与成品）；你的消息与助手的消息分开（你靠右浅底气泡，助手带头像、状态收在它这一轮）；资料改为资料卡，管理在右栏；生成中右栏放大当前一幕、分镜胶片逐幕亮起，进度卡带走动的计时与分段进度条。交接场景与选择器不变。V4 续 V3：按 V3 交接检查回执修正 retry-failed-scene：改为检查恢复操作的即时结果（任务回到配音阶段、只重做第 4 幕、其余幕保留），成片播放由 play-film 覆盖。V3 续 V2：进行中的任务改为每秒查询。V2 续 V1：范围不变（快捷版交接实现，逐幕创作只给概念稿），本版补齐关键交互与失败恢复的可运行场景，并修掉场景暴露的问题：播放器播放真实视频与音轨、恢复只重做没完成的部分、轮询在重试后自动接上、附件重试失败退回原因、支持直接粘贴正文。详见 `思路.md`「本版改动」。

## 怎么看

画面清单里每个画面对应一个状态，入口地址以 `#/` 开头。重点画面：

0. `compose` / `compose-web` / `style-picker`：左栏助手开场与输入框（产出切换与风格按钮在输入框里），右栏风格库；`style-picker` 是风格按钮弹出的选择面板。

0. `duration-picker` / `export-progress` / `export-done` / `export-unsupported`：开工前定时长；成片在浏览器里导出与兜底。
0. `phone-plus` / `phone-style`：手机输入框左下的「+」与「视频 · 风格」面板（产出切换在面板顶部）。
0. `assets` / `assets-team` / `phone-assets`：右栏「产物」页签，回看我的与团队生成过的成品。

## 实现方怎么接

- 整份应用 `设计文档/源码差异.diff`（19 个文件，基线 06fa8659：新页面目录、接口封装、navRegistry 与 toolboxStore 登记）。页面复用 `components/web-hosting/workbench/WorkbenchParts` 的 `WorkbenchLayout`、`PaneTabs`、`Segmented`、`WorkbenchPreview` 与 `fitComposerHeight`，不改动它们；风格面板用 `@radix-ui/react-popover`（已在依赖里）。在基线上 `git apply` 后 `tsc --noEmit` 退出码 0，相关文件 ESLint 零告警。
- 接口约定见 `services/real/quickCreation.ts`：时长预估（`POST /estimate`，返回目标秒数、自动秒数、全文照念秒数、幕数、预计耗时与依据；创建任务与出脚本都带 `duration`，脚本接口支持 `adjust`）、成片包（任务完成后带 `bundle`：画面代码、配音、时间轴，播放与导出都用它）、试看（创建任务带 `trial`，任务上的 `trial` 写状态与剩余幕数，`POST /runs/{id}/trial/approve` 接着做）、服务器导出兜底（`POST /runs/{id}/server-export`）、对话起稿（`POST /brief/messages` 发一句话、返回整个会话与结构化简报；`POST /brief/context` 同步产出、风格与附件的变化；`POST /brief/{id}/script` 出分镜脚本；创建任务时带 `briefId` 与确认过的 `script`。简报的 `ready` / `missing` 是唯一开工判据，「可以开始了」这类意图由模型结构化判定后落到它上面；正式实现回复走 SSE 逐字推送，模型走模型池，名字旁显示所用模型）、产物（`GET /assets?scope=mine|team`，返回已生成的成品）、风格库目录（分类、风格、来源授权；海报地址与风格说明位置由服务端维护）、作品、任务（创建 / 查询 / 重试 / 发布）、附件（上传 / 知识库 / 重新读取）。任务在服务端排队执行，进行中时页面每秒查询一次，恢复或重试让任务重新进行时自动接上；正式实现可换成推送，页面接口不变。
- 演示数据：`设计文档/演示数据.json`（由 `src/fixtures.ts` 导出），原型与实现取证用同一份；风格目录由 `tools/import-opuscar.py` 从风格库生成（`src/opuscar/`，只用于原型）。
- 验收计划：`设计文档/验收计划.md`，八种手段各写怎么做、示例、通过标准、谁做、什么时候做。
- 交接以 `交接清单.md` 为准（程序生成，按目标列验收项与回复模板）。

## 已知边界

1. 原型里的成片音轨是示意音，正式产品为配音；视频画面由模板代码渲染，正式合成可能带转场。
2. 团队并发上限（4）、单幕配音超时（10 分钟）与整条超时（2 小时）是按 30–60 分钟出片放大的占位值，需按服务端实测校准。
3. 导出进度在原型里按预估速度模拟（`browserExport.ts`），产物用演示成片文件；导出能力检测是真实的 WebCodecs 检测。正式实现按 `设计文档/成片时长与浏览器渲染.md` 第七节替换，需新增依赖 Mediabunny；画面代码必须是 Canvas / WebGL 并满足第六节的契约。
4. 对话起稿在原型里由 `src/briefEngine.ts` 按固定路线演示（不进源码差异），正式实现由服务端模型完成；所用模型池与单次对话轮数上限实现前确认。
5. 「从知识库选择」在原型里直接加入示例文档；正式实现复用 MD 转网页 PPT 的知识库选择交互，建议抽成公共组件。
6. 原型里的网页托管与百宝箱是示意页；正式实现分别是 WebPagesPage（已支持 `?focusSite=`）与百宝箱，不需要改它们。
7. 视频的配音与合成服务、费用口径在实现前确认。
8. 风格说明 STYLE.md 已取得使用授权，由服务端在生成时按编号读取；样片海报（CC BY 4.0）须保留署名。网页产出使用全部 99 种风格（已确认）；团队产物团队成员都能看，不另设可见范围（已确认）。
9. 出片方式已定：每次按风格说明从头生成，一支约 30–60 分钟；整条超时 2 小时、单幕配音 10 分钟、团队同时 4 个是占位值，按服务端实测校准。排队卡要列出正在生成与排在前面的人（姓名、稿件标题、还需或预计开始），由服务端提供排队看板数据（`QcQueueInfo.runningItems` / `aheadItems`）。
