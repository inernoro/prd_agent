# MAP 快速创作（V9）

## 目标

团队成员带来一份文档，选一个风格（模板），快速得到**能播放的视频**或**能浏览的网页**，并发布到网页托管。同一时段集中提交时，排队、后台继续和结果恢复都要看得见。

- 快捷版只做最快路径：产出（视频 / 网页）→ 模板 → 稿件 → 一句可选要求 → 快捷生成 → 预览 → 发布。
- 不知道怎么选的人走对话起稿：直接说想做什么，快速创作逐个问清、推荐风格，条件齐了出现「准备好了」，开工前先看分镜脚本。快捷路径保留，会用的人不用聊天。
- 与「视频创作智能体」分开：那边用生成式视频模型出镜头；这里的成品来自文稿、配音和可复用的模板画面代码。

## 关键取舍

1. **视频与网页共用一个入口，用「产出」切换，切换按钮在输入框里。** 两者的输入（稿件 + 风格 + 一句要求）、过程（排队 → 若干阶段 → 已生成）和去处（网页托管）完全相同。产出和风格都在输入框里决定：用户想的时候视线在输入框，将来和其他输入集成时这一组也跟着输入框走。切换后阶段名和预览形态随之改变：视频是「分镜 → 配音 → 合成」，网页是「大纲 → 版式 → 生成页面」。
2. **版式沿用网页生成工作台：一个对话，一个预览。** 左栏只有对话流和底部一个输入框；选模板、管理资料、看过程和成品都在右栏的大区域里。窄屏切成「对话 / 预览」两个页签（与网页生成同一组件）。
3. **对话里两个说话人一眼分得清。** 你的消息靠右、主色浅底气泡，资料卡收在气泡里；快速创作靠左、带头像与名字、不套气泡，它的状态（已保存、排队、进度、失败、完成）都是这一轮里的卡片，不再和你的消息交错。
4. **资料用同一套资料卡。** 输入框顶部只放一行摘要（份数、字数、读取中、失败）+ 两张资料卡 + 「+N」；点「管理」在右栏打开资料面板，按读取失败 / 稿件 / 知识库文档 / 图片分组，逐项重试或移除，右侧看正文。发送后，资料卡收在你的消息里，点「全部 N 份」在右栏只读回看。
5. **排队与失败分开写。** 排队卡只讲位置、前面几个、预计何时开始，并明确「排队不是失败」；失败卡先说已保存了什么，主按钮只重做没完成的部分（单幕失败只重做那一幕，超时从断点重新排队）。
6. **生成完成后，过程收成一行。** 注意力让给成品与「发布到网页托管」这唯一的主动作；需要时可展开回看过程。
7. **任务在服务端跑，地址带任务编号。** `?run=<编号>` 让用户离开、刷新或从作品列表点回时回到同一任务；完成后发站内通知。
8. **作品配色与界面主题隔离。** 模板画面（点阵纸、暖黄、手绘线）只写在 `TemplateFrames.tsx` 一个文件里，同一份代码用于模板缩略图、分镜、成片和发布页；界面其余部分只取 tokens.css 语义变量，白天主题自动换成 MAP 浅色档。
9. **发布复用网页托管已有的定位能力。** 「在网页托管中查看」跳到 `/web-pages?focusSite=<站点编号>`，WebPagesPage 已支持按此参数定位高亮，不需要改它。
10. **模板就是风格库里的风格。** 分类与风格取自 Lemo-Opuscar：按「画面像什么」分 15 类、共 99 种，每种有样片海报、样片名与一句话说明。风格与产出相互独立：同一个风格既能出视频（按风格说明逐帧画出成片），也能出网页（按它的配色、字体与版式出页面）。选择有两个入口：输入框里的风格按钮就地选，右栏风格库看大图和样片说明。
11. **右栏是「选择与资产」。** 新建时页签为「风格 / 产物」，任务中为「本次 / 产物」。产物只列已生成的视频与网页，可按我的 / 团队与产出类型浏览，能打开原任务、把风格带回输入框、去网页托管；多人一起挑风格时能直接看到这个风格做出来的样子。「我的作品」页继续管理全部任务（含进行中、失败），两处分工不重复。
12. **对话起稿：聊到条件齐了再开工，开工条件是结构化的。** 输入框上方的「创作简报」列出必填三项（做成什么、讲什么、风格）与建议两项（给谁看、时长），由服务端按对话、稿件、手动选择与默认值结构化给出，前端只显示，不从聊天文字里猜。助手每轮只问一个它还拿不准的问题，并给几个可以直接点的回答；推荐风格一次三个，每个带样片海报和一句为什么适合。必填齐了出现「准备好了」卡；直接说「可以开始了」效果一样，条件不够时助手说明还缺什么，不硬开始。开工前先出一版分镜脚本（每幕一句画面、一句旁白）给用户确认，可一键跳过；30–60 分钟的任务，花一两分钟确认方向是值得的。没有稿件也能只靠对话出片，文案由快速创作按对话先写。
13. **成片时长开工前就定，由字数保证。** 成片时长 ≈ 旁白字数 ÷ 配音语速，所以「要多长」落在「分几幕、每幕写多少字」上：服务端按目标算出幕数与每幕字数，写完脚本按同一公式校验在目标 ±15%，不够就补写，不交给模型自觉。时长和风格收在输入框同一个按钮上（「3 分钟 · 视觉笔记」），默认自动并直接写出估算值；脚本卡每幕写秒数，可「短一点 / 长一点」。
14. **服务器不渲染视频。** 成片交付成能播放的网页（画面代码 + 配音 + 时间轴），播放和导出都在用户浏览器里。前提是画面用 Canvas / WebGL 逐帧画（Lemo-Opuscar 的风格本来就是），每帧是像素，能直接交给浏览器的硬件编码器；浏览器合成不了才请服务器导出。详见 `设计文档/成片时长与浏览器渲染.md`。
15. **长片先试看，再做完。** 最费资源的是智能体写画面代码，不是渲染。3 分钟及以上默认先只做片头和第 1 幕给用户看，方向不对时只白做一成；满意从断点做完。

## 依据的规则

框架 FW-MAP-ADMIN V1（`spec/rules.md`，取自 prd-admin 正式源码）：正式 AppShell、语义令牌、双主题、lucide 图标、Button 组件、窄屏切换与 44px 触控、navRegistry 注册带 wip、长任务可见进度、错误先给恢复动作、请求走 apiRequest。

原型由 `prototype-build.mjs` 在基线 `06fa8659`（main）上用 prd-admin 正式代码构建：壳、组件和令牌都来自正式源码；新增页面与改动的注册文件即源码差异（`设计文档/源码差异.diff`），可在基线上直接 `git apply` 并通过 `tsc --noEmit` 与 ESLint（零新增告警）。

构建工具说明：PR #2108 里的 `prototype-build.mjs` 只支持 Tailwind v3（cds/web）。prd-admin 用 Tailwind v4，本稿补了三处通用能力，补丁在 `tools/prototype-build.prd-admin.patch`：识别 `@tailwindcss/vite` 并为稿件源码补 `@source`；`lazyPlaceholders`（路由注册表里其他页面的懒加载换成空模块，原型从 25 MB 降到 2 MB）；`omitAssets`（样式表里的卡片插画不内嵌）。三者只作用于原型，不进源码差异。应合入技能后再由其他稿件复用。

## 本版改动

### V9（成片时长可预期；服务器不渲染视频）

反馈：做视频的人不知道视频会有多长，可能想长也可能想短；大量反馈是给了一份教程，只生成了二三十秒。另外，能不能只生成代码网页、用用户的浏览器渲染视频，既省 CPU 又省带宽，但要物理上可行，并给实现方推荐框架。

原因：Lemo-Opuscar 的风格样片本身是 15–30 秒，生成时又没有时长目标，模型照样片长度写，教程也成了二三十秒。

| 问题 | V8 的样子 | V9 改成 |
|---|---|---|
| 开工前不知道会多长 | 简报里写「约 1 分钟（默认）」，改不了 | 「时长 · 风格」按钮写「3 分钟 · 视觉笔记」；面板顶部可选自动 / 约 1 / 3 / 5 / 10 分钟，自动直接写出估算值和依据（稿件字数、全文照念多长、幕数、预计生成耗时） |
| 教程被做成二三十秒 | 没有目标，模型自己定 | 服务端按目标算幕数和每幕字数，脚本总时长校验在目标 ±15%；培训、教程类在对话里先问一次想要多长 |
| 想改长短要等成片出来 | 只能重做 | 分镜脚本每幕写秒数、顶部写合计与目标，「短一点 / 长一点」重写这一版（一两分钟，不花生成的钱）；对话里说「5 分钟」「长一点」也行 |
| 整片做完才发现风格不对，白花 30–60 分钟 | 脚本确认后直接做完 | 3 分钟及以上默认先试看片头和第 1 幕（带配音，约占一成时间），满意从断点做完、试看的两幕沿用；不满意回去换风格或改要求；等确认时不占排队名额 |
| 服务器渲染视频，费 CPU 和带宽 | 成片是视频文件 | 成片是能播放的网页（约 3 MB / 3 分钟，视频文件约 90–180 MB）；发布不传视频；要文件时在用户浏览器里导出，有帧数进度、可取消；浏览器合成不了才请服务器导出 |

物理可行性与框架：画面必须是 Canvas / WebGL（任意 HTML 和 CSS 没法逐帧变成像素）；编码用浏览器自带的 WebCodecs，封装用 Mediabunny（MPL-2.0，可商用）；声音由服务端顺手编好 AAC 与 Opus，浏览器只编画面，所以 Safari 16.4 起就能导出。Remotion 的浏览器渲染作备选（公司许可、只支持部分 CSS）；服务端截图加 ffmpeg 只作兜底（仓库 2026-04 已删掉服务端 Remotion 路径）。全部写在 `设计文档/成片时长与浏览器渲染.md`。

原型里：时长预估、脚本按目标写、导出能力检测（真实的 WebCodecs 检测）都是真的；导出进度按预估速度模拟，产物用演示成片文件。新增画面 trial-ready、duration-picker、export-progress、export-done、export-unsupported，验收项 A-55 至 A-59，目标 G-13 至 G-15，交接场景 3 个（另把 3 个并进同画面的已有场景，CDS 限每稿 24 个）。

### V8（去掉塑料感；手机输入框做减法）

反馈：页面有一种肥肥胖胖的塑料感；字太多，输入框下的字、输入框边缘都是；手机上应该折叠一部分，左下角「+」和模型，右下角语音和发送即可，要学会做减法和布局。

量出来的原因与改法：

| 原因（实测） | 改法 |
|---|---|
| 手机按钮直接画成 44px 高，13px 的字只占三成高度（「用这个」是 62×44 的方块） | 点按区域与画出来的大小分开：按钮元素仍 44px，只画中间 30–32px 一块 |
| 手机一屏 14 个带描边的圆角盒子，层层套框 | 去到 4 个：推荐卡的按钮改为一行主色文字，简报已填项去框，风格与发送按钮去描边 |
| 主按钮不可用时是主色打五折，变成发灰的豆绿 | 改为实心中性底 |
| 手机输入框工具行塞了上传、知识库、视频 / 网页、风格、快捷生成，下面还有一行说明 | 左下「+」（上传、知识库）与「视频 · 风格」（产出切换收进它的面板顶部）；右下语音与一个动作：有字是发送，没字且稿件齐了是「生成」；输入框下不放字；空着时只占一行 |
| 开场把「从知识库选择 / 上传稿件」又列了一遍 | 手机上开场只留「用示例稿件试一下」，另两项在「+」里 |
| 弹出菜单在浅色是发灰的褐色、在深色是半透明（透出下面的字） | 两个主题都用实色的菜单底 |

语音输入复用正式实现的 `useSpeechInput`（浏览器语音识别，边说边出字），浏览器不支持时不显示入口。新增画面 phone-plus、phone-style。

### V7（对话起稿：不知道选什么的人也能用）

反馈：现在像「伪智能体」。有人问：不知道选哪个风格，去问它，会生成什么？他想做一支宣传片、不知道找什么模板，想先问问 AI，聊得差不多时说一句「可以开始了」，或者聊天里直接出现一个按钮，告诉他准备好了（已经拿到充分必要的条件）。

| 问题 | V6 的样子 | V7 改成 |
|---|---|---|
| 输入框里打字只会变成「补充要求」，问了也没人回答 | 只有一条路：放稿件 → 选风格 → 快捷生成 | 打字按 Enter 发给快速创作，它回复并追问；Ctrl / ⌘ + Enter 仍是快捷生成；开场给三个起头（我想做一个宣传片、给新同事做个培训短片、不知道选什么风格） |
| 不知道开工还缺什么 | 快捷生成按钮灰着，只在一行小字里写原因 | 输入框上方「创作简报」：必填 x/3、每项带勾或「待补」，齐了写「可以开工」 |
| 不知道选哪个风格 | 99 种自己翻 | 问清目的与感觉后推荐 3 个，带海报与理由；点「用这个」或说「第二个」都能选定，输入框的风格按钮与右栏同步 |
| 不知道什么时候算问清了 | 没有这个概念 | 必填齐了出现「准备好了」卡，复述简报，主按钮「开始生成（约 30–60 分钟）」；说「可以开始了」效果一样 |
| 等了一小时才发现方向不对 | 直接开跑 | 开工前先看分镜脚本，确认后正式排队；不想看可跳过；想改在对话里说 |
| 没有稿件就不能做 | 必须有稿件 | 讲什么可以来自对话，任务里写明「内容来自和快速创作的对话」 |

做法要点：
1. 判定「准备好了」的是服务端返回的结构化简报（`brief.ready` 与 `missing`），「可以开始了」这类开工意图也由模型结构化判定后落到同一个判据上，前端不靠关键词猜。原型用固定的几条路线（`src/briefEngine.ts`，不进源码差异）演示同样的形状。
2. 只有最新一条助手消息里的按钮可点，旧消息的选项收起，避免点到过时的选择；新内容出完后自动滚到它的底部，卡片不落在视线外。
3. 回复逐字出现，名字旁写这次用的模型与模型池（禁止空白等待，过程可见）；等回复时是一条在动的「正在理解你的需求」，不是静止的加载。
4. 新增画面 chat-start、chat-recommend、chat-ready、chat-script、phone-chat，验收项 A-49 至 A-54、目标 G-12，交接场景 3 个（聊天到准备好了并跳过脚本、说「第二个」与「可以开始了」后确认脚本、条件不够时说「可以开始了」），本机预跑 21 / 21 通过。
5. 发送按钮放进输入框右下角，工具行在 1280 宽下一行排完；手机上推荐卡改为左图右文，三张一屏可见。

### V6（按 main 最新设计规范与第二轮设计反馈修订）

反馈：模板按 Lemo-Opuscar 仓库的分类和提示词来做，现在的模板内容太少；输入框左下角的「视频 · 视觉笔记」就是选模板，可以在那里修改；右上角的「视频 / 网页」挪到输入框，方便用户思考，也方便以后做集成。

| 反馈 | V5 的样子 | V6 改成 |
|---|---|---|
| 出片 30–60 分钟可以接受，限制放大；排队要说清前面几个人、是谁，不把责任甩给用户 | 按几分钟出片设计（15 分钟超时）；排队卡只有格子和数字 | 超时放大到 2 小时、单幕 10 分钟，计时可到小时；排队卡先说原因（团队同时生成上限满了，与稿件无关），再列正在生成的人与还需、排在前面的人与预计开始，最后是你；失败文案写明原因在系统、不需要改稿件 |
| 模板太少 | 视频 3 个、网页 2 个自绘模板 | 风格库 15 类 99 种：类别行（带数量）+ 搜索 + 海报卡片；选中风格显示大图、样片名与时长、一句话说明和来源署名 |
| 左下角能选模板 | 「视频 · 视觉笔记」只是跳到右栏的链接 | 风格按钮：点开就地弹出选择面板（搜索、类别、列表），选完回到输入；底部可去右栏看大图 |
| 产出切换在右上角 | 预览栏右上角 | 输入框底部一行：上传、知识库 ｜ 视频 / 网页、风格 ｜ 快捷生成；手机上产出与风格单独一行 |
| 风格随产出变 | 切到网页换成网页模板 | 风格与产出相互独立，切换产出不改风格（「用这份稿件做网页」也保留原风格） |
| 右栏要兼顾资产 | 右栏只有选择和本次预览，回看以前的成品要离开去作品页 | 右栏改为「选择与资产」，加「产物」页签：我的 / 团队、视频 / 网页筛选，选中看大图与信息，可打开、用这个风格、去网页托管 |

关于「提示词」：风格数据（style.json，MIT）、样片海报（CC BY 4.0，须署名）与风格说明 STYLE.md 都可以用（风格说明已取得使用授权）。风格说明由服务端在生成时按编号读取、交给智能体，前端和界面只显示风格名、样片与说明，不展示全文。网页产出同样使用全部 99 种风格（已确认）。

按 main 最新设计规范补齐：

### V5（按设计反馈打磨界面）

反馈：输入框和对话粗糙、不稳定、杂乱；模板应在右侧选（左侧装不下）；多附件难看；生成中效果纤细没有质感；系统消息和用户消息交织，分不清哪条是自己发的。

做法：先找站内锚点，不另起风格。MAP 已有的「网页生成工作台」（`components/web-hosting/workbench`）就是同类任务——一份资料、一个风格、一次生成——本版直接复用它的 `WorkbenchLayout`、`PaneTabs`、`Segmented`、`WorkbenchPreview` 与输入框尺寸函数，度量照抄（输入框 16px 圆角、发送区 34px、进度卡任务清单、预览栏标题 + 底部一句下一步）。

### V2（续 V1）

V2，续 V1（DSN-1400E277）。目标：为关键交互和失败恢复补上 CDS 可以实际执行的交接场景，并修掉场景暴露出来的行为问题。

1. **13 个可运行场景**（`design.json.handoff.cases`），覆盖 19 条声明为关键操作（`interaction: true`）的验收项：三种稿件入口（示例、粘贴、上传）各自走到排队；附件读取失败的单项重试与移除；排队中离开再回到同一任务；单幕失败只重做这一幕；整条超时重新排队；播放成片（画面与声音、重点跳转、字幕开关）；发布失败后重试并落到网页托管；网页重点定位；同一份稿件改做网页；回看已发送附件。
2. **播放器改为播放真实的视频文件**：V1 的播放器只是按秒切换模板画面，没有媒体和声音。V2 用 `<video>` 播放成片，时间、字幕和重点都跟随 `currentTime`；原型内嵌一段 96 秒、带示意音轨的演示成片（由模板画面渲染，`tools/make-demo-film.mjs`），正式产品是配音成片。
3. **恢复只重做没完成的部分**：V1 的演示数据在重试时把所有幕重新算一遍，界面上会看到已完成的幕也在重做。V2 明确保留已完成的幕：单幕失败只重做那一幕，超时后重新排队、已画好的幕保持不变。
4. **页面轮询跟着任务状态走**：V1 在任务到达失败这类终态后停止轮询，重试后页面不会再更新。V2 只要任务回到排队、生成或发布中，就自动继续查询。
5. **附件重试失败不再卡在读取中**：重试请求本身失败时退回「读取失败」并写明原因。
6. **补上「直接粘贴正文」**：一次粘贴 300 字以上会自动作为一份稿件附件，输入框只留给要求；上传按真实文件名、大小和内容读取，空文件给出原因。
