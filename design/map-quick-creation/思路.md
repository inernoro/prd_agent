# MAP 快速创作（V1）

## 目标

团队成员带来一份文档，选一个模板，快速得到**能播放的视频**或**能浏览的网页**，并发布到网页托管。同一时段集中提交时，排队、后台继续和结果恢复都要看得见。

- 快捷版只做最快路径：产出（视频 / 网页）→ 模板 → 稿件 → 一句可选要求 → 快捷生成 → 预览 → 发布。
- 与「视频创作智能体」分开：那边用生成式视频模型出镜头；这里的成品来自文稿、配音和可复用的模板画面代码。

## 关键取舍

1. **视频与网页共用一个入口，用「产出」切换。** 两者的输入（稿件 + 模板 + 一句要求）、过程（排队 → 若干阶段 → 已生成）和去处（网页托管）完全相同，分成两个智能体会让用户先猜该进哪个。切换后模板、阶段名和预览形态随之改变：视频是「分镜 → 配音 → 合成」，网页是「大纲 → 版式 → 生成页面」。
2. **附件托盘只占一行。** 上一版附件一多就在输入框里堆成一大片。现在收起时只放一行摘要（数量、可用字数、读取中、失败数）和最多两个胶囊，其余收成「+N」；需要管理时展开限高列表（232px，超出滚动），按「稿件 / 知识库文档 / 图片」分组，失败项单独排在最前、写清原因与恢复动作。发送后，消息里的附件也收成一行，点开在右栏回看。
3. **排队与失败分开写。** 排队卡只讲位置、前面几个、预计何时开始，并明确「排队不是失败」；失败卡先说已保存了什么，主按钮只重做没完成的部分（单幕失败只重做那一幕，超时从断点重新排队）。
4. **生成完成后，过程收成一行。** 注意力让给成品与「发布到网页托管」这唯一的主动作；需要时可展开回看过程。
5. **任务在服务端跑，地址带任务编号。** `?run=<编号>` 让用户离开、刷新或从作品列表点回时回到同一任务；完成后发站内通知。
6. **作品配色与界面主题隔离。** 模板画面（点阵纸、暖黄、手绘线）只写在 `TemplateFrames.tsx` 一个文件里，同一份代码用于模板缩略图、分镜、成片和发布页；界面其余部分只取 tokens.css 语义变量，白天主题自动换成 MAP 浅色档。
7. **发布复用网页托管已有的定位能力。** 「在网页托管中查看」跳到 `/web-pages?focusSite=<站点编号>`，WebPagesPage 已支持按此参数定位高亮，不需要改它。

## 依据的规则

框架 FW-MAP-ADMIN V1（`spec/rules.md`，取自 prd-admin 正式源码）：正式 AppShell、语义令牌、双主题、lucide 图标、Button 组件、窄屏切换与 44px 触控、navRegistry 注册带 wip、长任务可见进度、错误先给恢复动作、请求走 apiRequest。

原型由 `prototype-build.mjs` 在基线 `949bfa27` 上用 prd-admin 正式代码构建：壳、组件和令牌都来自正式源码；新增页面与改动的注册文件即源码差异（`设计文档/源码差异.diff`），可在基线上直接 `git apply` 并通过 `tsc --noEmit` 与 ESLint（零新增告警）。

构建工具说明：PR #2108 里的 `prototype-build.mjs` 只支持 Tailwind v3（cds/web）。prd-admin 用 Tailwind v4，本稿补了三处通用能力，补丁在 `tools/prototype-build.prd-admin.patch`：识别 `@tailwindcss/vite` 并为稿件源码补 `@source`；`lazyPlaceholders`（路由注册表里其他页面的懒加载换成空模块，原型从 25 MB 降到 2 MB）；`omitAssets`（样式表里的卡片插画不内嵌）。三者只作用于原型，不进源码差异。应合入技能后再由其他稿件复用。
