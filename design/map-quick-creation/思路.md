# MAP 快速创作（V6）

## 目标

团队成员带来一份文档，选一个风格（模板），快速得到**能播放的视频**或**能浏览的网页**，并发布到网页托管。同一时段集中提交时，排队、后台继续和结果恢复都要看得见。

- 快捷版只做最快路径：产出（视频 / 网页）→ 模板 → 稿件 → 一句可选要求 → 快捷生成 → 预览 → 发布。
- 与「视频创作智能体」分开：那边用生成式视频模型出镜头；这里的成品来自文稿、配音和可复用的模板画面代码。

## 关键取舍

1. **视频与网页共用一个入口，用「产出」切换，切换按钮在输入框里。** 两者的输入（稿件 + 风格 + 一句要求）、过程（排队 → 若干阶段 → 已生成）和去处（网页托管）完全相同。产出和风格都在输入框里决定：用户想的时候视线在输入框，将来和其他输入集成时这一组也跟着输入框走。切换后阶段名和预览形态随之改变：视频是「分镜 → 配音 → 合成」，网页是「大纲 → 版式 → 生成页面」。
2. **版式沿用网页生成工作台：一个对话，一个预览。** 左栏只有对话流和底部一个输入框；选模板、管理资料、看过程和成品都在右栏的大区域里。窄屏切成「对话 / 预览」两个页签（与网页生成同一组件）。
3. **对话里两个说话人一眼分得清。** 你的消息靠右、主色浅底气泡，资料卡收在气泡里；快速创作靠左、带头像与名字、不套气泡，它的状态（已保存、排队、进度、失败、完成）都是这一轮里的卡片，不再和你的消息交错。
4. **资料用同一套资料卡。** 输入框顶部只放一行摘要（份数、字数、读取中、失败）+ 两张资料卡 + 「+N」；点「管理」在右栏打开资料面板，按读取失败 / 稿件 / 知识库文档 / 图片分组，逐项重试或移除，右侧看正文。发送后，资料卡收在你的消息里，点「全部 N 份」在右栏只读回看。
5. **排队与失败分开写。** 排队卡只讲位置、前面几个、预计何时开始，并明确「排队不是失败」；失败卡先说已保存了什么，主按钮只重做没完成的部分（单幕失败只重做那一幕，超时从断点重新排队）。
6. **生成完成后，过程收成一行。** 注意力让给成品与「发布到网页托管」这唯一的主动作；需要时可展开回看过程。
7. **任务在服务端跑，地址带任务编号。** `?run=<编号>` 让用户离开、刷新或从作品列表点回时回到同一任务；完成后发站内通知。
8. **作品配色与界面主题隔离。** 模板画面（点阵纸、暖黄、手绘线）只写在 `TemplateFrames.tsx` 一个文件里，同一份代码用于模板缩略图、分镜、成片和发布页；界面其余部分只取 tokens.css 语义变量，白天主题自动换成 MAP 浅色档。
9. **发布复用网页托管已有的定位能力。** 「在网页托管中查看」跳到 `/web-pages?focusSite=<站点编号>`，WebPagesPage 已支持按此参数定位高亮，不需要改它。
10. **模板就是风格库里的风格。** 分类与风格取自 Lemo-Opuscar：按「画面像什么」分 15 类、共 99 种，每种有样片海报、样片名与一句话说明。风格与产出相互独立：同一个风格既能出视频（按风格说明逐帧画出成片），也能出网页（按它的配色、字体与版式出页面）。选择有两个入口：输入框里的风格按钮就地选，右栏风格库看大图和样片说明。
11. **右栏是「选择与资产」。** 新建时页签为「风格 / 产物」，任务中为「本次 / 产物」。产物只列已生成的视频与网页，可按我的 / 团队与产出类型浏览，能打开原任务、把风格带回输入框、去网页托管；多人一起挑风格时能直接看到这个风格做出来的样子。「我的作品」页继续管理全部任务（含进行中、失败），两处分工不重复。

## 依据的规则

框架 FW-MAP-ADMIN V1（`spec/rules.md`，取自 prd-admin 正式源码）：正式 AppShell、语义令牌、双主题、lucide 图标、Button 组件、窄屏切换与 44px 触控、navRegistry 注册带 wip、长任务可见进度、错误先给恢复动作、请求走 apiRequest。

原型由 `prototype-build.mjs` 在基线 `06fa8659`（main）上用 prd-admin 正式代码构建：壳、组件和令牌都来自正式源码；新增页面与改动的注册文件即源码差异（`设计文档/源码差异.diff`），可在基线上直接 `git apply` 并通过 `tsc --noEmit` 与 ESLint（零新增告警）。

构建工具说明：PR #2108 里的 `prototype-build.mjs` 只支持 Tailwind v3（cds/web）。prd-admin 用 Tailwind v4，本稿补了三处通用能力，补丁在 `tools/prototype-build.prd-admin.patch`：识别 `@tailwindcss/vite` 并为稿件源码补 `@source`；`lazyPlaceholders`（路由注册表里其他页面的懒加载换成空模块，原型从 25 MB 降到 2 MB）；`omitAssets`（样式表里的卡片插画不内嵌）。三者只作用于原型，不进源码差异。应合入技能后再由其他稿件复用。

## 本版改动

### V6（按 main 最新设计规范与第二轮设计反馈修订）

反馈：模板按 Lemo-Opuscar 仓库的分类和提示词来做，现在的模板内容太少；输入框左下角的「视频 · 视觉笔记」就是选模板，可以在那里修改；右上角的「视频 / 网页」挪到输入框，方便用户思考，也方便以后做集成。

| 反馈 | V5 的样子 | V6 改成 |
|---|---|---|
| 模板太少 | 视频 3 个、网页 2 个自绘模板 | 风格库 15 类 99 种：类别行（带数量）+ 搜索 + 海报卡片；选中风格显示大图、样片名与时长、一句话说明和来源署名 |
| 左下角能选模板 | 「视频 · 视觉笔记」只是跳到右栏的链接 | 风格按钮：点开就地弹出选择面板（搜索、类别、列表），选完回到输入；底部可去右栏看大图 |
| 产出切换在右上角 | 预览栏右上角 | 输入框底部一行：上传、知识库 ｜ 视频 / 网页、风格 ｜ 快捷生成；手机上产出与风格单独一行 |
| 风格随产出变 | 切到网页换成网页模板 | 风格与产出相互独立，切换产出不改风格（「用这份稿件做网页」也保留原风格） |
| 右栏要兼顾资产 | 右栏只有选择和本次预览，回看以前的成品要离开去作品页 | 右栏改为「选择与资产」，加「产物」页签：我的 / 团队、视频 / 网页筛选，选中看大图与信息，可打开、用这个风格、去网页托管 |

关于「提示词」：风格数据（style.json，MIT）、样片海报（CC BY 4.0，须署名）与风格说明 STYLE.md 都可以用（风格说明已取得使用授权）。风格说明由服务端在生成时按编号读取、交给智能体，前端和界面只显示风格名、样片与说明，不展示全文。网页产出同样使用全部 99 种风格（已确认）。

按 main 最新设计规范补齐：
1. 验收计划写全八种手段（`acceptancePlan` 全部适用），每条验收项标覆盖维度，六个维度都有验收项；性能里「真实出片耗时」写了风险与理由；新增 `设计文档/验收计划.md`，每种手段写怎么做、示例、通过标准、谁做、什么时候做，含视觉 V-01 至 V-10、历史易错 K-01 至 K-07、冒烟 S-01 至 S-06、验收债务 D-01、D-02、D-04。
2. 每个画面写了就绪条件和实现地址（`impl`），新增画面 `style-picker`（入口动作点风格按钮）；风格目录读到之前页面不标就绪，程序截图不会拍到空风格。
3. 新增验收项 A-43 至 A-48 与目标 G-10、G-11，新增 5 个交接场景（就地换风格、搜索风格库、切换产出保留风格、从团队产物带回风格、任务中打开以前的产物），本机预跑 18 / 18 通过；新增画面 assets、assets-team、phone-assets。
4. 基线从 949bfa27 改到当前 main（06fa8659）：两者之间 prd-admin 只改了 3 个与本稿无关的文件，源码差异在新基线上编译通过。


### V5（按设计反馈打磨界面）

反馈：输入框和对话粗糙、不稳定、杂乱；模板应在右侧选（左侧装不下）；多附件难看；生成中效果纤细没有质感；系统消息和用户消息交织，分不清哪条是自己发的。

做法：先找站内锚点，不另起风格。MAP 已有的「网页生成工作台」（`components/web-hosting/workbench`）就是同类任务——一份资料、一个风格、一次生成——本版直接复用它的 `WorkbenchLayout`、`PaneTabs`、`Segmented`、`WorkbenchPreview` 与输入框尺寸函数，度量照抄（输入框 16px 圆角、发送区 34px、进度卡任务清单、预览栏标题 + 底部一句下一步）。

| 反馈 | V4 的样子 | V5 改成 |
|---|---|---|
| 模板在左侧挤 | 左栏上半是产出切换 + 两列小模板卡 | 右栏：产出切换在预览栏右上角，上方是选中模板的大图，下方 3 张模板卡 |
| 消息分不清 | 用户气泡、已保存提示、进度卡同一列交错 | 你的消息靠右主色浅底；快速创作带头像与名字，状态都收在它这一轮里 |
| 输入框粗糙 | 输入框里套着带边框的附件盒，盒里套胶囊 | 一张卡：资料托盘、细分隔线、输入区、底部一行（上传、知识库、产出与模板、快捷生成）；聚焦时主色描边 + 浅光晕 |
| 多附件丑 | 红边胶囊、展开后在输入框里 232px 列表 | 资料卡（类型色块 + 名称 + 一句状态），管理在右栏面板，失败组错误底色、原因单独一行 |
| 生成中单薄 | 细线竖排步骤 + 2×3 分镜小图 | 进度卡：大计时、分段进度条（当前段流动）、任务清单；右栏当前幕放大（配音中带声波与字幕），下方分镜胶片，待开始的幕是呼吸的骨架，正在画的幕有扫光 |
| 排队重复 | 排队卡下面又一张「正在排队」进度卡 | 只留排队卡：位置格子（生成中 / 排在前面 / 你）+ 图例 |

验收项随之更新：A-11、A-14、A-16、A-18、A-22、A-28、A-31、A-35 的描述改为新版式（A-16 的「列表限高 232px」改为「资料面板在右栏，列表区内部滚动」）；手机预览画面的进入动作改为点「对话 / 预览」页签。13 个交接场景与选择器不变，本机预跑 13 / 13 通过。


### V4（按 V3 交接检查回执修正）

V3 回执（检查编号 b94b5713）：9 个通过，3 个为隔离浏览器未完成（CDS 侧，沿用版本重跑），retry-failed-scene 仍在第 6 步失败。缩短用时没有解决它，说明问题不在快慢，而在这一步检查的对象：它要求点「重试第 4 幕」后在检查的等待内看到成片，而真实的单幕重做要几分钟，成片出现本就不是这次点击的即时结果。

修正：这个场景改为检查恢复操作的即时结果——任务回到生成中、配音阶段重新进行、第 4 幕在重做、第 1 幕保持已完成（新增阶段钩子 `data-stage` / `data-stage-status`）。成片能播放由 play-film 场景覆盖。本机预跑每步等待上限收紧到 1 秒，13 个场景全部通过；所有场景都只检查点击后立即可见的结果。

V2 的 CDS 交接检查（检查编号 d3ecba68，重跑 d51d61e0）13 个场景 12 个通过。首轮另有两个场景未过：redo-as-web 停在进入画面、review-sent-attachments 为隔离浏览器未完成（CDS 侧），按回执沿用本版重跑后都已通过，属于平台波动。稳定失败的只有一个：

### V2（续 V1）

V2，续 V1（DSN-1400E277）。目标：为关键交互和失败恢复补上 CDS 可以实际执行的交接场景，并修掉场景暴露出来的行为问题。

1. **13 个可运行场景**（`design.json.handoff.cases`），覆盖 19 条声明为关键操作（`interaction: true`）的验收项：三种稿件入口（示例、粘贴、上传）各自走到排队；附件读取失败的单项重试与移除；排队中离开再回到同一任务；单幕失败只重做这一幕；整条超时重新排队；播放成片（画面与声音、重点跳转、字幕开关）；发布失败后重试并落到网页托管；网页重点定位；同一份稿件改做网页；回看已发送附件。
2. **播放器改为播放真实的视频文件**：V1 的播放器只是按秒切换模板画面，没有媒体和声音。V2 用 `<video>` 播放成片，时间、字幕和重点都跟随 `currentTime`；原型内嵌一段 96 秒、带示意音轨的演示成片（由模板画面渲染，`tools/make-demo-film.mjs`），正式产品是配音成片。
3. **恢复只重做没完成的部分**：V1 的演示数据在重试时把所有幕重新算一遍，界面上会看到已完成的幕也在重做。V2 明确保留已完成的幕：单幕失败只重做那一幕，超时后重新排队、已画好的幕保持不变。
4. **页面轮询跟着任务状态走**：V1 在任务到达失败这类终态后停止轮询，重试后页面不会再更新。V2 只要任务回到排队、生成或发布中，就自动继续查询。
5. **附件重试失败不再卡在读取中**：重试请求本身失败时退回「读取失败」并写明原因。
6. **补上「直接粘贴正文」**：一次粘贴 300 字以上会自动作为一份稿件附件，输入框只留给要求；上传按真实文件名、大小和内容读取，空文件给出原因。
