# MAP 课程 · 自动化测试实践 · 设计思路（V1）

## 目标

学员在 MAP 里学完《自动化测试实践》：用 Agent 做代码评审、视觉验收、单元测试和联合测试，发现问题后修复、复测、交付。页面要做到三件事：

1. 在学习中心找到课程，知道从哪一课接着学；
2. 每一课的视频、PDF 教材、图文由学员自选，进度能接上；
3. 选一个练习亲手做一遍，完整经历「Agent 检查 → 你判断 → 修复 → 复测 → 交付」。

## 关键取舍

- **挂在学习中心，不另开入口。** 学习中心已是「我的 → 学习中心」与百宝箱里的正式入口，短教程也在这里。课程作为它的新分区（排在短教程之前），课程页与练习页是它的子页。不新增侧栏菜单，学员的心智是「学东西都去学习中心」。
- **一课一页，三种材料是同一课的三种读法。** 材料切换和本课标题放同一行，切换不换页、不丢位置；缺的材料按钮留在原位写「无」并说明原因（例如本课图文已有逐步截图），不让按钮消失或跳位。
- **视频：章节和逐字稿合成一栏。** 首版把章节条放在视频下、逐字稿放在右边，两者时间点重复，占两份注意力。合并后按章节分组显示逐字稿，当前行高亮并自动滚到可见，点一行跳到那一秒；宽屏在右、较窄时在视频下方。
- **PDF：逐页图连续阅读，另给原文件下载。** 原生 PDF 内嵌在手机上常只显示第一页、各浏览器表现不一；逐页图（服务端上传时生成）在手机与桌面一致。缩略图标出本课页码，打开时定位到上次读到的页或本课第一页，翻出本课范围时给「回到本课」。
- **练习的主角是工作台。** 左边是被检查的东西（代码或截图），Agent 的意见直接以编号标在代码行或截图区域上；右边只放「这一步要做的事」。五步进度条在页头，手机上收成「第 n/5 步」一行字。
- **练的是判断，不是点按钮。** 每个练习都故意放了至少一处误报（纯函数被建议加锁、容差内的 1px 阴影、依赖当前日期的测试）。逐条决定采纳或驳回，驳回必须写一句理由（给常用理由一键填入）；复测用同一组输入，判错时只告诉你「哪条检查没过」，回到判断后在判错那条下面写明复测看到了什么。对错只在服务端判定，答案不下发给页面。
- **复测通过才有交付。** 交付说明按「能做什么 / 怎么证明 / 还没做到什么」三段起草：采纳的修复进第一段，复测项进第二段，驳回理由自动进第三段，学员可以改。
- **一次练习是一条服务端记录。** 评审和复测在服务端跑，地址带 `run`；离开课程再回来，练习卡显示「进行中，可续上」，按钮变「接着做」，回到同一次练习。
- **视觉锚点：沿用学习中心与 MAP 管理后台的皮。** 颜色只用 tokens.css 语义变量，圆角 9 / 10 / 12px，正文 13–15px；课程素材（视频帧、教材页、截图）是作品画面，单独成图。

## 依据的规则

- 框架 FW-MAP-ADMIN V1 的 R-01 至 R-10（见 `spec/rules.md`），逐条在自检里通过；
- 预期管理：Agent 运行显示阶段、进度、已用与预计剩余及依据，模型名来自网关返回；
- 产物即体验：评审中意见逐条出现并同步标到代码上，不用静止的加载圈；
- 手机密度：进内容前只有一条控制栏，主动作吸底，375 宽无横向溢出；
- 学习中心与教程体系现有约定（`.claude/rules/onboarding-tips.md`）：课程区与短教程分开，不改动短教程的数据与行为。

## 待定问题

- 课程内容的来源与维护方式（谁上传视频、PDF，逐页图在哪一步生成）需要产品确认；本稿按「后台上传后由服务端生成逐页图与缩略图」设计。
- 练习完成的经验值（本稿 +40）是否并入学习中心现有的经验与等级，需要与短教程的计分口径统一。
- 真实评审耗时：原型按约 9 秒演示（对应真实约 70 秒），实现时按网关实测中位数校准预计耗时。
