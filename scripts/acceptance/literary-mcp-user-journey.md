# 文学创作 MCP 验收提示词

下面整段是发给执行验收的智能体的原文，从「你的任务」开始复制即可。

---

## 你的任务

一位客户用「智能体 + MAP」给文章配图，反馈了下面 7 个问题。你要**像这位客户一样把配图这件事完整做一遍**，
逐条确认这 7 个问题现在还在不在。最后交回一张表：每个问题一行，写清「还在 / 已解决」，并附证据。

**7 个问题都通过，才算客户的问题被解决了。任何一条没通过，就是没解决。**

| 编号 | 客户的原话 | 「已解决」长什么样 |
|---|---|---|
| 问题 1 | 能不能不要让用户上传文章，直接用智能体加 MAP 就把图配好 | 只在智能体对话里给文章、提要求，图就配好了；全程不需要打开网页上传任何东西 |
| 问题 2 | 图片风格要用「全域粉销风格」，智能体说风格是平台预设、没法指定 | 指定了哪套风格，图就是哪套风格 |
| 问题 3 | 水印要用「水印配置1」，智能体说水印没法指定 | 指定了哪套水印，图上就是哪套水印 |
| 问题 4 | 单篇最多只能配 4 张 | 6 个小节就能配 6 张 |
| 问题 5 | 想看这篇文章的历史配图，别删掉，最好在当前页面就能找到全部 | 文章页面上就能打开一个列表，重画前、改稿前的旧图都在里面，一张不少 |
| 问题 6 | 能用，但很难用 | 智能体一次就能做对，不会反复报错、绕圈，也不需要回头问你怎么操作 |
| 问题 7 | 会导致数据乱 | 一篇文章始终只有一份；网页和智能体轮流改，谁的改动都不丢；两边看到的内容一致 |

---

## 你要扮演两个角色

- **客户的智能体**：一个刚接上 MAP 的普通智能体。**只能**用 MAP 提供的工具，只看工具自带的说明。
  不许读 MAP 的代码和文档，不许绕过工具直接调接口。（客户的智能体就是这样，你知道得比它多，测出来的结果就不作数。）
- **客户本人**：用浏览器登录 MAP，点左侧导航进入页面（不许在地址栏直接输网址），看到什么记什么，不替系统找理由。

---

## 准备：把客户的账号还原出来（客户本人在网页上做）

为了能**一眼看出**用的是不是客户指定的那套，两套要明显不同：

1. 文学创作 → 风格 / 参考图
   - 新建「日常蓝调」，参考图选一张**蓝色为主**的图，**设为当前启用**
   - 新建「全域粉销风格」，参考图选一张**粉色为主**的图，**不要启用**
2. 水印
   - 新建「水印配置2」，文字写「默认水印二号」，**绑定到文学创作**
   - 新建「水印配置1」，文字写「指定水印一号」，**不要绑定**
3. 百宝箱 → 智能体接入 → 连接新客户端，勾选「文学创作」，复制密钥（sk-ak-...）。
4. 把 MAP 接到「客户的智能体」上：地址是预览域名后面加 `/api/mcp`，认证头填 `Authorization: Bearer 你复制的密钥`。
   预览域名由主控方给你，不要自己拼。
5. 打开文学创作列表，记下现在一共有几篇文章，记作 N。

怎么看结果：**图偏粉色 = 用了「全域粉销风格」，偏蓝色 = 没用上**；
**图上写着「指定水印一号」= 用了「水印配置1」，写着「默认水印二号」= 没用上**。

---

## 第一步：客户的原始请求（验问题 1、2、3、4、6）

把下面这句话和后面的文章一起，原样发给「客户的智能体」：

> 这篇文章使用 MAP 平台进行配图，每个小节配一张图，图片风格使用全域粉销风格，水印使用水印配置1。

```
全域粉销：把每一次曝光都变成可以再次触达的粉丝

一、为什么是「全域」
过去品牌把预算拆给不同渠道，每个渠道各算各的账。线上投放、门店活动、包装扫码，彼此不认识同一个顾客。全域的意思，是让这些触点认出同一个人。

二、从流量到粉丝
流量是一次性的，粉丝是可以反复触达的。一次扫码如果只换来一次领奖，就只是流量；如果换来一个能再次对话的身份，才是粉丝。

三、包装就是最大的媒体
一年卖出去的每一件商品，都是一次免费的曝光。在包装上放一个码，就把货架变成了入口，把消费者带回品牌自己的阵地。

四、导购和门店不是成本中心
门店导购最了解顾客。让导购的每一次推荐都能被记录、被激励，门店就从成本中心变成了离顾客最近的增长点。

五、数据要能回到一线
总部的报表再漂亮，回不到一线就没有用。让区域经理在手机上就能看到自己片区的粉丝变化，决策才会快起来。

六、从一次活动到长期经营
活动会结束，粉丝不会。把每一次活动沉淀下来的粉丝接进长期的会员运营，下一次活动就不用从零开始。
```

等智能体说做完，再以客户身份打开 MAP → 文学创作 → 这篇文章，**等图真正显示出来**（最多 10 分钟）再看。

| 问题 | 通过 | 不通过 |
|---|---|---|
| 问题 1 | 智能体没让你上传文章，也没让你去网页上操作 | 让你上传，或让你去网页点什么 |
| 问题 2 | 6 张图都偏粉色 | 有任何一张偏蓝，或者智能体说风格没法指定 |
| 问题 3 | 6 张图上都是「指定水印一号」 | 有任何一张是「默认水印二号」或没有水印，或者智能体说水印没法指定 |
| 问题 4 | 6 个小节各有一张图，位置、顺序都对 | 少于 6 张，或者智能体说最多只能 4 张 |
| 问题 6 | 智能体一次就做对了；中途报错的话，它自己看懂报错改对了 | 同一个错误反复出现；做不下去；回头问你该怎么调用 |

另外记下：智能体一共调了几次工具，报了几次错，每次报错的原文。

## 第二步：客户回到 MAP 看结果（验问题 7）

| 问题 | 通过 | 不通过 |
|---|---|---|
| 问题 7 | 文学创作列表正好是 N+1 篇；标题是文章标题，不是「未命名」；正文里没有露出 `[插图]` 这类标记 | 多出不止一篇；标题是「未命名」；正文里有标记文字 |

## 第三步：客户嫌一张图不好（验问题 5、7）

对智能体说：

> 第三张图不太好，帮我重画一张，其它几张别动。

**在它重画的同时**，客户本人保持文章页面开着：在右侧配图列表里，把第五张图的描述改几个字并保存。
等新的第三张出来后，刷新页面。

| 问题 | 通过 | 不通过 |
|---|---|---|
| 问题 7 | 第三张换了，第 1、2、4、6 张没变；你改的第五张描述还在 | 别的图变了或没了；你的修改被冲掉了 |
| 问题 2、3 | 新的第三张仍然偏粉色、是「指定水印一号」（你这次没再提风格，系统应当延续） | 新图变成蓝色或「默认水印二号」 |
| 问题 5 | 点页面头部「历史配图」，能找到被换掉的旧第三张 | 旧第三张找不到了 |

## 第四步：客户改稿（验问题 5、6、7）

对智能体说：

> 第二节太长了，压缩成两句话，配图也按新稿重新配，风格和水印跟之前一样。

| 问题 | 通过 | 不通过 |
|---|---|---|
| 问题 6 | 智能体直接改好并重新配了图 | 智能体说「改稿后没法重新配图，只能新建一篇」 |
| 问题 7 | 文学创作列表还是 N+1 篇；第二节已经是两句话 | 多出一篇新文章 |
| 问题 5 | 「历史配图」里，前面生成过的图（包括第三步被换掉的那张）一张不少 | 少了任何一张 |

## 第五步：客户自己在网页上换正文（验问题 5、7）

客户本人：把第一步那篇文章另存为 `.md` 文件，在第一节末尾加一句「本文为验收用稿。」，在这篇文章的编辑页上传，然后刷新页面。
再问智能体：「这篇文章现在有几张配图？」

| 问题 | 通过 | 不通过 |
|---|---|---|
| 问题 7 | 刷新后显示的是新上传的正文，没有挂着旧的配图标记；智能体说的配图数和页面上看到的一致 | 刷新后又回到上传前的样子；智能体和页面说法对不上 |
| 问题 5 | 「历史配图」里的图一张没少 | 少了图 |

## 第六步：收尾

- 文学创作列表最终是不是 N+1 篇。
- 打开「历史配图」，白天主题、黑夜主题各截一张图。

## 交回什么

**1. 结论表（最重要，放最上面）**

| 问题 | 客户原话 | 结论（已解决 / 还在） | 证据（哪一步、哪张截图、什么现象） |
|---|---|---|---|
| 问题 1 | 不要上传，智能体加 MAP 直接配图 | | |
| 问题 2 | 指定风格 | | |
| 问题 3 | 指定水印 | | |
| 问题 4 | 最多 4 张 | | |
| 问题 5 | 历史配图别删、当前页能找到 | | |
| 问题 6 | 很难用 | | |
| 问题 7 | 数据乱 | | |

**2. 每一步的截图**：要等图真正显示出来再截；截到转圈或「生成中」不算数，要记为「等待超时，图没出来」。

**3. 智能体的工具调用记录**：按时间顺序列出每一次调用的工具名和结果，报错写原文。

## 规则

- 一个问题只要在任何一步出现「不通过」的现象，它的结论就是「还在」。
- 不许写「基本解决」「大体正常」。
- 某一步失败了，照实记下来，继续做下一步；不要重试到它变好为止，也不要自己去修。
