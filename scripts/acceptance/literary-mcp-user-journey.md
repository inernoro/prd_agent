# 文学创作 MCP 验收：从用户提问题的地方重演一遍

这份是**发给执行验收的智能体的原文**，从「一、你要做什么」开始整段复制即可。

为什么这样验：上一轮验收按开发者思路写判据（接口返回了没有、图出来了没有），
所以用户真正遇到的问题一个都没测到。这次不写接口判据，而是把用户当初遇到问题的那条路**原样再走一遍**，
看那些问题还会不会出现。问题都出自用户的原话：

| 来源 | 用户原话 / 现场 |
|---|---|
| 最初的需求 | 文学创作能不能不要让用户上传文章，直接用智能体工具加 MAP 就能生成图片 |
| 第二个需求 | 我希望看到文学创作的历史配图，并不要删除它，最好在当前页面就有一个列表能找到这篇文章所有的图 |
| 使用反馈 | 能用，但是很难用，会导致数据乱 |
| 智能体现场 | 「图片风格使用全域粉销风格，水印使用水印配置1」——智能体答：风格和水印是平台预设、不在 API 参数里，没法指定；单篇最多 4 个配图标记 |

---

## 一、你要做什么

你要扮演两个角色，**严格分开**：

- **演员**：一个刚接上 MAP 的普通智能体。你**只能**用 MAP 提供的 MCP 工具干活，只看工具自己的说明。
  不许读 MAP 的代码、文档、接口说明，不许用 curl 直接调接口。原因：要测的就是「一个普通智能体只看工具说明能不能用好」，
  你知道得比它多，测出来的结果就不作数。
- **用户**：一个写营销文章的人。你用浏览器打开 MAP 网页，像普通用户一样点导航进去看（不许在地址栏直接输网址），
  看到什么就记什么，不解释原因，不替系统找理由。

每一幕做完，按第五节的表格填一行。**出现问题信号就照实记 FAIL，然后继续下一幕**，不要停下来修，也不要重试到它变好为止。

## 二、还原用户现场（第 0 步，用户角色在网页上做）

用户当时的账号里已经有一套叫「全域粉销风格」的风格和一套叫「水印配置1」的水印，但它们**不是**默认启用的那一套。
把这个现场原样搭出来，并让两套之间**一眼能看出区别**——否则你没法从图片上判断用的是哪一套：

1. 文学创作 → 风格 / 参考图：
   - 建「日常蓝调」：参考图用一张以蓝色为主的图，**设为当前启用**
   - 建「全域粉销风格」：参考图用一张以粉色为主的图，**不要启用**
2. 水印：
   - 建「水印配置2」：文字写「默认水印二号」，**绑定到文学创作**
   - 建「水印配置1」：文字写「指定水印一号」，**不要绑定**
3. 百宝箱 → 智能体接入 → 连接新客户端，勾选「文学创作」，复制 sk-ak 密钥。
4. 演员会话接上 MAP：MCP 地址是预览域名后加 `/api/mcp`，认证头填 `Authorization: Bearer sk-ak-...`
   （Claude Code 用 `claude mcp add`，其它客户端按各自的方式加远程 MCP）。
   预览域名由主控方提供，或在仓库根目录跑 `python3 .claude/skills/cds/cli/cdscli.py --human preview-url` 取得，不要自己拼。
5. 记下文学创作列表里现在一共有几篇文章（记作 N0）。

判读方法：图偏粉色 = 用了「全域粉销风格」，偏蓝色 = 用了默认风格；图上写着「指定水印一号」= 用了「水印配置1」，
写着「默认水印二号」= 用了默认水印。

## 三、要配图的文章（第一幕原样发给演员）

```
全域粉销：把每一次曝光都变成可以再次触达的粉丝

一、为什么是「全域」
过去品牌把预算拆给不同渠道，每个渠道各算各的账。线上投放、门店活动、包装扫码，彼此不认识同一个顾客。全域的意思，是让这些触点认出同一个人。

二、从流量到粉丝
流量是一次性的，粉丝是可以反复触达的。一次扫码如果只换来一次领奖，就只是流量；如果换来一个能再次对话的身份，才是粉丝。

三、包装就是最大的媒体
一年卖出去的每一件商品，都是一次免费的曝光。在包装上放一个码，就把货架变成了入口，把消费者带回品牌自己的阵地。

四、导购和门店不是成本中心
门店导购最了解顾客。让导购的每一次推荐都能被记录、被激励，门店就从成本中心变成了离顾客最近的增长点。

五、数据要能回到一线
总部的报表再漂亮，回不到一线就没有用。让区域经理在手机上就能看到自己片区的粉丝变化，决策才会快起来。

六、从一次活动到长期经营
活动会结束，粉丝不会。把每一次活动沉淀下来的粉丝接进长期的会员运营，下一次活动就不用从零开始。
```

## 四、剧本（每一幕都先把「对演员说的话」逐字发过去，再按「观察」做）

### 第一幕：用户最初的请求

**对演员说**（连同第三节的文章一起发）：

> 这篇文章使用 MAP 平台进行配图，每个小节配一张图，图片风格使用全域粉销风格，水印使用水印配置1。

**观察**：
- 演员有没有让你上传文章，或者让你去网页上点什么？（用户最初的需求就是不想这样做）
- 演员有没有说「风格 / 水印是平台预设，没法指定」，或者「最多只能 4 张」？
- 最后是不是 6 张图都出来了？等到图片真正显示出来再判，最多等 10 分钟。看到的是转圈、「生成中」就截图，不算数。
- 6 张图是不是都偏粉色、都写着「指定水印一号」？
- 演员一共调了几次工具，中途报了几次错，每次报错之后是怎么处理的？全部记下来（「难用」就体现在这里）。

**问题信号**：要你上传或去网页操作；说做不到 / 只能 4 张；少于 6 张；颜色或水印不是指定的那套；
同一个错误反复出现、演员绕不出来。

### 第二幕：用户回到 MAP 看结果

**用户角色操作**：登录 MAP → 左侧导航「文学创作」→ 找到这篇文章，打开它。

**观察**：
- 文学创作列表里是不是**正好多了 1 篇**（列表应为 N0 + 1 篇）？标题是不是这篇文章的标题，而不是「未命名」？
- 打开后 6 张图是不是在各自小节的位置上，顺序对不对？
- 正文里有没有残留 `[插图]` 这类标记文字？

**问题信号**：多出不止 1 篇；标题是「未命名」；图不全、位置错、顺序乱；正文里露出标记文字。

### 第三幕：用户不满意其中一张

**对演员说**：

> 第三张图不太好，帮我重画一张，其它几张别动。

**用户角色同时做**：在演员重画的过程中保持文章页面开着；在右侧配图列表里打开第五张图的描述，随便改几个字并保存。

**观察**（等第三张新图出来后刷新页面）：
- 第三张换成新图了吗？其它四张（1、2、4、6）有没有变？
- 你对第五张描述的修改还在吗？
- 新的第三张是不是仍然偏粉色、写着「指定水印一号」？（演员这次没被提醒风格，它应该自己延续用户要的那套）
- 点页面头部的「历史配图」：被换掉的旧第三张还能找到吗？

**问题信号**：其它图变了或消失了；你的修改被冲掉了；页面显示的状态和演员说的不一致（比如演员说「画好了」，页面还在转圈）；
旧的第三张找不到了。

### 第四幕：用户改稿

**对演员说**：

> 第二节太长了，压缩成两句话，配图也按新稿重新配，风格和水印跟之前一样。

**观察**：
- 演员有没有说「改稿后没法重新配图，只能新建一篇」？
- 文学创作列表还是 N0 + 1 篇吗？（改稿不应该多出一篇新文章）
- 打开文章：第二节已经是两句话，配图是新的。
- 「历史配图」里，第一幕到第三幕生成的所有图（包括第三幕被换掉的那张）是不是都还在？

**问题信号**：要求新建一篇；列表多出文章；旧图少了任何一张。

### 第五幕：用户自己在网页上重新上传正文

**用户角色操作**：把本文档第三节里那篇文章另存成 `.md` 文件，在第一节末尾加一句「本文为验收用稿。」，在这篇文章的编辑页上传它。
然后刷新页面。

**观察**：
- 刷新后页面显示的是新上传的正文吗？还是又变回了上传前的旧标记、旧配图？
- 「历史配图」里的图有没有少？
- **对演员说**：「这篇文章现在有几张配图？」——它的回答和你在网页上看到的一致吗？

**问题信号**：刷新后回到旧状态；旧图少了；演员说的和页面看到的对不上。

### 第六幕：收尾

- 文学创作列表一共是不是 N0 + 1 篇？
- 打开「历史配图」，白天主题、黑夜主题各截一张图，截图里要看得到所有旧图。

## 六、判定规则（不许改）

- 任何一幕出现「问题信号」，这一幕就是 FAIL。不许写「基本通过」「大体正常」。
- 截图必须是图片真正显示出来之后拍的；截到转圈、「生成中」，就记为「等待超时，产物未出现」，这一幕记 FAIL。
- 某一幕失败后，不要重试到它变绿为止，照实记下来继续往下走。
- 最终结论：六幕全部 PASS 才算通过；任何一幕 FAIL 都算没通过，并在最上面写清是哪几幕。

## 七、给主控方：事后复核

剧本跑完后，可以再跑一次 `scripts/acceptance/literary-mcp-driver.py` 做机器复核（判据见同目录 README）。
它查的是剧本里看不到的那一层：幂等重试会不会重复入队、无水印对照图是不是真的没打水印。
它只能补充剧本，不能替代剧本——用户遇到的问题都出在真实操作顺序里，只靠接口判据测不出来。
