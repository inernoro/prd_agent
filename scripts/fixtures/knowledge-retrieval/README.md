# 知识库检索固定评测

这套隔离语料包含 13 篇短文与 36 个固定问题：12 条直接表达、10 条同义表达、6 条跨文档、4 条无答案、4 条无权限。`secret` 是专门构造的权限探针，不能导入提问者的可读库。语料属于受控工程验收，不代表真实用户问题的分布。

当前主干基线 `3035365def7b30a28309b89a21756717fda846dd`：文档目录按标题、摘要与前 2000 字预览做字面量搜索；向量存储、切块和网关通道存在，但没有调用它们的检索服务。网页“向我提问”读取当前网页，未接知识库。离线重放这套问题的字面量语义，28 条有答案题 recall@5 为 0；这不是线上 API 实测，也不代表人工换关键词后的能力。

## 重跑基线

在仓库根目录运行：

```sh
python3 scripts/acceptance/kb-retrieval-eval.py --mode baseline --output work/kb-baseline.json
```

脚本不调用模型、不改任何知识库。Python 字符串扫描耗时不能当作系统检索延迟，报告中的 API 延迟、引用正确率与无依据作答率保持空值。

## 真实模型评测

先在统一模型网关为既有“知识库-文档向量化”“知识库-检索向量化”配置相同的 embedding 模型，为既有网页提问配置 chat 模型；不另设模型 URL、key 或模型名配置。Stub 结果不能用于语义效果验收。

在已确认的分支预览中，用正常登录与导航创建一个临时私有知识库，导入 `corpus.json` 中 `access=reader` 的十二篇正文；用另一个无共享关系的账号创建另一临时私有库，只导入 `secret`。两库都不得公开或共享给对方。创建本人托管网页并开启“向我提问”。记录站点ID、两库ID和固定语料到实际条目ID的映射。映射放在 `work/kb-mapping.json`，格式如下：

```json
{
  "siteId": "本人的测试网页ID",
  "storeId": "可读测试库ID",
  "deniedStoreId": "另一账号的不可读测试库ID",
  "entries": {"index": "实际条目ID", "access": "实际条目ID"}
}
```

`entries` 必须列全十二篇可读文档。令牌通过安全环境变量 `KB_EVAL_TOKEN` 提供，不写进文件或命令历史。显式指定测试预览地址后运行：

```sh
python3 scripts/acceptance/kb-retrieval-eval.py --mode live --base-url "$KB_EVAL_BASE_URL" --mapping work/kb-mapping.json --output work/kb-live.json
```

脚本只读这两库，通过已有问答 API 发起付费模型调用，不创建、重建或清理任何库。运行前自行确认是隔离测试库与获准的模型额度。脚本结果记录逐题命中、引用回读、错误与延迟；不记录令牌或原文全文。

- recall@5：每题前五个片段覆盖的相关文档比例，28 条有答案题宏平均。请求错误仍以 0 进入分母。
- 引用正确率：引用链接指向预期库和条目、原文接口回读成功、摘录与内容哈希相符，并属于固定相关文档。还须人工逐题检查摘录能否充分回答问题；引用可打开不等于回答充分。
- 无依据作答率：完成回答中，非拒答且无有效依据的比例；拒答计入完成回答分母。超时、配置错误和 HTTP 错误不冒充正确拒答，单列错误数。
- 检索延迟：Worker 内刷新、查询向量化、排序和原文核验之和，报告 p50/p95；另列包含排队及回答核对的端到端耗时。冷启动建索引与热查询必须分别保存结果，不混成一个数字。
- 无权限：四道题直接指定不可读库，必须 403、零检索结果、零上下文与零私密探针泄露；不能仅在结果展示时隐藏。

失败可能仍消耗模型额度。若缺模型凭据、模型绑定不兼容、网关不可达或预览无法访问，保持实际指标为空并报告阻塞，不用桩向量或预期答案填数。

## 用户路径与时效验收

正常登录 → 左侧“网页托管” → 打开本人网页预览 → “向我提问” → 在“回答依据”选择测试库 → 用自然语言提问 → 阅读服务端摘录 → 点击“打开原文” → 阅读器打开对应条目。跨文档题应有两篇原文，无答案题应明确拒答；在浅色与深色主题都走一遍。分享与团队访客不能使用此入口读取自己的私有知识，避免将内容写进站点所有者的会话审计。

随后修改正文并保存，再次提问；删除一篇文档再提问；用原本可读的团队库撤销共享后再提问。下一次请求读取当前正文与权限，120 秒内返回新结果或明确失败；不得返回旧片段。等待期间修改、删除或撤权，应阻断本次引用输出。正在更新的新内容若无法及时完成索引，不承诺成功回答。服务不会周期扫描或重建生产全库。

本地 Mongo 集成测试使用桩模型证明 Worker、增量复用、跨文档引用、真实正文、更新删除撤权与错误路径。它不证明语义召回、真实模型可用、浏览器引用链接打开或公网延迟。完成远端验收后，将评测报告、原文回读与真实浏览器路径证据归档至验收知识库，并只清理本轮自建的测试数据。
