你能得到什么

这一屏答一个问题：这次改动做完，你手上多了什么、少了什么麻烦。下面每一条都在后面章节有对应的验收判据。

一个入口

左侧导航多一项「对话」。登录进去就能说话，没有第二次认证、没有装客户端。

多轮不丢

任务在服务端跑完。关掉页面、刷新、换设备回来，进度和内容都还在。

对话里出图

说一句「画一张海报」就出图，图直接落进你现有的素材库，不用另开视觉创作页。

对话里存档

一句「记下来」就写进知识库，给你一条能点开的链接。下次直接问，它自己去翻。

不自己造轮子

agent 循环直接用官方 Claude Agent SDK，我们只写适配。不新建运行时、不新建鉴权，回滚等于删一个路由。

首版明确不给你的（写在这里就是承诺不偷偷做，也不假装有）
  • 联网搜索、抓网页
  • 上传文件让它读（长文档解析）
  • 自定义人设 / 角色市场
  • 跨会话长期记忆（换个会话它不记得你）
  • 把百宝箱里所有工具一次性接进来

这五条不是做不了，是首版故意不做。全部进技术债务台账，等这一版被真人用起来再按真实呼声排序。

S2

架构图

谁做什么

先答最要紧的一句：对话的 agent 循环用官方 Claude Agent SDK，我们一行都不写。它已经在这个仓库里跑着（就是驱动那个工程对话入口的同一个运行时容器），我们只做适配。

先把四个东西分清楚

这四个名字经常被混在一起讲，其实职责完全不同。表看完再看图。

名字它到底是什么跑在哪对外域名本次动它吗
MAP业务主体，就是你天天用的这个平台（后端加管理前端）主服务容器有 新增：对话页、对话接口、事件翻译、三把工具的实现。本次写的代码全在这里
agent 运行时
claude-sdk-sidecar		 Agent 的大脑。内核是官方 Claude Agent SDK，循环、上下文管理、工具调用协议全是它自带的 独立容器，只在内网，和主服务是邻居无 复用：不改它的代码，只是多一个调用方
模型网关
llmgw		 管模型池、调度和调用日志的那一层。已经有一个和 Claude 原生格式兼容的入口 独立容器有，独立子域 复用：运行时把模型请求指向它，日志与模型池自动生效
CDS部署平台。负责把上面这些编排进分支预览平台自身有 不动。它是「部署在哪」，不是并列的一个部件
CDS Agent 是一个功能，不是一个部件。它用上面那个运行时去做基础设施运维操作 ———— 不用、不改。你说的那一坨指的是这个功能，不是那个运行时

这一行是本次方案的关键区分：运行时是好的，那个功能的部署姿势才是问题。它把运行时用在了跨容器的分支预览场景， 于是链路长、要二次认证、延迟高。通用对话不走那条路——运行时就在主服务隔壁的内网里，一跳就到。

本次新增（我们写的） 复用现有（别人写的，不改） 用户侧 明确不碰

写与不写的分界线

别人写好的，直接用，一行不碰

  • agent 循环：什么时候继续问、什么时候收尾，SDK 自己管。
  • 上下文管理：历史怎么裁、怎么压缩，SDK 自己管。
  • 工具调用协议：模型怎么声明要用工具、结果怎么回灌，SDK 自己管。
  • 流式协议：文字增量、工具开始、工具结果、用量、终态，运行时已经吐好了。
  • 轮数上限、超时、取消：都是传给运行时的参数，不是我们实现的机制。

我们只写这四样，别的一律不写

  • 会话与消息的存储、断线续订（复用平台已有的任务与事件流）。
  • 把运行时的事件翻译成页面上的消息气泡与工具卡。
  • 三把工具的实现，各自转发给平台已有的出图与知识库能力。
  • 对话页面本身。
  • 明令禁止：自研 agent 循环、自研 SDK、自研工具调用协议。命中即熔断。
为什么这么接，模型池和日志还能生效

官方 SDK 允许把模型请求指向任何一个格式兼容的地址。我们的网关正好已经有这样一个入口， 而且带模型池路由与调用日志。于是「用别人的 SDK」和「模型仍归我们的网关管」这两件事不矛盾—— SDK 负责怎么思考，网关负责用哪个模型、记什么账。两边都不用为对方改代码。

S3

数据流转与鉴权

数据从哪来、经过谁、每一跳拿什么凭据。橙色是我们新增的执行节点，绿色是别人的现成部件，灰底菱形是鉴权点。注意第 4 步：循环在运行时里，不在我们这儿。

四个鉴权点，一句话各自说清

鉴权点这一跳是谁在调谁拿什么凭据为什么不是新东西
A浏览器调 MAP你现在登录平台用的那把凭据，一模一样不新建登录、不发第二把钥匙、不做设备配对
BMAP 调 agent 运行时运行时的内网令牌，服务之间用，走内网不出容器网络这条链路已经在跑着，本次只是多一个调用方
C运行时调模型网关网关的服务密钥，用户看不到也不需要知道网关早就在用，本次只是把运行时的模型出口指过去
D工具桥回调 MAP 读写你的数据沿用发起这次对话的那个人的身份，权限不放大工具桥与权限判断都是现成的，原样复用
这里没有「超远距离传输」

鉴权 B 那一跳是同一个容器网络里的邻居调用，不出机房、不经公网、不需要用户再认证一次。 你之前遇到的延迟和认证麻烦，来自那个运维功能把运行时放到了分支预览里、隔着好几层往回打。 本次的部署姿势不同，所以那些问题不会跟过来。

失败了会怎样（这一段决定它像不像个成品）

哪里坏了页面上你看到什么数据会不会烂在半路
模型超时或报错这一轮转红，写清是模型的问题，给「重试这一轮」按钮不会。这轮标记失败，历史完整保留
agent 运行时挂了明确提示运行时不可用，而不是假装在思考不会。任务标记失败，可重新发起
出图失败工具卡转红并写原因，对话继续，可换描述再来不会。出图任务本来就有失败态
知识库写入失败工具卡转红，明确说没存进去，不给假链接不会。写入是一次原子操作
你把页面关了下次进来接着看，中途内容按序号补齐不会。任务在服务端跑完
模型绕圈停不下来到轮数上限自动收尾，如实说卡住了并给出已完成部分不会。上限是传给 SDK 的硬参数，不靠模型自觉

角色业务流

防断头用的。每条链路的终点必须是「这个人手里拿到了东西」，不能停在「系统提交成功」。终点格子是绿的才算数。

普通用户不懂技术，只想要结果
登录用现在这把账号，不做任何额外配置
点左侧「对话」不用记地址，不用问同事在哪
直接说话空会话有三个建议问法兜底
看它干活阶段名和进度一直在变，不是干等
拿到产物图在对话里、条目有链接、答案带出处
终点检查图必须真的显示出来才叫完成，卡在「正在生成」不算。入库必须给能点开的链接，不能只说「已保存」。
产品经理要把结论沉下来，还要给团队看
把会上结论粘进来让它整理成条理清楚的一段
说「记进知识库」它自己选空间、起标题，你可以否
点链接核对当场打开看排版对不对
把链接甩群里用现有的分享能力，不用新学
终点检查链接必须是团队点开就能看的那种，而不是只有本人能看的私有草稿。权限沿用文档空间既有规则。
管理员 / 开发要能查、能限、能背锅

终点检查「页面选甲、后台跑乙」是本仓库出过的老问题，所以这条被写成验收判据第 6 条，必须当场对得上。
S5

验收方式

你自己就能核

防自嗨用的。每条判据都写清「谁来核、怎么核、什么算过」，不接受「我通读自审过」「代码逻辑没问题」这类说法当证据。第 7 条专门用来卡「有没有偷偷自己造轮子」。

#要证明什么你怎么亲自核谁来核什么算过
1真能多轮连问三句，第三句里说「按你第一句说的那个来」你它接得住，没重新问一遍
2断线不丢它正在干活时刷新页面，或者直接关掉过一分钟再进你回来内容齐全，任务照跑完
3出图闭环说「画一张横版的发布日海报」，然后一直等到底你图真的显示在对话里。停在进度条上不算
4入库闭环说「把这套配色记进知识库」，然后点它给的链接你链接能打开，内容就是刚才那段
5检索闭环新开一个会话，问上一步存的那件事你答得出来，且标了出处能点开
6模型没串页面上指定一个模型，去网关日志查这一次调用管理员日志里跑的就是你选的那个
7没有自研循环看改动文件清单，搜有没有「问模型 - 调工具 - 回灌 - 再问」这类代码评审一行都没有。循环全在运行时的官方 SDK 里
8没有越界看改动文件清单评审运行时内核、那个运维功能、鉴权，三者一个字未碰
9两套皮肤都行白天黑夜各切一次，各截一张图验收不破版、不出现看不清的字
10等待期有内容盯着任一超过两秒的等待验收屏幕上一直有东西在变，不是一个死转圈
11失败讲人话故意写一句会让它失败的要求验收红态 + 说清原因 + 会话还能继续

算数的证据

  • 在真实预览地址上、从左侧导航点进去截的图，地址栏可见。
  • 白天和黑夜两套各一张，页脚的部署标记入镜，证明是最新那一版。
  • 出图那张必须拍到图本身，入库那张必须拍到点开后的条目。
  • 验收报告归档进验收中心，给一条能直接打开的深链。

不算数的证据

  • 「接口返回成功」「测试全绿」——这些是必要条件，不是验收本身。
  • 截图里还在转圈，说明文字却写「已完成」。这叫断头验收，直接退回。
  • 用旧版本的截图充数。
  • 「我通读了两遍代码，逻辑没问题」。
  • 只测新建的会话，不测刷新后的老会话。
S6

范围契约

防止两个月做成一坨。这一节是可以拿来卡我的：越过下面任何一条线，你有权叫停。

本期做这些（就这么多）

  • 一个页面：会话列表 + 消息流 + 输入框。
  • 一个执行器：问模型、调工具、回灌、再问，轮数有硬上限。
  • 三把工具：生成图片、写入知识库、检索知识库。
  • 一条权限、一条导航、一个百宝箱条目（先标未完成）。

本期不做（想做也不做，全进债务台账）

  • 联网搜索、抓网页、上传文件解析。
  • 自定义人设、角色市场、多智能体互相调用。
  • 跨会话长期记忆、用户画像。
  • 把百宝箱所有工具接进来。
  • 改任何现有表结构、改任何现有鉴权。
  • 自研 agent 循环、自研 SDK、自研工具调用协议。这条永远不做，不只本期。

熔断线：命中任意一条，立刻停下来找你，不许自己往前冲

  • 连续八个提交没有新增可用功能，只在改文档、改脚本、改计划。
  • 工具数量超过三把，或者有人提议「顺手把某某也接上」。
  • 出现任何自研 agent 循环、自研 SDK、自研工具调用协议的代码。这条是红线中的红线。
  • 改动伸进了 agent 运行时的内核代码，而不是只加适配与配置。
  • 改动碰到了那个基础设施运维功能、分支预览的运行时部署、或任何鉴权代码。
  • 改动行数超过第一轮基线的两倍，或者文件范围扩出第一轮清单。
  • 同一份计划文档被重写五次以上，而卡点没有消失。
S7

要你拍板的

六个岔路口

每个都给了默认选项。你什么都不说，我就按橙色那个走；想改哪个直接点名。

1入口放哪
左侧一级导航「对话」+ 百宝箱条目推荐。这本来就是个面向所有人的日常入口，藏在百宝箱里等于没有。百宝箱那份先标未完成，验收过了再转正。
先只进百宝箱，低调试水更保守，但用户找不到就没人用，也就拿不到真实反馈来排后面的优先级。
2首发是不是就这三把工具
就三把：出图、写知识库、查知识库推荐。这三把正好覆盖你问的「生图 + 本地持久化到知识库」，且底层全是现成的，接错的风险最低。
再加一把「查平台数据」能问「上周谁提了几个缺陷」这类问题，但要额外处理权限收敛，会让第一版拖长一到两天。
3会话数据存哪
新开一套独立的会话记录推荐。现有那套会话绑着产品需求解读的角色概念，混进来会互相污染，以后谁都不敢动。
复用现有会话表省一点建表工夫，但要给现有结构加通用字段，属于改存量，违反本期「不改现有表结构」。
4模型谁来定
默认跟随平台，页面上可切推荐。普通用户不用管，你和管理员想试新模型时当场切，还能顺带验证第 6 条判据。
完全由管理员锁死可控性最好，但用户遇到模型不给力时只能等人改配置。
5第一阶段做完就给人用吗
给，标未完成，收真实反馈推荐。纯多轮对话本身就有价值，早一天上线就早一天知道大家真正想要哪把工具。
三个阶段全做完再一起放观感更完整，但把「不要过度开发」的风险又拉回来了，中间没有任何真实反馈来纠偏。
6运行时自带的只读文件工具，通用对话要不要关掉

背景：agent 运行时目前默认开着三个只读文件工具（读文件、按内容找、按文件名找），是给代码审查场景准备的。通用对话用不上，而且口径讲不清。

关掉，只留我们注册的三把工具推荐。给运行时补一个按次生效的开关即可，属于适配层配置，不动 SDK 内核。用户问一句不会读到仓库文件，权限口径干净。
先不关，接受它能读仓库文件省一点工夫，但普通用户的对话会带着代码读取能力，出了事说不清是谁批准的。不建议。
S8

成本与退出

三个阶段，每个阶段自己就能验收、自己就能停。你在任何一个阶段结束时说「够了」，都能拿到一个完整可用的东西，不会留半截。

一
纯多轮对话，零工具

页面、转发与事件翻译、事件流、断线恢复。循环直接交给运行时，我们这一阶段一行循环代码都不写。这一阶段结束就已经回答了「有没有能对聊的智能体、在哪用」。

可停点：此时上线即可用，判据 1、2、7、8、9、10、11 全部可验。
二
挂上出图

第一把工具接进来，同时把工具卡这套交互定型，后面两把照抄。

可停点：判据 3 可验。到这里就回答了「能不能在对话里生图」。
三
挂上知识库读写

写入和检索两把一起上，因为它们要配套才有意义：存得进去、查得出来。

可停点：判据 4、5 可验。到这里三个问题全部回答完毕。

怎么退出

  • 关掉那条权限，入口立刻消失，其他人无感。
  • 不改任何现有表结构，回滚不需要数据迁移。
  • 不改任何现有鉴权，回滚不影响别人登录。
  • 新数据在独立集合里，真要清理就是删一个集合。

规模量级

  • 后端新增：一个接口层、一个转发与事件翻译层、三个工具适配。没有循环、没有 SDK。
  • 前端新增：一个页面，消息渲染直接复用现有组件。
  • 预计触及八到十二个文件，不含测试。
  • 超出这个量级就是走偏了，按熔断线处理。
