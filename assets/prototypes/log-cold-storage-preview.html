3. 数据与权限如何流动
① 管理员登录
现有日志权限 + 独立归档管理权限
② 归档任务
后台持久化任务与租约，读取完整 BSON，不调用大模型
③ 压缩与加密分块
每块记录范围、文档数、哈希与版本；限制内存、并发与带宽
④ 冷库与异机校验
使用存储服务凭据 / 受限 SSH 身份；凭据不进入浏览器
⑤ 原页面查询回读
鉴权后读取、校验和解密，原请求号可定位完整正文
失败点用户看到数据去向
存储或异机不可达归档未完成，可重试；原日志仍在不修改热库，不生成成功回执
校验不一致 / 解密失败恢复校验未通过，保留原件并提示管理员核查隔离该块，禁止冷热迁移
进程重启 / 中途取消任务中断，可续跑已确认批次临时块不进入正式索引，不重复删除或计费
磁盘或资源不足暂停归档，等待容量恢复保留全部已确认数据，业务请求优先

5. 你可以怎样验收
要证明什么怎样自己核对通过条件
日志不丢选一条旧日志归档，再用原请求号打开原文、时间、状态、关联信息与归档前一致
归档失败不损坏数据模拟存储失败，重新查看原日志原文仍完整；页面不给“成功”
异机副本不是空文件查看批次哈希与文档数，再下载解压副本哈希匹配，可读且记录数一致
真正可以恢复在隔离实例恢复本次备份并查询全程不写正式库，文档数/索引/关键查询检查通过
权限有效使用无日志权限的账号尝试打开正文或下载拒绝访问，不泄漏存储密钥或正文
正式服务保持可用备份归档期间正常使用业务入口资源限制生效，业务探针与延迟达标，否则暂停后台任务
不作为通过证据：只有 API 成功、只看容器健康、只有 dry-run、只有旧截图或空的“已完成”页面。


6. 范围与阶段
步骤一：完整归档与校验
完整内容压缩加密保存到异机冷库；校验、实际回读及检索索引全部就绪前，保留热库原件。
步骤二：释放热库空间
全部安全条件通过后，清理热库对应的正文，保留检索索引，查询自动读取冷库；冷库日志完整保留，不设自动销毁。
备份与恢复演练独立进行
业务库和日志全部纳入异机备份；在工作站隔离 Mongo 中实际导入，核对记录与索引。旧大归档通过评估后才处理。
本期不做：修改正式库副本集拓扑、秒级灾备、跨地域集群、购买新云资源、删除唯一历史日志、给普通用户展示内部交付台账。
范围熔断与退出
增加清单外的业务模块、扩出约 25 个源文件、引入新公共容器、需要迁正式库拓扑或连续 3 个提交无可验证功能增量时，暂停并重新确认。关闭归档开关可停新增任务；已经归档的块仍可读取，未通过验证的热库正文不会清理。


7. 决策与成本
决策默认建议替代选项的影响
功能入口MAP 系统日志中的“归档日志”入口已确认；备份与恢复仍由独立运维流程管理
是否删除原文校验回读成功后迁出热库正文，冷库完整保留只保存副本不会释放正式机空间，因此不作为最终策略
冷库位置先使用已授权的私有异机存储；对象存储必须私有或先认证加密工作站离线会使归档暂停；独立长期在线存储需另确认资源
投入边界分阶段交付，每阶段有可独立核对的产物；不触发付费模型容量与读取费用取决于现有存储；不在本次自动购买
当前正式 Mongo 为单节点，在线逻辑备份包含一个时间窗口，不能称为事务级同一时点快照。恢复演练会明确标记这个边界。
这是功能方案预览。演示数据为虚构记录，正式环境状态须以实际备份和恢复证据为准。
