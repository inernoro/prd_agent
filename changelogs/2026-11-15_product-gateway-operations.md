# 2026-11-15 LLM Gateway 运维任务连续性与页面治理

## 已实施

- 概览优先展示最近请求，直接进入所选请求详情，保留原统计范围；显示数据生成时间、失败请求入口。服务连通状态不再暗示所有上游可调用；统计读取失败与真实无请求分开展示。
- 请求页以 URL 白名单筛选为唯一来源。打开/关闭详情不清空筛选；独立详情、调用链和原请求之间保留任务身份与固定时间窗。调用链返回可恢复本标签页最近五分钟内已加载的列表摘要、选中行和滚动位置；刷新/超时后显示明确的原请求锚点，不持久缓存正文或凭据。退出、身份或租户权限变化清除摘要。
- 详情先展示完整失败依据与只读调用链核因入口，保留费用未知/明确零值、模型回退三态和逐次上游尝试。调用链减少重复卡片，身份编号与关联/费用规则按需展开；单页不显示无意义翻页。
- 审计读取失败仍保留筛选并可重读，少量数据自然结束，单页不显示 1/1 翻页。登录页改为单列账号表单，明确控制台账号、MAP 入口和应用密钥的边界。
- 与公开模型工作台统一导航名称为“公开模型”。

## 验证与边界

- 同一 DOM 连续旅程在旧源码上因返回丢失已加载批次失败，新实现通过；覆盖迟到筛选响应不能覆盖恢复列表。费用和回退既有展示测试继续通过。
- 已完成 1440/390 宽、明/暗主题的同数据浏览器 fixture 对比和错误恢复操作，证据来源为 deterministic-fixture，不代表真实预览验收。
- 完整 Web build 已通过。独立审批及真实预览路径仍待收口，未以构建或 fixture 代替真实用户路径。

## 用量与限制可信恢复

- 限制未成功读取时显示未知，禁用编辑与保存，避免把初始空值提交成关闭限制。读取恢复后才填入真实配置，修改表单按需展开，预算占用、预占与速率状态继续常驻。
- 保存响应丢失与明确拒绝分开表达：结果未确认时保留本次草稿，阻止盲目重提，重新读取服务端限制后核对；保存反馈在操作旁带时间呈现。
- 用量聚合读取失败不再显示“暂无请求”；费用和账单仍区分未知、明确零值和真实空态。缺价模型入口保留对象名称进入详情，弱身份不承诺唯一线路。
- 确定性 DOM 测试旧基线因未知限制仍可保存失败，新实现覆盖失败读取、真实值恢复、编辑保存及 NETWORK_ERROR 信封的未知结果；浏览器四矩阵完成同一 fixture 路径。真实预览配置写入未执行。
