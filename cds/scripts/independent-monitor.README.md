# 独立 CDS 故障入口运维

探测器运行在被检查 CDS 之外。所有真实身份、地址、凭据和运行记录保存在服务器私有目录，禁止提交 Git。仓库只保存程序、测试与空配置约定。

## 私有配置

- Python 3；依赖固定在 independent-monitor.requirements.txt。
- config.json 必须为 0600，目录 0700。字段包括 cdsBase、headers、publicUrl、identity、publicIdentity、publicConsoleUrl、storage；可选 bark。
- identity 包含 observer（检查方）、subject（故障对象），各自包含稳定 id、name、environment，可选 location。使用业务别名，不从 IP、主机名或域名猜测身份。
- publicIdentity 只放明确允许公开的 name 和 environment，公开投影忽略位置、地址、密钥和额外字段。内部监控项目与读数只留在私有状态。
- storage 使用 region、bucket、objectKey、secretId、secretKey，对象存储凭据只存在运行配置。对象仅发布白名单摘要，公开读取；为独立页面来源配置 GET/HEAD CORS，保留已有规则。
- publicUrl 为独立 HTML 页面地址，片段 feed 指向公开摘要。片段不发送到页面托管服务器；同一浏览器后续从本地保存的 feed 继续读取。不要把实际地址写进 HTML 源码或示例。
- bark 使用 key、可选 serverUrl 与 iconUrl，仅私有文件可读；头像应为独立托管的公开 HTTPS 图片，不带签名参数。没有配置就明确显示未接通，不能视为已通知。
- 内部通知可在链接片段携带当时的名称、环境、采集结论与时间。片段不发送给静态托管服务器，不写入公开快照；页面明确区分通知时事实与最新外部检查。

## 启动与维护

使用隔离 Python 环境安装固定依赖，运行 independent-monitor.py --config 加私有配置路径；--once 执行一轮。systemd 采用专用服务账号、开机启动、失败重启、UMask=0077、NoNewPrivileges、PrivateTmp、只读系统目录，仅开放服务数据目录写权限，并限制内存与 CPU。

每分钟检查一次；页面每两分钟读取对象存储，数据超过三分钟明确显示过期。运行快照不再通过 Git 发布，也不依赖代码仓库的提交历史或匿名 API 配额。更换存储时先验证新摘要 HTTPS 与跨域可读，再切换通知入口并停止旧发布器。

## 告警边界

CDS 能给出新鲜汇总时，内部指标告警由 CDS 发送；入口失联、汇总不可读或检查停摆时才由外部接管通知。连续三次失败建立事件；同一事件持续更新，严重度升级仅通知一次；连续正常十分钟后恢复，采样空档不计入恢复。

通知写明检查方与故障对象，按对象稳定 ID 分组。改名不改变 ID；不自动互相重启。先发布快照再发送，失败最多重试三次，间隔五分钟；没有成功送达过故障，就不发恢复。网络响应丢失仍可能导致重复受理，不承诺网络层恰好一次。

## CDS 身份设置

系统设置 → 通知 → 通知身份，可修改当前实例名称、环境和可选位置。管理员也可用 cdscli monitor identity 查看，或加 --file 从私有 JSON 配置更新。真实配置文件不可加入版本控制。对端目标身份由 targets 按监控 ID 明确关联，不以名字猜测。

## 验证与回滚

运行 test-independent-monitor.py，覆盖持续事件、稳定恢复、采样间断、身份白名单和通知深链。验收还需检查实际快照更新时间、系统服务运行、身份显示、手机推送受理与页面滚动。独立页成功不等于 CDS 内部修复上线。

回滚时恢复上一版程序与配置，保留私有事件和投递记录；不要恢复向 Git 发布运行数据。暂停探测会使页面明确显示数据过期。

## 统一手机通知

主服务保留检查与持久化待投递事件，独立进程统一发送手机通知。接收端登记 RSA 公钥后，只能用对应私钥解开通道配置与事件信封；普通通道读取接口仍不返回密钥。解密就绪确认后才能切换发送所有者，切换后主服务不会因外部进程离线而自行恢复发送。

接收端额外依赖 `cryptography`。私钥、解密后的通道缓存、投递记录和配置文件仅保存在服务账号私有目录，权限 0600；不得进入仓库、公开快照或日志。独立进程持有文件锁，防止同一配置启动两个发送者。

同一数据源的采集异常按项目、环境和来源归并，真实指标失败独立记录。普通事件等待 30 秒归并；单次外部请求超时 15 秒，检查间隔与连续失败次数另外配置。稳定恢复沿用 10 分钟判据。Bark 无幂等投递凭证，发送超时记录为待核实，不盲目重发；需要在投递台账核实，不能声称绝对恰好一次送达。


## 第三方心跳哨兵

外部监控每轮成功发布快照即留下心跳；第三方只读取这个心跳，不探测主服务、不读取业务指标、不接管业务发送队列。主服务故障但心跳新鲜时不会再报外部监控故障。明确超过三分钟的快照建立一个失联事件；无法读取或格式异常跨两轮复核后建立同一类事件，文案说明无法确认，不能断言主机已宕机。

心跳恢复需至少三次正常检查并跨越十分钟；检查空档超过十五分钟会重新计时。同一事件仅尝试一次故障和一次恢复通知，持久化发送意图先于发送；未确认送达不自动重试，没有已受理故障就不发送恢复。下次独立失联建立新事件。

部署在独立状态页仓库的 GitHub Actions，使用统一 concurrency 队列；每五分钟调度，读取超时十五秒。GitHub 调度可能延迟或丢弃，公开仓库六十天无活动会自动停用定时工作流，因此这是尽力而为的第三方兜底，不是十五秒通知 SLA。需要严格时限时，应迁移至有可用性承诺的心跳服务，不增加第二个同时发送者。

配置只放 Actions 的 WATCHDOG_CONFIG Secret：heartbeatUrl、publicUrl、watchdogPublicUrl、displayName、environment、iconUrl、bark，以及 storage 的 region、bucket、secretId、secretKey、stateKey、publicKey。禁止保存到仓库、构建产物和公开日志。上线前须显式初始化版本为 1 的私有台账及独立演练台账；运行时台账丢失或损坏会失败关闭，禁止自动重建导致重复报警。存储 ACL 必须分别为台账 private、白名单摘要 public-read；摘要 CORS 沿用状态页来源。

只有该工作流写入台账，禁止从另一台主机并发执行同一配置。人工演练使用隔离台账和模拟心跳，实际业务监控持续运行；重复执行同一演练不重复通知。运行记录看 Actions 结果，事件与受理记录看私有存储，手机链接通过片段携带通知时事实和独立摘要入口。停用或回滚只停该工作流，保留台账，不能因此恢复主站直接发送业务通知。
