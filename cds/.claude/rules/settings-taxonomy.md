# CDS 设置页分组词表（Settings Taxonomy）

**一句话**：系统设置与项目设置共用六组词表（常用 / 接入 / 运行 / 数据 / 观测 / 危险区），新页签先回答「用户来这里要问什么」再落组，禁止新开组名、禁止把页签塞进大杂烩。
**什么时候撞上**：往 `CdsSettingsPage.tsx` / `ProjectSettingsPage.tsx` 加、挪、删页签，或给设置页写导航文案时。

---

## 判定口诀

**这个页签，用户来是要回答哪个问题？**

| 组 | 问题 | 例 |
|---|---|---|
| 常用 | 我今天最可能来点什么 | CDS 更新（只允许系统设置有这一组） |
| 接入 | 这是谁、从哪来、谁能进 | 登录、密钥、GitHub、评论模板 |
| 运行 | 它怎么跑起来 | 环境变量、项目配置、新分支默认、调度器 |
| 数据 | 它的数据放哪、分不分、备不备、搬不搬 | 数据库隔离、基础设施、存储、备份、迁移 |
| 观测 | 它跑得怎么样 | 统计、活动日志、Webhook 日志 |
| 危险区 | 删了就回不来 | 删除项目、危险操作 |

答不上来 = 页签本身没想清楚，先别加。

## 三条硬约束

1. **组名只能用词表里的六个**。`TabGroup.label` 的类型是 `SettingsGroupLabel`（`web/src/lib/settingsTaxonomy.ts`），写别的编译不过；不要为了「这个不太一样」新开一组——组少而稳，新功能落进既有组。
2. **顺序固定、危险区垫底、每个页签只登记一次**。守卫：`tests/web/settings-taxonomy-guard.test.ts`。
3. **一个页签四处登记才算通**：`TabValue` 类型、`tabGroups` 导航、`<TabsContent>` 面板、`settingsSearchIndex.ts` 的 `*_TAB_LABELS`（命令面板搜不到等于一半用户找不到）。周期备份与数据库隔离的守卫测试是范例，照抄。

## 易错两条

- 环境变量归**运行**不归数据：它是配置，不是数据本身。
- 缓存诊断归**数据**不归观测：它的动作是修盘、迁盘，不是看图。

## 数据分类（与分组正交）

「数据」组里每个页签都要能说出自己管的是哪一类：配置（能重建、备）/ 业务数据（不能重建、备）/ 运行态（能重建、不备、随分支删）/ 审计证据（不能重建、备）。定义在同一个文件的 `DATA_CLASS_META`，完整说明见 `doc/design.cds.settings-taxonomy.md`。

## 与其他规则的关系

- `scope-naming.md` 管「系统级还是项目级」（哪一页）；本条管「落哪一组」（页内哪一块）。两者都要过。
- 根 `.claude/rules/navigation-registry.md` 管功能入口要登记；本条是它在设置页内部的细化。

## 历史背景

2026-09-02 做「数据库隔离」项目级页签时发现：项目设置 11 个页签全在「运行时」组，用户找数据类设置没有落点；两页组名各写各的。用户提出「设置的分类、数据的分类做一个分类类别」，本规则与词表同批落地。
