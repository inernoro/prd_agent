为什么现状那一屏难看四条根因
1

结论位承载了整段原始日志

没有门禁 JSON 时 headline 取 errorLines[0]，而这条 error 自带 19 行 stderr 尾巴。一句话的位置装了 1418 个字符。

2

日志被当成散文排版

日志靠换行传达结构，<h3> 里换行全被折叠成空格，17px 粗体让每个字都在喊。

3

最该看的那句被压成灰字

「目标仍在 06efeb6」等于生产没受影响，却挂在文字墙下面 11px 的尾巴里。

4

五条重复告警各占一行

dedupeKeepOrder 只去重完全相同的行，curl 的重试告警因「N retries left」数字不同而全部逃逸。

刻意不做的事三条边界

不改后端接口

信息全部从 run.logs 现有行提取。识别不出就如实说「未能提取判据」，退回原文。

不做通用日志解析器

只加「产物下载失败」一种形状。不把 WARN 全当噪音，那等于关掉一整类真实告警。

不碰颜色系统

颜色全取自现有 token。红色只用于状态标识，正文一律常规前景色。
