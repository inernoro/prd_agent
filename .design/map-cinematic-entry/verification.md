# MAP 角色成形登录与沉浸首页交接

**一句话**：保留已认可的角色构图，重做线稿、网格、空间扫描和连续睁眼；以关键帧和真实登录验收。
**谁该读**：产品、设计与接手维护的人。
**读完能做什么**：理解视觉取舍、动作顺序、真实路径和降级边界。

## 参考与视觉决定

用户提供的原片为 3840×2160、60fps、19.317 秒。已按每秒一帧拆出 0–19 秒共 20 张图，重点核对 15 秒黑场、16 秒蓝色轮廓、17 秒闭眼与网格、18 秒半睁与品牌描边、19 秒睁眼和品牌填充。用户明确允许借鉴风格与另辟路径，不要求复制原品牌、原素材或每根头发。

上一版的问题已取证：密集边缘滤镜代替线稿；闭眼与睁眼整图交叠造成重影；品牌、导航和操作区过早一起出现。本轮采用本项目角色的独立矢量轮廓、贴合面部的曲线格网、沿空间推进的材质扫描，以及受同一时间线驱动的眼睑与局部皮肤形变。虹膜保持原位置，由移动眼睑逐渐露出；没有整张闭眼图向睁眼图交叉淡化。

沿用此前独立生成的开眼与闭眼角色图，未挪用参考视频品牌或素材。闭眼图作为局部皮肤及睫毛纹理来源，不作为覆盖虹膜的整图透明叠层。矢量线稿是本项目独立绘制的简化结构线，面部格网为二维曲面投影，没有声称使用三维骨骼角色。

## 入场顺序

| 场景时间 | 画面目标 |
|---|---|
| 0–2 秒 | 黑场中轮廓逐段生成，中央实际能力搜索随后就绪 |
| 1.55–2.6 秒 | 面部格网沿脸部逐渐展开 |
| 2.25–3.9 秒 | 材质按空间扫描推进，仍保持闭眼 |
| 4.45–6.05 秒 | 眼睑连续抬起、下缘放松，依次经过微睁、半睁和全睁 |
| 4.5–6.6 秒 | MAP 先描边，再填充；快捷入口随后进入 |
| 6.5–7.2 秒 | 导航渐入，结束后释放临时绘制资源并恢复通知弹出 |

身份核验仍以真实权限响应为准；成功后的白场到黑场衔接约 1.58 秒。无需等片头播完才能搜索；提前打开能力或工作台会恢复正常导航。手机操作区放到眼睛下方，保留角色动作的可见范围。

## 八维交接

| 维度 | 事实 |
|---|---|
| 入口 | 原登录页与首页；未新增 Agent、菜单或业务 API |
| 文档与决定 | 本记录解释原创取舍与阶段目标，验收图和播放记录保存在产品之外 |
| 契约与数据 | 沿用权限、SSO 回跳、首次改密与真实能力搜索；非首页回跳不启动首页片头 |
| 测试与证据 | 几何阶段、101 档眼睑连续性、准备超时、绘制降级、通知暂停与登录状态均有回归；逐帧和正常速度记录另附 |
| 发布与运维 | 按同提交 CI 与 CDS 发布；公网复测结果见交付记录；未发布生产 |
| 安全与隐私 | 不修改账户、权限和通知确认状态；凭据经内存管道传递，不进入源码、日志或报告 |
| 已知边界 | 不支持 WebGL 或绘制准备超时会立即恢复静态角色与可操作首页；减少动态效果时跳过片头 |
| 后续约束 | 替换角色画面时要重新校准线稿和眼睑位置；不要恢复整图交叠或用帧率代替视觉验收 |

## 验收方式

沿登录表单进入首页，按秒查看整体；睁眼段按 0.1 秒取样，并进行正常速度播放。检查虹膜是否提前出现、眼睑是否单一且连续、网格是否贴合、品牌是否分层进入、导航与通知是否在适当时机恢复。再从中央搜索进入真实知识库，并验证工作台往返与手机布局。

减少动态效果、绘制不可用和图片准备超时均须保持搜索与导航可见，不留下黑场。通知只暂停弹出及自动消费计时，结束后仍是原来的待处理通知。
