## 落地状态

2026-08-29 全部落地。**此处此前写着「2026-08-28 全部落地」，是错的**，纠正记在这里：
那天跑的 `/复刻` 只并排比了 `Curl` / `TestIO` 两屏（当天改的就是试跑区），
`Main` 那屏根本没进比对，却把「全部落地」写到了九张画板头上。结果是 `Main` 画板
最重要的两条结构改动整整少了一天没落地，直到用户拿着截图问「为什么和设计稿对不上」：

- **一次性密钥常驻在页签之上**（画板注释原话：它不再属于任何一个页签）。实现里它一直在
  「接入信息」页签内，和地址、用途三等分一行——切到 cURL 页它就消失了，而它是全屏唯一
  取不回来的东西。
- **页签降级成分段控件**。实现里是三张带副标题的大卡，和内容同重，占掉整整一行。

教训与判据同源：比对范围必须等于画板范围，只比「这次改过的那屏」就是用一屏的结论
去覆盖九屏（`predicate-and-wiring-discipline` 形状 1：判据比它该管的范围窄）。

守卫：`e2e/llmgw-quickstart-states.mjs`（输入输出同宽、空态占位、流式三点与耗时、
requestId 深链、「再跑一次」、输入内容进 cURL 与真实请求体；2026-08-29 新增两条钉住
上面那条结构约束——密钥主区必须排在页签容器之上、切到 cURL 页后密钥仍在。
做过红绿闭环：把密钥塞回「接入信息」页签，后者立刻红）。

## 偏差台账

| 项 | 处置 | 理由 |
|---|---|---|
| 输入框可上下拖拽调高（`resize: vertical`） | 有理由保留 | 画板画的是静态一屏，长提示词需要能展开；不影响与输出块的同宽同圆角 |
| cURL 页签整屏可纵向滚动 | 有理由保留 | 试跑区多出 88+88 之后，1440x900 内要么压扁这一对、要么把片段压成两行。判据改成「输入、输出与两个按钮必须在首屏内」，片段可落到折线以下；接入信息页仍是零滚动 |
| 浅色档输入框底 `--bg-input`（#ffffff） | 已改画板 | 画板原先画成 `#f1f5f9`，与仓库真实 token 不符——改画板对齐实现，而不是让实现偏离全站输入框 |
