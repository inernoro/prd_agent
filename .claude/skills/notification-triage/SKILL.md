# 通知分诊

1. 在 MAP 通知中心打开通知，核对环境、来源、请求结果和事故状态。使用请求编号查看网关日志，区分整个请求的结果和某条上游线路的结果。
2. 使用服务端已确认的原因和受影响范围分级。

   | 已确认的信号 | 通知决策 |
   | --- | --- |
   | 上游明确返回余额或额度耗尽、访问被拒 | 首次记录并提醒。整次请求失败标为紧急，已有备用结果或结果待确认标为重要。 |
   | 网关保护规则已拦截 | 首次记为重要。核对保护窗口、调用方与阈值。 |
   | 上游返回普通限流 | 首次记为一般。同一路线五分钟内连续影响至少三笔不同请求后升为重要。 |
   | 可用性失败 | 单次记录。同一路线五分钟内连续出现至少三笔不同请求失败后，按整次请求结果升为紧急或重要。 |
   | 接近限额、流量预警、恢复 | 保存在面板，作为观察和复盘信息。 |

3. 使用事故身份合并重复记录。身份要区分环境、部署、租户和线路。确认通知后继续依据后续实际调用判断是否恢复。
4. 额度耗尽时核对账户及可用线路。限流时核对限额类型、恢复窗口和受影响请求。遇到 CDS 入口持续失败时核对独立探测器的 DNS、TLS、HTTP 和采集日志。
5. 对有权限的值班人员给出已观察事实、影响、时间和可操作的下一步。保密凭据、原始请求与响应正文、供应商私密诊断。

运行时规则在 `prd-api/src/PrdAgent.Api/Services/GatewayNotificationPolicy.cs`，分诊前核对当前实现和通知链接。
