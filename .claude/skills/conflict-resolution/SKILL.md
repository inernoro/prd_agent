# 安全冲突处理

> 版本：v2.0.0 | 默认只在用户明确要求时执行

## 目标

在不覆盖用户工作、不猜测业务语义、不依赖固定分支名和技术栈的前提下完成合并。技能只负责当前仓库，不假定存在 `main`、特定目录、特定包管理器或特定 CI。

## 输入

- 可选目标分支，例如 `origin/release`。未提供时自动发现远端默认分支。
- 可选推送授权。未明确授权时只完成本地合并和报告。
- 仓库规则。按 `AGENTS.md`、`CLAUDE.md`、`.cursor/rules/`、贡献指南、CI 配置和包清单的顺序发现。

## 执行流程

### 1. 建立安全边界

1. 确认位于 Git 仓库且当前分支不是 detached HEAD。
2. 用 `git status --porcelain` 检查工作区。存在未提交修改时停止，不自动 stash、不丢弃。
3. 识别默认分支：优先 `git symbolic-ref refs/remotes/origin/HEAD`，其次读取远端信息，最后才在确实存在时尝试 `main` 或 `master`。
4. 当前分支等于目标分支或仓库声明的受保护分支时停止。
5. 记录合并前 `HEAD`，作为恢复锚点；不执行 `reset --hard`、强推或删除分支。

### 2. 获取目标并预判风险

```bash
git fetch --prune origin
git merge-base HEAD <target>
git diff --name-status HEAD...<target>
```

按变更内容分级：

| 等级 | 情况 | 处理 |
|---|---|---|
| L1 | 不同文件或可自动合并 | 执行合并后校验 |
| L2 | 同文件局部冲突，语义可由上下文确定 | 逐块解决并解释选择 |
| L3 | 数据迁移、鉴权、公开契约、锁文件、生成产物或大段同区重写 | 停止并列出选项，请用户决定 |

### 3. 执行合并

```bash
git merge --no-edit <target>
```

若发生冲突：

1. 用 `git diff --name-only --diff-filter=U` 列出冲突文件。
2. 读取冲突文件及最近的仓库规则，只解决冲突块。
3. 不把 `--ours`、`--theirs` 当作默认方案；按双方意图合成。
4. 每解决一批文件后检查是否仍有冲突标记。
5. 无法证明语义正确时执行 `git merge --abort`，回到锚点并报告阻塞。

### 4. 自动发现校验命令

优先级：

1. 仓库规则明确要求的命令。
2. CI 工作流实际运行的命令。
3. 受影响包的 manifest 脚本，例如 `package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`、解决方案文件。
4. 没有可靠来源时不编造命令，标记为“未发现仓库校验契约”。

至少检查：冲突标记、工作区状态、合并提交、受影响模块的类型/编译/测试。校验失败时不推送。

### 5. 输出

```markdown
# 冲突处理报告

- 当前分支：<branch>
- 合并目标：<target>
- 合并前锚点：<sha>
- 冲突文件：<count>
- 风险等级：L1/L2/L3
- 处理结果：已合并/已中止/等待决策
- 已运行校验：<commands and results>
- 未验证事项：<none or list>
- 推送状态：未授权/已推送/因校验失败未推送
```

## 不可违反

1. 不处理未提交工作区。
2. 不猜默认分支，不硬编码仓库结构。
3. 不用破坏性命令掩盖冲突。
4. 不因文本能合并就声称行为正确。
5. 不在未授权或校验失败时推送。
