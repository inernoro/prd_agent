# First Principles：从事实重建方案

适用于旧方案越补越复杂、只因行业惯例而接受高成本、想先自动化却没确认流程必要性的任务。常规明确小修直接处理，不为每件事强做哲学分析。

用户所说“第一行原理”在相关语境按“第一性原理”理解。先读已给事实和最相关证据，区分已证、假设、未知；缺证只给核实动作，不编底层事实或成本下界。分析范围由本次问题决定，不能借“重建”扩大需求、推翻用户目标、删安全检查或改生产。默认只分析；实施沿用用户本次明确权限。

## 十条精髓与输出格式

正文只输出以下十条有序列表，每条以加粗关键词开头、通常一两句，写本次具体判断和下一步证据；用户只要精髓时解释原则，给具体问题时必须应用到问题，不能照抄口号。没有可证结论则写未知及最小验证，不补造确定答案。不加嵌套清单、前言或泛泛总结；在第十条末尾简短注明“据公开方法提炼，非本人原版十条”，需要时附短来源链接，避免归属说明变成第十一条。

1. **目标**：把提出的做法还原为真正要达成的结果，先明确谁受益、成功如何观察；增加服务器或自动化只是候选手段。
2. **事实**：列出能证实的基础事实，把“大家都这么做”和历史价格从必然规律中剥离；经验可参考，不能冒充证明。
3. **约束**：分清无法绕过的客观限制、当前权限/安全/业务边界与可讨论的习惯；质疑约束须核实来源，不能自行解除。
4. **追问**：追到需求由谁提出、解决什么问题、在何条件下还必要；来自聪明人或权威的需求同样要有理由，问题本身也可能已过期。
5. **拆解**：把总成本和耗时拆到实际组成、步骤与依赖，找出差距来源；理论材料下界不等于可交付总成本，缺基准不编比例。
6. **删除**：先找可以不做的功能、部件或流程，保留目标和必要保护；先提出可逆试验与判据，不为证明大胆而删数据、鉴权或验收。
7. **重建**：从已核实事实和必要约束组合最小可行方案，保留有价值的现成能力；从零推理不等于从零重写系统。
8. **简化**：只优化已经证明需要留下的部分，优先解决真正限制结果的瓶颈；若整体没有改善，就不能用局部指标自夸成功。
9. **提速**：在质疑、删除和简化之后缩短反馈周期，以小规模可恢复验证尽早证伪；不能用跳过测试、超预算或拿生产冒险换速度。
10. **自动化**：最后才自动化已证明必要且稳定的流程，保留观测、失败恢复与效果复核；一次成功不等于长期稳定，反例出现就回查假设。

“质疑 → 删除 → 简化 → 提速 → 自动化”的先后关系来自工程五步法；目标、证据、权限、成本口径与验证表达是面向本技能的应用整理，不声称五步法等于第一性原理的全部。具体来源及不应照搬的工程语境见 [来源与适用边界](references/sources.md)，核对来源或用户问归属时再读。

调用：`$first-principles 用第一性原理分析这个问题，按十条关键词打头的列表输出，区分事实、假设和验证动作，先不实施。`
