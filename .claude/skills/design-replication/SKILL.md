# 设计稿复刻（Design Replication）

> **版本**：v1.0.0 | **触发**：`/复刻`、"复刻"、"还原设计稿"、"贴稿"、"设计稿比对"

## 一、核心命题

**复刻的验收面是像素并排，不是规格清单。**

按设计稿的「意思」实现，编译过、类型过、守卫过、自己通读也挑不出毛病——然后用户
打开一看：「差那么一点点」。这不是手艺问题，是**验收面选错了**：拿一份自己从设计稿
读出来的规格，去验一份自己照那份规格写的代码，两边同源，永远自洽。

唯一能戳破这个闭环的证据是：**设计稿的那一屏和实现的那一屏，并排放在同一张位图里。**

判定口诀：**每一个画板，我手里有没有一张左设计稿右实现页的并排图？** 没有 = 还没验。

---

## 二、「差一点点」的五个成因（对照自查）

| # | 成因 | 长什么样 | 唯一解 |
|---|------|---------|--------|
| 1 | **从没渲染过设计稿** | 只读了稿子的源码/数据模型/逻辑，把它当规格文档读，没在浏览器里看过一眼 | 先渲染再动手，见第三节 Step 1 |
| 2 | **画板漏了** | 稿子有 6 个画板（异常态/全正常/空态/只读视角/详情/新建），只复刻了主态；空态和只读视角上线才被发现是空白 | 枚举全部画板，一个都不许跳 |
| 3 | **用规格代替像素** | 「卡片内边距一档、chip 一档」这类文字契约都满足了，但列宽比例、字重层级、行高节奏全是自己拍的 | 并排图，看的是关系不是数值 |
| 4 | **文案没逐字抄** | 稿子列头写「证据（后端已有，此前未显示）」，实现写成「证据」；稿子写「池仍在承接」，实现写「降级中」 | 文案从稿子里复制，不许凭记忆重写 |
| 5 | **只看一个主题 / 一个宽度** | 深色贴了，浅色的分隔线和淡色文字全糊；1440 对了，1280 挤成两行 | 双主题 x 至少两个断点宽度 |

成因 1 是根，2-5 都是它的下游：没渲染过，就不知道有几个画板、文案是什么、
两个主题各长什么样。

## 三、执行流程

```
复刻进度：
- [ ] Step 1: 起环境 + 渲染设计稿，肉眼看一遍
- [ ] Step 2: 枚举画板，建画板清单
- [ ] Step 3: 逐画板抄文案与结构，写实现
- [ ] Step 4: 用同一套参数渲染实现页
- [ ] Step 5: 并排拼图，逐画板列偏差
- [ ] Step 6: 偏差归档（改掉 / 有理由保留 / 待办），再报完成
```

### Step 1：起环境 + 渲染设计稿

```bash
SK=.claude/skills/design-replication
WORK=<scratchpad>/replication
bash $SK/scripts/setup.sh "$WORK" "<设计稿解压目录>" 8899
```

`setup.sh` 干三件事，缺一件都渲染不出来：装 Playwright；把 React UMD 用 curl
（走代理）抓到本地——画布在浏览器里直连 unpkg 会 `ERR_CONNECTION_RESET`；起 http
静态服务——`file://` 下画布 runtime 取自己的源码会被 CORS 拦掉，截图会是一片空白。
它最后会把每个画布**URL 编码后**的地址打出来，文件名带中文时直接复制，不要手拼。

然后渲染默认那一屏，**并且真的用 Read 看那张 PNG**：

```bash
node $SK/scripts/render.mjs --url "http://127.0.0.1:8899/<编码后的文件名>" \
  --out "$WORK/shots/design" --tag design --vendor "$WORK/vendor" --width 1440
```

`render.mjs` 会在正文字符数过少时报「多半没渲染」并以非零退出。**截图存在不等于
渲染成功**——这条自检就是防止拿一张空白图当证据（同 `closed-loop-acceptance.md`）。

### Step 2：枚举画板

看第一张图的顶部，设计稿通常自带画板切换器（一排按钮）。把每个按钮登记成一个画板，
连同它的中文文案一起，作为后面 `--state` 的输入。**画板清单要写进交付消息**，
让用户能核对有没有漏。

```bash
node $SK/scripts/render.mjs --url "..." --out "$WORK/shots/design" --tag design \
  --vendor "$WORK/vendor" --width 1440 \
  --state 'alert=总览 · 有池异常' \
  --state 'allok=总览 · 全部正常' \
  --state 'empty=总览 · 空态' \
  --state 'readonly=总览 · 只读视角' \
  --state 'detail=池详情' \
  --state 'create=新建池'
```

### Step 3：抄文案与结构

逐画板对着截图写实现。**所有用户可见文案从稿子里复制**，包括列头的括号补充、
空态的整句引导、按钮上的省略号。文案是复刻里唯一不许「等价改写」的部分——
它同时也是最容易被凭记忆写歪的部分。

### Step 4：渲染实现页

**同一个脚本、同样的宽度和主题**跑实现页。取证方式必须一致，否则并排图里会混进
「取证参数不同」造成的假差异。

```bash
node $SK/scripts/render.mjs --url "<预览域名深链>" --out "$WORK/shots/impl" --tag impl \
  --width 1440 --storage "$WORK/auth.json" --state 'alert=...' ...
```

预览地址走 `python3 .claude/skills/cds/cli/cdscli.py --human preview-url` 取根域名，
路由自己按真实改动追加（`CLAUDE.md` §11），禁止手拼域名。登录态用 Playwright 的
`storageState` 存进 `$WORK/auth.json`，**凭据只走环境变量，不落文件**。

### Step 5：并排拼图

```bash
node $SK/scripts/pair.mjs --design "$WORK/shots/design" --impl "$WORK/shots/impl" \
  --out "$WORK/shots/pair"
```

`pair.mjs` 按「画板 + 主题 + 宽度」三者相同才配对，配不上的会单独列出来——
**那些就是设计稿有、实现还没有的屏**，是最硬的漏做证据。

然后**逐张 Read 并排图**，按这个顺序看（从粗到细，先看关系再看数值）：

1. 有没有整块内容缺失 / 多出来
2. 主次区块的面积比、列宽比例
3. 竖向节奏：分组间距是不是同一套档位
4. 字重与字号的层级差（标题压不压得住、次要信息淡不淡）
5. 状态色的语义分配（严重度色不许和来源标签撞色）
6. 逐字核文案

### Step 6：偏差归档

每条差异必须落到三个去处之一，**不许「看着差不多就过」**：

| 处置 | 判据 | 动作 |
|------|------|------|
| **改掉** | 设计稿是对的，实现偏了 | 当轮修，重跑 Step 4-5 |
| **有理由保留** | 实现刻意不同（真实数据形态、既有 token、后端没这个字段） | 写进交付消息，一条一句理由 |
| **待办** | 该改但超出本次范围 | 落 `debt.{module}.md`，不许只留在对话里 |

台账模板见 `reference/deviation-ledger.md`。

## 四、硬规矩

1. **没渲染过设计稿不许动手写代码。** 读源码读出来的规格不是设计稿。
2. **每个画板都要有并排图。** 少一张就是少验一屏，交付消息里要写清有几个画板、比了几张。
3. **双主题 + 至少两个宽度**（推荐 1440 / 1280）。单主题过关不算过关。
4. **文案逐字抄。** 等价改写在复刻里一律算偏差。
5. **空白截图不算证据。** `render.mjs` 报了正文字符过少就是取证失败，先修再截。
6. **偏差要么改、要么有一句理由、要么进台账**，三者取一。
7. **凭据不落盘。** 登录信息走 env，`storageState` 属于工作目录产物，不进仓库。

## 五、输出模板（交付消息里必须有）

```
【画板】设计稿 N 个：<逐个列出>
【比对】并排图 N x 2 主题 x M 宽度 = K 张，路径 <...>
【偏差-已改】<一条一行>
【偏差-保留】<一条一行 + 理由>
【偏差-待办】<一条一行 + 落到哪个 debt 文件>
【预览】<cdscli 根域名 + 本次改动的真实深链>
```

## 六、与其他规则/技能的关系

- `.claude/rules/closed-loop-acceptance.md`：空白/加载中截图不许当完成证据——本技能的
  正文字符自检就是它在复刻场景的落地。
- `.claude/rules/real-visual-acceptance.md`：真人路径 + 双主题 + 最新部署取证。本技能
  管「像不像稿子」，那条管「功能对不对」，**两条都要过**，不能互相替代。
- `.claude/rules/predicate-and-wiring-discipline.md` 形状 8：拿不成立的东西当证据。
  「我按规格实现了」正是这一形状——规格是自己读出来的，不能反过来证明自己贴稿。
- `.claude/rules/miduo-review-lens.md` 镜头 2（比例与美感）：并排图就是这面镜头的取证手段。
- `/验收`（create-visual-test-to-kb）：功能验收归档，跑在本技能之后。
- `/preview`、`/cds-deploy`：拿到可访问的实现页地址。
