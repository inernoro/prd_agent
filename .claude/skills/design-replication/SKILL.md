# 设计稿复刻（Design Replication）

> **版本**：v2.0.0 | **触发**：`/复刻`、"复刻"、"还原设计稿"、"贴稿"、"按设计稿生成页面"

## 一、核心命题

**复刻的验收面是证据，不是我的转述。**

失手的形态永远是同一个闭环：我读设计稿，读出一份规格；照这份规格写代码；再拿这份规格
验这份代码。两边同源，永远自洽——然后用户打开一看：「元素、样式、布局、功能，最多 40% 像」。

戳破这个闭环要三样**不经过我转述**的东西：

| 证据 | 戳破什么 | 谁产出 |
|---|---|---|
| 逐画板切图 + 逐条文案文件 | 「我以为稿子是这么写的」 | `extract-design.mjs` |
| 量出来的档位表（圆角/字号/字重/色） | 「圆角小一点、标题粗一点」这种拍脑袋数值 | `extract-spec.mjs` |
| 文案覆盖率 + 档位差 + 并排图 + 别人的审查 | 「我看了觉得像」 | `audit.mjs` / `pair.mjs` / 对抗式审查 |

判定口诀：**我说「像」的依据，是我看的，还是量出来的？** 是我看的 = 还没验。

## 二、精度是怎么丢的（六个成因，逐条自查）

| # | 成因 | 长什么样 | 唯一解 |
|---|------|---------|--------|
| 1 | **从没渲染过设计稿** | 只读稿子的源码/数据模型，把它当规格文档读 | Step 1 先渲染 |
| 2 | **用规格代替像素** | 把稿子读成一段文字笔记（"卡片内边距一档、chip 一档"），然后照笔记写 | Step 2 量档位表，照表写 |
| 3 | **token 层没先落** | 每屏对着截图现调数值，第二屏必然与第一屏漂移，还撞双皮肤棘轮 | Step 3 先补 token 再写组件 |
| 4 | **画板漏了** | 稿子 11 屏只做了主态，空态/只读/异常上线才发现是空白 | Step 1 产出画板清单，一个都不许跳 |
| 5 | **文案没逐字抄** | 稿子写「上传网页」，实现写「上传站点」；括号补充被砍掉 | 文案从 `text-*.txt` 复制，不凭记忆 |
| 6 | **检查是自证** | 「我按规格实现了」「我看了觉得像」 | Step 5 机械核对 + Step 6 对抗式审查 |

成因 1-3 是**生成侧**的精度（写之前手里有什么），4-6 是**检查侧**的精度（写完拿什么判）。
两侧都补齐，才是「更精准」；只补一侧，另一侧会把精度吃回去。

## 三、执行流程

```
复刻进度：
- [ ] Step 0: 起环境
- [ ] Step 1: 取证据 —— 画板清单 + 逐画板切图 + 逐条文案
- [ ] Step 2: 取规格 —— 量出设计系统档位表
- [ ] Step 3: 落 token —— 档位对到 token 层，缺的先补（闸门：缺项归零才动组件）
- [ ] Step 4: 照证据写实现（一屏一屏来，文案从文件复制）
- [ ] Step 5: 机械核对 —— 文案覆盖率 + 档位差 + 并排图
- [ ] Step 6: 对抗式审查 —— 别人给相似度，不是我自己给
- [ ] Step 7: 偏差归档（改掉 / 有理由保留 / 待办），再报完成
```

### Step 0：起环境

```bash
SK=.claude/skills/design-replication
WORK=<scratchpad>/replication
bash $SK/scripts/setup.sh "$WORK" "<设计稿解压目录>" 8899
```

`setup.sh` 干三件事，缺一件都渲染不出来：装 Playwright；用 curl（走代理）把 React UMD
抓到本地——画布在浏览器里直连 unpkg 会 `ERR_CONNECTION_RESET`；起 http 静态服务——
`file://` 下画布 runtime 取自己的源码会被 CORS 拦掉，截图是一片空白。它最后会把每个画布
**URL 编码后**的地址打出来，文件名带中文时直接复制，不要手拼。

### Step 1：取证据（画板清单 + 切图 + 逐条文案）

```bash
node $SK/scripts/extract-design.mjs --url "http://127.0.0.1:8899/<编码后的文件名>" \
  --out "$WORK/design" --vendor "$WORK/vendor" --width 1600
```

产出 `index.json`（画板清单，含每个画板的 `top` / `height`，Step 2 要用）、逐画板 PNG
（超高的自动切段，一张糊成缩略图的整图等于没有证据）、`text-<画板>.txt`（逐条文案）。

它在两种情况下**硬失败**：正文字符过少（没渲染出来）、识别不出画板。宁可失败也不输出
一份「只有一个画板」的假清单——那会让后面每一步都以为稿子只有一屏。

**画板清单要写进交付消息**，让用户能核对有没有漏屏。然后逐张 Read 切图，看一遍。

### Step 2：取规格（量档位表，别读笔记）

对**每个要做的画板**各量一次（`--y-from/--y-to` 取自 `index.json`）：

```bash
node $SK/scripts/extract-spec.mjs --url "http://127.0.0.1:8899/<编码后的文件名>" \
  --out "$WORK/spec/board-01" --vendor "$WORK/vendor" --width 1600 \
  --y-from 1240 --y-to 3040
```

`spec.md` 会告诉你这一屏真实用了几档圆角（比如 5/6/7/9/10/11/12）、几档字号、
几个字族分别管什么。**这些是事实，不是我读出来的印象**——照着它写组件，才不会每屏靠感觉调。

浅色主题再跑一次 `--theme light`，两套值都要有。

### Step 3：落 token（闸门）

```bash
node $SK/scripts/tokens-map.mjs --spec "$WORK/spec/board-01/spec.json" \
  --tokens prd-admin/src/styles/tokens.css --out "$WORK/spec/board-01"
```

输出三类：**已有 token** / **接近但不等**（多半是同一档被写歪，判一下）/ **缺 token**。
缺的先在 token 层补上（**语义名字**，暗浅双写），重跑到缺项为 0，再写组件。

**为什么是闸门**：跳过这一步，设计稿多出来的那几十档值只能以字面量散进几十个组件——
撞 `.claude/rules/admin-dual-theme.md` 的硬编码棘轮，且「这一档到底多少」不再有单一出处，
下一屏必然漂移。补 token 的动作要写进交付消息（改了共享层）。

### Step 4：照证据写实现

一屏一屏做，做完一屏走一遍 Step 5，不要攒到最后。硬规矩：

- **文案从 `text-<画板>.txt` 复制**，包括括号补充、单位、省略号、空格。等价改写在复刻里算偏差。
- **数值从 `spec.md` 抄档位**，不要自己在截图上估。
- 设计稿与项目既有约定冲突时（对比度、圆角档、间距档）：**先按设计稿做**，把冲突写进偏差
  台账让用户裁决；不要自作主张改成项目习惯，也不要为了让某条守卫变绿而改设计值——
  守卫误伤就修守卫的判据精度（`predicate-and-wiring-discipline.md` 形状 6）。
- 拿不到的数据（稿子里的 PDF 页数、视频时长这类后端没有的字段）：**留空或补数据源，不许估一个**
  （`no-rootless-tree.md`）。留空的进偏差台账「待办」。

### Step 5：机械核对（文案覆盖率 + 档位差 + 并排图）

先用同一套参数渲染实现页，再量它的规格，然后对：

```bash
# 同一个 render.mjs、同样的宽度与主题，取证方式必须一致
node $SK/scripts/render.mjs --url "<预览域名深链>" --out "$WORK/shots/impl" --tag impl \
  --width 1600 --storage "$WORK/auth.json"

node $SK/scripts/extract-spec.mjs --url "<预览域名深链>" --out "$WORK/spec/impl-01" \
  --storage "$WORK/auth.json" --width 1600 --scope '<这一屏的根容器选择器>'

node $SK/scripts/audit.mjs --design "$WORK/spec/board-01" --impl "$WORK/spec/impl-01" \
  --out "$WORK/audit/board-01"

node $SK/scripts/pair.mjs --design "$WORK/shots/design" --impl "$WORK/shots/impl" \
  --out "$WORK/shots/pair"
```

`audit.md` 给三个判据：**文案覆盖率**、**硬缺失条数**、**档位缺失数**。
后两项归零，才轮到看并排图判「像不像」——它们不是审美问题，是事实问题。

**让覆盖率变成真判据**：设计稿里的样例数据（站点名、文件大小、「12 分钟前」）也算文案，
实现页跑另一套数据时会被算成缺失。所以取证前**把实现页的数据喂成设计稿那一套**
（mock / 种子数据 / 预览环境造几条同名记录），覆盖率才直接可读。做不到就用 `--ignore`
排掉明确属于数据的条目——但**不许**因为「反正是数据」整段无视：结构文案（按钮、列头、
空态引导、括号补充）混在同一份清单里，那些一条都不能缺。

然后**逐张 Read 并排图**，从粗到细（先看关系再看数值）：

1. 有没有整块内容缺失 / 多出来
2. 主次区块的面积比、列宽比例
3. 竖向节奏：分组间距是不是同一套档位
4. 字重与字号的层级差
5. 状态色的语义分配（严重度色不许和来源标签撞色）
6. 逐字核文案

预览地址走 `python3 .claude/skills/cds/cli/cdscli.py --human preview-url` 取根域名，
路由按真实改动追加（`CLAUDE.md` §11），禁止手拼域名。登录态用 Playwright 的
`storageState` 存进 `$WORK/auth.json`，**凭据只走环境变量，不落文件**。

### Step 6：对抗式审查（相似度不由我宣布）

按 `reference/adversarial-review.md` 起 3-5 个互不通气的审查体，每个只给证据、
不给我的结论与台账，各分一个镜头（骨架 / 组件 / 排印 / 文案 / 色彩）。
每个至少列 12 条可核对的差异，并各自给一个相似度百分比。

**声称「已复刻」之前跑，不是之后补。** 用户说「不像」之后更要换审查体重跑，不许自辩。

拿到报告先逐条去并排图上复核（审查体也会看花眼），确认的进台账，然后重跑 Step 4-5，
直到新一轮的问题都落在「保留 / 待办」两类。

### Step 7：偏差归档

每条差异必须落到三个去处之一，**不许「看着差不多就过」**：

| 处置 | 判据 | 动作 |
|------|------|------|
| **改掉** | 设计稿是对的，实现偏了 | 当轮修，重跑 Step 5 |
| **有理由保留** | 实现刻意不同（真实数据形态、既有 token、后端没这个字段） | 写进交付消息，一条一句理由 |
| **待办** | 该改但超出本次范围 | 落 `debt.{module}.md`，不许只留在对话里 |

台账模板见 `reference/deviation-ledger.md`。**改了后端就逐条列出来**——加功能还好，减功能很麻烦。

## 四、硬规矩

1. **没取证不许动手。** 读源码读出来的规格不是设计稿；手里没有 `text-*.txt` 就别写文案。
2. **没量规格不许调数值。** 圆角字号来自 `spec.md` 的档位表，不来自我在截图上的估计。
3. **token 缺项没归零不许写组件。** 否则值散进几十个文件，第二屏必漂移。
4. **每个画板都要有并排图 + 一份 audit.md。** 少一张就是少验一屏，交付消息要写清有几屏、验了几屏。
5. **双主题 + 至少两个宽度**（推荐 1600 / 1280）。单主题过关不算过关。
6. **文案逐字抄。** 等价改写一律算偏差。
7. **相似度不自评。** 对抗式审查跑过、复核过，才谈「像」。
8. **空白截图 / 空档位表不算证据。** 脚本报了硬失败就是取证失败，先修再截。
9. **偏差要么改、要么有一句理由、要么进台账**，三者取一。
10. **凭据不落盘。** 登录信息走 env，`storageState` 属于工作目录产物，不进仓库。

## 五、精度闸门（报「完成」前逐条核）

```
- [ ] 画板清单来自 extract-design 的 index.json，不是我数的
- [ ] 每屏都有 spec.md，组件里的数值能在档位表里找到出处
- [ ] tokens-map 缺项 = 0（补的 token 已暗浅双写）
- [ ] audit.md 的硬缺失 = 0、档位缺失 = 0
- [ ] 文案覆盖率写进了交付消息（不是「已核对」四个字）
- [ ] 并排图逐张 Read 过，双主题 x 两个宽度
- [ ] 对抗式审查跑过 ≥3 个审查体，报告逐条复核过
- [ ] 偏差全部归档，后端改动逐条列出
```

任一为否，不许说「已按设计稿完成」。

## 六、输出模板（交付消息里必须有）

```
【画板】设计稿 N 屏：<逐个列出> | 本次做了 M 屏
【规格】档位表 <spec.md 路径> | 新补 token X 条（暗浅双写）：<逐条列出>
【核对】文案覆盖率 <P>% · 硬缺失 0 · 档位缺失 0 | 并排图 N x 2 主题 x M 宽度 = K 张
【审查】对抗式审查 <n> 个，相似度 <逐个列出>，剩余问题均为保留/待办
【后端】<本次改动的后端逐条；无则写「无」>
【偏差-已改】<一条一行>
【偏差-保留】<一条一行 + 理由>
【偏差-待办】<一条一行 + 落到哪个 debt 文件>
【预览】<cdscli 根域名 + 本次改动的真实深链>
```

## 七、与其他规则/技能的关系

- `.claude/rules/predicate-and-wiring-discipline.md` 形状 8：拿不成立的东西当证据。
  「我按规格实现了」正是这一形状——规格是我自己读出来的，不能反过来证明我贴稿。
- `.claude/rules/closed-loop-acceptance.md`：空白/加载中截图不许当完成证据——脚本的
  正文字符自检就是它在复刻场景的落地。
- `.claude/rules/real-visual-acceptance.md`：真人路径 + 双主题 + 最新部署取证。本技能
  管「像不像稿子」，那条管「功能对不对」，**两条都要过**，不能互相替代。
- `.claude/rules/admin-dual-theme.md`：Step 3 的 token 闸门就是为它服务——先落 token，
  才不会在组件里堆硬编码撞棘轮。
- `.claude/rules/no-rootless-tree.md`：稿子上有、系统拿不到的数据留空并进台账，不许估。
- `.claude/rules/miduo-review-lens.md` 镜头 2（比例与美感）：并排图是这面镜头的取证手段。
- `/验收`（create-visual-test-to-kb）：功能验收归档，跑在本技能之后。
- `/preview`、`/cds-deploy`：拿到可访问的实现页地址。
