# 模板到真实页面验收

适用于模板有样例数据，真实页面需要读取配置、异步媒体、保存状态或调用后台服务的改动。先把用户要求改什么、前一版已经确认什么写成可验证条目，再从真实入口取证。

## 基线与复测表

一行只写一个能失败的检查。取证记录写状态、数据身份、实际主题、CSS 视口宽高、DPR、裁切或滚动位置以及实现版本。把选择、保留、允许退让和待确认项写进同一份表。

| 对象和状态 | 来源与预期 | 现场操作 | 证据与判定 |
|---|---|---|---|
| 带图标的折叠触发器 | 最新用户指令决定哪些视觉文字隐藏，先前确认的图标和触发区保留 | 初次打开、点击、键盘打开、再收起 | 查看图标可见、展开状态实际变化、屏幕阅读器名称可读 |
| 媒体与参照物 | 测可见像素边界及对齐参照，记录外框、资源绘制区和宽高比 | 从实际设置中选择，再量桌面与窄屏 | 量相对高度与对齐点，查素材来源、内在尺寸、加载及是否有裁切 |
| 展开项和候选列表 | 行名称、当前选中内容和候选媒体来自实际配置 | 展开、切换、关闭、重开 | 显示选中内容、真实缩略图和名称，长文字省略，操作仍可用 |
| 列表、位置和生成 | 存储对象的稳定 ID 或原文锚点来源决定结果归属 | 使用能暴露相似内容错配的样本，完成主流程并复开同一记录 | 比较每个 ID、前后内容、顺序和实际加载结果，也检查数量 |
| 环境与实际执行 | 目标站点的真实版本、请求和运行记录 | 在用户授权的目标环境重复同一路径 | 以部署版本和业务执行证据判定。页面型号标签不能证明实际调用 |

用户修改一项时，用上一版受影响状态重新检查既有保留项。遇到「水印看起来歪」这类反馈，先把截图、DOM 外框、资产内部边界分开取证。图片确认含有透明留白时，可量 Alpha 边界，并比较裁切前后的同一块像素。确认是否发生旋转、留白偏心、缩放失真或渲染变形后再归因。页面遮挡也要复现来源，例如业务粘性栏和预览工具浮层用各自的关停或复测路径确认，报告记录真实原因。

## 回放与真实运行

回放适合双方使用同一组样本，检查版式、布局与文案。真实运行从正常登录、导航和用户操作开始，记录实际选择、资源及结果。状态很多时先验证最能暴露风险的路径，再覆盖实际受影响的状态。视图对照、业务通过、正式复测各自有记录，一张静态截图或一次模拟登录不替代完整路径。

- 打开具有代表性数据的记录，验证默认状态、展开或关闭、选择更新以及另一会话重开。含持久化行为时，在新会话验证同一记录。
- 看媒体的内在尺寸、宽高比、加载状态及与选中项的对应关系。空态和加载失败保留可辨认的名称与控制。遇到未知型号，检查通用图标与真实型号名仍在。
- 对文案溢出、视觉等高、图标存在和结果顺序，优先用浏览器断言结合肉眼复看。准备一个实测旧值或历史错误样本，证明检查确实会失败。
- 用稳定位置或身份把 AI 结果与原始意图对应。遇到重复、乱序、遗漏、越界或中断时，由软件判定规则处理，验证正常执行和需要兜底的结果。
- 产物或实际模型依赖异步请求时，等待真实结果及可观测状态。用同一请求标识串起页面动作与上游日志。验证目标站版本后才做目标站复测，保持用户指定的发布顺序。

## 文学创作配图工作台回归案例

这是用于复盘的产品案例。下面的尺寸、名称和退让策略来自这次用户选择。新任务使用自己的测量与需求。

| 当时遇到的问题 | 下次最早检出它的检查 |
|---|---|
| 演示使设置看起来更紧凑，但真实结果区的预览可见空间、可展开性和重开状态需要单独验证 | 同一结果文章对比展开与收起，量下方预览首屏可见范围，再从列表重开并检查默认收起 |
| 把水印「高度塞满」理解为整行高，曾按 40 CSS 像素渲染。用户指明参照是 OpenAI 图标 | 开工表写清「水印实际绘制高度等于模型图标」。用已测 40 对 16 的旧值做反例，合格版本两者约 16，中心线差为 0 |
| 用户看水印疑似倾斜，初始模板里的 SVG 示意与线上渲染 PNG 来源不同 | 比对原 320 × 320 PNG 的实际 130 × 34 可见区域和页面裁切结果。此次外框同一水平方向样点上边与下边坐标一致，透明通道一致，CSS 无旋转 |
| 去掉「生成设置」四字时误删滑杆图标 | 把视觉文字、滑杆图标、箭头、点击区和无障碍名称各列一条，回归时独立检查。用只有箭头的版本做失败对照 |
| 折叠栏缺少能区分用户锚点的图标，或堆满摘要遮住控件 | 核对锚点图标语义、水印在左及两个模型的保留顺序。在本次 320 CSS 像素触控视口测可见与不溢出 |
| 展开后只有名称，用户要直接看到设置内容 | 展开后核对提示词真实单行摘要、水印样张和名字、参考图实际缩略图和名称、两枚模型图标；再开候选菜单核对图样与名称。常见图标来源可扩展，未知型号使用语义回退 |
| 刷新或从列表重开显示「自动安排」，掩盖用户已经设了锚点 | 新会话重开同一篇文章，核对从实际原稿或已保存设置恢复「尊重用户锚点」。内存状态与真实保存分开检查 |
| 重复句让第二节的提示词错插到第三段；模型漏返也可能让计数不一致 | 用两处有稳定顺序的用户锚点和重复句，核对第二节后、第四段后各一个结果。逐个断言锚点、提示词与图片顺序，补测重复编号、漏返和中断。只查总数会漏掉交换或错位 |
| 截图里的型号与真正执行环境容易被混为一谈 | 写作操作用请求标识对应网关实际上游模型。分支预览可用它自己的配置；目标正式站另验 V4.1 Flash 与两张图，在独立发布前置成立后按授权执行 |

本次更新的输入包括用户确认的局部截图、分支的宽高与原位测量，以及 [PR 视觉验收](https://cds.miduo.org/reports?project=prd-agent&folder=f0f7e8f0bf5d45abaaf5e12752908edb&report=63a47c73e7314e3b9ec66abc56c24f6f)。报告中此次预览已验两条提示词及其位置。分支上的新一轮正式两图与网关验证仍以实际发布后的证据为准。
