# 对抗式审查（Adversarial Review）——复刻的第二只眼

> 机械核对（`audit.mjs`）能抓「缺文案 / 缺档位」这类事实问题，抓不了「元素在，但摆错位置 /
> 层级压不住 / 这块根本是另一种控件」。后者只有**另一双默认我写错了的眼睛**能抓。
>
> 硬规矩：**复刻的相似度不由实现者自己宣布。** 自己判的相似度在本仓库有过实测——
> 我自称「已贴稿」的那一屏，四个独立审查体各自打分都落在 35% 左右，与用户的判断一致。

---

## 一、什么时候必须跑

- 声称某一屏「已复刻 / 已贴稿 / 已完成」**之前**（不是之后补一份）。
- 用户说「差得远 / 不像 / 只有 N% 相似」之后——此时**必须换审查体重跑**，不许自辩。
- 一屏改了三轮以上还在被挑同类问题时（说明我的看图口径本身歪了）。

## 二、怎么起

一次起 3-5 个**互不通气**的审查体，每个只给证据、不给我的结论：

- 设计稿画板切图（`extract-design.mjs` 产物）
- 实现页同视口截图（`render.mjs` 产物）
- 并排图（`pair.mjs` 产物）
- 逐条文案（`text-*.txt` / `text.txt`）

**不要**给它们我的偏差台账、我的规格笔记、我的自评——那会把我的盲区一起传染过去。
每个审查体分一个不同的镜头（见第四节），避免五份报告说同一件事。

## 三、审查体提示词模板（照抄，只改画板名与路径）

```
你在做设计稿复刻的对抗式审查。默认立场：**这份实现是错的**，你的任务是找出证据，
不是确认它对。找不到问题不算你赢，算你没看仔细。

材料：
- 设计稿：<design/NN-屏X.png>（若切了多段，逐段看完）
- 实现页：<impl/impl.xxx.dark.1600.png>
- 并排图：<pair/pair.xxx.dark.1600.png>
- 设计稿逐条文案：<text-NN-屏X.txt>

按下面四个维度逐条列问题，每条必须写成「设计稿是 A，实现是 B，位置在 C」的可核对形式，
禁止写「整体感觉不够精致」这种无法验证的话：

1. 元素：有没有整块内容缺失 / 多出 / 被换成了别的控件（下拉换成了按钮组之类）
2. 文案：逐字对，包括括号补充、单位、省略号、空格
3. 样式：圆角 / 字号 / 字重 / 字距 / 颜色语义（哪一档用在哪类信息上）
4. 布局：区块位置、面积比、列宽比、对齐关系、竖向间距节奏、贴边还是浮卡

要求：
- 至少列 12 条。列不满就说明你还没逐块扫过，回去接着看。
- 最后给一个相似度百分比，并写明扣分主要来自哪几条。
- 另起一节「我不能确认的」：材料不足以判断的点（比如 hover 态、动效、真实数据形态），
  明确写出来，不要猜一个结论填上去。
```

## 四、镜头分工（避免五份重复报告）

| 审查体 | 只看 |
|---|---|
| A 骨架 | 区块划分、面积比、列宽、贴边/浮卡、外壳与栏的关系 |
| B 组件 | 每个控件的形态：这块到底是 chip 还是 button，是表格还是卡片 |
| C 排印 | 字号字重层级、字距、字族分工（display / body / mono 各管什么） |
| D 文案 | 逐字，含标点与括号补充；顺便抓语序 |
| E 色彩与状态 | 颜色语义分配、状态色是否撞色、双主题各自是否成立 |

## 五、拿到报告之后

1. **先复核再动手**：每条去并排图上找证据，确认是真差异还是审查体看花眼（它也会错）。
   复核不通过的当场记下来，不要沉默地忽略。
2. **归档**：确认的差异全部进偏差台账（`deviation-ledger.md`），三种处置取其一。
3. **不许挑软柿子**：只修文案不修布局，下一轮同样的分数还会回来。
4. **重跑取证 → 再审一轮**，直到新一轮审查体给出的问题都落在「保留 / 待办」两类。
