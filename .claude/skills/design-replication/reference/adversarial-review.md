# 设计复刻对抗式审查

文案和档位都匹配时，仍可能存在组件错位、资产比例错误、控件丢失或状态恢复错误。复核先看用户确认的原始证据，再看实现侧取证。

## 材料与分工

给审查者用户原始要求、范围内每个关键状态的模板和真实页面截图、同条件并排图、实测值及可复现操作。等审查者独立列完问题后，再对照实施说明和已批准偏差。相同问题反复发生时，换一种看法重新取证。例如从整屏切到对象和邻区，从目测换成 DOM 与资产像素，从单次打开换成新会话重开。

| 检查面 | 要找的证据 |
|---|---|
| 布局关系 | 内容数量、轴向、尺寸参照、相邻区域遮挡、窄屏退让 |
| 组件和资产 | 图标是否可见、原始素材与可见区域、比例、对齐、加载和回退 |
| 文案和样式 | 固定文字、主题下的状态语义、具体组件样式，动态内容是否来自当前选择 |
| 操作与保留项 | 命中的目标状态、恢复行为、已有控件与能力、真实数据与截图是否对应 |

有多个审查者时按风险分工。局部改动可以用精确的反例和第二遍取证复核。输出已确认的差异和证据，说明材料不足的项。差异数量和相似度百分比不做门槛。

## 记录与处理

- 每项写明状态、位置、预期、实际和证据。涉及尺寸时给相对参照和实测值。涉及位置时给前后内容或对象身份。
- 一项差异先复核再修，确认后进 [偏差台账](deviation-ledger.md)。保留用户已接受的选项，缺少参考的状态标明依据。
- 抓到旧错误的检查应在修复后转绿。复测改动项和关联保留项。真实点击、保存及重开记录按 [模板到真实页面验收](live-page-validation.md) 核对。
