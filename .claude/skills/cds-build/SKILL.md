# 按 CDS 稿件实现

## 1. 接入当前项目

- 从输入提取稿件编号和可选版本。稿件链接用于定位既有 CDS 实例、项目和固定版，编号或项目冲突时先核对。只有编号时使用当前仓库已绑定的 CDS 项目。
- 加载同一技能包的 `cds` 技能。直接从仓库加载时，核心说明在 `.claude/skills/cds`。通过 CDS 分发安装时，在当前项目安装接入页提供的完整归档，再用已有授权自检。已有旧版技能时同样使用完整归档。仍缺读权限时，从当前 CDS 项目发起授权申请，由相应成员在页面批准。验收取证另需具备验收写权限的项目授权。
- 用 `cds_design_read` 的 `view: "intake"` 或 `cdscli design intake --project <项目>` 查找精确 `designId`。回读失败时报告实例、项目、动作和回执，凭据由 CDS 正常授权流程保存。

## 2. 固定实施目标

- 使用接入清单的 `implementationTargetVersion`。历史实例尚无此字段时，从 `upgrade.status === "active"` 读取 `upgrade.targetVersion`，否则读取 `baselineVersion`。值为 `null` 或未登记时，先请有权评审人定实施版本。请求中明确指定的版本须与实施目标一致。新版发布期间继续使用已锁定的版本。
- 用 `cds_design_read` 的 `view: "delivery"` 或 `cdscli design delivery <稿件> --version <目标版>` 读交付索引、验收规则和实现画面。读包内原文时，使用 MCP 的 `view: "file"` 或给该 CLI 命令加 `--file <包内路径>`。从索引打开 `交接清单.md` 和需要的源码差异。
- 用 `view: "handoff"` 或 `cdscli design handoff <稿件> --version <目标版>` 回读交接检查。检查失败、待运行或无法回读时，在原反馈记录缺失条件和处理人，等固定目标满足交接门禁后开始修改代码。使用历史稿时以 CDS 返回的该版交接状态为依据。
- 读取当前工程提交和 CDS 的已实现版本。用 `cds_design_read` 的 `view: "diff"` 或 `cdscli design diff <稿件> --from <已实现版> --to <目标版>` 核对净变化。先用程序检查源码差异是否能直接应用。已签收且当前实现与目标一致时，回读原提交和验收回执即可。

## 3. 实现并回填

- 先按 [CDS 设计闭环](../cds/reference/design-loop.md#六实现方按交接清单实现) 在同版反馈里回复验收项、做法和待澄清点，再按项目规则写测试和实现。按交付清单推进，发现不兼容的差异时，把文件和理由写回同一线程。
- 同一验收运行使用目标稿件版本、同一实现提交以及该稿件指定的演示数据。通过 CDS 正常入口绑定实现画面、上传或生成所需证据、逐项记录结论。把运行编号和实现提交留在稿件里，请设计方独立复核。
- 回复固定稿件链接、实施版本、实现提交、验收运行和仍待处理的条件。定实施基线、签收和正式发布各自使用已有角色与授权。遇到缺失条件时在原线程记录精确的待办和处理人。
