# CDS 骨架自检

按改动冻结范围，按实际渲染修骨架。发起方只需提供日期、Git 范围或指定路由。默认检查上一完整自然日 `Asia/Shanghai` 的 `origin/main`，共享改动纳入所有可能受影响的路由。

## 适用场景

- 自动化检查当日改过的 CDS 页面，修正候选代码并汇报。
- 功能分支交付前复验路由、加载骨架或手机布局。
- 指定某条路由重新比对骨架、真实组件和左侧菜单。
- 共享导航、主题或骨架样式改动后复查下游页面。

## 执行清单

- [ ] **确定范围。** 从仓库根目录阅读 `AGENTS.md`、`cds/CLAUDE.md` 与实际变更对应的专项规则。每日任务刷新配置分支的远端引用，保留现有工作区。运行范围脚本，记录基础和目标 SHA，登记候选路由、兼容入口及影响面。日期范围采用第一父提交链上两端快照的净改动。宽泛的共享或未登记文件由人工阅读差异补齐路由，不能以登记表为空推断无影响。
- [ ] **设计用例。** 依次读取同仓库的 `acceptance-test-design`、`acceptance-scenario-orchestrator` 和 `create-visual-test-to-kb`。先查左侧菜单和直达页面，再查二级页、查询视图和其他受影响入口。加上能暴露差异的账号角色、数据状态、断点或返回路径。有可用子智能体且任务允许并行时，按路由分组，统一使用冻结构建和截图条件。公共壳或共享骨架由一个负责人整合。
- [ ] **复现差异。** 打开实际页面，分别采集代码块等待、数据等待和加载完成态。浏览器本地延迟只用于观察等待，可用仓库合成响应或受控预览。每组保持路由、角色、查询参数、主题、滚动位置与视口一致。记录截图、DOM 锚点及受影响组件。优先查菜单高亮与可用性，再比对标题、工具栏、目录、筛选、分栏、卡片、表格、画布和响应式排列。
- [ ] **更新骨架。** 在独立工作区或发起方指定的修复分支修复已复现的差异。优先复用加载完成态的容器、公共布局类和断点。代码和数据等待尽量使用同一骨架。对初次请求无法知道的权限、分组、条数和服务类型，只对齐能预知的区域。保留正常权限检查、重试、慢加载反馈和减少动效行为。
- [ ] **重跑与复核。** 同路由同数据复拍，桌面 `1920×1080`，手机独立触控上下文 `390×844`。左右拼图左侧骨架、右侧真实组件。核对实际页面和截图，记录代码等待到数据等待的连续性，以及骨架到真实内容的关键区域偏移。跑前端类型检查、构建、加载覆盖守卫和对应的浏览器回归。
- [ ] **报告。** 按仓库验收流程归档，以 `verify-open.mjs` 确认正文、截图和内部链接可打开。汇报每条路由的状态、修复内容、证据、遇到的问题、阻塞和关闭条件。线上预览或测试账号不可用时保留未验证范围。本地合成数据只支持候选版界面结论。无受影响页面时汇报两个 SHA 和核查结果。

## 调用

```text
$cds-skeleton-review                         # 上一完整自然日
$cds-skeleton-review --date 2026-11-20        # 指定业务日
$cds-skeleton-review --base HEAD~1 --head HEAD
$cds-skeleton-review 路由=/project-list
```

使用 [范围、截图与自动化接入](reference/runbook.md) 的命令执行。自动化只传入范围、授权的修复交付位置和报告归属，流程以本技能为准。缺少交付分支时，保留工作区改动或可应用的补丁。提交、推送、合并和上线沿用项目已有授权。

## 结果格式

```markdown
### 阶段一 · 范围与基线
- [x] 日期、来源分支、基础及目标 SHA
### 阶段二 · 修复与复拍
- [x] 已修复并复验的页面
- [ ] 未验证的页面和原因
### 阶段三 · 报告
- [x] 报告链接和打开校验

| 页面 | 桌面 | 手机 | 修复与验证状态 | 证据或阻塞 |
|---|---|---|---|---|
```

## 示例

输入「检查 `/project-list`，加载时手机菜单入口和实际页面不一致」。先在手机视口延迟页面代码，确认入口是否消失；复用公共顶栏后，复拍打开的抽屉，并检查当前项目列表高亮保持到真实内容出现。报告记录桌面与手机取证、修复位置，以及首次请求前无从判定的暂停分组和服务类型。如果同版本线上预览尚未生成，将线上验证列为阻塞。
