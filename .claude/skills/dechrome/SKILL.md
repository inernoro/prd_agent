# 去牛皮癣

把有效内容与高频操作提前，并实际完成页面改进。审计报告、静态扫描和构建通过都不能独立代表治理完成。

## 适用场景

- 标题、说明、徽章、工具栏层层叠加，数据迟迟不出现。
- 少量记录被多层卡片、满高表体或单页分页撑成空架子。
- 长期成功横幅、低频配置或教程挤走主操作。
- 系统性检查整个产品，并防止共享组件或后续改动使问题回潮。

编辑画布、图表、日志、预览与主从详情可能需要填满空间；留白、卡片、折叠本身不构成缺陷。

## 先读规则，再建立范围

1. 读取仓库 AGENTS、模块规则、调试方式、主题、信息密度及交付规范。适用规则优先于本技能默认值；用户范围与授权优先。
2. 从路由、导航、权限与用户任务盘点所有实际页面、详情、二级标签、折叠、弹层。重定向记别名，不拿别名充页面覆盖数；查导航但未在路由出现的工作区。
3. 建立逐页账本：页面目标、使用频率及依据、核心操作、进入路径、角色、状态、优先级、证据、处理结果。没有遥测时将频率标为推断。
4. 按频率、任务阻碍和严重度排序。全页面任务必须逐页给结论；`保留`和`受阻`也是明确结论，未打开的页面不能写通过。

**统计分开报告**：盘点表面、实际观察、共享组件影响、微改、已证明任务收益及真实验收分别列数。一个路由下多状态不重复算已治理页面；声明改动、删除边框或通过构建，均不能升级为治理完成。不强制每页产生 diff。

详细账本与测量约定：[证据契约](reference/evidence-contract.md)。可用 [账本检查器](scripts/check_ledger.py) 检查漏项；它不判断视觉缺陷，也不证明盘点完整。

## 判据：候选现象 + 任务成本 + 人工核实

| 候选现象 | 必须核实的任务成本与边界 |
|---|---|
| 标题、徽章、副标题、横幅重复同一事实 | 是否推迟首条有效数据或主操作；保留必要身份、权限与异常 |
| 少量信息被多层卡片/边框/折叠包裹 | 是否各自表达独立分组；合并无语义层，不牺牲阅读与点击热区 |
| 成功回执常驻整行 | 是否为可退场的短暂成功；失败、等待、一次性凭据和授权范围需持续可读 |
| 两条数据仍满高、单页仍翻页 | 测最后记录到表体底部的空隙；保留计数、大集合滚动和分页 |
| 固定高度、占位容器、错误 flex 产生空白 | 核实主轴、basis、min-height 与滚动归属；工作画布不能机械改为自然高度 |
| 低频配置/说明挤走高频操作 | 记录频率依据与完成任务多出的滚动/步骤；主操作不能全部藏进菜单 |

静态 CSS 搜索、卡片数量和面积比例只产生候选。必须实际打开页面并检查截图与交互，不能凭源码或旧截图定案。

## 执行循环

- [ ] **打开当前页面。** 正常登录、从真实导航进入，记录实际地址、版本、角色、视口、主题与数据摘要；截图避免凭据和个人信息。不能打开就标受阻并继续不依赖它的工作。
- [ ] **先设计验收。** 使用可用的验收设计流程；没有相应技能时，写清目标、前置、动作、可观察断言、失败影响和禁止替代证据。覆盖默认页、二级标签、展开、空态、少量、大量、加载、错误、权限及代表性桌面/窄屏/明暗主题；不适用需给理由。
- [ ] **固定基线。** 锁定版本、数据、具体UI状态、角色、视口、主题、文档与局部滚动位置、字体与加载完成点。测首条有效数据位置、数据前非必要区域及高度、核心任务的滚动量与步骤、少量表体空隙及大量末项可达性。列出每块为何非必要。
- [ ] **解释保留。** 保留结论必须有具体任务、必要空间/状态与实页证据；“打开过”“只读看过”“缺证据”不能代替理由。没有足够判断依据就标受阻或待核实。
- [ ] **制定本页门槛。** 从基线与任务需要制定目标，不能用统一面积比例代替可用性。说明哪些状态、功能、字号、热区与键盘路径必须保持。
- [ ] **实施。** 优先现有布局与共享组件：合并重复层级，删除无语义容器，低频说明按需展示，短暂成功用合适反馈，少量记录自然排布。保留清晰分组，不裁内容、不隐藏必要状态、不通过增加菜单步骤制造紧凑。
- [ ] **证明实际收益。** 每项修复说明匹配状态下发生了什么可观察变化、如何减少任务成本。schema v2 的 `fixed` 要有 `verified_effect`；指标/布尔目标必须真实改变并引用执行证据。同值、只换class或微改不能充当治理完成；小变化是否有用由任务证据判断，不设像素面积门槛。
- [ ] **建立防回潮。** 用浏览器测关键内容与操作可见性、遮挡、局部/文档溢出、少量自然排布和大量末项可达性。保留代表性旧布局反例：同一断言旧版失败、修改后通过。只断言 class 或截图数量不够。
- [ ] **控制取证并发。** 代码可独立并行，构建与浏览器按实际 CPU 配额限流；保留超时诊断，不能把启动、夹具形状或加载故障当作旧布局失败。
- [ ] **交叉复核。** 以用户场景、状态转换和边界对抗检查改动；复测共享组件其他使用方。失败则修复后重测，不能绕过断言或放宽门槛凑通过。
- [ ] **真实预览验收。** 查询平台实际返回的入口，正常登录、导航、操作；核对部署版本，完成桌面/窄屏/明暗主题及核心路径。分别标记确定性数据、真实预览、真实外部集成，不能互换证明。
- [ ] **核对报告。** 每组图锁定同数据、同状态、同视口与同滚动；默认图相同的反馈修复应展示实际触发后相同时刻的反馈状态，不冒称默认布局改变。默认同图既不能证明修复，也不自动证明功能修复无效。发布后核对实际加载图的内容身份（原始字节哈希，发生转码则核解码内容与人工匹配），不能只检查nonzero或naturalWidth。报告提供可读原图缩放/前后切换，每组标明变化、不变和未证明项。
- [ ] **交付。** 更新仓库要求的 changelog/交接/债务台账；按授权提交推送独立分支。创建 PR、合并和生产发布需要各自授权。交付账本、已修页面、同条件前后截图/测量、实际操作、测试、真实预览及剩余问题。

## 受阻与安全边界

- 403、503、缺角色/数据、错误入口或版本不匹配应写“未验收”及具体原因。可继续实现和确定性回归，但不能用构建成功宣称页面优化已完成。
- 只执行当前任务授权的真实操作。验证生产配置可用只读、打开表单再取消；写入、计费调用、授权与删除等路径可用明确标记的隔离数据，并说明真实路径缺口。
- 不批准其他操作者的授权请求，不删除无关资源以获得部署空间，不绕过权限或平台门禁。
- 截图、存储状态、真实数据与凭据不进入技能包、公开代码或公开报告。可复用断言优先采用脱敏合成数据。

## 输出格式

| 页面/状态 | 目标与频率依据 | 优先级 | 人工确认的问题或保留理由 | 修复 | 前后测量/截图 | 操作与回归结果 | 真实预览结论/剩余项 |
|---|---|---|---|---|---|---|---|

全页面结论与实际覆盖一致；盘点量、URL量、共享影响面、状态格数和已治理数不得混用。真实但无任务收益证据的局部调整记录为 `minor-change`，不能为了过检查改成 `retained`。区分“代码与确定性回归完成”和“真实预览已验收”；存在受阻项时总体验收不能写全通过。

## 示例

输入：“治理管理台上游页，随后覆盖其余页面，不只出审计。”

执行：从侧栏进入上游页，发现两条记录前有重复维护卡；先固定 1440×900 与 390×844、明暗主题和两条合成记录。验收门槛为首条数据在基线基础上提前至少 60px、维护仍可展开、错误持续可见、行高/字号保持、主操作键盘可达；对照旧版证明断言失败。将维护移到数据之后并按需展开，复测其他共享清单的详情、筛选、少量和大量状态。

输出示例（数值为演示，不能复用为其他页面门槛）：桌面首条数据 411→308px，数据前已确认的多余区域 80→0px；窄屏同条件 509→406px。筛选、展开、关闭详情和错误重试通过。另一页若仅去表尾边框、首数据与操作都没变，应记微改，不能合并进上述收益计数；若仅修成功反馈6秒退场，需补“成功后第7秒”的同条件前后图。若分支预览返回 503，结论为“确定性布局通过；真实预览未验收”。随后继续账本中其余页面，保留任务必需的日志工作区高度。

## 安装与打包

技能源可放在项目已有宿主的 `skills/dechrome/`。本仓库正文只维护 `.claude/skills/dechrome/`；其他宿主按项目规则镜像，不增加第三套宿主或用户主目录。

```bash
python3 scripts/package_skill.py --output /tmp/dechrome.zip
python3 scripts/check_ledger.py /path/to/ledger.json
```

账本使用schema v2；v1必须逐项补证据或降级，禁止只改版本数字沿用旧fixed。打包命令在技能目录执行。ZIP 含 `dechrome/` 根目录与[安装说明](reference/install.md)，只使用 Python 标准库。打包可验证产物一致性，不会安装、上传或发布；项目级安装时，存在 `.claude` 和 `.agents` 两个宿主就两边都装，没有宿主则兜底 `.agents/skills`。
