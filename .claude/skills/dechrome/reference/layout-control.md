# 布局掌控：先决定注意力，再决定容器

布局应承接用户的工作顺序，并让用户预测点击后的对象、结果与返回位置。视觉简洁服务这个目的；文字、卡片、留白的数量本身不能判定好坏。

## 从实页理解原则

以下以2026-11-16匿名访问的OpenRouter公开页面为观察来源，不是对其设计规范的官方表述，也不代表登录后管理台审查。使用时仍须打开目标产品的当前页面，不能把参考站的结构直接当作目标产品答案。

| 原则 | 参考站的实际表现 | 在目标页面要回答什么 |
|---|---|---|
| 空间服从任务 | [模型列表](https://openrouter.ai/models)给筛选独立侧区，结果连续排列；[供应方页](https://openrouter.ai/provider/openai)采用较窄的居中阅读区；[模型详情](https://openrouter.ai/openai/gpt-4.1)用章节导航与较宽的数据区 | 这里是在查找、比较、维护还是阅读？宽度和分区是否支持这个任务，而非一律满铺或卡片等分？ |
| 主次是相对关系 | 名称、说明、属性用稳定位置和不同强调程度组织；同类记录的关键属性可连续扫描 | 用户先认对象，再作什么判断？正常事实、异常、辅助解释是否都在抢同一层注意力？ |
| 阅读位置要可预测 | 相邻记录延续同一结构；详情围绕当前对象组织章节和操作 | 同一事实是否总在相近位置？动作是否清楚属于当前对象？能否顺着视线找到下一步？ |
| 响应式要重新分配空间 | 手机列表的筛选通过明确入口打开独立面板；详情章节侧栏变成章节选择，属性重新排列 | 窄屏是否仍是完整任务，而不是缩小的桌面？重要状态与主操作是否直接可见，低频工具是否可发现且能返回？ |
| 信息按判断时机出现 | 模型详情长说明有明确展开/收起操作，主要属性与后续数据区保持分工 | 哪些信息现在就影响决定，哪些属于对象内部事实或可选解释？展开后能否读全，返回后是否保持上下文？ |

## 不应照搬的部分

- 模型市场介绍、供应方流量图表服务浏览与选型；维护清单未必需要。不能把参考站的大图表或介绍区搬到高频维护数据之前。
- 参考站部分描述采用省略展示，不授权裁掉名称、标识、必要状态、权限、错误或安全边界。可选说明需有完整阅读入口。
- 手机固定操作栏适用于其具体任务；目标产品必须核实遮挡、键盘、弹层和滚动归属，不盲目复制浮动入口。
- 正常配置事实可在已有对象详情中查看；缺配置、异常、未知、历史结果及其时间范围仍要在作决定的位置表达。不能把“当前配置近7天无调用”缩成没有配置边界的“无调用”。

## 改动前后的整页复核

先用一句话说明用户来此要完成什么，再分别指出定位对象、判断差异、执行主操作、确认结果的位置。找不出明确主区或下一步，就先改信息组织，不先改圆角、阴影和间距。

桌面与手机均需亲看：同类信息的对齐与密度梯度、完整对象标识、直接主操作、异常与恢复、少量数据的自然结束、大量数据的连续浏览，以及展开和返回后的上下文。参考图、整洁截图或技术检查通过不能替代这些判断。

没有遥测时不虚构频率；无法进入登录后的参考页面时明确范围。通过既有基线和验收记录说明布局改善了什么；只减字、换色或移除边框的局部工作按实际收益描述，不能升级为整页设计成熟。
