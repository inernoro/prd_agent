# 创建计划与跟踪进度

## 先创建计划

1. 理清用户要拿到的结果和任务范围。按需只读检查实际入口、现状、依赖与风险，标出影响计划的假设。目标缺失时只问一个关键问题。
2. 在对话里给出完整的 Markdown 清单。大章节按阶段，小章节按步骤，步骤下面列可独立验收的待办。每项用稳定编号和 `- [ ]`，一并写清通过条件和取证方式。阶段与待办的数量随任务规模调整。涉及新功能入口时写清用户从哪里进入。
3. 初始状态写「待确认」，填上已验收项数、当前阶段、已知问题、阻塞及下一步。只有用户确认计划或已经明确授权执行时才开工。用户只要求计划时，给出计划后停在该交付。此技能默认在对话中维护清单。用户指定计划文件或已有任务记录时，同步更新那里。向 CDS 工程规划提交提案须有相应指令或授权。

```markdown
# {任务名称}执行计划

- **目标与范围**　{要交付什么，关键依赖或假设}
- **当前进度**　待确认 · 阶段 1 尚未开始 · 已验收 0/{待办总数} 项
- **遇到的问题**　{已知问题及影响，暂无则写无}
- **阻塞与原因**　{卡住的待办、原因、影响和解除条件，暂无则写无}
- **下一步**　确认计划后开始 1.1.1

## 阶段 1 · {阶段交付结果}

### 步骤 1.1 · {步骤名称}

- [ ] 1.1.1 {待办及产出}。验收标准为{可观察结果和验证方法}。
```

## 执行时更新同一份清单

- 开始时标出正在执行的待办。每完成并验证一项，立即改成 `- [x]`，记录结果或证据，更新阶段、已验收数和下一步，并在对话中让用户看到更新。已有原生计划工具时可同步状态，仍保留带验收标准的清单。
- 未通过、未验证、等待中或跳过的项保持未勾选，并写清状态。普通问题记录现象、影响和处理进展，继续推进可执行工作。真正卡住时，写清待办编号、具体原因、已尝试动作、受影响范围、解除条件及由谁处理。可独立推进的待办继续做，解除阻塞后回到原条目。
- 继续或被问进度时，先回读已展示的计划或指定的记录，保留编号、勾选和证据。范围变化时注明原因并更新总数，保留原验收约定的变更记录。
- 收尾时逐项对照目标，展示最终清单或其入口，汇总通过证据、剩余项及原因。全部必做项通过验收后才标记整个计划完成。
