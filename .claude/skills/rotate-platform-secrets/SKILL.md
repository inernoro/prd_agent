# 平台密钥轮换

## 目标

把密钥轮换执行成可恢复的状态机，而不是一次性替换。全过程只记录密钥名称、指纹、版本和状态，不记录密钥值。

## 强制顺序

1. 读取 `references/provider-matrix.md`，列出凭据、消费者、最小权限、验证方式、旧密钥撤销点和回滚方式。
2. 先划定风险边界。只有凭据值进入了受影响的数据、日志、主机或调用链，或权限本身已经不再最小时，才进入轮换集合；同机出现其他故障不等于所有外部凭据都泄漏。
3. 运行 `scripts/rotation_state.py init --file <临时状态文件> --items <逗号分隔名称>` 建立不含密钥值的轮换台账。初始化后确认无需轮换的项目，必须运行 `exempt --reason <原因> --evidence <证据>`，不得用口头“应该没事”跳过。
4. 盘点真实消费者。检查运行容器环境、部署配置和服务日志中的键名或指纹；禁止输出值。
5. 签发新密钥。权限必须小于或等于旧密钥；能限制仓库、桶、动作、来源或有效期时必须限制。
6. 把新值写入 CDS 时通过标准输入：

   ```bash
   printf '%s' "$NEW_SECRET" | python3 .claude/skills/cds/cli/cdscli.py env set --key KEY --value-stdin --scope PROJECT
   ```

   不得使用 `KEY=VALUE`、`--value VALUE`、shell trace、命令历史或临时明文文件传密钥。
7. 部署一个明确的不可变版本，使所有消费者加载新密钥。仅修改配置但不重启消费者不算生效。
8. 分别验证新密钥的真实业务动作，而非只看配置存在：读取、写入、OAuth 登录、备份上传与校验、应用启动等。
9. 使用 `scripts/rotation_state.py mark` 记录每个项目已部署、已验证。任何消费者未验证都停止，不撤销旧密钥。
10. 撤销旧密钥后，再次运行同一组业务验证，并确认日志中没有旧指纹继续使用。
11. 清除 shell 变量和临时文件，输出只含名称、指纹、时间、验证结果和未完成项的报告。

## 安全熔断

- 新密钥验证失败：保留旧密钥，回滚消费者配置，不继续轮换下一项。
- 无法确定消费者：记为阻塞，不能按“应该没人用”撤销。
- 认定无需轮换：必须给出可复核证据，例如凭据仅存在于未受影响的 0600 进程环境文件、受影响数据中没有明文或可解密副本、主机完整性检查未发现控制权扩散。豁免不是轮换成功，报告必须单独列出。
- 提供方只给读写一体权限：先用保留锁、版本控制或服务端策略消除删除能力；做不到时明确记录风险，不能声称最小权限完成。
- 数据库凭据轮换前必须有已验证恢复副本；先新增用户或双凭据过渡，再切消费者，最后删除旧用户。
- OAuth 双密钥并存时，先部署并完成真实回调登录，再撤销旧 secret。
- 会话签名密钥轮换会使登录态失效；必须安排窗口并验证重新登录。

## 完成标准

- 每个密钥都有新版本指纹、最小权限说明、部署版本、正向业务验证、旧密钥撤销证据和撤销后复验。
- 状态文件通过 `scripts/rotation_state.py verify`，输出 `ready=true`。
- 仓库、日志、进程参数、测试报告和交接中不存在密钥值。
- 任何未完成项必须标记阻塞，不得写“全部轮换完成”。
