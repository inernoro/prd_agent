# 实战坑与处理

来自 2026-11-17 官方技能发布的实际经历。现象是排查线索，不把当时的工具缺口或环境状态变成永久规则；下一次先看实时 schema、当前源码和目标实例响应。

| 实际遇到的情况 | 下次直接怎么做 |
|---|---|
| MCP 能搜到，但 fork 返回 `TASK_INTENT_REQUIRED`，宿主工具当时只显示 `id` 参数 | 先核对/刷新实时 schema。当前服务端源码公开 `clientRequestId`，或接受 `Idempotency-Key` 请求头；只在工具确实支持时使用，同一操作及重试保持稳定。宿主仍不暴露时，取包直接 GET 搜索/详情返回的公开 `zipUrl`，不猜参数、不反复 POST、不重新上传 |
| 搜索结果是官方 `1.0.0`，`createdAt/updatedAt` 仍是固定旧日期、`downloadCount` 为 0 | 官方条目是虚拟对象，当前时间戳是固定值，官方 fork 也不累加计数。用版本、实际运行 SHA 和下载内容判断是否生效；这些字段不能证明“没更新/没人下载” |
| `sort=new` 时间游标没有发现刚上架的官方技能 | 无关键词/标签的 Open API 列表不注入一般官方目录，固定时间戳也无法表示新发布。官方更新按 key/版本检查；社区新增轮询与官方版本同步分开处理 |
| Python 默认网络请求拿到 Cloudflare `1010`，正文不是 JSON/ZIP | 保存状态、类型及脱敏正文，识别边缘拦截；改用现有 CDS CLI 的请求封装、正常浏览器或 `User-Agent: curl/8.5.0` 再走同一公开入口。不要把错误页送进 JSON/ZIP 解析器，也不关闭 TLS 校验 |
| 市场返回 `http://` 下载 URL，实际包由 HTTPS 返回 | 下载时跟随重定向并记录最终 URL，匿名读取不附带 Key。核对最终地址、内容类型、ZIP 与文件内容；别因字符串协议不同就重传包，也别无条件认定任何重定向都正确 |
| 两次下载的 ZIP 整包哈希不同，文件却相同 | 动态 ZIP 可能包含不同的时间戳；保留整包哈希作取证，但以逐文件路径、字节及允许的运行时地址替换判断一致性 |
| 分发测试通过后工作区又出现生成 JSON 的修改 | 测试会重跑生成器，通常只改变 `generatedAt`。先看语义差异，提交本次技能变化，保留已有改动；不要把“测试通过”误解成“工作区一定干净” |
| 同步主干后官方生成目录冲突或目录数量不同 | 合并源技能与注册配置后重新生成，核对既有主干条目未丢。不要拿试用时的目录数量、旧生成物或另一侧 JSON 作为答案 |
| 机器人评论仍指向旧 SHA，或 CDS 实例列表显示未接入，但默认查询已有有效入口 | 逐项核对当前调用身份、实例作用域、项目与分支。用当次权威预览查询和部署记录读回公开入口/镜像 SHA；不拿旧链接证明当前版本，也不为目录状态提示重复申请凭据 |
| 发布只改了一份内嵌目录，现有全量流程仍重建服务 | 先核对当前发布目标策略与实际变更范围，复用受管流程并连续探测入口。该次主页面一直可用，但 API 出现短暂 502/504，随后恢复；交付如实报告观察窗口与恢复，不能写成零停机。不在技能维护任务里顺手重构发布链路 |
| 正式 API 搜索和匿名下载已通过，打开市场页面仍要求企业微信 SSO 扫码 | 保留公开业务链路的成功证据，登录态页面单独写未验证；需要该 UI 验收时由真实登录完成。公开读取不需要为此索要 Key，也不伪造登录态 |

## 错误处理的出口

- `TASK_INTENT_REQUIRED` 是操作标识问题，不是技能不存在。工具写请求结果未知时先回查已有任务/结果，再决定是否重试；不要通过换标识制造第二次操作。
- HTTP 错误、`success=false`、解析错误均保留可关联本次操作的脱敏响应；不要只保留一个“下载失败”。源码、配置和鉴权问题按各自原因处理。
- 官方目录已提交但未发布，输出“源码已更新，市场仍是旧版本”；预览通过但正式未发布，输出各自实例。页面、公开 API、ZIP 内容与技能实际效果分别给结论。
- 本次验证的事实可以沉淀为流程；个人审美心得、私有截图/路径、测试账号和业务数据不进入通用技能包。
