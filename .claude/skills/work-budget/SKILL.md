# Work Budget：先看成果与代价，再开工

解决两件事：用户投入之前知道会拿到什么、值不值得；投入之后及时发现偏离，避免长时间空转或半途无交代。估时是有依据的预测，不是保证，也不能替代实际工作量和成果判断。

## 本轮做什么

- **估**：默认模式，有限只读探查后给一张可决策的开工卡，等待用户确认。不实施业务修改、不跑耗时构建或付费验证、不自动提 PR。用户已有明确范围、预算和执行授权时，沿用授权，不重复请求相同确认。
- **做**：确认具体开工卡后按范围执行，持续核验产出和剩余投入；用户可缩范围、拒绝、暂停或取消。确认目标不等于授权合并、生产发布、数据删除或付费，遵守本次权限与仓库规则。
- **校准**：用户要求复盘，或本次执行超时/严重失准时，核对原卡与实际证据，修正局部评估方法并验证。只创建本技能不等于自动评估/实施用户历史任务。

与 `/cds-plan` 同用时把阶段、待办、验收条件与预算放在同一份计划，不串行索取两次同一确认；与 game-over 同用时将实际要求的 PR/评审/部署验收等待计入估算，仍遵守合并授权。与 kill-debt 同用时每段目标任务附自身预算和前置结果；这些技能缺失不阻碍本技能使用。

## 1. 估算本身也要限量

加载技能后、读取任务资料前先取得可靠时间并记录评估开始；再读仓库/目录规则与状态，记录源码身份，保留脏工作区。发现最相关入口、依赖、测试、workflow 和少量同类交付记录，不为估时扫全仓。默认本轮评估总预算 **5 分钟**，包含探查、出卡和必要整理，只读且无付费；这是用户未指定时的评估上限，不是实施预算。探查需预留出卡时间，逐次检查耗时，临近上限不启动来不及完成的操作，直接交已知事实与缺口；扩展评估另有明确授权后进行。首次计时晚于探查时保留缺段，不能重置起点声称按时；无可靠时钟时说明无法精确计时，改为一次短探查和简短开工卡，不伪称遵守分钟上限。

优先确认会推翻方案/时长的事实：问题还存在吗、入口和依赖能找到吗、环境/凭据可用吗、已有实现能复用吗、实际 CI/Review 是否触发、验收是否含外部费用/人审/发布。仅检查凭据存在与权限状态，不打印敏感值。缺关键事实先给有限核实选项，不能一边“估算”一边偷偷完成实现，也不因缺完整资料就无限调查。

## 2. 从可验收结果拆工作量

先讲最终交付与第一份有用产物：用户实际能做什么、怎样证明、在哪里查看。说明不包含的目标和各环境边界；纯调查可交付有证据的判断，但用户要功能时不能把报告或代码骨架当功能交付。

给用户看得懂的结果样例或前后操作路径，而非只说“优化架构”。已有截图/产物可用作参照，文字示例须标明是预期效果而非实测结果；UI 或生成物的方向仍难判断时，把有明确样品的短原型作为独立可选阶段，先确认其预算，不借预览之名直接做完整实现。

按实际风险列必要工作包：复现/契约、实现与集成、测试及失败修复、真实验收、明确要求的 PR/评论闭环、适用部署/等待、交接清场。小任务合并简写，避免管理成本超过任务本身。列出依赖、共享资源、并行前提和返工触发点；不靠文件数、代码行数、测试数量推算价值。

分别估 **Agent 有效投入**、**CI/外部等待**、**用户等到结果的总时长**。总时长按依赖关键路径计算，互相重叠的等待不重复相加；并行 Agent 的累计投入不能冒充墙钟时长缩短，未获授权/不可用的并发不能计作既成条件。总成本含失败重试、集成、复验和交付，不只算写代码。付费金额/Token 未知则写未知及授权条件，不编美元或模型速度。

每个区间写依据：当前命令/运行记录、可比任务的版本与差异，或明确标为经验判断。没有历史样本不伪造 P90、成功概率或精确完成时间。高不确定性改给有明确产出的短验证阶段，验证完再决定后续；不能用“几分钟到几天”搪塞，也不能用固定倍率掩盖未知。全量目标明显大于用户预算时直接说不匹配，给可用小切片/延期/不做的选择，不假承诺全量。

## 3. 给用户一张具体开工卡

使用 [开工记录与校准](references/estimate-and-calibrate.md) 中的字段，开工卡正文默认一屏，证据可附链接，不展开完整实施计划；简洁说明：

- 最终产物、首个可验收切片、验收证据与交付终点。
- 工作包、投入/等待/总时长区间、依据与置信程度、主要未知。
- 推荐完整做/缩小做/先验证/不值得当前做，以及理由。
- **建议硬上限**与**首个成果检查点**，明确哪些是待确认建议。默认检查点建议为实施上限的 25% 与 15 分钟中更早者，小任务按实际缩短；它是进展复核，不要求提前交付完整功能。
- 达到上限时能留下什么、哪些依赖还可能阻止最终交付，以及需要用户决定的真正取舍。

估计上沿不是自动延期许可，建议上限也不是已获预算。用户说“按这张卡执行”才接受其中明确列出的范围、时间口径和上限；只确认目标、变更某个选项或含糊赞同，不能推断其接受未展示预算。已有预算的范围内常规执行不反复确认，新增代价或产出改变再交具体决策。未获实施授权时以 ESTIMATED 收口，这是本次评估任务完成，不是执行半途而废。用户已授权的调研/预算记录保存按仓库约定处理，不借此修改业务文件。

## 4. 做：按成果和预算双线复核

开工前保存确认卡的不可变基线、接受时间、技能版本、实际执行范围、时间口径和硬上限，重启/换 Agent 后能续接；优先仓库已有任务系统或会话附件，必要时用仓库外任务记录。不要把临时台账、验收报告做成产品页面或新增入库敏感文件。只有聊天记忆时明确持久化限制，不伪称已有可恢复监控。

执行期按卡片检查点、每次有意义阶段完成/失败和长外部等待复核：已耗时、实际可验收结果、剩余工作、预计还需多久、是否仍能在预算内到达承诺结果。用真实时间/工具回执，不凭叙述猜工时。工具执行/自动 CI 等待默认计入实施墙钟预算；用户审批/明确暂停区间默认单列并从实施计时扣除，不能把普通等待改名“暂停”绕过上限。计时口径可按用户明确指令变更，保留原记录；资料缺段就标未知。正常等待仍有可推进工作时继续，按宿主要求发进展，不用“持续推进”越过预算。

第一检查点没有可核查进展、同一路径重复失败未增加证据、预计剩余时间已超剩余预算，或产出与用户确认的结果偏离时，立即复核原因；能在原范围/预算内纠正则自主纠正，否则停止新增耗时工作，提交已完成结果和具体缩范围/加预算/停止选择，不等花完再说。不得靠删验收项、把功能改成报告、增加无关提交来凑“成果”。普通可修失败继续解决，真正缺授权/外部依赖、安全/预算边界触达才按边界收口。

达到硬上限不再启动实现、完整测试、部署或重试。安全停止可控且归属本任务的本地工作，不能强杀共享服务；对已发出的外部任务记录真实运行状态和取消权限，不擅自取消或重发。留出必要安全收尾，说明已完成/未完成/未验证、证据、版本、剩余资源及精确续接点，以 BUDGET_STOP 或 BLOCKED 收口，不能称完成。若用户只要快看现有成果，先交现有产物，不再开展新调查。

本技能依赖 Agent 在可执行时检查预算，**不是宿主强制计时器**。长工具调用、断线或宿主结束可能阻止及时停下；调用前设置可用的短超时/有界轮询，避免单次阻塞超过剩余预算，不能承诺离线自动停止或后台续跑。因工具越界未能及时停止须如实记录，不能倒填按时结束。

## 5. 校准：原估计保留，方法据证据修

交付、预算中止或阻塞时，对照原卡记录耗时与产出。超过原估计上沿/硬上限、检查点严重偏离、耗时虽未超但承诺产物未达到，均触发偏差复盘。单个工具超时不自动等于整体估时失败，先查工具与整体预算各自的限制。明显高估也记录，但不能因一次快交付就整体调低所有估计。

按 [校准规则](references/estimate-and-calibrate.md) 区分漏算、错误假设、范围改变、执行低效、外部故障和记录缺失；可多因，但要给时间线/证据，不写“任务比想象复杂”就完事。重新预测保留为新版本，不能改写原估计、重置计时或只扩大区间，让历史看起来准确。

用户要求失准后修本技能时，在可用授权与预算内发现技能的真实源文件，修改造成错误的局部规则/参考类，提升版本并做针对性前向测试。修技能本身也有工作量：在开工卡单列复盘/修技能的建议上限；若原任务已耗尽且没有单独修技能预算，只交现有证据与具体修正方案，取得追加预算后实施，不以“自我改进”为由继续无上限工作。不能改个人只读安装副本假称仓库已修，也不把校准授权扩大成合并/发布授权。

修正必须让相同已知失败在新规则下更早暴露，并在一个不同场景不误停、不多问授权；结构校验只证明文件有效。保留修正前后差异与证据，并用下一次真实任务检验预测表现，未经历未来实测只能称“规则修正且行为回归通过”，不能称“估时已准确”。无法归因时记录不足与下一轮需补的观测，不盲调倍率。
