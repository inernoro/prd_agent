# 文档写作原则

## 先服务决策

- 第一屏回答结论、影响和下一步。
- 技术细节放在其支持的决策之后。
- 同一事实只保留一个权威位置，其他位置使用链接。

## 区分信息性质

| 类型 | 写法 |
|---|---|
| 事实 | 给来源或可复现证据 |
| 假设 | 标明验证方式 |
| 决策 | 写负责人、日期和取舍 |
| 建议 | 写收益、成本和优先级 |
| 待办 | 写负责人和完成条件 |

## 面向非技术读者

- 用“用户会看到什么、能完成什么”解释功能。
- 首次出现的术语用一句话解释。
- 命令和路径放在操作步骤中，不用它们代替业务说明。
- 错误处理写成“出现什么现象时，下一步做什么”。

## 可维护性

- 使用绝对日期，避免“昨天”“下周”。
- 避免复制会频繁变化的完整清单，优先链接权威来源。
- 文档与代码不一致时明确标注，不静默选择一方。
- 删除无信息章节、占位语和无法执行的口号。

## 安全

- 不记录密钥、密码、访问令牌或个人敏感数据。
- 只写安全获取凭据的渠道。
- 截图、日志和示例数据在写入前做脱敏。
