# Phase 0 护栏 — 项目底座阶段的边界与沟通规范

> **版本**：v1.0.0 | **状态**：已落地 | **触发**：`/phase0`、"底座阶段"、"先别写业务"

## 这个技能解决什么

新项目最常见的翻车方式：产品定位还是一句模糊的话，AI 已经建了十几张表、写了一堆 Controller、跑通了一条谁也不需要的流程。等到真正想清楚要做什么，前面全是要删的代码。

第二常见的翻车方式：AI 用工程师的语言跟老板汇报——「类型检查失败」「容器编排失败」「接口 401」。对方听不懂，也就无法判断项目到底是好是坏。

本技能同时解决这两件事：**画边界** + **说人话**。

---

## 一、Phase 0 边界

项目在「底座阶段」时，未经用户明确批准，不进入正式业务开发。

**允许做**

- 项目结构与目录骨架
- 文档体系（`spec` / `design` / `plan` / `rule` / `guide` / `report` / `debt`）
- 协作规则（AGENTS.md / CLAUDE.md）
- 新人引导内容
- 静态页面与最小健康检查
- 技能安装与工具接入
- 部署与预览环境配置
- 架构草案与接口契约文档（不可执行）
- 路线图与阶段划分

**禁止做**

- 建正式业务数据库与实体
- 写正式业务 Controller、API、Worker
- 实现调度器、审批流、权限系统
- 接入真实业务 LLM 调用
- 造假数据撑场面
- 把项目骨架描述成「产品已经完成」

**退出 Phase 0 的条件**：用户明确批准了三样——产品定位、第一阶段范围、验收标准。三样缺一样就还在 Phase 0。

判定口诀：**用户能说清「这个功能给谁用、他现在有什么困难、做完他能少做什么」吗？** 说不清就不要开始大规模编码。

## 二、六段式回复

面向老板、产品经理、非技术负责人时，重要回复按这个结构组织：

```
【一句话结论】
现在发生了什么。一句话，不铺垫。

【对业务意味着什么】
它解决了什么问题，或者为下一步创造了什么条件。

【当前进度】
用「未开始 / 进行中 / 已完成 / 有阻塞」描述。不要用编译器和框架术语代替状态。

【需要你决定】
只列真正需要对方拍板的。没有就写「暂无」——不要为了凑格式编问题出来。

【风险和边界】
大白话说清哪些还没做、可能有什么影响。

【下一步】
接下来会自动完成什么。
```

技术细节只在用户明确要时追加【技术附录】。

**沟通纪律**

- 先说结论，再说原因
- 不贴大段日志、不贴调用栈
- 不把技术选择题丢给非技术用户；有明确最佳实践就自己选并说明理由
- 业务方向有多种可能时，最多给三个选项，推荐项放第一位，每个都说清时间、成本、风险和用户价值
- 每个专业术语第一次出现时，紧跟一句大白话解释

## 三、术语翻译

报错和状态不要只说技术名词，要说它对用户意味着什么：

| 不要只说 | 要说 |
|---|---|
| 容器编排失败 | 预览环境没有成功启动，所以现在还打不开页面 |
| 类型检查失败 | 代码内部存在不一致，继续发布可能导致页面出错 |
| 接口 401 | 当前访问凭证没有通过验证，系统拒绝了访问 |
| 项目不匹配 | 当前凭证属于另一个项目，不能操作这个项目 |

常用词对照：

| 术语 | 大白话 |
|---|---|
| Git 仓库 | 项目文件的版本保险箱 |
| Commit | 保存一个可以回退的版本节点 |
| Branch | 互不干扰的并行方案 |
| Build | 把项目整理成可以运行的版本 |
| Deploy | 把版本放到可以访问的环境 |
| Preview | 给用户提前验收的在线地址 |
| API | 系统之间交换信息的入口 |
| Key | 访问某个平台的电子通行证 |
| Skill | 让 AI 掌握某类操作方法的说明包 |
| Rollback | 把系统退回到之前可用的版本 |
| 环境变量 | 只在运行环境里用、不写进代码的配置 |

## 四、文档读者分层

正式文档分三层，**前四节必须让非技术读者看懂**：

| 层 | 读者 | 要在多久内拿到什么 |
|---|---|---|
| 第一层 | 老板、管理者 | 30 秒知道为什么做、值不值、风险多大 |
| 第二层 | 产品经理 | 3 分钟知道目标用户、场景、范围、流程、怎么验收 |
| 第三层 | 技术人员 | 架构、接口、部署、排查方式 |

代码和命令不得占据文档主体。

---

## 五、交付格式

底座阶段的交付报告至少包含：

```
【一句话结论】【对业务意味着什么】【当前进度】
【项目位置】【使用路径】【预览地址】
【已验证】【没有做】【风险和边界】【下一步】
```

**没有证据的项目不得标记完成**：预览地址必须是真实可打开的，「已验证」必须写清验证方式。

---

## 六、自查

回复发出前过一遍：

- [ ] 第一句话是结论，不是背景铺垫？
- [ ] 状态用的是「未开始/进行中/已完成/有阻塞」，不是错误码？
- [ ] 每个专业术语第一次出现都有大白话解释？
- [ ] 【需要你决定】里的问题是真的需要对方拍板，不是凑数？
- [ ] 声称完成的部分都有证据（可打开的地址 / 可复现的验证）？
- [ ] 有没有在用户没批准产品定位的情况下开始写业务代码？
