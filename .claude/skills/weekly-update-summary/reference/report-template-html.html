WHAT SHIPPED按「谁能多做什么」写

1. 模型网关具备对外发布条件

外部客户 / 合作方内部各产品线
以前
网关只能内部用。正式对外发布需要的检查项（发布前冒烟、灰度密钥隔离、费用账本核对、发布阶段报告）没打通，不敢往外发。
现在
正式发布链路全部收口——发布前自动冒烟（连不收费的通道也纳入）、灰度试探用独立密钥（不再借用业务密钥）、账本与阶段报告逐项校验、正式环境的字体与文件上传路径修好。
意味着
模型网关从「内部工具」变成「可以对外交付的产品」，具备售卖与接入谈判的前提。
验收背书通过 · 发布验收「模型网关三项能力与日志体验」(07-23)、「日志与三项能力生产闭环」(07-26)

技术出处：#1218 #1239 #1241 #1242 #1248 #1249 #1252 #1253 #1254 #1255 #1256 #1260

2. 每一次 AI 调用都能逐条查清

运维客户成功财务对账
以前
调用日志一行行挤在一起看不清，想查某次调用要翻代码或问研发。
现在
日志表重排成高信息密度，鼠标悬停就能看到相关对象，点进去有独立详情页；图片类调用也补上了同级别观测数据；手机上也能看。
意味着
客户问「我这次为什么失败 / 为什么这么贵」当场能答，不用等研发排期查日志。
验收背书通过 ×4 · 日志控制台与独立详情、请求记录信息密度与下钻、日志实体悬浮卡与详情页、请求记录信息密度与正式发布

技术出处：#1224 #1229 #1234 #1238 #1240 #1245 #1244 #1251

3. 部署平台的正式发布不再卡住、不再认错项目

所有研发团队运维
以前
正式发布页会卡住不动、排队越积越多、实时日志会断；同一个代码仓库用不同写法（带不带 https、走不走代理）会被当成两个不同项目。
现在
发布阶段能被正确识别、排队有守卫不再堆积、日志不再断流；仓库地址不管怎么写都归成同一个项目身份。
意味着
发布这件事从「要盯着、可能要重来」变成「点了就能走完」。
验收背书有条件通过 · 部署平台「数据库复制集模式」(07-23)

技术出处：#1213 #1208 #1209 #1235 #1223

4. 多项目、多租户之间的数据不再串门

所有客户合规
以前
项目级密钥能列出别的项目；预览地址会连内部备用域名一起暴露；外部长连接地址没有限制。
现在
项目密钥只能看到自己项目；对外只暴露公开预览域名；外部长连接地址收紧；灰度密钥与业务密钥隔离；单点登录边界收紧。
意味着
把「一个客户看到另一个客户的数据」这类事故的入口逐个堵上，是对外售卖前的必要条件。
验收背书本周未单独验收——这批安全改动缺独立证据，是当前最大的证据空白，已列入下周 P1

技术出处：#1212 #1221 #1218，以及周初「生产更新防护」与周末「收紧单点登录边界」两次主干提交

5. 录音转笔记真正好用了

内部团队（会议纪要）产品用户
以前
录音上传会产生重复条目，转写不是实时的，快捷录音会重复启动。
现在
录音有保护机制、会议纪要能自动整理、重复条目问题修掉、转写实时出字、录音可交互播放。
意味着
开完会直接出纪要这条路走通了。
验收背书通过 ×5 · 录音交互式播放、录音转笔记单文档体验、快捷录音与同页转录、快捷录音防重复启动、录音实时转写
