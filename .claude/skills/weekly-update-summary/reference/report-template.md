# 周报 md 底稿模板（v2 · 业务优先）

> 被 SKILL.md Phase 5 引用。生成报告时按此模板输出到 `doc/report.{ISO_YEAR}-W{WEEK_NUM}.md`。
>
> 读者是**老板 / 产品经理 / 业务经理**，不是工程师。章节顺序即优先级：读到一半停下也已拿到关键信息。
> 技术细节一律降到附录。配套：`reference/report-template-html.html`（读者交付的周刊版，与本文件同构同数）。
>
> 硬性：禁 emoji（CLAUDE.md 规则 0）；所有数字来自 git 与 `scripts/collect_week_context.py`，不许估算；
> 正文出现的内部代号必须在术语表里有中文解释（纪律 11）。

```markdown
# 周报 {ISO_YEAR}-W{WEEK_NUM} ({MONDAY} ~ {SUNDAY})

> **本周一句话**：{一句话说清本周最重要的业务进展。老板只读这一句也不亏。禁止写技术名词。}

> **统计基线**：`origin/{DEFAULT_BRANCH} @ {SHA前7位}`（采集时间 {YYYY-MM-DD HH:MM UTC}，纪律 3.5）。
> **数据来源**：git 主干提交与 PR + 日报知识库 + CDS 验收中心 + 缺陷台账 + 部署版本（纪律 12 四源）。
> {任一源不可用时，在此写明「<源名>不可达：<原因>」——禁止静默省略}
> **口径**：仅统计 `origin/{DEFAULT_BRANCH}` 主干（禁 `--all`），按提交日期文本过滤 `{MONDAY} ~ {SUNDAY}`；PR 以本周实际落地主干的 merge/squash commit 为准，不信 GitHub `mergedAt`。
```

## 与 v1 的差异（改版理由，勿回退）

| v1 | v2 | 为什么 |
|----|----|--------|
| 头部先甩提交数/行数 | 头部先给「本周一句话」 | 老板不关心行数，关心结论 |
| 无验收信息 | 质量闸置于第一节，含未通过清单 | 「做完了」不等于「做对了」，只报喜的周报无价值 |
| 无日报关联 | 一周脉络逐日挂日报深链 | 想看细节要能一键下钻 |
| 按模块/PR 组织正文 | 按「谁能做什么」组织正文 | 模块名对业务读者是黑话 |
| 技术名词直出 | 术语表 + 首次出现即翻译 | 非技术读者看不懂内部代号 |
| mermaid timeline | 表格化一周脉络 | 表格能放链接，timeline 不能 |
