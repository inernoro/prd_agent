# 生成类交付与归档参考

用于网页、PPT、报告等生成类任务的交接，尤其适合跨生成、持久化、恢复和发布的工作。
按实际变更选用相关段落；本参考不增加执行权限、审批步骤或每次必跑的测试矩阵。
具体完成数、提交号、PR、截图与在线报告放本轮验收知识库或任务外归档索引，不写死在技能中。

## 平台与智能执行的职责

- 以本项目为例，MAP 负责输入、进度、权限与预算、原稿留存、文件安全与完整性、版本、保存、恢复和发布。
- OpenDesign/Codex 等智能执行负责按用户目标设计、生成和自查；平台如实展示结果与诊断，避免重复实现一套内容评审。
- 执行器按任务选择合适的原生技能，接入不等于用对技能；模型调用沿现有 LLMGW 项目契约，不绕过网关或擅换模型池。
- 视觉反馈用于明确用户想改什么，不自动变成平台审美分数、占位词黑名单或固定修复轮数。
- 保留真实资源、路径、权限和发布安全检查；先证明触发的是安全事实，避免把合法交互文本当资源依赖。
- 需要改变职责或扩大行为时，回到用户目标和实际调用合同，不由自动 Review 意见单独授权扩张。

## 产物各阶段分别取证

| 阶段 | 能证明什么 | 不能据此宣称什么 |
|---|---|---|
| 生成 | 指定任务产出了可读取的正文或文件 | 已完整保存、已发布 |
| 保存 | 原包、清单与持久记录可读且身份关联正确 | 已在用户页面完整展示 |
| 编辑 | 原产物被按意图修改，保存后仍能恢复 | 旧任务被重新生成或历史已成功 |
| 恢复 | 同一存量结果经正常服务流程重新承接 | 原失败从未发生、可以绕过权限或版本冲突 |
| 发布 | 正常发布绑定与实际公网文件一致 | 只有容器健康或预览存在就算交付 |

区分预览与权威原包；存在结果 key 不等于对象可读，预览相同也不能代替文件清单和原包核对。
对同一产物关联任务、修订与输入来源；恢复成功后继续保留原失败记录和本次恢复事实。

## 优先保全和恢复，减少无效重跑

- 首次失败先保留原稿、持久结果、清单与脱敏错误，再判断失败发生在生成、收集、保存还是发布。
- 已有完整结果时，先核现有承接入口能否只用该结果；普通重跑按钮可能新建任务或再次调用模型。
- 承接须沿原身份、输入快照和当前版本约束，不手改数据库状态，不把预览注入为正式产物。
- 已选“仅恢复存量结果”的路径无有效结果时应明确失败，不能悄悄回退到重新生成。
- 发送前按有效预算口径核余额与在途费用风险；缺量明确估算，沿用仍有效的授权，不重复询问同一授权。
- 只在必要且已获授权时新增模型执行；用免费本地代表验证代码，不以付费重跑充当诊断循环。
- 区分一次业务执行与其内部多次模型请求；恢复前后比较同任务的调用记录，避免把内部轮次误报为重试。
- 额度、赠送来源或价格缺失时标为未知，不据“未计价”声称免费，也不推算成真实零费用。

## 登录、浏览器与并行占用

- 优先延续用户原登录与指定的内置浏览器路径，先确认当前页面、账号与目标任务，避免反复新建会话。
- 正常 SSO 与现成授权可沿用；不读取或复制浏览器令牌，不因 UI 缺入口另造凭据或绕过授权。
- 多人并行时说明谁持有浏览器、工作树、发布窗口及共享资源；使用各自隔离工作树保留他人改动。
- 只读观测与执行分开，重复点击前先确认原任务是否仍在运行；等待方不另发同一业务任务。
- 协调记录不能冒充独占锁或发布授权；实际占用、生产身份和现行发布规则仍以执行时事实为准。

## 进度清单与可读报告

- 以原需求逐项列当前阶段、开发状态、验收结论、证据入口、未完成原因与下一步。
- 开发通过、云端检查、真实发布和业务验收分别标记，未知或未执行保持原样，不用一个“完成”覆盖。
- 长任务展示已有阶段与日志；模型请求成功不等于收集或保存成功，前端等待结束也不等于服务端已取消。
- 报告先写用户现在能做什么、哪些仍不能做，再给真实路径、可读截图和必要诊断证据。
- 截图使用本次实际环境与操作结果，保留首失败，避免用加载图、旧部署图或模拟页面替代结果。
- 归档前打开在线报告检查正文与证据是否可读；报告发布成功和被测业务通过是两个结论。

## 主干与实际生产分别对账

- PR 合并只证明修改进入对应目标分支；是否进入主干、实际生产 revision、运行配置与静态产物分别核对，不能互相替代。
- 热修复沿现有发布技能，以最新实际生产为基线最小承接已验修改，保留他方业务，不整树覆盖主干。
- main 合并提交不是生产提交的祖先，不能直接判定漏发；热修复或拣选承接需核有效内容等价与继承证据。
- 同源校验可在证明完整输入一致时复用；输入改变就说明影响，不拿旧提交的云端绿门签新候选。
- 区分实际构建、跳过、运行中与失败；按现有发布合同核对目标提交的 CI、官方产物及真实入口。
- 主干前进按保护规则正常同步并核范围，出现冲突或目标合同变化先收口，不循环追赶或绕过保护。
- 生产准备、发布窗口与业务验收由当前授权确定；历史例外、旧批准不自动转给新提交或新范围。

## 旧 PR 留存与会话归档

- 逐项记录本任务 PR 属于已合并、有效修改已由其他提交承接、仍有有效未合内容或后续债务。
- 混合 PR 按功能核归属；关闭旧 PR 不证明全部修改已承接，也不证明原需求已验收。
- 对仍有效的代码给出保留位置或承接提交，对未关闭问题保留稳定债务或 issue、影响与关闭条件。
- 用户选择搁置时记录该决定及共享影响，保留未完成结论；不为凑齐清单擅改共享配置或公共上游。
- 会话归档本身不授权删除源码、分支、证据或债务，也不代替正常 PR 合并与复核。
- 只归档用户授权的会话范围，不把某个会话的收尾扩大为整个共享项目的清理或归档。

交接最终给出当前结果、实际证据索引和剩余责任人；按需保留限制，不重新发起已完成的生成或验收。
