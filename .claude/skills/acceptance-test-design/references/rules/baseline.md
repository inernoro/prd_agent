# 通用验收基线

## 适用范围

当目标仓库没有更高优先级的验收规范时使用。本基线不绑定具体组织、平台、报告系统或技术栈。

## 最低契约

1. 验收范围必须锚定需求、缺陷、PR、commit、版本或明确时间窗口。
2. 每个结论必须对应可观察断言和主证据。
3. 用户界面、API、后台任务、部署和数据迁移使用与其责任边界一致的证据。
4. 环境不可用、权限不足或关键依赖缺失时结论为阻塞，不拿错误页冒充功能证据。
5. 不可逆操作必须有隔离数据、清理方式和停止条件。
6. 报告必须区分已执行、未执行、未覆盖和失败。
7. 密钥、密码、访问令牌和个人敏感数据不得进入报告、仓库或公开日志。

## 建议档位

| 档位 | 适用情况 | 最低要求 |
|---|---|---|
| L0 | 文案或低风险局部改动 | 主路径、目标状态、一个负面检查 |
| L1 | 常规功能、接口或交互改动 | 角色、主流程、异常、持久化或刷新后状态 |
| L2 | 权限、支付、迁移、发布或高风险链路 | 多角色、并发/恢复、真实环境、回滚和可观测证据 |

档位不决定截图数量，只决定风险覆盖深度。

## Verdict

- `PASS`：所有必测断言有合格主证据，且没有未处置的阻断问题。
- `FAIL`：至少一个必测断言失败，或出现安全、数据、权限等阻断问题。
- `PARTIAL`：部分范围通过，但存在明确未覆盖项；不得表述为完整通过。
- `BLOCKED`：环境或输入使验收无法可靠执行。
