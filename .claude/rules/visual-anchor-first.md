# 视觉锚点优先（不许凭空赌品味）

**一句话**：没拿到「像什么」的锚点之前，不要动手做视觉——凭意图直接生成界面是掷骰子，掷三次不中是概率问题不是努力问题。
**什么时候撞上**：接到「做个页面 / 改版 / 美化一下」而对方没给参考、没给设计系统的时候。

---

## 一、这条规则的由来

2026-09-09 做公共藏书阁，连赌三版全被否：

| 版本 | 我赌的方向 | 用户的判词 |
|---|---|---|
| 一 | 卡片列表平铺 | 没气质 |
| 二 | 东方藏书楼（宋体巨字 + 朱印 + 竖排 + 纸纹） | 好老气 |
| 三 | 四个方向让他选（便当格 / 编辑部 / 终端 / 路径） | 丑死了 |

换了设计师智能体重做，同样被判丑。用户原话：「你俩难道卧龙凤雏两位吗」。

转折点是一句话：**「像 Linear」**。从那句起，收敛只用了两轮——因为不用再猜了。

---

## 二、根因：中间那一层是空的

人类设计师接这活的顺序是：

```
意图 → 找参考（Dribbble / Mobbin / 竞品截图 / 自己常用的 App）→ 定「像谁」→ 动手
```

AI 直接跳成：

```
意图 →（空）→ 像素
```

中间那层**视觉锚点**没有，就只能从训练分布里取一个「典型的好设计」——而典型即平庸。更糟的是反馈粒度：「老气」「丑死了」只能告诉你结果不对，告诉不了你哪里不对，所以第二次的命中率和第一次一样。

**这不是努力能补的**，加大投入只会把同一个骰子掷得更用力。

---

## 三、强制动作

### 1. 动手前先要锚点，一句话就够

问法要具体到能收敛，别问「你想要什么风格」（对方答不上来）：

> 「像哪个产品？Linear / Notion / 小红书 / Vercel，或者随手截一张你觉得顺眼的图。」

对方给了名字或图，就**去把它的真实度量抠出来**（下一条）。给不出来，用第 4 条兜底。

### 2. 锚点是拿来量的，不是拿来念的

说「像 Linear」然后做出一个圆角 22px、标题 82px、满屏渐变的东西，那不是 Linear，是**仿冒品**。本仓库真实发生过：

| | Linear 的真实度量 | 我第一次"仿"出来的 |
|---|---|---|
| 圆角 | 6–8px | 22px |
| 正文 | 13px | 15–16px |
| 列表行高 | 36–40px | 60px+ |
| 强调色 | 只在选中态与主按钮 | 到处都是 |

**每个度量都放大了一倍**。所以：锚点在站内就去读源码（`grep -oE "(border|boxShadow|borderRadius|fontSize)[^,;]{0,90}" 目标文件 | sort | uniq -c | sort -rn`），锚点在站外就凭对它的具体记忆列出度量表并写进注释，让下一个人能核对。

### 3. 站内已有的皮，永远优先于站外的

「借用 XX 页面的风格」是最好的锚点——它可以被 grep，度量是硬的，而且天然和产品一致。本仓库做藏书阁最后就是借了智识殿堂（`pages/library/LibraryLandingPage.tsx`）的粗野骨架，只换配色。

### 4. 拿不到锚点时的兜底：把赌注拆小

不要赌整页。做**一个组件的 N 个变体**（一张卡片、一个列表行），一次给 6–8 个，让对方指一个，再往外放大。反馈从「整页重做」变成「选一个」，成本降一个数量级。

### 5. 主观词要变成可指的档位

「太吓人」「清淡一点」「老气」都是不可执行的。把它变成**带实测数值的档位表**让对方指：

- 「对比度吓人」→ 四个力度档，每档标 WCAG 实测比值（14.9:1 / 9.9:1 / 7.2:1 / 5.3:1）
- 「要背景」→ 四种背景按缩略图并排，标浓度百分比
- 「配色」→ 四套并排，每套浅暗双档

**一次对比胜过三轮猜**。做档位表时注意别把无障碍指标调穿——本仓库第一版档位表把次文压到 2.4:1（AA 下限是 4.5），调淡不等于调到看不清。

## 四、自查清单（动手做任何视觉之前）

- [ ] 我有锚点吗？（一个产品名 / 一张图 / 站内一个页面）
- [ ] 没有的话，我问了吗？还是直接开始猜了？
- [ ] 有锚点的话，我把它的**真实度量**抠出来了吗，还是凭印象仿？
- [ ] 站内有没有现成的皮可以借？（借站内 > 仿站外）
- [ ] 拿不到锚点时，我是在赌整页，还是拆成变体让人指？
- [ ] 对方给的是主观词吗？我把它变成带数值的档位表了吗？
- [ ] 档位表里的极端档有没有调穿无障碍下限？

## 五、与其他规则的关系

- `design-replication` 技能：拿到设计稿之后的还原流水线。本规则管的是**它之前那一步**——连稿都没有时怎么办。
- `miduo-review-lens.md`：交付前用用户的眼睛过一遍。本规则更早：**动手前**先拿到用户的眼睛看惯了什么。
- `chief-designer-usability.md`：管好不好用；本规则管好不好看这件事该怎么收敛。
- `admin-dual-theme.md`：锚点定了之后，颜色一律走 token，不许硬编码。
