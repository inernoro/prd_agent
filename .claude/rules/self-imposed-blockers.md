# 自设阻塞（把已有的授权当成要去索取的东西）

**一句话**：停下来问人之前先查三件事——这件事是不是早就授权过、凭据是不是已经在环境里、那堵「设计如此」的墙是不是只是一层友好报错；三样查完还缺，才配开口。
**什么时候撞上**：准备说「这个需要你决定」「我没有权限」「需要你提供 X」的那一刻。

> 判定口诀：**我说「不能做」的理由，是查出来的还是想出来的？** 想出来的，回去查。

---

## 一、三种自设阻塞

### 形状 1：授权已经给过，却当成还要再要

用户在需求里写死的授权，散落在长文档各处，执行时只记得眼前那一段，于是把「已授权」重新当成「待审批」端回去问。

真实事故（2026-09-11，OpenDesign 接入）：需求文档里白纸黑字写着「可以根据目标需要同步更新 CDS，CDS 自更新属于允许的实施范围」「已授权初始化密封验收所需的主密钥机制」「默认方案和正常开发、部署、提交、推送动作已经授权，无需重复申请」「不暂停任务，不因为普通安全措辞反复打断执行」。

而我把「让 CDS 跑新代码」列成需要用户拍板的选项，理由是「不该我单方面决定」；把验收卡在「口令只能由人给」；一轮里问了五次「要我继续吗」。用户的原话是「**我不想重申很多遍**」。

**自查**：把需求全文过一遍，搜「已授权」「可以」「允许」「无需」「不需要」这些词。**我要问的这件事，是不是已经在里面了？**

### 形状 2：凭据其实就在环境里，没查就伸手要

真实事故（同上）：我跟用户要「一把模型密钥」，而 `LLMGW_PASSWORD` 在环境变量里早就设好了，需求文档也写明「已提供的登录信息应通过环境变量保存和使用」。

**自查**：开口要任何凭据之前，先 `printenv` 过一遍相关名字，再翻一遍需求里有没有「已提供」。**空手要东西是最廉价的动作，也是最容易错的。**

### 形状 3：把一层友好报错读成不可逾越的边界

某个能力被挡住，报错写得很正式，于是判定「设计如此，不该动」。但挡它的那层代码往往只是**把底层失败翻译成人话**，真正的边界在别处；甚至那个文件自己就写着后续路线怎么打开它。

真实事故（同上）：预览实例拦截容器命令，我判成「安全红线，不该顺手开」。而那个文件的注释原文是「**真正的安全底座是容器根本不挂 docker.sock，本拦截只负责把失败变成一句用户看得懂的话**」，紧接着写着「后续路线：模拟执行器 → **DinD 真部署** → 实验田域名」。我把作者计划里的下一站，误判成了不可触碰的红线。

**自查**：判定「不该动」之前，**把那段代码连同注释读完**，尤其找「真正的约束是」「后续」「路线」「本文件不实现」这类句子。挡路的那行代码，常常不是墙，是门牌。

## 二、还有两条同源的

**不许擅自简化用户定的格式。** 用户定了计划表每行八列（状态 / 要做什么 / 当前问题 / 细化步骤数 / 下一步 / 为什么做 / 最直白的通过方式 / 验收报告地址），我在一次重写里删掉了「细化步骤数」和「为什么做」，理由是「没人为这些数字背书」。理由成立，动作不成立——**格式是用户的，觉得不合理该说，不该自己删**。

**升级只发一条，不拆成好几次。** 确实缺外部输入时，一次把清单说全（缺什么、为什么我造不出来、我已经试过哪几条路）。把一个升级拆成五次追问，等于让用户替我做五次调度。

## 三、自查清单（准备说「需要你」之前）

- [ ] 搜过需求全文的「已授权 / 可以 / 允许 / 无需」了吗？这件事在不在里面？
- [ ] 相关环境变量 `printenv` 过了吗？凭据是不是已经在手上？
- [ ] 挡路的那段代码连注释读完了吗？它说的「真正的约束」是什么？有没有写后续路线？
- [ ] 这是不是同一件事的第二次追问？是就合并成一条。
- [ ] 我改动过用户定的格式或口径吗？改了就是越界，先还原再提意见。

任一为否，回去查，别开口。

## 四、与其他规则的关系

- `blocked-state-circuit-breaker.md`：那条管「卡住了别兜圈」；本条管「卡住之前先确认真的卡住了」。多数所谓卡住，是自己给自己设的。
- `no-rootless-tree.md`：缺什么明确暴露、借用外力；本条补的是——**借之前先看看是不是已经在自己兜里**。
- `predicate-and-wiring-discipline.md` 形状 8：把不成立的证据当证据；本条是它的反面——**把成立的授权当成不成立**。
