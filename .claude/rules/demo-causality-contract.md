# 演示的因果契约（点了才所得）

**一句话**：演示型界面里每一次状态翻转都得有可见的施动者——旁白说「点了」，画面上就必须有一只手在那一拍按下去，且顺序是先走到、再按下、然后那件事才发生。
**什么时候撞上**：做自动播放的产品演示（首页各幕、功能预览、录屏式动画），或给这类界面补动效。

> 判定口诀：**把演示静音、遮住旁白，光看画面——能看出「是谁让它动的」吗？** 看不出，就是东西自己在变。

---

## 一、为什么这条单独成规

「东西自己在变」不会报错、不会红、通读代码也挑不出来。它只在一个人真的坐下来看完一遍时才显形，而那个人通常是用户。

本仓库首页九幕，长期是「有节拍、没施动者」：旁白写着「点了 AI 改写」「点运行」「选一个」「点通过」，画面上浮层自己冒出来、流水线自己开跑。**同一个洞开了六次**，因为每次都是一幕一幕单独做的，没人问过「这九幕合起来，因果讲得通吗」。

---

## 二、三条契约

### 契约 1：旁白宣称的动作，画面上必须真的发生

旁白里出现点击类动词（点了 / 划中 / 选中 / 按下 / 勾选 / 拖进）的那一拍，就必须有一次可见的按下。

- 反过来不要求：动作发生了但旁白只写结果（「已发送」「换个风格」），照样该有手。
- **打字类动词（输入 / 敲 / 搜）例外**：那一拍指针该停在输入框上，**不该按下去**——按下去反而是假动作。
- 纯系统叙事的幕（一条请求穿过三层、模型池自动切换）本来就没有人在操作，不要为了「有手」硬加手。判据是旁白：它没宣称动作，就不需要手。

### 契约 2：先走到，再发生

顺序固定为「移过去 → 按下 → 然后那件事才发生」。反过来（东西先变、指针后到）**比没有指针更假**——它明确告诉观众这只手是贴上去的装饰。

落地要点：

- 目标在下一拍才被点 → **提前一拍**把指针停在它上面，到点那一拍就是「原地按」。
- 指针需要走位时，按下的视觉必须**延迟到走位结束**（波纹、按下动画都延后一个走位时长）。
- 按下是**一次完整手势**（按下去、弹回来，约 260ms），不是挂在整拍上的状态——一拍常有 1–2 秒，状态挂整拍看着像鼠标键被摁住不放。

### 契约 3：落点认元素，不认坐标

指针每一拍只声明**指向谁**（目标元素上的标记），实际落点运行时量。

手写百分比必然漂：演示面板里常有偏移子容器（给侧栏让出宽度的画布、独立定位的顶栏），指针挂在面板根上而目标活在子容器里，两套坐标系差着一整个侧栏的宽度，怎么调都对不上。跨行的行内目标（被划中的一段文字）要取**最后一个行框**，否则落在段落框右边的空白里。

## 三、怎么审查（三层，由便宜到贵）

「每次点击都截图」是能想到的最笨的办法，只配当兜底，而且只截被前两层点名的那几帧。

| 层 | 手段 | 抓什么 | 成本 |
|---|---|---|---|
| 1 | **静态守卫**（CI 每次跑） | 旁白有动词、走位表没按下 | 零 |
| 2 | **衔接录像机**（真浏览器逐帧） | 「凭空出现」：某一刻一堆东西变了，之前没人点过 | 几分钟 |
| 3 | **截图** | 只对 1、2 报出来的那几帧取证 | 人工 |

本仓库的落地：守卫 `prd-admin/src/lib/__tests__/sceneSeamContract.test.ts`（契约 1）与
`sceneCursorWiring.test.ts`（契约 3）；录像机 `prd-admin/scripts/landing-seam-audit.mjs`。

**录像机的一条硬经验**：判据不许挂在亚秒动画上。无头浏览器在软渲染（SwiftShader）下实测
rAF 约 400ms 才出一帧，500ms 的波纹只落 1–2 帧，采样必然漏——第一版就是这么测出
「按下 0 次」，差点当成真结论。按下要另外暴露一个**整拍都成立的机读属性**给工具读，
视觉归视觉、判据归判据。

## 四、自查清单（交付任何演示型界面前）

- [ ] 遮住旁白只看画面，能看出是谁让它动的吗？
- [ ] 旁白写了点击动词的每一拍，都有一次可见的按下？
- [ ] 打字那一拍是「停在输入框」而不是「按下去」？
- [ ] 每次按下都是**先到位再按**，不是一边飞过去一边已经发生了？
- [ ] 按下是一次手势，不是挂满整拍的状态？
- [ ] 落点声明的是元素，不是手写坐标？
- [ ] 纯系统叙事的幕，没有为了凑手而硬加手？

## 五、与其他规则的关系

- `expectation-management.md`（预期管理总纲）：本规则是它在**演示**这一面的落地——观众的预期是「有人在操作」，画面必须兑现。
- `miduo-review-lens.md` 镜头 4（变化可感知）：那条管「变了要看得见」，本条进一步管「变化得有主语」。
- `predicate-and-wiring-discipline.md` 形状 2（链路只建一半）：指针量不到目标会**静默消失**，页面照常渲染、测试照常绿——契约 3 的守卫正是为这种静默退化设的。
- `closed-loop-acceptance.md`：那条管「产物要真的出现在截图里」，本条管「产物出现之前那只手要真的按下去」。

## 六、历史背景

2026-08-28 用户看完首页：「完整度大概 80%，衔接部分有点问题，你可以想个办法，如何审查衔接
（所见即所得，点了才所得）……最笨的办法就是每次用户点击、触发效果都截图看看，这样当然很蠢，
不过算作兜底的办法了」，并要求「从更高的维度来看，而不是我说一点你改一点」。

按此写了衔接录像机去量，才发现问题不是零散的：九幕有节拍、只有两幕有施动者，另外五幕的旁白
全都在宣称没有发生的点击。本规则与两条守卫同批落地。
