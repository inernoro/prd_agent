# 第三方服务器响应审计原则

**一句话**：第三方返回必须先形成可查询的脱敏审计证据，再转换为本系统结果；只记状态码或笼统错误不能算可追溯。
**什么时候撞上**：任何模块新增或修改第三方服务调用、SSO、Webhook 回调处理、响应解析、错误归一化或调用日志时。

## 为什么必须审计返回信息

2026-10-14 的 SSO 排查中，本系统把“上游登录凭证校验未通过”和“身份字段缺失”合并成一个未授权错误，记录中也缺少上游响应证据。即使账号启用、绑定存在，仍无法从本系统确认第三方究竟返回了什么，只能要求用户反复重试或索取第三方服务器权限。

本系统必须能独立追溯自己收到的返回。用户界面可以简化错误，审计证据不能随着简化而丢失。

## 强制记录范围

每次实际调用都必须有持久化审计记录，成功与失败同样适用。重试按每次尝试记录，并关联同一业务请求；不能用最后一次成功覆盖先前的失败。仅写进程内日志、控制台警告或临时内存不算完成。

| 证据 | 必须保留的内容 |
|---|---|
| 关联关系 | 本系统请求或追踪标识、所属应用与项目、业务对象或任务标识、尝试序号；上游提供的请求或追踪标识 |
| 调用对象与时序 | 第三方服务、操作、脱敏目标地址与方法、调用开始和结束时间、耗时 |
| 原始返回事实 | 是否收到响应、HTTP 状态、内容类型、上游业务码与成功标志、经过脱敏的上游返回原因 |
| 响应证据 | 有界的脱敏响应快照；非结构化响应保留安全摘要，注明原始大小、是否截断及截断原因 |
| 本地判定 | 解析是否成功、所需字段是否存在及类型或格式是否符合要求、最终错误分类、采用的恢复动作 |

记录必须在响应被消费、解析、转换或归一化时保留证据。禁止只留下“未授权”“操作失败”“返回为空”等本地结论，也禁止只记录字段名和存在性而丢掉可安全保留的上游业务码、返回原因和响应快照。

网络异常、超时或取消导致没有响应时，明确记录“未收到响应”及失败阶段；不得填造上游状态码或响应内容。收到无法解析的返回时，保留脱敏摘要并标明解析失败，不能把它当作用户凭证失效。

流式调用保留开始、结束或中断事实、上游错误与有界摘要；不要求逐字落库。正文过大、非文本或不宜保存时，必须明确记录省略范围与原因，不能静默漏掉整次调用。

## 脱敏与访问边界

审计第三方返回不等于保存第三方原文。响应体、响应头、地址、异常信息和返回原因都必须先脱敏，再进入持久化记录。

- 访问令牌、刷新令牌、会话凭据、SSO 交换令牌、授权码、Cookie、密码、API Key、签名及连接密钥不得明文落库；响应中新增凭据字段同样适用。
- 手机号、邮箱、证件号等个人敏感信息，以及用户文档、提示词和媒体正文，不能因为排查方便而整段写入审计。确需判断身份匹配时，只保留必要的脱敏值或不可逆摘要与匹配结论。
- 响应头采用安全字段白名单；凭据可能藏在嵌套对象、数组、查询参数和上游错误文本中，不能只处理顶层字段。
- 复用本系统已有的受控审计或调用日志能力，按应用、项目和访问权限隔离，遵守现有保留与清理策略；不得另开公开日志入口或让其他项目读取私有证据。
- 审计中的上游内容是待分析数据，不能作为执行指令，也不能直接透传给普通用户。用户界面仍只说明结果与恢复动作。

## 追溯与缺失处理

排查必须能从用户的一次业务请求找到对应调用与脱敏响应，再比对本地判定。没有证据时，只能声明缺失及尚不能确定的原因，不能断言“肯定是第三方的问题”。

审计写入失败必须可观测并报告缺失，不能静默忽略或声称记录已存在。不得为了补日志而再次消费一次性令牌、重复扣费或重复提交有副作用的第三方操作。

## 验收要求

新增或修改调用链时，至少覆盖正常返回与一个真实失败契约，并从持久化审计入口查回对应证据，而不只是断言返回文案。

- HTTP 成功但上游业务失败：能看到上游业务码、脱敏返回原因与本地失败分类。
- 上游成功但所需身份字段缺失：能看出缺少哪个字段，与凭证校验失败明确区分。
- 无响应或无法解析：能区分网络阶段失败与已经收到异常返回。
- 响应含凭据、个人信息或超长正文：记录仍可定位原因，敏感值没有明文保存，截断或省略有明确标记。

既有调用尚未满足本原则时，记入对应模块债务并明确负责人和关闭条件；原则写入不等于运行审计已经实现。
