# 项目发布合同不可绕过

**一句话**：项目维护并通过 CI 的发布脚本是默认入口，CDS 只执行指定提交，不推断业务部署方式。
**什么时候撞上**：修改发布策略、执行器、发布界面、CI 或发布技能时。

- 默认文件名是 `cds-release.sh`，支持 check / deploy；项目代码或资源变化必须同步维护发布兼容性。
- `project-script` 必须读取完整提交的 Git blob，不读取脏工作区或服务器旧文件；同提交 CI、语法、正文指纹和 check 均不得跳过。
- `managed-script` 仅由用户明确选择并单独审查，不因为项目文件缺失自动兜底。旧部署模式只兼容已有目标。
- 禁止为使发布变绿而删校验、借用其他提交 CI、热改服务器脚本或换旧模式；失败应通过项目 PR 修合同并重新 CI。
- 历史回滚使用不可编辑的脚本正文证据与原提交；远端仍必须核对 Git 文件正文。预览工作区退役不能丢失历史取证。
- 项目脚本部署或最终检查失败后恢复上一成功记录，保留本次失败及恢复证据；取消后不允许继续写入。
- 修改合同同步后端、前端、目标历史指纹、技能和回滚，补真实 Git 与脚本执行测试；推送前完整测试及两端类型/构建，云端全绿后才合并。
- 发布完成必须经过真实控制台路径并检查公网 HTML、入口资源与健康状态，不能把 API 诊断当用户验收。
